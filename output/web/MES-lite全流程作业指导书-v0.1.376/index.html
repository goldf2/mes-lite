1. 登录与工作区导航

流程 001

使用站内帮助中心

目的按当前账号权限搜索并阅读当前版本的作业指导书。

  1. 在任一工作区展开“工作台”菜单。
  2. 点击“帮助中心”。
  3. 需要独立全屏查看时，在快捷帮助中点击“打开完整帮助中心”，系统会新开页面且保留当前业务页面。
  4. 使用搜索框输入页面、单据、岗位或操作关键字。
  5. 展开目标流程，逐步操作并核对结果检查。

结果检查独立帮助页面显示系统版本、可读流程数和章节；无权限的流程不会出现，原业务页面保持不动。

流程 002

查看当前页面操作帮助

目的不离开当前业务页面即可查看与该页面关联的操作流程。

  1. 进入需要操作的业务页面。
  2. 点击顶部问号按钮。
  3. 在右侧抽屉展开相关流程并查看步骤、结果和截图。
  4. 点击“新页面全屏查看”只查看当前功能，或点击“打开完整帮助中心”在新页面检索全部流程。

结果检查抽屉只显示当前页面且当前账号有权读取的 SOP；两个底部入口均在新页面打开，不中断当前业务操作。

流程 003

登录系统

目的使用分配的操作员账号进入系统。

  1. 打开系统登录页。
  2. 输入登录账号和密码。
  3. 点击“登录”，等待工作台加载。

结果检查顶部显示当前人员名称，左侧出现有权限的功能菜单。

流程 004

查看工作台

目的在班前确认生产、库存和待办概况。

  1. 进入 MES 工作区。
  2. 查看常用功能、生产负荷和待处理事项。
  3. 发现红色或橙色预警时进入对应功能核查。

结果检查统计卡片与当前演示业务数据一致。

流程 005

使用所有功能

目的从完整功能目录进入业务页面。

  1. 在工作台点击“所有功能”。
  2. 按业务分组找到目标功能。
  3. 只会显示当前账号拥有权限的页面。

结果检查页面按物料、生产、物流、库存、配置、工具等分组。

流程 006

切换 ERP 工作区

目的进入销售、发货和退货业务。

  1. 点击左上角“ERP”工作区。
  2. 点击“所有功能”。
  3. 选择销售订单、发货管理或退货管理。

结果检查左侧菜单切换为 ERP 业务导航。

2. 物料与 BOM 主数据

流程 007

查询物料

目的查询物料编码、规格、单位和库存概况。

  1. 进入 MES > 物料 > 物料管理。
  2. 使用顶部搜索框输入编码、名称或规格。
  3. 需要时切换列表/卡片视图并打开详情。

结果检查目标物料及库存单位正确显示。

流程 008

新建物料

目的建立可用于库存和生产的统一 Material 主数据。

  1. 点击“新建物料”。
  2. 填写编码、名称、规格、分类、库存单位和主要计量方式。
  3. 按需要填写默认价格、安全库存和客户。
  4. 保存后返回列表复核。

结果检查新物料可被 BOM、订单、收发货等业务选择。

流程 009

进入 BOM 工作区

目的查找物料并维护 BOM 版本。

  1. 进入 MES > 物料 > BOM 设置。
  2. 搜索并选择目标产出物料。
  3. 查看当前版本、状态、输入项和输出项。

结果检查BOM 工作区显示目标物料和版本状态。

流程 010

维护并发布 BOM

目的定义整批投入、主产出和副产出。

  1. 新建或打开草稿 BOM。
  2. 填写基准产量、投入物料、数量和单位。
  3. 维护主产出与副产出比例。
  4. 校验无误后发布，生产只能引用已发布版本。

结果检查发布版本显示“已发布”，投入单位与物料计量方式一致。

3. 生产订单与班后实绩

流程 011

查看生产订单

目的查看生产计划及统一状态。

  1. 进入 MES > 生产 > 生产订单。
  2. 按订单号、物料或状态搜索。
  3. 关注草稿、已发布、生产中、已完成和已取消状态。

结果检查列表显示计划数量、日期、BOM 和当前状态。

流程 012

新建生产订单

目的建立物料化生产计划。

  1. 点击“新建生产订单”。
  2. 选择产出物料、已发布 BOM、计划数量和计划日期。
  3. 填写班组或备注后保存。

结果检查订单以“草稿”创建，此时不可登记实绩。

流程 013

发布生产订单

目的将已复核计划转为可执行任务。

  1. 打开草稿订单详情。
  2. 核对物料、数量、日期和 BOM。
  3. 点击“发布订单”并确认。

结果检查状态由“草稿”变为“已发布”。

流程 014

确认订单可执行

目的确认发布后实绩入口已经解锁。

  1. 发布完成后重新查看订单详情。
  2. 确认状态为“已发布”。
  3. 确认“登记班后产量”按钮可用。

结果检查发布状态与操作按钮保持一致。

流程 015

登记班后生产实绩

目的按人员、设备、作业文件、投入和产出记录可回放的班后实绩。

  1. 点击“登记班后产量”。
  2. 填写实际日期并从启用员工中选择一人或多人。
  3. 从订单工作中心范围内选择本次实际使用的设备。
  4. 选择适用于订单物料或工作中心的已生效作业文件。
  5. 按现场记录填写实际投入、主产出、副产出及库位。
  6. 保存后先核对实绩草稿中的人员、设备和文件版本快照，再执行确认。

结果检查实绩草稿保存成功；确认前必须同时具备设备和作业文件快照，或分别填写明确的例外原因。

流程 016

核对生产实绩执行上下文快照

目的确认班后实绩保存的是当时实际设备和作业文件版本，而不是可漂移的主数据引用。

  1. 打开生产订单详情并找到目标班后实绩。
  2. 在“实际设备”中核对设备编码、名称、型号、状态和所属工作中心快照。
  3. 在“作业文件”中核对标题、版本、状态、类别、适用物料和工作中心快照。
  4. 主数据后续调整时，以实绩卡片保存的历史快照解释当时执行条件。

结果检查实绩卡片独立显示人、机、法证据；来源设备或文件后续修改不会改写既有快照。

流程 017

登记无设备或无作业文件的例外

目的在合法的无设备或无文件场景保留可审计原因，避免用空值伪装完整执行记录。

  1. 在登记实绩时确认本次确实没有可选择的实际设备或适用作业文件。
  2. 对应选择保持为空，并在其例外原因中填写 2 到 200 个字符的具体说明。
  3. 继续核对人员、投入、产出和库位后保存草稿。
  4. 确认前再次核对例外原因；确认后原因与上下文快照均不可修改或删除。

结果检查每一类缺失上下文都有明确原因；手机端保持单列滚动和底部保存操作，不遮挡最后一项。

4. 生产产出批次与质检

流程 018

查看产出批次与质量状态

目的从生产实绩核对内部批次、检验单和当前库存状态。

  1. 进入生产订单详情并展开已确认实绩。
  2. 在每项产出下查看内部批次号和检验单号。
  3. 区分待检、已放行和冻结状态。

结果检查每项新产出具有唯一内部批次，待检任务只允许判定一次。

流程 019

填写合格判定

目的记录抽样结果并准备整批放行。

  1. 在待检批次点击“合格放行”。
  2. 录入抽检数量、合格数量和不合格数量。
  3. 填写检验结论说明并核对批次号。

结果检查合格数量与不合格数量之和等于抽检数量，整批合格时不合格数为 0。

流程 020

确认整批放行

目的把检验合格的整批产出从待检转为可用。

  1. 点击“确认整批放行”。
  2. 等待保存成功并刷新订单详情。
  3. 核对批次状态、判定人和抽样结果。

结果检查批次显示“已放行”，待检库存减少、可用库存增加。

流程 021

填写不合格判定

目的记录不合格样本和冻结原因。

  1. 在另一待检批次点击“不合格冻结”。
  2. 录入抽检、合格和不合格数量。
  3. 在说明中写清不合格现象和冻结原因。

结果检查抽样关系校验通过，说明可供后续处置人员理解。

流程 022

确认整批冻结

目的阻止不合格产出进入领料或发货可用量。

  1. 点击“确认整批冻结”。
  2. 等待保存成功并刷新订单详情。
  3. 核对批次状态、判定人和抽样结果。

结果检查批次显示“冻结”，待检库存减少、冻结库存增加。

流程 023

核对库存状态

目的在库存总账复核质量判定后的可用、待检和冻结数量。

  1. 进入 MES > 库存 > 库存管理。
  2. 搜索质检涉及的产出物料。
  3. 核对总量、可用、待检、冻结及库位余额。

结果检查总库存等于可用、待检和冻结之和，质量判定不改变总量或总成本。

流程 024

核对质量状态流水

目的确认放行或冻结可以从统一库存流水回放。

  1. 进入 MES > 库存 > 库存流水。
  2. 搜索产出物料或质量来源。
  3. 核对 QUALITY RELEASE / QUALITY HOLD、批次、状态方向、操作人和时间。

结果检查状态转换流水数量变化为 0，但明确记录待检到可用或冻结的转换。

5. 质量任务与不合格处置

流程 025

启用来料检验标准

目的只为需要来料质量控制的物料显式启用入库待检。

  1. 进入 MES > 生产 > 质量任务，点击“检验标准”。
  2. 新建或复制标准，选择物料和“来料入库待检”来源。
  3. 配置抽样方式、最低/最高数量和逐项接收标准。
  4. 完成质量审批后发布标准。

结果检查已发布标准显示“来料入库”；只有该物料后续收货会自动转待检，未启用标准的物料保持直接可用。

流程 026

接收来料检验任务

目的由质检岗位接收仓管收货后自动生成的来料检验任务。

  1. 进入 MES > 生产 > 质量任务。
  2. 在“待检任务”中按内部批号、物料或来料单搜索。
  3. 核对来源显示“来料入库”、检验单号、标准快照和建议抽样数。
  4. 展开检验项目快照，确认接收标准与来料检验计划一致。

结果检查质检员可读取授权库位的任务；仓管员只能完成收货，不能代替质量判定。

流程 027

逐项判定来料质量

目的按生效标准和建议抽样数完成来料逐项检验。

  1. 在来料待检任务点击“合格放行”“不合格冻结”或“部分判定”。
  2. 进入全屏表单，核对抽检、合格和不合格样本数量。
  3. 逐项选择结果，填写实测值、项目备注和检验结论。
  4. 确认总判定与逐项结果一致后提交。

结果检查系统拒绝低于标准建议抽样数、项目缺失或总判定矛盾的提交。

流程 028

核对来料合格放行

目的确认来料库存由待检转为可用并保留完整检验事实。

  1. 切换质量任务“全部记录”。
  2. 按来料内部批号搜索已完成检验。
  3. 核对“已放行”数量、标准快照、抽样和判定人。
  4. 在库存或批次谱系复核同批次可用余额。

结果检查同一批次待检余额归零、可用余额增加，总数量和总成本不变。

流程 029

查看来料质量趋势

目的单独分析供应来料的批次和样本质量表现。

  1. 点击“质量趋势”。
  2. 选择日期范围，并把来源切换为“来料入库”。
  3. 点击“刷新统计”。
  4. 核对完成批次、批次合格率、样本合格率、不合格项目和物料排名。

结果检查趋势只统计已完成来料检验，不把待检或已随红冲取消的任务计入分母。

流程 030

查看检验标准版本

目的按物料和任务来源查看草稿、已发布和已停用标准。

  1. 进入 MES > 生产 > 质量任务。
  2. 点击页内“检验标准”。
  3. 按标准编码、物料或状态搜索。
  4. 展开检验项目，核对方法、接收标准和变更原因。

结果检查同一标准编码的多个版本独立显示，只有草稿可编辑。

流程 031

新建检验标准草稿

目的为物料建立任务来源、抽样规则和完整检验项目。

  1. 在检验标准页点击“新建检验标准”。
  2. 填写编码和名称，搜索并选择适用物料。
  3. 选择生产入库、来料入库待检或退货入库来源，设置全检、固定数量或比例抽样。
  4. 逐项添加项目名称、检验方法和接收标准。
  5. 填写建立原因并保存草稿。

结果检查标准以 v1 草稿建立，发布前可继续编辑。

流程 032

发布检验标准新版本

目的使新检验任务引用经批准版本，同时保留旧版历史。

  1. 在草稿行展开项目并完成发布前复核。
  2. 点击“发布”并确认不可覆盖提示。
  3. 核对新版本显示“已发布”。
  4. 核对同物料同来源的旧发布版本自动显示“已停用”。

结果检查同物料同来源始终只有一个生效版本，历史任务快照不受影响。

流程 033

核对检验任务标准快照

目的确认待检批次自动带入当时生效标准和建议抽样数。

  1. 进入“质量任务”并搜索待检批次。
  2. 核对标准编码、版本、名称和建议抽样数。
  3. 展开“检验项目快照”核对任务建立时的接收标准。

结果检查任务保留独立快照，后续发布新标准不会改写已建任务。

流程 034

按标准逐项记录检验结果

目的按建议抽样数填写样本结果并完成每个标准项判定。

  1. 在待检任务选择合格、不合格或部分判定。
  2. 确认抽检数量不低于标准建议值。
  3. 为每个检验项选择合格或不合格，填写实测值和必要备注。
  4. 填写结论说明并提交。

结果检查系统校验抽样下限、全部项目完整性和总判定一致性。

流程 035

上传质量检验凭证

目的把测量报告、现场照片或客户凭证绑定到具体检验单。

  1. 在检验任务点击“质量附件”。
  2. 点击“上传文件”并选择 50 MB 以内的凭证。
  3. 上传后核对附件数量和缩略入口。
  4. 点击附件确认可通过受权 API 预览。

结果检查附件只对拥有质量任务、附件权限且在授权库位范围内的人员可见。

流程 036

查看质量趋势

目的按日期、物料和来源分析批次与样本质量。

  1. 点击页内“质量趋势”。
  2. 选择日期范围，必要时限定物料或任务来源。

  4. 在库存流水复核质量报废记录。

  3. 核对让步放行数量、操作人和偏差许可号。

  2. 核对解冻放行和让步放行分别记录。
  3. 向下核对初始判定冻结与放行记录。

结果检查四条动作各自保留数量、原因、人员和处置编号。

  3. 核对内部批号、供应批号、库位和分配数量。

  1. 在产出追溯弹窗点击左侧原料批次。
  2. 确认中间当前批次已切换为来料批次。
  3. 在右侧查看所有相邻下游产出，需要时可继续点击。

结果检查同一原料批次对应的多个生产产出均可查看，弹窗不重叠。

  2. 向下查看“客户发货批次”。

结果检查分配合计等于发货数量；历史未追踪库存会明确标为兼容批次，不伪造成来料或生产批次。

流程 082

从发货批次查看客户去向

目的从内部批次正向确认发货单、客户、物流和退货累计。

  1. 在客户发货批次点击“查看谱系”。
  2. 查看“客户履约追溯 > 客户发货去向”。
  3. 核对发货单、客户编码/名称、发出数量、已退数量、库位和物流号。

结果检查客户发货去向显示对应发货记录；尚未收货的退货不会提前形成回流批次。

流程 083

查看退货单

目的查看客户退货、原因和处理状态。

  1. 进入 ERP > 销售 > 退货管理。
  2. 按退货单、物料、发货单或原因搜索。
  3. 核对数量、退回库位和待处理状态。

结果检查退货可追溯原发货单和客户。

流程 084

新建退货单

目的登记客户退回物料。

  1. 点击“新建退货单”。
  2. 选择物料并填写数量、退回库位和原因。
  3. 按需填写外部凭据、备注和附件。
  4. 保存后等待授权人员处理。

结果检查新单状态为“待处理”，库存尚未返库。

流程 085

按原发货单登记可退数量

目的在界面中复核原发货单是必选项，避免退货脱离客户和出库批次。

  1. 点击“新建退货单”。
  2. 在“原发货单”选择目标单据。
  3. 核对自动带出的客户、物料和“剩余可退”提示。
  4. 选择退货待检库位后再填写数量和原因。

结果检查仅显示仍可退的发货单；物料不可随意替换，数量上限等于剩余可退数量。

流程 086

处理退货返库

目的确认退货接收并增加指定库位库存。

  1. 在待处理退货上点击“处理”。
  2. 核对数量和退回库位。
  3. 确认后检查成功提示、库存和流水。

结果检查状态变为“已处理”，退回库位库存增加。

流程 087

确认退货已收货

目的核对业务单状态与库存质量状态分离。

  1. 在待收货退货单点击“处理”。
  2. 等待成功提示并刷新列表。
  3. 核对退货状态为“已收货”。

结果检查列表显示已收货，但这不代表批次已可用；必须继续完成质量判定。

流程 088

核对原发货批次与退货待检批次

目的确认退回数量从原发货批次分配，并形成独立、可质检的退货批次。

  1. 打开已收货退货单“详情”。
  2. 查看“原发货批次来源”，核对原批次、本次退回数量、发货单和库位。
  3. 查看“退货待检批次”，核对批次号、待检状态、状态数量和检验单号。

结果检查来源分配合计等于退货数量；退货批次号以 RT- 开头且质量状态为待检。

流程 089

从退货批次反查原发货

目的从退货回流批次反向定位客户、原发货单和原出库批次。

  1. 在退货待检批次点击“查看谱系”。
  2. 查看当前批次说明与质量检验单。
  3. 在“客户退货来源”核对原批次、退货单、原发货单、客户和退回数量。

结果检查退货批次显示原发货单和客户；来源内部批次可继续点击追溯。

流程 090

填写退货批次合格判定

目的对已收货退货批次执行整批质量放行。

  1. 在退货详情点击“合格放行”。
  2. 填写抽检数量、合格数量、不合格数量和结论说明。
  3. 确认合格数与不合格数之和等于抽检数，且整批合格时不合格数为 0。
  4. 点击“确认整批放行”。

结果检查系统保存检验人、判定和抽检结果，并把整批库存由待检转为可用。

流程 091

核对退货批次已放行

目的确认质量结果和库存状态已经同步落账。

  1. 提交质量判定后留在退货详情。
  2. 核对批次状态从“待检”变为“已放行”。
  3. 核对判定、抽检、合格、不合格数量和检验人。

结果检查批次显示“已放行”，状态数量保持不变，质量判定信息完整。

流程 092

从原发货批次查看退货回流

目的从原出库批次正向确认客户退回数量及其最终质量状态。

  1. 从退货批次谱系点击来源内部批次。
  2. 查看“客户发货去向”，核对发出数量和已退累计。
  3. 查看“退货回流批次”，核对退货批次、状态、数量、库位、退货单和客户。

结果检查原发货批次显示发出和已退累计；回流批次显示最终质量状态，并关联原发货单和退货原因。

10. 文档与设备台账

查看受控文档

  2. 按标题、正文、产品或备注搜索。
  3. 点击“在线阅读”或“详情”查看版本和附件。

结果检查能确认文件标题、版本、状态和适用范围。

流程 094

新建受控文档

目的上传原文件或创建在线作业正文。

  1. 点击“新建文档”。
  2. 上传原文件或填写在线正文。
  3. 关联物料、类别、版本和工作中心。
  4. 保存后在列表复核状态。

结果检查文档可按适用范围检索并保留原始附件。

流程 095

查看设备台账

目的核对设备基础资料、当前状态和运行事件入口。

  1. 进入 MES > 设备 > 设备台账。
  2. 搜索设备编码、名称、型号或工作中心。
  3. 核对设备当前状态、现场位置和事件数量。

结果检查台账显示可用、使用中、故障、维护中或停机状态；状态不能在基础资料中直接改写。

流程 096

新建设备

目的建立设备基础台账。

  1. 点击“新建设备”。
  2. 填写编码、名称、类型和工作中心。
  3. 填写位置、厂商、型号、参数和备注；不要在基础资料中设置运行状态。
  4. 保存后复核列表。

结果检查设备以“可用”作为初始状态，可用于后续运行事件、派工和产能关联。

流程 097

上报设备故障

目的把现场故障作为可审计事件登记并立即改变设备状态。

  1. 进入设备台账，在目标设备点击“事件”。
  2. 点击“报告故障”。
  3. 填写现场可核对的故障原因和已采取的安全措施。
  4. 确认设备编码、当前状态和原因后点击“确认记录事件”。

结果检查设备转为“故障”，时间线保留原状态、原因、操作人和发生时间。

流程 098

恢复设备并回放事件时间线

目的恢复设备前完成试运行，并核对故障持续时间与完整状态链。

  1. 在故障设备的事件弹窗点击“恢复可用”。
  2. 填写维修结果、试运行结论和复核说明。
  3. 确认记录后重新打开“事件”。
  4. 核对恢复、故障、开机事件的状态链、人员、原因和故障持续时间。

结果检查设备回到“可用”；故障事件记录从故障发生到恢复的持续时间，恢复事件不重复计算。

流程 099

查看到期设备点检任务

目的按到期、逾期和异常状态找到当前工作中心需要处理的点检任务。

  1. 展开 MES 的“设备”菜单并进入“设备点检”。
  2. 先查看到期、逾期和异常记录计数。
  3. 使用“到期任务”筛选，并按计划、设备或工作中心搜索。
  4. 核对设备、周期、下次到期时间和完整检查清单。

结果检查页面只显示当前账号工作中心范围内的点检计划，到期任务可直接执行。

流程 100

新建设备点检计划

目的为一台设备建立不可直接改写的周期点检标准和完整项目清单。

  1. 在设备点检页面点击“新建点检计划”。
  2. 填写唯一计划编码、名称、周期和首次到期时间。
  3. 搜索并选择当前工作中心范围内的设备。
  4. 逐项添加项目名称、检查标准和可选单位，一次保存计划。

结果检查新计划进入到期任务或全部计划；项目清单保存后只能暂停或恢复计划，不能覆盖历史标准。

流程 101

逐项完成设备点检

目的按计划快照完整提交实测值、结果、人员和整次说明。

  1. 在到期任务卡片点击“执行点检”。
  2. 核对实际点检时间和每一项标准。
  3. 逐项选择正常或异常，并填写实测值；异常项必须填写异常说明。
  4. 填写整次说明后点击“确认完成点检”。

结果检查系统一次保存全部项目、点检人、到期周期与审计记录，并把下次到期时间推进一个周期。

流程 102

复核异常点检与现场附件

目的从异常记录回看点检事实，并保留现场照片或报告。

  1. 切换到“异常记录”筛选。
  2. 核对异常记录号、点检时间、点检人和异常说明。
  3. 确认原设备已进入故障状态，并在设备事件时间线中存在对应故障事件。
  4. 按需要在该次记录下上传现场照片、测量报告或维修凭证。

结果检查异常点检记录不可改写；设备原为可用或运行中时，同一事务生成故障事件，附件继承点检与工作中心权限。

流程 103

查看到期设备保养计划

目的按到期和逾期状态找到当前工作中心需要生成工单的周期保养任务。

  1. 展开 MES 的“设备”菜单并进入“设备维保”。
  2. 查看到期保养、逾期、维修中和待处理计数。
  3. 切换到“到期计划”，按计划、设备、工作中心或负责人搜索。
  4. 核对计划周期、下次到期时间、完整项目清单以及是否已生成工单。

结果检查页面只显示当前账号工作中心范围内的保养计划；同一计划和到期周期不会重复生成活动工单。

流程 104

新建设备保养计划

目的为一台设备建立不可直接覆盖的周期保养标准和项目清单。

  1. 在设备维保页面点击“新建保养计划”。
  2. 填写唯一计划编码、名称、周期、首次到期时间和说明。
  3. 搜索并选择当前工作中心范围内的设备。
  4. 逐项添加项目名称和作业标准，一次保存计划。

结果检查计划进入到期或全部计划；项目清单保存后只能暂停或恢复计划，不能覆盖历史工单标准。

流程 105

登记设备故障维修工单

目的把真实故障现象登记为可执行、可追溯的纠正性维修工单。

  1. 在设备维保页面点击“新建维修工单”。
  2. 搜索并选择发生故障的设备。
  3. 填写维修主题、优先级、要求完成时间、负责人和客观故障现象。
  4. 核对信息后点击“创建维修工单”。

结果检查系统创建待处理维修工单；原为可用或运行中的设备同时进入故障状态并保留故障事件。

流程 106

开始设备维修或保养工单

目的明确现场作业开始时点，并阻止设备在维修期间被视为可生产。

  1. 切换到“待办工单”并核对工单、设备、负责人和故障现象或保养来源。
  2. 在待处理工单点击“开始维修”。
  3. 确认工单状态由“待处理”变为“维修中”。
  4. 到设备台账核对同一设备状态已经同步变为“维修中”。

结果检查工单记录开始人和开始时间，设备事件链增加进入维修状态的事件。

流程 107

完成维修并领用备件

目的一次提交真实作业结果和备件领用，让设备、库存、成本与批次保持原子一致。

  1. 在维修中工单点击“完成并领料”。
  2. 计划保养工单须逐项确认全部清单达标；故障维修填写故障原因。
  3. 按“搜索—选择物料—选择库位—填写数量—添加”录入全部备件。
  4. 填写维修或保养内容、完成时间并点击“确认完成并过账”。

结果检查工单完成、设备恢复可用；备件按可用批次扣减库存并形成库存流水、成本金额和批次分配。

流程 108

复核维保历史与备件批次

目的从完成事实回看工单、作业结果、设备恢复、备件成本和实际消耗批次。

  1. 在设备维保页面切换到“完成记录”。
  2. 核对工单号、设备、负责人、故障现象和实际作业结果。
  3. 在“备件领用”中核对物料、数量、库位和实际批次。
  4. 按需要上传维修照片、校准报告或外协凭证，并到库存流水反查同一业务来源。

结果检查完成工单、设备恢复事件、备件库存流水、成本和批次分配可相互追溯，完成事实不可覆盖。

新建物料工艺路线

流程 122

按仓库岗位执行来料命令

目的使用岗位账号完成收货交接，并把整单红冲限制给仓库主管。

  1. 普通仓管进入物流 > 来料管理，核对待收货单可编辑并显示“整单收货”“整单拒收”。
  2. 确认收货后核对受控物料进入待检、非受控物料进入可用；普通仓管不显示“整单红冲”，直接调用也返回 403。
  3. 仓库主管复核原单、批次、质量状态和下游使用情况后，使用有红冲权限的账号打开已收货单。
  4. 点击“整单红冲”，填写具体原因并在库存流水、批次、质量任务和审计中复核成对恢复。

结果检查来料录入、收货/拒收、红冲和质量判定使用四层独立权限，页面动作与服务端门禁一致。

流程 163

分配物流状态命令权限

目的把单据登记、库存正向执行、业务确认和高风险取消/冲销分配给不同岗位。

  1. 使用权限管理员账号进入账号与权限 > 组权限。
  2. 选择仓库作业组，确认其具有发货执行、退货收货和流程转移确认，但没有签收、取消、拒绝或冲销。
  3. 选择仓库管理组，依据仓储负责人签字增加发货取消、退货拒绝和流程转移冲销。
  4. 选择销售发运组，确认其可确认客户签收、取消待发货和拒绝退货，但不能执行仓库出入库。
  5. 保存后分别使用通用编辑、普通仓管、仓库主管和销售跟单账号复核按钮与 HTTP 403。

结果检查61 个资源中的七个物流状态命令独立授权；既有角色、组和个人例外不会由通用修改自动扩大权限。

流程 164

仓管确认发货并扣减库存

目的由普通仓管复核待发货单并执行批次、库存和成本的正向发出。

  1. 使用普通仓管账号进入销售 > 发货管理，筛选待发货。
  2. 复核客户、销售订单、物料、发货库位、数量和物流单号。
  3. 点击“确认发货”，等待状态变为已发货。
  4. 在详情、库存流水和批次追溯中复核实际批次、数量、成本和可信操作人。

结果检查普通仓管可以执行发货库存过账，但页面不显示客户签收和取消命令；直接越权调用返回 403。

流程 165

销售确认客户签收

目的由销售跟单确认客户已签收，不允许其代替仓库执行库存发出。

  1. 使用销售跟单账号进入销售 > 发货管理，筛选已发货。
  2. 复核发货单、客户、物流单号和发货时间。
  3. 点击“确认签收”，等待状态变为已签收。
  4. 在操作记录中核对 DELIVER 动作、操作人和前后状态。

结果检查销售跟单可确认客户签收，但不能执行库存发货；签收动作不重复扣减库存。

流程 166

有原因取消待发货单

目的在尚未扣减库存前，由获批主管结束错误或已撤销的待发货单。

  1. 使用仓库主管或销售负责人账号打开待发货单。
  2. 确认单据尚未发货且没有库存、成本或批次过账。
  3. 点击“取消发货”，填写至少 2 个字的具体原因。
  4. 确认后核对状态为已取消，并在操作记录中复核 CANCEL、原因、操作人和前后快照。

结果检查取消仅允许待发货状态且必须记录原因；普通仓管与通用编辑账号没有该命令。

流程 167

仓管接收入库退货

目的由普通仓管核对原发货来源，将客户退货接收入库并进入待检状态。

  1. 使用普通仓管账号进入销售 > 退货管理，筛选待处理。
  2. 复核原发货单、客户、物料、剩余可退数量、退回库位和退货原因。
  3. 点击“确认退货收货”。
  4. 在详情、质量任务、库存流水和批次追溯中核对独立退货批次及 QUARANTINE 数量。

结果检查普通仓管可以接收入库退货但不能拒绝申请；退货库存进入待检，不直接增加可用量。

流程 168

有原因拒绝退货

目的由获批销售或仓库主管拒绝不符合协议的待处理退货，且不产生库存。

  1. 使用销售跟单或仓库主管账号打开待处理退货单。
  2. 核对客户、原发货、物料、数量及退货协议依据。
  3. 点击“拒绝退货”，填写至少 2 个字的具体原因。
  4. 确认后核对状态为已拒绝、没有退货批次或库存流水，并在操作记录中复核 REJECT 原因。

结果检查退货拒绝与退货收货分离授权；拒绝必须有原因且不会产生库存或质量任务。

流程 169

仓管确认正向流程转移

目的由普通仓管确认同物料、同数量的正向移库，不改变总库存和总成本。

  1. 使用普通仓管账号进入生产 > 流程转移，找到草稿转移单。
  2. 复核物料、来源库位、目标库位、数量和操作员工。
  3. 点击“确认移库”，再次核对移动方向后确认。
  4. 在库位余额和库存流水中核对一出一入，总库存、计价数量和成本层保持不变。

结果检查普通仓管可确认正向移库但不能冲销；库存只在两个获批库位之间移动。

流程 170

主管有原因冲销流程转移

目的由获批主管在目标库位余额足够时恢复原移库，保留完整原因和审计。

  1. 使用仓库主管或生产主管账号打开已确认流程转移单。
  2. 复核目标库位仍有足够可用数量，确认没有造成单边恢复风险。
  3. 点击“冲销”，填写具体原因并确认。
  4. 核对数量从目标库位移回来源库位，一出一入流水、REVERSE 审计和总库存/成本守恒。

结果检查冲销与草稿修改、正向确认独立授权；普通仓管调用冲销返回 403，主管必须填写原因。

16. 人员数据范围与临时授权

配置本人和指定库位范围

授予个人临时权限

流程 173

配置工作中心和全库范围

结果检查生产订单、派工、实绩、统计与任务只覆盖所选工作中心；库存业务按已保存的全库范围执行。

17. Coolify 发布、备份与恢复

流程 174

固定生产提交并关闭自动部署

  4. 只有在备份、CI 和维护窗口就绪后才人工 Redeploy。

结果检查生产发布由完整提交和人工维护窗口双重控制；推送 main 不再自动部署。

流程 175

配置持久备份目录

  2. 核对 data 映射到 /app/data。
  3. 核对 uploads 映射到 /app/public/uploads。

结果检查Directories 显示 3 项，三个业务目录均为独立持久挂载。

流程 176

  2. 填写命令 node /app/scripts/runtime-backup.mjs create。

  4. 设置 1800 秒超时并保存。

流程 177

执行并验证首份生产备份

目的确认真实生产数据库和附件能生成通过完整校验的归档。

  1. 在每日备份任务点击 Execute Now。
  2. 等待 Recent executions 显示 Success。
  3. 展开执行结果，记录 archivePath 与 SHA-256。
  4. 核对 databaseQuickCheck=ok、附件记录数和清单文件数。

结果检查首份生产一致备份成功并保存可追溯的归档路径、SHA-256 和清单统计。

流程 178

验证生产就绪状态

目的在发布或恢复后确认应用、数据库、迁移、持久目录和备份新鲜度同时可用。

  1. 打开 https://mes.szxiangshu.com/api/health/ready。
  2. 确认 HTTP 状态为 200 且整体 status 为 ready。
  3. 逐项核对 database、migrations、dataStorage、attachmentStorage 和 backupFreshness。
  4. 任一硬检查失败时停止验收并按返回项排查。

结果检查所有硬检查与备份新鲜度均为 pass，Coolify 同时显示 Running (healthy)。

流程 179

核对迁移前备份与启动日志

目的证明每次非空生产部署会先完成一致备份，再执行迁移和启动服务。

  1. 完成固定版本 Redeploy 后进入应用 Logs。
  2. 核对 data、uploads 和 backups 三个目录权限均已就绪。
  3. 记录启动前 create 结果中的归档、SHA-256、附件数和 quick_check。
  4. 确认 76 个迁移无待处理、Next.js Ready 且顶部 Running healthy。

结果检查新容器先生成经验证备份，再执行迁移并健康启动；旧容器只在新容器健康后移除。

流程 180

执行应用级恢复演练

目的在不改写在线生产和源候选的前提下，证明恢复数据能够启动隔离应用并通过关键业务抽查。

  1. 准备已验证的恢复候选数据库和附件目录，并确认目标目录与报告文件不存在。
  2. 执行 npm run storage:drill:application，填写数据库、附件、目标、报告、环境和操作人参数。
  3. 等待全附件哈希、迁移、readiness、临时管理员登录、物料/库存/生产单和附件原文件抽查完成。
  4. 核对报告中所有检查为 PASS、RPO/RTO 达标，并确认临时管理员已清理、源候选 SHA-256 未变化。

结果检查隔离应用恢复验收通过，报告记录完整应用 RTO；在线生产和源候选未被改写，异地副本与真实 Coolify 挂载切换仍单独验收。

流程 181

预检 Product 到 Material 映射

目的在进入生产维护窗口前，只读验证人工映射签字、引用一致性、库存风险和数据漂移。

  1. 在停止写入的生产恢复候选上先执行 audit 和 plan，并将映射文件交给熟悉业务数据的负责人逐行核对。
  2. 为每个 Product 填写 materialId、materialCode、库存处置和非空 decision.note，最后填写真实确认人及确认时间。
  3. 执行 product-material-migration.mjs preflight，并把输出写入不存在的新报告文件。
  4. 只有报告为 PASS、readyForApply=true 且 databaseSha256Before 与 databaseSha256After 相同时，才允许安排备份和维护窗口 apply。
  5. 若报告为 FAILED，按错误修正；如提示签字后数据变化，废弃旧映射并重新生成，禁止绕过预检。

结果检查未签字、缺少核对依据、引用冲突、非零库存或签字后漂移都会在写数据前被拒绝并留档；预检本身不创建备份、不回填数据库。

暂不作为现行 SOP 的治理项

  • 生产、退货和显式启用标准的来料质量闭环与岗位动作权限已贯通；正式上线前仍须按企业审批制度配置岗位权限、数据范围并使用真实不合格评审单验收。
  • 供应商、来料待检、生产投入产出、发货和退货回流已形成可搜索全景；未发布来料检验标准的物料仍直接入可用库存，跨工厂或供应商系统集成不在本阶段。
  • 岗位任务、生产命令、来料收货/拒收与红冲命令、本人/工作中心生产范围与库位库存范围已经分层；已有安装须按岗位审批显式授予新来料命令，部门/班组范围尚未独立建模。
  • 设备开机、停机、故障和恢复已形成事件时间线，周期点检、保养、维修工单、备件批次成本和现场附件已贯通；真实产量采集与 OEE 口径仍待企业确认。
  • 生产实绩已冻结实际设备和作业文件版本；没有设备或文件时必须分别保存例外原因。文件快照只保存正文和附件元数据清单，法规级原件固化仍需内容哈希与保留策略。
  • 旧 Product 与 Material 仍需分阶段迁移，禁止继续扩展旧模型写入口。
