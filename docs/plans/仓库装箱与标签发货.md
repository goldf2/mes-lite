# 仓库装箱、箱签与选箱发货

日期：2026-10-21
状态：实施方案；具体字段、接口与验证结果须在实现合拢后复核，本文不表示已发布。

## 1. 本期范围

先完成仓库独立装箱、逐箱标签打印、发货选箱，并完整保留原有散货发货。同一张发货单允许货箱与散货混合；客户单仍按产品、规格和实际数量展示，箱号是追溯补充，不能代替产品明细。

容器本身不编号、不维护周转状态。纸箱、金属网箱、塑料周转盒仅是包装类型；唯一 `BX-*` 身份属于本次装箱的货物内容。每次重新装货创建新的装箱记录，补打沿用原装箱身份。

本期不制作三维界面、不启用拖动移库、不推算未测量的坐标，不强制所有散货贴标；空间扩展模型与货物定位保留明确关联。

## 2. 库存与装箱身份

复用 `PackageDocument` / `PackageDocumentItem`，使新仓库装箱可独立于发货单存在。首期仓库新装箱采用一箱一种产品、一个真实批次、一个当前库位，历史多明细货箱保留原记录。

装箱时选择产品、真实可用批次、库位和实装数量，登记包装类型、日期、人员及可选外形尺寸、重量、生产/质检人员。可关联的生产和检验事实沿用原记录；手工补填是标识信息，不能自动成为质量放行凭证。

装箱只是为既有库存建立包装分配，不新增库存、不生成收货、成本或出库流水。对相同物料、批次、库位及质量状态，实物分配满足：

`真实批次实物数量 = 有效在库货箱数量 + 尚未装箱的散货实物数量`

已有受控发货欠库时，`Stock.qty` 是净账数量，不能直接等同上述实物总量；散货仍可按原规则形成欠库。选箱部分必须真实足额，散货实际可消费量要排除其他未选箱，差额登记欠库。后补入库只补散货欠库，不再次扣原箱或挪用未选箱。

新装箱数量不能超过可用且未被其他货箱分配的数量。散货发货、生产领料、移库、盘点和质量处置同样必须识别有效装箱分配，不能使已打印标签的货物被后台其他出口重复消耗。原预留量在同一可用口径中计算，避免重复扣减。

## 3. 标签

标签数据取自本箱实际明细，禁止取整张发货单的第一项产品作为箱内名称。显示装箱编号、产品编码/名称/规格、数量及单位、生产批次、包装类型、包装日期、包装人员、生产人员和质检人员；缺少的信息显示未填写，不编造人员或检验结论。长内容必须有可阅读的换行或明确的完整查看入口。

复用已有二维码、标签介质尺寸、打印弹窗和 `LabelPrintJob` 记录，支持单箱、选中箱及补打。每次打印保存当时的业务数据与纸型快照。浏览器打印请求只表示发起请求，不表示打印机已经物理出纸；本期不新增静默打印桥。

二维码只提供装箱身份解析；扫码必须重新检查账号、权限、库位范围、装箱当前状态和内容。当前位置由系统最新记录提供，不把纸面位置当作唯一事实。标签内容变化后旧内容快照不能自动变成新内容；拆箱、重新装货应停止使用旧标签。

## 4. 发货

发货录入保留“添加散货”，增加“选择货箱”。选箱只展示当前用户有权访问且处于可发货状态的仓库装箱记录；带出产品、数量、单位、批次和库位。箱内数量不在发货单里另行改写，需要调整时先处理装箱内容。

一个箱只能被一张有效待发货单占用。重复添加、过期页面同时选箱、已发货、已取消/作废、质量不可用、库位越权等情况应由服务端拒绝；前端禁用不能替代事务校验。

同一发货产品行满足：

`实际发货数量 = 已选货箱内容数量 + 本次散货数量`

保存待发货单只建立货箱关联/占用，不扣库存。取消时释放占用。归档仍占用仓库箱的待发单时同步取消再释放；恢复只恢复历史记录，不能重新确认出库，需要新建选箱发货单。确认发货时在同一库存事务中消费所选箱的实际批次及成本，再处理明确的散货来源；不能用其他批次代替箱内批次。散货原有受控欠库规则保留，已实物装箱的部分不得形成虚拟欠库。

签收不重复改变库存。受控冲销应恢复原批次、成本、库存和对应装箱事实；原单、关联历史和标签身份不得因冲销删除。重发、取消、冲销的可选箱规则须与实际状态服务一致。

客户发货单仍输出产品编码、名称/规格、数量及单位、价格/金额；同产品可以汇总，原明细来源保留。示例：两个各 200 件的箱加散货 50 件，客户行显示 450 件，同时可查看两个箱号。

## 5. 为立体仓库保留的空间边界

空间与库存身份分开：仓库/布局版本/空间节点描述实际结构，库存库位继续作为记账依据，装箱摆放关系描述唯一当前位置。正式布局使用毫米和相对父节点的 XYZ/朝向，后续可表达楼层、区域、货架、层和库位；地面堆放无需虚构货架。

货物尺寸、当前库位、可选空间坐标、定位确认时间及变更版本由本期模型支持或明确预留；未测量时坐标留空，界面只能声明已知库位。位置不是第二份库存余额，也不允许装箱单头和明细各自维护互相矛盾的位置。

后续三维布局编辑与实际搬货分开。跨库位移动必须调用既有库存事务并记录实际批次、成本及摆放历史；同库位坐标调整只改变摆放。空间可视化与点击/拖动不能绕过质量、库存、权限和审计门禁。

## 6. 兼容、权限与迁移

- 保留历史发货货箱 `BX-*`、照片、打印记录及发货关系；新模型不凭空为旧箱回填真实批次或坐标。
- 仍可纯散货、纯货箱及混合发货。不能继续用“只要有箱，箱内数量必须覆盖整单”的旧校验。
- 独立装箱操作使用明确库存/装箱权限及库位数据范围；发货动作沿用原发货录入、确认、签收、冲销分权。准确资源键以最终权限配置为准。
- 装箱与归档、占用与释放、打印请求、发货与冲销均保留操作责任和审计；二维码不成为公开业务数据入口。
- 新表列采用加性迁移，部署前遵守一致备份。出现新装箱及选箱发货写入后，不得运行无法识别包装占用的旧写入代码；回退以关闭相关写入、保留新数据及前滚修复为原则。

## 7. 回归与验收计划

现有 `scripts/verify-shipment-packages.ts` 采用临时 SQLite、`prisma migrate deploy` 和合成来料/客户/物料，是本功能的基础业务回归入口。新增场景需调用真实领域服务和事务，不以源码关键字检查替代业务事实断言；不连接生产数据库。

| 场景 | 必须核对的结果 |
| --- | --- |
| 独立装箱 | 不需先建发货单；批次/库位/产品/数量一致；库存、成本、流水不增加 |
| 重复分配 | 第二箱超过未装箱数量时整笔失败，无残余单头/明细/摆放 |
| 标签 | 同单多产品按本箱取值；尺寸与快照正确；补打原号；长名称/人员可读 |
| 纯散货 | 原建单、受控欠库、确认、签收、取消、冲销及退货行为兼容 |
| 纯选箱 | 自动生成具体产品数量；只扣实际箱内批次，不能 FIFO 替换批次 |
| 混合 | 同产品多箱加散货正确求和；不要求箱覆盖整单，不重复扣量 |
| 并发/重复 | 同箱重复添加或被另一待发货单占用时拒绝；确认重试不重复出库 |
| 取消/冲销 | 取消释放占用不改库存；冲销准确恢复原批次/成本/包装事实 |
| 其他库存出口 | 生产耗用、移库、调整及质量处置不能消费已分配到箱的数量 |
| 权限 | 读写分权、库位越权、归档或已发箱、无登录扫码均受服务端约束 |
| 历史 | 旧发货和旧货箱能查看、追溯、按原规则冲销，不伪造批次 |
| 空间扩展 | 一个箱只有一个正式当前位置；空坐标保持未知，摆放不形成第二份库存 |

直接相关兼容回归：`verify:shipment-packages`、`verify:shipment-return-lots`、`verify:shipment-reversal`、`verify:shipment-negative-stock`、`verify:scan-print`、`verify:business-document-print`、库存事务/批次/生产耗用，以及 HTTP 权限与数据范围检查。

真实浏览器必须使用合成库存，验证桌面与手机装箱、选择/移除箱、散货混合数量、错误态和标签预览；打印版面核对真实尺寸。浏览器打开打印预览不等于实物标签已打印。版本、精确提交 CI、迁移、生产健康及业务验收分别记录。
