# 可停靠工作区交互实验

## 目的

本实验用于验证 MES-lite 将页面外壳升级为工作区的可行性，不接入真实业务 API，也不替换当前生产页面。

实验路由：`/workspace-lab`

## 工作区区域

工作区由以下区域组成：

- 顶部导航：一级业务入口。
- 顶部工具：搜索、视图、新建和页面操作。
- 左侧停靠区：可放置导航或工具面板。
- 主显示区域：业务列表、详情或编辑器，切换布局时保持挂载。
- 右侧停靠区：可放置工具或导航面板。

## 已实现的实验能力

- 导航常驻、工具常驻、专注和完整四个布局预设。
- 顶部导航和顶部工具独立显示或隐藏。
- 导航面板、工具面板可停靠到左侧、右侧或改为弹窗呼出。
- 面板题头可拖动到左右停靠提示区。
- 同侧存在多个面板时使用标签切换，避免继续压缩主显示区域。
- 导航弹窗使用一级、二级双列结构。
- 工具弹窗允许移动，并可连续切换属性、关联、附件、历史和 AI。
- 实验偏好保存到当前浏览器的 `localStorage`。

## 实验代码边界

- `DockingWorkspaceLab.tsx`：只负责工作区状态、区域组合和事件协调。
- `workspaceLab.ts`：布局类型、预设、偏好校验和持久化键。
- `components/WorkspaceChrome.tsx`：通用按钮、面板位置控件和左右停靠区。
- `components/WorkspacePanels.tsx`：导航面板与工具面板的演示内容。
- `components/WorkspaceMain.tsx`：始终保持挂载的主业务区域。
- `components/WorkspaceOverlays.tsx`：布局菜单、可移动工具浮窗等覆盖层。

正式化时应保留“外壳、面板、主视图、偏好模型”之间的依赖方向，业务页面只能向工作区注册内容和能力，不应自行复制停靠逻辑。

## 明确不在实验范围

- 不读取和修改 MES-lite 业务数据。
- 不写入数据库，也不新增 API。
- 不接入现有权限、审计或工作台偏好。
- 不实现任意嵌套、上下分组和多窗口布局。
- 不修改现有主页面、导航和工具栏。
- 不将实验路由加入正式功能导航。

## 验证重点

1. 切换预设时，主显示区域的选中记录和搜索条件不能丢失。
2. 导航和工具换边时，主显示区域只能重新排版，不能重新挂载。
3. 隐藏固定导航或工具后，仍必须存在可发现的呼出入口。
4. 左右停靠区为空时，应释放空间给主显示区域。
5. 窄屏不强制展示固定侧栏，后续正式实现应统一降级为弹出面板。

## 后续正式化条件

实验经确认后，正式实现应先提取 `WorkspaceShell`、`DockZone`、`WorkspacePanel` 和模块注册表，再逐步迁移现有导航与工具。不得直接把实验组件复制进 `app/page.tsx`。
