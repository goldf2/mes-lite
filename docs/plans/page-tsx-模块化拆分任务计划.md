# `app/page.tsx` 模块化拆分任务计划

## 1. 目标

将当前同时承担应用壳、导航、页面状态、数据请求和业务视图的 `app/page.tsx` 拆分为稳定的应用入口、公共应用壳和独立业务页面模块。

拆分完成后：

- `app/page.tsx` 只负责鉴权入口与应用装配，不再保存生产订单、库存或仪表盘业务状态。
- 导航、权限过滤、URL 连续性、桌面/移动布局和顶部工具栏仍只有一个公共实现。
- 仪表盘、生产订单和库存分别拥有自己的数据请求、筛选、编辑状态和视图组件。
- 既有 37 个页面模块注册、权限资源、URL 参数和响应式行为保持兼容。
- 拆分过程中不修改数据库模型、接口契约或业务状态流转。

## 2. 非目标

- 不重写现有业务接口。
- 不在本次拆分中改变页面视觉设计或业务操作流程。
- 不为了缩短文件创建缺少业务语义的碎片组件。
- 不复制导航、顶部工具栏、权限判断或页面注册表。

## 3. 拆分边界

### 3.1 应用入口

`app/page.tsx` 仅保留 `HomeApp` 挂载；鉴权和全局页面装配由应用壳统一负责。

### 3.2 公共应用壳

应用壳负责：

- 当前操作员与全局权限判断；
- 页面注册、一级/二级导航和页面切换；
- URL 与页面连续性；
- 桌面侧栏、顶部导航、移动导航和布局偏好；
- 全局消息、AI 助手及账号菜单；
- 将已注册的业务页面装配到 `PageModuleBoundary`。

应用壳不得负责具体业务数据查询、表单字段和交易状态流转。

### 3.3 业务页面模块

- 仪表盘：指标查询、负荷、状态分布和库存预警。
- 生产订单：列表、筛选、卡片/列表视图、新建、详情和实绩入口。
- 库存：列表、筛选、卡片/列表视图、数据一致性提示、维护和库存调整。

最终目录分别为 `modules/workspace`、`modules/production` 和 `modules/inventory`。每个领域模块只通过根目录 `index.ts` 暴露页面入口；`HomeApp` 不直接依赖 `ui/` 内部文件。

状态保留在最接近所有调用者的位置；只有跨页面共享的状态才提升到应用壳。

### 3.4 共享定义

页面键、导航分组、图标、权限资源和页面模块类型使用单一注册数据源。业务类型放入对应领域模块，不在应用入口重复声明。

## 4. 实施阶段

1. 盘点 `page.tsx` 的类型、状态、副作用、请求和 JSX 所有权。
2. 提取共享页面键、导航注册和纯函数。
3. 迁移仪表盘垂直切片并回归。
4. 迁移生产订单垂直切片并回归。
5. 迁移库存垂直切片并回归。
6. 提取并收缩应用壳，最终精简 `page.tsx`。
7. 更新前端结构文档、发布说明和版本号。

以上阶段已完成。下一批超大页面继续按“修改触达、形成可验证垂直切片、再迁移”的方式推进，不进行没有业务收益的全仓库搬家。

## 5. 验收标准

- `app/page.tsx` 不包含业务接口请求、业务筛选状态或大段页面 JSX。
- 生产订单和库存的创建、查询、详情、调整及公共工具栏行为保持不变。
- 仪表盘、生产订单和库存各有明确模块入口，不从应用壳反向读取局部状态。
- `npm run verify:page-modules` 通过。
- `npm run verify:release-notes` 通过。
- TypeScript、定向 ESLint 和生产构建通过。
- 至少验证一个桌面视口和一个窄屏视口的导航及页面切换。

## 6. 回滚策略

每个垂直切片单独迁移并保持可构建。若某一阶段出现行为回归，只回退对应页面模块，不撤销已经稳定的公共边界和其他业务模块。
