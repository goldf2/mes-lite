# ADR 0020：桌面导航采用同一模型的单列与双列布局

## 状态

已采纳，2026-08-06。

## 背景

MES 功能增加后，单列折叠菜单能够节省横向空间，但用户在配置、工具、账号权限等二级入口较多的模块中频繁切换时，需要重复展开和定位。固定双列导航能让一级功能和当前二级入口同时保持可见，但不适合所有屏幕宽度，也不应因此复制菜单、权限和路由定义。

## 决策

1. 桌面导航提供“单列折叠”和“双列导航”两种用户可选布局，设置入口统一放入公共页面选项。
2. 两种布局必须由同一个 `DesktopNavigationGroup[]` 模型驱动；业务菜单、权限过滤、当前状态、路由和排序仍只在应用壳定义一次。
3. 双列左侧一级区域固定 84px，右侧使用剩余侧栏宽度并只显示当前一级功能的二级入口；两列独立滚动。
4. 双列仅在 1280px 及以上显示；1024–1279px 自动使用单列，移动端维持底部常用入口与抽屉导航。
5. 单列与双列分别保存宽度，均保留拖动、键盘调整和双击恢复默认值；导航偏好只保存在当前浏览器。
6. 两种布局共用侧栏功能搜索；搜索覆盖全部有权访问的菜单项，双列模式保持一级列固定并在二级列展示按分组归类的结果。

## 结果

- 功能较多时可以更快切换，业务内容优先的用户仍可选择紧凑单列。
- 新增、删除或调整菜单只改公共模型，两种布局同步生效。
- 功能搜索随公共菜单和权限过滤自动更新，不产生独立的搜索索引或路由表。
- 响应式回退不会产生第三套菜单或改变移动端交互。
