# ADR 0030：单厂 MES、Material 主档与旧生产写入冻结

状态：接受
日期：2026-08-12

## 背景

MES-lite 当前运行方式是单工厂、单实例、SQLite 和本地持久附件。代码已把用户侧物品统一称为 `Material`，但 `Product` 仍被 BOM、工艺路线、生产订单、库存、成本、发货和退货等旧外键引用；生产又同时保留 `ProductionOrderActual`、`DailyProductionReport`、`PickItem`、`WorkReport` 和 `StockIn` 多条过账链。

如果继续让兼容模型承接新数据，后续质量、批次和库存状态将无法建立唯一事实链，数据迁移风险也会持续增长。生产环境的可验证备份挂载和恢复演练尚未完成，因此本版本不能直接做破坏性 Schema 或数据迁移。

## 决策

1. 当前产品合同固定为单厂轻量 MES；MRP-lite 与 ERP-lite 只作为辅助能力，多租户 SaaS 不是当前承诺。
2. `Material` 是唯一用户侧物品主数据；`Product` 只作为待退出的旧外键兼容投影。
3. 系统不再为 `Product` 创建或补齐 `Stock`；库存完整性只以有效 `Material` 为对象。
4. 新生产事实只写入 `ProductionOrder + ProductionOrderActual`。
5. 禁止创建新的 `DailyProductionReport`；保留既有记录的查询、修改、确认和冲销能力。
6. 旧领料、报工和入库接口只服务于 `materialId=null` 的历史工单；物料工单返回 `410`。
7. 增加只读模型收敛审计和结构守卫，旧 Product 外键的允许集合只能缩小，不能增长。
8. Product 外键物理退出和统一订单状态机延后到阶段 1B，并以生产备份、恢复演练、人工映射和前后统计为前置条件。

## 与 ADR 0025 的关系

[ADR 0025](./0025-shared-multitenant-saas-data-cells.md) 描述长期商业 SaaS 候选架构。它在当前阶段暂停，不能作为当前 Schema 增加 `tenantId`、PostgreSQL、RLS 或 DataCell 的实施授权。未来若真实商业需求重新启动多租户工作，必须在本 ADR 的单厂领域模型收敛后重新评审。

## 后果

正面影响：

- 新数据不再扩大 Product/Material 双轨和多套生产过账事实。
- 阶段 1B 可以从稳定、可审计的存量边界开始迁移。
- 阶段 2 的批次、质量和库存状态能够围绕唯一物料与实绩链设计。

需要承担：

- 极少数仍依赖旧 URL 创建日报或给新工单领料/报工/入库的外部调用会收到 `410`，必须迁移到生产实绩接口。
- 旧表与旧外键暂时仍存在，数据库结构尚未完成物理收敛。
- 生产库的 Product 映射、独占库存和历史记录必须在维护窗口单独盘点。

## 回滚

本决策版本不改 Schema 和数据。紧急情况下可回退应用版本恢复旧写入口，但不得把该回退当成长期解决方案。阶段 1B 的每次数据迁移必须另行提供迁移前备份、统计校验和恢复步骤。

详细规则见[单厂 MES 产品边界与核心模型收敛](../architecture/单厂MES产品边界与核心模型收敛.md)。
