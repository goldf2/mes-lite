# ADR 0041：物流状态动作使用独立命令权限

状态：已接受

日期：2026-08-14

## 背景

发货草稿、确认发货、客户签收和取消曾共同依赖 `shipment.update`；退货登记、收货入库和拒绝共同依赖 `return.update`；流程转移草稿、确认移库和冲销共同依赖 `flowTransfers.update`。这些动作风险不同：草稿只改变单据，发货/退货收货/移库确认会改变库存、成本或批次，签收是销售履约确认，取消、拒绝和冲销会结束或反向业务事实。继续共用通用更新会让资料编辑人员意外获得库存命令。

## 决策

1. `shipment`、`return` 和 `flowTransfers` 继续控制页面读取、草稿新建/编辑和归档。
2. `shipmentDispatch.update` 控制库存发出；`shipmentDeliver.update` 控制客户签收；`shipmentCancel.update` 控制必须填写原因的待发货取消。
3. `returnReceive.update` 控制退货接收入库；`returnReject.update` 控制必须填写原因且不产生库存的退货拒绝。
4. `flowTransferConfirm.update` 控制正向库位移动；`flowTransferReverse.update` 控制必须填写原因的反向恢复。
5. 新安装普通仓管获得发货执行、退货收货和转移确认，不获得签收、取消、拒绝或冲销；仓库主管另外获得取消、拒绝和转移冲销；销售发运组获得签收、取消和拒绝，不获得仓库出入库；生产执行组可确认正向转移，生产主管另可冲销。
6. 已有角色、内置/自定义组和个人覆盖补齐七个资源时默认全关，不从三个通用 `update` 自动继承；权限管理员必须依据岗位审批显式授予。
7. 页面只显示有效权限对应的按钮，但 API、单据状态和人员数据范围仍是安全边界。发货、签收、取消、退货收货和拒绝新增请求级审计；取消、拒绝和转移冲销保存具体原因。

## 结果

- 单据维护、仓库正向执行、销售确认与高风险反向动作形成独立授权，运行时资源从 54 个增加到 61 个。
- 仪表盘“待发货”和“退货待收货”只按正向仓库命令生成，不再因通用编辑权限出现。
- 升级不会静默扩大既有账号权限；维护窗口完成岗位签字前，相关账号可能暂时不能执行状态命令，这是有意的安全停止线。
- 不新增 Prisma 模型或平行库存服务；`modules/sales` 和 `modules/production` 继续拥有状态机、库存、成本与批次事务。

## 回滚

应用可固定回滚到上一个已验证提交，但不得删除新权限设置或用通用更新旁路已经产生的库存、批次和审计事实。回滚前暂停物流写入并备份数据库与附件；已经发货、收货、移库或冲销的业务事实不得通过数据库降级撤销。
