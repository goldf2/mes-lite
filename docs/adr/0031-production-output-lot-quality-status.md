# ADR 0031：生产产出内部批次、质量判定与库存状态

状态：接受

日期：2026-08-13

## 背景

MES-lite 的 `ProductionOrderActual` 已能把投入、产出、成本层和订单进度原子过账，但此前所有产出直接成为可用库存。旧 `QCRecord` 没有连接当前生产实绩、库存成本层或统一库存流水；来料的供应商批次号也不是可贯穿生产与发货的内部批次。

如果一次同时建设来料、生产、质量、处置、发货和全谱系，迁移面过大且无法用一条现场任务验证。阶段 2 因此先交付最小、可回放的生产产出切片。

## 决策

1. 以 `InventoryLot` 作为统一内部批次主记录，先接入新的生产实绩产出；一个产出最多对应一个批次。
2. 用 `InventoryLotBalance` 按批次、库位和状态保存数量、核算数量与成本，用 `InventoryLotTransaction` 保存每次入账或状态转换事实。
3. 库存状态第一阶段固定为 `AVAILABLE`、`QUARANTINE` 和 `HOLD`。`Stock`、`StockLocationBalance`、`InventoryCostLayer` 与批次余额同步保存状态投影。
4. 新生产产出全部先进入 `QUARANTINE`，并自动生成 `QualityInspection` 待检任务。旧 `QCRecord` 保留历史兼容，但不再作为新生产质量主流程。
5. 第一阶段只支持整批判定：合格从 `QUARANTINE` 转为 `AVAILABLE`，不合格从 `QUARANTINE` 转为 `HOLD`。状态转换不改变总数量、核算数量和总成本。
6. 质量判定必须具有独立的 `quality.update` 权限；当前入口放在生产订单详情，不新增一级页面。服务端事务与审计是安全边界。
7. 普通领料、发货、FIFO 成本消费和库存调整只使用 `AVAILABLE`；待检和冻结库存不可被这些路径消费。
8. 所有表和字段使用可加性迁移。部署不自动回填历史批次，也不改写原有库存为待检。

## 明确不包含

- 来料接收生成内部批次及供应商批次关联。
- 生产投入批次分配和投入—产出父子谱系。
- 发货、退货的批次选择与客户反向追溯。
- 部分放行、复检、让步接收、返工、报废和解冻。
- 跨工单质量任务页、抽样方案、检验项目和质量附件。

## 后果

正面影响：

- 新产出不再未经质量门禁直接成为可用库存。
- 数量、成本与状态可由批次交易、库存流水和审计共同回放。
- 后续可逐段接入来料、投入和发货，不需要重建生产产出事实。

需要承担：

- 状态余额在汇总、库位、批次和成本层存在受控投影，所有写入必须保持事务一致。
- 当前整批放行后，如果尚无批次消费分配，不能安全判断已消耗量，因此不允许直接冲销该产出批次。
- 历史库存和生产产出不会自动获得批次；追溯覆盖范围必须明确标注版本起点。

## 回滚

迁移只增加表、列和索引。尚未写入新批次时，可回退应用并保留新增结构；已经写入批次、质量或状态交易后，不删除新表、不做破坏性回迁，应该修复并前滚。回退旧应用前必须确认没有待检/冻结数量，否则旧版本会误读可用库存。生产执行前仍需一致备份和非覆盖恢复验证。
