# ADR 0003：产品文档使用可配置的两级类别

## 状态

已接受，2026-07-30。

## 背景

产品文档已经从单一作业指导书扩展为图片、PDF 图纸、检验文件、包装文件等通用资料。继续在 `WorkInstruction` 中保存“适用工序”，以及在前端和 API 中写死类别枚举，会把通用资料重新绑定到生产工艺，也无法表达“作业指导书 / 机床作业”“作业指导书 / 环境作业”等现场分类。

## 决策

- 用户侧功能入口继续命名为“产品文档”。
- “作业指导书”保留为默认一级类别，不作为独立功能菜单。
- 新增 `DocumentCategory` 主数据，支持一级、二级类别；文档可以直接使用一级或二级类别。
- 默认建立作业指导书、图纸、工艺文件、检验文件、包装文件、设备文件和其他一级类别，但类别名称和新增项不再由前端或 API 枚举写死。
- 类别可新增、改名；存在二级类别或产品文档引用时禁止删除。
- `WorkInstruction` 使用 `categoryId` 关联类别，删除原字符串 `category` 和 `processName` 字段。
- 产品文档的适用范围、注意事项和其他通用说明统一写入 `note`。
- 产品全景图按 `materialId` 展示全部相关产品文档，不限制最近条数。

## 影响

- 迁移会把已有固定类别映射到同名默认类别，并保留产品文档、附件、版本、状态和备注。
- 产品文档不再与工艺路线或工序形成隐式绑定；如果未来需要受控发放，应另建明确的发布/适用范围模型，不能恢复自由文本工序字段。
- 类别管理沿用产品文档权限并记录审计日志。
