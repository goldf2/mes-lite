# ADR-0013：多产出 BOM 与生产订单单轨化

- 状态：已接受，分阶段实施
- 日期：2026-08-03

## 背景

旧 BOM 使用“方案类型”区分生产转换和一对一转换，且只能表达一种产出。实际生产可同时得到主产品、副产品、可回收料或废料；一对一只是数量比例，不是独立的 BOM 类型。

系统同时存在“工单”和“生产日报”两条生产路径。生产日报原用于跳过 BOM 直接记产，但现在已确定所有非纯移库的生产转换必须选择 BOM，继续保留两套生产口径会导致重复报产。

## 决策

1. 删除 BOM 的“方案类型”概念；一对一、一对多和多对多都由基准批量数量表达。
2. 新增 `BOMOutput`，每个 BOM 必须有且只有一项主产出，可有多项其他产出。`BOMItem` 继续保存基准批量的投入。
3. `BOM.productId` 及 `outputQuantity/outputUnit` 暂作为主产出索引和已有成本算法的兼容投影；真实产出集合以 `BOMOutput` 为准。
4. 同一物料不得在同一 BOM 中同时作为投入和产出。同物料跨库位移动使用“流程转移”，不创建 BOM。
5. “工单”收敛为“生产订单”：可事前建立基本信息并在班后登记实绩，也可在产后直接补录。两种方式共用 BOM 快照、投入/产出实绩、库位过账、成本和冲销。
6. 独立“生产日报”将不再作为生产入口；其菜单位置改为“每日盘点”。盘点只记录账面数、实盘数、差异和原因。发现漏报生产时应生成关联的补录生产订单，不得伪装成盘盈。

## 实施分片

- 本分片实现无类型的多投入/多产出 BOM，并将旧 BOM 主产出回填为 `BOMOutput`。
- 下一分片把现有生产日报的库存过账和冲销能力迁入生产订单实绩；在此之前不只改菜单名称，避免界面语义与实际过账行为不一致。
- 生产订单完成库存闭环后，再上线每日盘点差异单并下线旧日报入口。

## 后果

- BOM 可正确表达一次生产的全部投入和全部产出。
- 生产计划与产后统计使用同一订单身份，避免仪表盘和库存重复统计。
- 盘点差异与生产实绩分账，日后可追溯每个库存差异的真实原因。
