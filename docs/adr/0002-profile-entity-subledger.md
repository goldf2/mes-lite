# ADR 0002: 在库存总账之上增加型材实体子账

## 状态

已接受

## 背景

现有 `Material + Stock + StockLog + InventoryCostLayer` 已支持物料规格、双单位余额、成本层、幂等库存流水和来料红冲。铝型材业务还需要回答“现场具体可用哪根、多长、来自哪批”，而同一物料规格可能同时存在不同实际长度。

如果直接把实际长度加入普通 BOM 或把每根型材强制建成独立物料，会导致主数据爆炸，也无法表达同长批次、拆分、余料谱系和切割实绩。

## 决策

保留现有库存总账，并增加型材实体子账：

- `ProfileSpec`：扩展 `Material` 的型材稳定属性。
- `MaterialInProfileLine`：记录一次来料中的“实际长度 + 数量 + 追溯粒度”。
- `ProfileStockEntity`：记录同长批次、单根或余料实体的长度、数量、状态、位置、来源和谱系。
- `ProfileStockMovement`：记录实体可用数量和状态的追加式变化，使用唯一幂等键。
- `Stock/StockLog/InventoryCostLayer`：继续作为兼容数量总账、双单位总账和成本账。

确认收货和红冲必须在同一个数据库事务内同时更新总账与实体子账。实体已拆分、占用、耗用或报废后，不允许直接红冲原来料单。

## 数量不变量

每个实体满足：

```text
quantity = availableQty + reservedQty + consumedQty + scrappedQty + splitQty
```

`splitQty` 表示已经从同长批次转移到子实体的数量。查询可用库存只汇总 `availableQty`，因此父批次和子实体不会重复计数。

## 兼容策略

- 没有实测长度行的历史或普通来料单只更新现有库存总账，不自动伪造实体。
- 已有 `Stock` 数据不会反向生成虚假的长度实体；实体覆盖率可单独显示。
- 旧库存、生产日报和发货 API 继续读取 `Stock`。
- 后续切割执行必须同时引用实体子账和总账库存事务。

## 影响

正面影响：

- 同一规格可管理多个实际长度。
- 可以按业务需要在同长批次和单根之间切换追溯粒度。
- 余料、切割计划和实绩可沿实体谱系扩展。
- 迁移不破坏既有库存和成本逻辑。

代价：

- 需要持续校验总账数量与实体覆盖数量的关系。
- 已有库存若没有来源长度，只能作为“未实体化余额”继续存在。
- 后续领料、锯切、冲销必须同时维护两套相互校验的账。
