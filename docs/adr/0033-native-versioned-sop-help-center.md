# ADR 0033：原生版本化 SOP 帮助中心

状态：已接受

日期：2026-08-13

## 背景

现有 138 个流程虽然已有 Markdown、DOCX、PDF 和离线 Web，但内容硬编码在生成脚本，网站无法按当前页面和账号权限复用。继续维护平行网页和文档会产生版本漂移，也无法在代码变化时自动发现 SOP 未同步。

## 决策

- `sop/manifest.json` 是流程标题、目的、步骤、结果、页面键、权限资源、岗位、截图和验证版本的唯一内容源。
- MES-lite 增加原生“帮助中心”，顶部问号打开当前页面帮助抽屉；两个入口都通过 `/api/sop` 按登录账号的资源读取权限过滤。
- 截图保留在受控文档目录，并通过鉴权接口返回，不放入可匿名访问的公共目录。
- Markdown、DOCX、PDF 和离线 Web 都由同一清单生成；版本取自 `package.json`，不在脚本重复硬编码。
- 每个版本维护 `sop/change-impact.json`。业务代码变化而没有更新影响声明时，CI 失败；流程标记为更新时，受影响流程必须有当前版本的复核和截图。

## 结果

SOP 成为产品功能和发布门禁的一部分。用户在系统内获得与页面相关、符合权限的操作说明；实施方仍可交付离线和打印格式。代价是每次业务流程变化必须同步维护清单并重新拍摄受影响截图，这属于受控发布成本。

## 回滚

移除 `helpCenter` 页面、问号抽屉和 `/api/sop*` 路由即可回退运行时能力；`sop/manifest.json` 与生成器仍可继续作为离线文档单一内容源。没有数据库迁移或数据回滚。
