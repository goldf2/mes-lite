# ADR 0035：设备状态作为可审计运行事件

状态：接受

日期：2026-08-14

## 背景

设备台账原先把 `status` 当作普通基础字段。任意有设备更新权限的人员都可以覆盖当前状态，无法回答何时停机、为何故障、谁执行恢复、故障持续多久，也无法区分资料维护与现场运行命令。

## 决策

1. `Equipment.status` 保留为高效当前快照，但基础资料输入严格拒绝该字段，新设备固定从 `AVAILABLE` 开始。
2. 开机、停机、故障和恢复由明确状态机校验；非法转换返回 409。
3. 每次命令只追加一条 `EquipmentEvent`，状态快照与事件在同一数据库事务更新；历史命令不修改业务内容，仅允许恢复动作补齐被关闭事件的结束时间和持续时间。
4. 恢复关闭最近一条未结束的故障、停机或维护事件，并把持续时间写回被关闭事件；恢复事件不重复保存该时长。
5. 归档导致的停机也创建 `ARCHIVE` 事件，并关闭仍未结束的故障、停机或维护事件；事件通过外键和触发器阻止被物理删除。
6. 时间线读取使用 `equipment.read`，运行命令使用独立 `equipmentEvents.update`；前端可见性不代替 API 鉴权。
7. SQLite 触发器保证新设备从 `AVAILABLE` 开始、状态快照只能跟随最新匹配事件改变，事件业务事实只追加且不可删除；恢复或归档只允许一次性补齐结束时间和持续时间。

## 影响

- 设备状态变化可按原因、人员和时间回放，故障/停机持续时间可计算。
- 升级安装首次补齐新权限时从原设备资源继承，保证现有岗位不中断，但部署后必须按企业审批收窄。
- 本 ADR 不引入点检、保养、维修工单、自动采集或 OEE；这些能力应在后续垂直切片中引用事件事实，而不是重新建立平行状态字段。
