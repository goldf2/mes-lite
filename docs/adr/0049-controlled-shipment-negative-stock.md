# ADR-0049：发货允许受控负库存，后续可用入库自动补账

- 状态：已接受
- 日期：2026-09-04

## 背景

小型加工厂可能先开具并确认发货单，实物入库记录稍后补录。若发货必须等待账面库存充足，现场会改用线下单据或虚假入库；若简单关闭全部负库存校验，则生产领料、调拨、批次和成本都会失去约束。

## 决策

1. 只有确认发货可把所选物料、库位的总量和可用量扣为负数；生产领料、调拨和普通库存动作仍不能扩大负库存。
2. 发货时先消费当时真实可用的内部批次和成本层，不足数量写入一条与发货明细唯一关联的 `ShipmentStockShortage`。
3. 后续同物料、同库位形成可用内部批次时，系统按欠库创建时间自动补齐发货批次、核算量和成本，补账明细写入 `ShipmentStockShortageSettlement`。
4. 可用入库已经增加总数量，补账只消费新批次及其核算量和成本，不再次扣减总数量。
5. 数据一致性检查仅接受不超过尚未补齐发货欠库的负数量；预留、待检、冻结、返工、核算数量和金额仍不得为负。
6. 欠库未补齐的发货明细不能登记客户退货，因为尚无完整真实批次和成本可供回流。
7. 发货冲销必须同时恢复原发货数量、已消费成本层、后补批次和成本，并把欠库及其补账记录保留为已冲销事实。

## 后果

- 现场可以先确认发货、后补实际入库，不需要伪造入库单。
- 负库存有明确的发货单、明细、物料和库位来源，不成为无法解释的账面黑箱。
- 发货成本在欠库补齐前是暂定值；详情以“待补库存”标识，补齐后恢复为真实批次追踪。
- 欠库按原发货库位补齐；若后续来料进入其他库位，应先按正常流程转移到原发货库位。

## 回滚

应用可回滚到上一已验证版本，但存在欠库记录时不得降级数据库或恢复旧应用写入。应先暂停发货和入库写入，备份数据库，补齐或冲销所有开放欠库，再按迁移恢复手册执行。
