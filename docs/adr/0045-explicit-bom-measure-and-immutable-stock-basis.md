# ADR 0045：BOM 显式计量维度与库存记账口径冻结

- 状态：已接受，2026-09-05
- 取代：ADR 0007 中允许已有业务历史物料直接修改库存口径的部分

## 背景

物料可以同时具有长度、重量和数量等计量维度。BOM 如果在关联物料时直接读取物料当前的库存单位数值，操作员容易把不同量纲的数量当成同一数值使用。物料库存、库位余额、预留、发货和成本层又必须有一个稳定的对账口径。

## 决策

1. 系统内部保留唯一的库存记账维度和单位，前台称为“库存记账口径”，不再把它作为可随意切换的业务主单位。
2. 物料有库存余额、库存流水、来料、成本层、BOM、生产或发货历史后，不得直接修改库存记账口径。需要改变时，创建新物料版本或执行有明确换算关系、影响范围和审计记录的迁移。
3. BOM 投入和产出行必须显式选择计量维度和录入单位。相同量纲使用单位目录换算；跨量纲必须使用物料标准关系或批次实测关系，禁止默认按数值 1:1 换算。
4. 保存或发布 BOM 时，必须同时冻结录入维度、录入单位、录入数量、库存记账数量、换算来源、换算关系版本和库存单位快照。物料后续调整不改变已发布 BOM。
5. 没有可靠换算关系的 BOM 行必须阻止保存/发布并提示补充数据；历史缺少快照的 BOM 不得通过猜测自动修复。

6. 该规则是应用级计量规则，不仅适用于 BOM 编辑器。来料、库存过账、库位调拨、领料、生产实绩、入库、发货、退货、库存调整、成本计算、物料导入导出、报表和物料全景都必须通过同一套计量维度识别、单位目录换算、跨量纲关系校验和快照机制；页面不得各自实现隐式的 1:1 换算。

7. 所有涉及数量的命令必须在服务端再次校验量纲和换算关系，前端只负责提供选择、预览和错误提示。库存过账统一写入库存记账单位，原始录入单位和换算依据写入业务明细或流水快照。

## 结果

- `33 mm`、`0.033 m` 和对应的重量不再被当成同一个无单位数字。
- 物料可按长度编制 BOM，同时按重量进行库存核算，但两者之间必须有可追溯的换算依据。
- 现有 `entryUnit`、`entryQuantity`、`conversionRateUsed` 和 `unitVersionUsed` 快照字段继续复用；后续补充显式计量维度快照，避免仅从物料当前设置反推历史含义。
- 旧 BOM 的单位异常只能在确认标准或批次换算关系后复制为新版本，不能直接把旧数量改写成另一量纲。
- 同一物料在不同页面不会出现“BOM 按 mm、生产按 m、发货按主单位却不提示”的分裂行为；所有数量都能追溯到录入单位、记账单位和换算依据。
