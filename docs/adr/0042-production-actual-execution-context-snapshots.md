# ADR 0042：生产实绩冻结实际设备与作业文件版本

状态：已接受

日期：2026-08-15

## 背景

生产订单已经冻结 BOM，班后实绩也保存员工、投入、产出、库位、批次和质量事实，但实际设备及当时执行的作业文件仍只存在于现场记忆或可变主数据中。设备名称、状态、工作中心和文件正文、版本、附件清单都可能在事后修改；若实绩只保存外键，历史无法回答“当时使用了哪台设备、按哪个版本执行”。

同时，小微工厂确有纯手工作业、临时返修或当时没有适用电子文件的场景。把两类关联简单设为数据库非空会制造虚假选择，把它们保持可空又会继续留下静默缺口。

## 决策

1. 在 `ProductionOrderActual` 下新增 `ProductionOrderActualEquipment` 和 `ProductionOrderActualWorkInstruction` 两类归一化快照，不把多对象事实塞入单个 JSON 字段。
2. 设备候选只包含订单派工或默认工艺路线工作中心内、未归档且当前处于可用/运行状态的设备；文件候选只包含未归档、已生效，并适用于订单主产出物料或这些工作中心的文档。
3. 前端只提交来源 ID。生产领域服务在保存草稿的事务内重新读取并冻结设备编码、名称、类型、型号、状态、工作中心，以及文件标题、版本、状态、类别、适用范围、正文、附件清单和来源更新时间。
4. 每张实绩必须分别满足“至少一台设备，或填写设备例外原因”和“至少一份作业文件，或填写文件例外原因”；原因长度为 2 到 200 个字符。历史实绩由加性迁移填写明确的历史迁移原因，不伪造过去不存在的选择。
5. 实绩确认前由服务再次检查两组条件；数据库触发器阻断绕过服务的无上下文确认，并保护已确认或已冲销实绩的快照和例外原因不可更新或删除。
6. 文件快照保存正文和附件元数据清单，但不复制附件二进制。当前单厂轻量 MES 继续以持久化附件目录、备份和恢复演练保护原文件；若客户法规要求逐字节固化，再增加内容哈希、对象版本或受控副本，不在本切片制造第二套附件存储。
7. 页面复用公共一对多关联编辑骨架，执行“搜索 - 添加 - 已选列表 - 移除 - 一次保存”；桌面双列、移动单列。领域候选、确认和不可变规则仍只由生产服务及数据库拥有。

## 结果

- 人员、设备、作业方法、投入/产出、批次和质量事实可以从同一生产实绩回放，“人机料法”手工执行上下文缺口关闭。
- 来源设备或文件后续改名、转工作中心、停用、更新版本或归档，不会改写既有实绩。
- 例外场景保持可操作，但必须留下明确原因，不能用空值冒充完整记录。
- 新增两个 Prisma 模型和第 82 个迁移；既有接口 URL、权限资源、库存、成本、批次与质量状态机不变。
- 本决策不等于自动采集、设备节拍、停机原因分析或 OEE 已完成。

## 回滚

本迁移只增加可空字段、快照表、索引和保护触发器，并为历史实绩补原因。部署后若应用需要回滚，应先暂停生产写入并完成数据库/附件一致备份，然后固定到上一已验证提交；旧应用会忽略新增表和字段。不得删除已经产生的快照或通过降级迁移清空历史原因。重新部署本版本前应在隔离副本重放全部迁移并验证确认、冲销和触发器约束。
