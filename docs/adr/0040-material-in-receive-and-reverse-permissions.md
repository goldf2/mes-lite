# ADR 0040：来料收货与红冲使用独立命令权限

状态：已接受

日期：2026-08-14

## 背景

来料草稿编辑、确认收货、拒收和整单红冲曾共同依赖 `materialIn.update`。其中编辑只改变待收货单据，收货会过账库存/成本并可能建立质量任务，红冲会反向库存、批次、成本层及质量任务。继续共用一个更新权限，会让资料录入或质量只读岗位意外具备仓库库存命令。

## 决策

1. `materialIn` 继续控制来料页面读取、草稿新建/编辑和归档。
2. `materialInReceive.update` 独立控制确认收货和拒收；仪表盘“待收货”任务使用同一资源。
3. `materialInReverse.update` 独立控制必须填写原因的整单红冲。
4. 新安装的仓库作业组获得收货/拒收但不获得红冲；仓库主管组另获得红冲。质量、计划和基础访问组不获得仓库命令。
5. 已有安装补齐两个资源时默认全关，不从旧角色、内置/自定义组或个人覆盖的 `materialIn.update` 自动继承；由权限管理员在维护窗口依据岗位审批显式授予。
6. 页面按钮按有效权限显示，但 API 和领域数据范围仍是安全边界；权限通过后仍须校验库位范围、单据状态、批次/成本未被使用和质量任务状态。

## 结果

- 单据录入、库存过账、库存冲销和质量判定形成四层独立授权。
- 升级不会静默扩大既有账号权限，但部署后仓库岗位在审批前可能暂时不能收货或红冲，这是有意的安全停止线。
- 不新增页面、Prisma 模型或平行库存服务；`modules/receiving` 继续拥有状态与事务规则。

## 回滚

应用可回滚到上一个精确提交，但不得删除新权限设置或用通用更新绕过已产生的库存/质量事实。若业务暂不启用新版本，应在维护窗口暂停来料写入并恢复部署前应用；不执行破坏性数据库降级。
