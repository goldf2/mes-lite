# ADR 0019：页面顶部工具栏采用强制注册契约

## 状态

已采纳，2026-08-06。

## 背景

系统已经用 `PageModuleBoundary` 将页面划分为六类，但该边界过去只输出页面键、模块类型和样式类，不约束搜索、筛选、视图和页面操作的位置。`TopBarPortal` 也只能由业务页面主动调用，遗漏时不会失败。结果是设备、员工等新页面使用顶部工具栏，而客户、供应商、配置和权限等旧页面继续把同类操作放在内容卡片内。

原 `verify:page-modules` 只校验 34 个入口是否分类，因而“页面已经进入公共边界”被误当成“页面已经完整接入公共框架”。

## 决策

1. 每个 `PageModuleDefinition` 必须声明 `toolbar: required | none`，不允许隐式状态。
2. `TopBarPortal` 在所属 `PageModuleBoundary` 注册自身；要求工具栏但没有注册的页面在开发环境输出明确错误。
3. 由应用壳直接渲染工具栏的生产订单列表、创建页、详情页和库存页，必须通过 `toolbarProvided` 显式声明，不能依赖视觉上“似乎存在”。
4. 仪表盘、系统设置、锯切成本、硬件工具和数据工具当前没有独立页级搜索/筛选/视图操作，登记为明确例外；新增页级操作时必须先改为 `required`。
5. `verify:page-modules` 同时校验工具栏策略：当前 29 个页面强制公共顶部工具栏，5 个页面为明确例外。

## 结果

- 遗漏顶部工具栏会在开发期暴露，不再依赖人工截图发现。
- 页面分类与框架接入不再混为一谈。
- 复杂业务页面仍可保留领域内核，但页级搜索、筛选、视图和操作必须通过公共工具栏挂载。
