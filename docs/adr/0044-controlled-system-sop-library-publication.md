# ADR 0044：系统 SOP 以清单驱动方式受控登记到产品文档库

日期：2026-08-15

状态：已接受

## 背景

MES-lite 的在线帮助由 `sop/manifest.json` 随代码版本发布，最终 PDF/DOCX 则保存在 Git 和 Docker 发布树之外，并通过一个公开只读 OSS 地址交付。客户同时希望在 MES-lite 的产品文档库中保存同版离线成品。

若在 Webhook 部署或容器启动时自动写入生产数据库，会把代码部署身份扩张为业务文控身份；若只依赖人工上传，又无法证明站内副本、OSS 文件和应用版本一致，也难以安全重试。

## 决策

1. 使用最终发布清单中的版本、精确对象路径、文件大小和 SHA-256 作为 OSS 与站内副本的共同事实源。
2. 提供独立维护命令，支持本地成品目录或单一 OSS 公开基地址；从 OSS 读取时只请求当前应用的 `v<版本>/manifest.json` 和精确版本文件，不依赖 `latest`。
3. 命令默认只读预检，不在自动部署、容器启动或数据库迁移中执行。写入必须显式增加 `--apply`、一致备份引用和启用的文控账号。
4. 写入账号必须拥有文档类别新增、产品文档新增/修改和附件新增权限。预检不补写默认权限，不使用部署进程身份代替业务操作人。
5. 新版本先建立 `DRAFT` 通用文档并补齐两个附件；只有两份文件再次通过清单校验后，才在同一事务中启用当前版、归档旧受控版本并写发布审计。
6. 受控记录使用专用标记和成品指纹。人工同名文档、额外附件、重复数据、归档同版本或文件漂移一律阻断，不自动接管或覆盖。

## 影响

- 相同版本和成品指纹可安全重试，重复执行不会新增文档、附件或审计。
- 文件写入无法与 SQLite 事务形成单一原子提交，因此中断时保留未生效草稿；重试补齐缺失附件，旧生效版本不受影响。
- 站内附件继续使用现有持久目录和 50MB 单文件上限；超限成品仍可只在 OSS 提供下载，但不能伪装为已登记站内副本。
- 旧受控版本只改为 `ARCHIVED`，不删除记录和文件。回滚由文控人员重新启用上一版、归档当前版并记录原因。
- 真实生产发布仍依赖客户提供 OSS 地址/凭据、最新一致备份和真实文控账号验收；临时数据库回归不能替代这些外部证据。
