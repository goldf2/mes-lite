# ADR 0036：设备点检作为不可变周期事实

状态：已接受

日期：2026-08-14

## 背景

设备台账和运行事件只能回答“设备当前是什么状态、什么时候发生过状态变化”，不能证明某个班次是否按既定标准逐项检查。若直接在设备表保存“最后点检结果”，历史标准、逐项实测、人员和异常原因会被后续更新覆盖，也无法可靠联动故障事件和现场附件。

## 决策

1. 使用 `EquipmentInspectionPlan` 与 `EquipmentInspectionPlanItem` 保存一台设备的周期、下次到期时间和有序检查标准。计划创建后不可改写主体或项目，只允许暂停、恢复以及由一次完整记录推进下次到期。
2. 使用 `EquipmentInspectionRecord` 与 `EquipmentInspectionResult` 保存一次完整执行事实。记录冻结应检时间、实检时间、点检人、汇总结果、项目名称/标准/单位快照、实测值和说明；记录与结果不可更新或删除。
3. 每次执行必须提交计划的全部项目；异常项目必须填写说明。客户端生成 `operationId`，服务端唯一约束保证重复请求只返回原记录。
4. 当设备处于 `AVAILABLE` 或 `IN_USE` 且点检异常时，在同一数据库事务创建 `FAULT` 事件、改变设备状态并把事件关联到点检记录。设备已经处于其他异常/停机状态时仍保存点检事实，但不制造非法状态转换。
5. 点检使用独立 `equipmentInspections` 权限资源，并叠加工作中心数据范围；记录附件使用 `EQUIPMENT_INSPECTION_RECORD` 所有者类型，继续叠加 `attachments` 动作权限。
6. SQLite 触发器保护计划/项目/记录/结果的不变式；服务层负责事务级完整清单与幂等。两层缺一不可。

## 结果

- 到期、逾期和异常任务可从稳定事实计算，不依赖可覆盖的设备字段。
- 异常点检、故障时间线、人员、审计和附件具备同一追溯链。
- 历史标准不会随计划调整漂移；标准变更需要建立新计划并暂停旧计划。
- 本决策不等于已交付保养、维修工单、备件、设备采集或 OEE，这些能力继续作为后续切片。

## 回滚

旧版本代码不会访问四张新增表，因此应用回滚时保留数据表和记录，不执行破坏性降级。回滚前暂停点检写入，恢复到已验证应用提交；重新升级后继续使用原计划、记录和下次到期时间。
