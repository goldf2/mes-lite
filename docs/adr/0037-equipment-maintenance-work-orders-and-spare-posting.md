# ADR 0037：设备维保工单与备件过账形成同一事实闭环

状态：已接受

日期：2026-08-14

## 背景

设备事件和周期点检已经能够说明设备状态变化与检查结果，但仍不能回答“谁在何时开始维修、做了什么、用了哪个库位的哪一批备件、设备何时恢复”。如果维修记录、设备恢复和库存扣减分别提交，任何一步失败都会留下设备已恢复但库存未扣、库存已扣但工单未完成等不一致事实。

## 决策

1. 使用 `EquipmentMaintenancePlan` 与 `EquipmentMaintenancePlanItem` 保存周期保养标准；计划和项目创建后不可覆盖，只允许暂停、恢复以及完成对应周期工单后推进下次到期。
2. 使用 `EquipmentMaintenanceWorkOrder` 统一计划保养和故障维修。合法状态仅为 `OPEN → IN_PROGRESS → COMPLETED` 或 `OPEN → CANCELLED`，完成和取消事实不可逆。
3. 计划保养工单通过“计划 + 到期时点”唯一约束阻止重复活动工单；故障维修通过客户端 `operationId` 保证重试幂等。
4. 开始工单时在同一事务记录 `MAINTAIN` 设备事件并把设备切为 `MAINTENANCE`；完成工单时记录 `RECOVER` 事件并恢复为 `AVAILABLE`。
5. 计划保养完成必须提交全部计划项目的 `PASS` 结果。结果保存为 `EquipmentMaintenanceWorkResult`，之后不可更新或删除。
6. 备件领用通过库存模块公开入口过账。每项 `EquipmentMaintenanceSpareUsage` 保存物料、库位、主量/核算量、单位换算、成本法和金额快照；`EquipmentMaintenanceSpareLotAllocation` 保存 FIFO 实际批次分配。
7. 工单完成、设备恢复、计划推进、库存流水、成本和批次分配在同一数据库事务中提交；任一步失败全部回滚。
8. 维保使用独立 `equipmentMaintenance` 权限资源，并叠加工作中心范围；物料和库位候选叠加库存库位范围。附件使用 `EQUIPMENT_MAINTENANCE_WORK_ORDER` 所有者类型并继续要求附件权限。
9. SQLite 触发器保护计划、项目、状态机、完整保养结果和完成事实；服务层负责跨模块事务、幂等、权限和数据范围。库存跨模块调用只经过 `modules/inventory` 公共入口。

## 结果

- 到期计划、维修待办、开始维修、设备恢复、备件库存/成本/批次可以在一条工单链中互相核对。
- 备件领用不建立第二套库存算法，继续使用当前库存批次与成本口径。
- 历史计划标准、完成结果和实际批次不会被后续修改覆盖。
- 设备自动采集、停机原因采集、节拍和 OEE 仍未交付；在采集来源、时间同步和质量口径明确前不制造手工 OEE 数字。

## 回滚

应用回滚时先暂停新的维保写入，固定到上一已验证提交；保留六张新增表、库存流水、设备事件和完成事实，不执行破坏性降级。旧版本会忽略维保表，但仍能读取已经形成的设备与库存事实。只有迁移或数据库损坏且应用回滚无效时，才经业务确认恢复部署前数据库与附件一致备份。
