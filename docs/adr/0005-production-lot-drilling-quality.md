# ADR 0005：用生产批次承接锯切、可选钻孔、质检与成品入库

- 状态：已接受
- 日期：2026-07-30

## 背景

现有 `WorkReport`、`QCRecord` 和 `StockIn` 是面向普通工单的基础对象：

- `WorkReport` 直接读取当前工艺路线，不能稳定关联锯切任务及原料实体谱系；
- `QCRecord` 有数据表但没有完整 API 和页面；
- `StockIn` 只校验工单状态，不能限制某一批合格数量是否已入库；
- 无钻孔产品不应为了统一流程多做一次无意义操作。

锯切合格件需要一个稳定对象承接后续加工和质检，同时保留从原料实体到成品库存的追溯链。

## 决策

1. 锯切任务完工后，按 `切割任务 + 切割需求` 创建 `ProductionLot`。
2. 生产批次保存工单、成品物料、锯切需求、来源任务、数量分桶和材料成本快照。
3. 是否需要钻孔由工单创建时冻结的工艺快照判断：
   - 包含 `DRILLING` 工艺类别时，合格切件进入待钻孔；
   - 否则直接进入待质检。
4. 工艺快照新增 `templateCategory`。孔型、图纸和备注保存为批次/钻孔实绩快照，不固化尚未确认的参数结构。
5. 钻孔与质检采用追加实绩：
   - 钻孔把待钻孔或返工数量分解为合格、返工、报废；
   - 质检把待检或返工数量分解为合格、返工、报废；
   - 无钻孔批次可直接质检。
6. 只有质检合格数量可以成品入库，累计入库不得超过累计合格。
7. 成品入库复用 `StockIn`，增加生产批次、目标物料、幂等键、双单位、成本和冲销字段；库存变化仍使用 `Stock`、`StockLog` 与成本层。
8. 钻孔、质检和入库均支持受约束的反向操作。已有后续业务时禁止越级冲销。
9. 旧工单报工、旧 `QCRecord` 和旧入库接口继续保留，避免破坏现有数据与流程。

## 数量不变量

生产批次始终满足：

```text
切割合格数量
= 待钻孔数量
+ 待检数量
+ 返工数量
+ 质检合格数量
+ 报废数量
```

`已入库数量` 是 `质检合格数量` 的子集，不能参与上述相加，且不得超过质检合格数量。

## 结果

- 无钻孔产品不会产生额外钻孔操作。
- 有钻孔产品可记录孔型、图纸、合格、返工与报废。
- 质检和入库按批次数量受控，不再只依赖工单状态。
- 原料实体 → 锯切任务 → 生产批次 → 钻孔/质检 → 成品入库形成可查询链路。
