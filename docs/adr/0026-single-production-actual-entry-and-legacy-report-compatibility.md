# ADR-0026：生产实绩唯一入口与旧日报数据兼容

## 状态

已采纳，2026-08-09。

## 背景

系统曾提供独立“统计分析/生产日报”页面，以 BOM、人员和库位直接登记产量。生产订单后来建立了新的班后实绩闭环，支持订单 BOM 快照、实际投入、多产出、库存原子过账和冲销。旧页面随后从页面注册、导航和应用壳中移除，但前端文件、工作台功能键和自动校验残余仍然存在。

继续维护两套实绩入口会造成状态语义、权限、库存过账规则和用户认知分叉；直接删除旧数据表和接口则可能破坏服务器中的历史正式记录。

## 决策

1. 当前生产实绩只允许从生产订单详情进入，使用 `ProductionOrderActual` 闭环。
2. 删除不可达的 `StatsPage.tsx` 以及对应高级搜索、页面规模和工作台快捷键配置。
3. 已保存的旧工作台偏好遇到 `stats` 键时静默丢弃，并由默认仪表盘入口补位。
4. `stats` 权限资源暂时保留，因为统计接口和流程转移仍在使用；权限资源名称与工作台功能键是不同概念。
5. `DailyProductionReport` Prisma 模型、数据库迁移、历史关联保护和 API 暂时作为只保留兼容能力，不在本轮删除或迁移。
6. 未来下线旧日报模型前，必须先盘点服务器正式数据，提供到生产订单实绩或只读历史档案的映射、校验、备份和回滚方案。

## 结果

- 消除第二套不可达生产实绩 UI，前端减少 936 行。
- 用户只需理解“生产订单 → 详情 / 登记实绩”一条路径。
- 本轮不执行数据库迁移，不修改服务器正式数据。
- `v0.1.322` 将暂留的 4 条兼容 API 收薄，并把输入、日期编号、BOM/人员/耗用快照、查询、确认过账和冲销恢复集中到 `modules/production`；这不改变“旧入口保持移除”的决策，也不表示旧模型可以长期并行承载新生产实绩。
