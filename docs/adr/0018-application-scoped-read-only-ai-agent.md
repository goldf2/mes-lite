# ADR 0018：采用应用级只读 AI Agent 与受控工具边界

## 状态

已采纳，2026-08-05。

## 背景

MES-lite 的模块和业务闭环逐步增多。完全依赖静态教学说明会增加维护成本，也难以根据当前页面、用户权限和实时数据回答具体问题。直接把通用聊天模型接入数据库又会产生越权、误写、数据泄露和提示词注入风险。

## 决策

- 在 Web 应用壳提供一个全局 AI 协作入口，桌面端和移动端复用同一组件及服务端接口。
- Agent 聚焦 MES-lite 业务范围，不提供通用聊天和互联网工具。
- 第一阶段仅提供系统指导、物料、库存、BOM、生产订单和经营概览六个只读工具。
- 工具列表按当前账号资源权限生成，执行时再次鉴权；模型和前端均不构成权限边界。
- 使用 OpenAI 兼容协议对接国产模型，默认配置指向阿里云百炼，但模型供应商和模型 ID 由环境变量决定。
- 默认不持久化对话正文；审计只记录模型、工具、数据来源和页面上下文。
- AI 可以替代大段教学和首次使用说明，但不能替代确定性的字段提示、校验、状态和确认。
- 回答采用按问题类型固定的范式：结论先行，实时查询必须包含查询条件和关键数据，教学回答包含步骤和注意事项，分析回答区分依据、风险和建议，写操作请求必须先声明未执行。

## 结果

- 用户可以从任意业务页面直接询问系统使用方法和实时业务数据。
- 数据访问仍由现有 MES 权限与 Prisma 查询控制，不向模型提供任意数据库能力。
- 没有模型配置时系统仍可正常运行，AI 面板只显示配置状态。
- 后续增加写操作需要单独 ADR，并实现预览、人工确认、事务、鉴权和审计闭环。
