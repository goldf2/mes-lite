# ADR 0034：附件路径可移植与应用级恢复演练

状态：接受

日期：2026-08-13

## 背景

`DocumentAttachment.storagePath` 的历史记录保存了容器内绝对路径 `/app/public/uploads/...`。技术候选恢复能证明数据库、附件清单和 SHA-256 正确，但把候选挂载到本机或另一服务器目录后，附件 API 会把旧绝对路径判为当前根目录之外，无法完成新实例附件抽查。

仅把绝对路径检查关闭会允许任意路径读取，破坏附件对象级鉴权后的文件系统边界；批量改写生产表又会让恢复演练产生额外数据变更。

## 决策

1. `MES_LITE_UPLOAD_DIR` 继续是唯一当前附件根目录。
2. 只有当历史路径严格位于 `/app/public/uploads`（或演练时显式配置的 `MES_LITE_LEGACY_UPLOAD_DIR`）内部时，才提取相对路径并映射到当前根目录。
3. 当前根目录自身、其他绝对路径、`..` 越界和符号链接不受支持，继续拒绝。
4. 不批量改写 `DocumentAttachment.storagePath`，保证恢复候选原数据不变。
5. 增加非覆盖应用级演练命令：复制数据库及附件并全量哈希，部署当前迁移，创建仅存在于复制库的随机临时管理员，启动生产构建，验证 readiness、登录、代表性只读业务 API 与附件原文件哈希，停止应用并清理临时账号。
6. 证据报告只记录版本、数量、SHA-256、检查状态和 RPO/RTO，不记录业务明细、附件名称、账号或密码。

## 影响

- 历史容器绝对路径可随恢复候选安全迁移到新挂载根目录。
- 附件 API 仍通过对象权限和文件根目录双重限制，不增加任意文件读取路径。
- 应用级演练会改动隔离复制库以部署迁移和创建临时账号，但不改写源候选或在线生产。
- 本机应用 RTO 不能替代真实 Coolify 停机与挂载切换 RTO；异地取回也仍需独立凭据和环境验收。
