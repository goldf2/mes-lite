# 项目记忆记录协议

本协议定义如何把重要对话和工程事实沉淀到项目文件，使新的 AI 或开发者不依赖聊天历史也能恢复工作。保存的是可复用的状态、结论和证据，不是逐字聊天记录。

## 一、信息分层

### 热信息：每次接手先读

| 文件 | 唯一职责 |
| --- | --- |
| `CURRENT_STATE.md` | 当前项目状态的唯一摘要 |
| `NEXT_ACTIONS.md` | 当前可执行任务、优先级和验收标准 |
| `PROJECT_BRIEF.md` | 稳定目标、范围和长期约束 |

### 温信息：按当前任务读取

| 文件 | 唯一职责 |
| --- | --- |
| `SESSION_LOG.md` | 研发过程、改动、验证和接续点 |
| `DEBUG_LOG.md` | 问题复现、证据、根因、修复和回归验证 |
| `DISCUSSIONS.md` | 有后续影响的方案讨论、结论和未决问题 |
| `DECISIONS.md` | 已确认且需要长期遵守的决策 |
| `RELEASE_LOG.md` | 发布、部署、回滚和线上验证事实 |

### 冷信息：需要时查询

`RUNBOOK.md`、`QUALITY_GATE.md`、`SECURITY_AND_PRIVACY.md`、`RISK_REGISTER.md`、`MODEL_AND_EVAL.md` 和 `docs/adr/` 保存长期运行规则与专题资料，不应重复当前状态。

## 二、何时必须记录

在以下节点发生后及时写入，不必等待会话自然结束：

1. 用户确认范围、优先级、方案或关键取舍。
2. 完成一段可运行、可测试或可交付的工作。
3. 得到新的测试、构建、安装、部署或现场验证证据。
4. Debug 获得新的复现步骤、排除证据、根因或回归结果。
5. 出现阻塞、风险、待用户决定的问题或状态记录失真。
6. 发布、回滚、部署失败、切换版本或切换运行环境。
7. 准备换 AI、换任务、换目录或中断当前工作。

不记录寒暄、重复复述、未经采纳的随口想法、完整思维过程或逐字对话。

## 三、写入顺序

一次实质工作结束时按需执行：

1. 先把专项证据写入 `DEBUG_LOG.md`、`DISCUSSIONS.md`、`DECISIONS.md` 或 `RELEASE_LOG.md`。
2. 在 `SESSION_LOG.md` 追加本次研发摘要，并链接专项编号。
3. 将 `CURRENT_STATE.md` 重写为当前真实状态，删除已经失效的“当前”描述。
4. 更新 `NEXT_ACTIONS.md`：关闭已完成项，加入新任务并写明验收标准。
5. 如果命令、门禁、安全边界或长期风险改变，再更新对应专题文件。

## 四、证据与状态

所有重要陈述使用以下状态之一，正文可直接写中文标签：

- `已验证`：有当前代码、命令输出、测试、界面操作或部署证据。
- `待验证`：计划已存在，但尚无足够证据。
- `假设`：用于指导排查的暂时解释，不能当作根因或结论。
- `已确认决策`：用户或有权限的负责人已明确接受。
- `已阻塞`：存在明确阻塞条件，并写明解除条件。

证据至少包含日期时间和以下一项：命令及结果摘要、测试名称、文件路径、提交号、版本号、环境、可复现操作或用户验收。不要仅写“已测试”“应该可以”“已部署”。

## 五、单一事实来源

- 当前状态只在 `CURRENT_STATE.md` 汇总；历史日志不回写成另一份状态页。
- 下一步只在 `NEXT_ACTIONS.md` 排序；其他文件使用任务编号链接它。
- 问题调查只在 `DEBUG_LOG.md` 维护完整证据；会话日志只写摘要和问题编号。
- 已确认决策写入 `DECISIONS.md` 或独立 ADR；讨论文件只保留讨论过程和开放问题。
- 发布结果只在 `RELEASE_LOG.md` 维护；`CURRENT_STATE.md` 只引用当前线上版本和最近验证。
- 文档与代码、Git、构建或运行环境冲突时，以当前可复核证据为准，并立即修正文档。

## 六、格式规则

- 时间统一使用 `YYYY-MM-DD HH:mm Z`，例如 `2026-09-04 14:30 +08:00`。
- 使用稳定编号：任务 `TASK-YYYYMMDD-NN`、问题 `BUG-YYYYMMDD-NN`、讨论 `DISC-YYYYMMDD-NN`、发布 `REL-YYYYMMDD-NN`。
- 最新条目放在文件顶部；已有编号不得复用。需要纠错时保留原记录并追加“更正”。
- 使用项目相对路径；跨项目引用使用绝对路径并解释边界。
- 记录结果摘要，不粘贴超长日志。原始日志可放入专门制品目录并从记录中链接。
- 不记录密钥、令牌、Cookie、真实个人账户、生产凭证或未脱敏数据，只记录变量名和安全获取方式。

## 七、恢复检查

新接手者在修改前应能回答：

1. 项目解决什么问题，当前范围是什么？
2. 当前真实运行状态和最新验证证据是什么？
3. 最高优先级任务及验收标准是什么？
4. 哪些内容已验证、待验证、属于假设或已经阻塞？
5. 最近一次 Debug、关键讨论、决策和发布分别是什么？
6. 应从哪个文件、命令或可复现步骤继续？

任一问题无法回答时，先查代码和运行证据，再补正文档；不要依靠模型记忆猜测。
