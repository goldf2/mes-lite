# AI 开发工作流

本文件定义 AI 协作开发的标准节奏。目标是让每次会话都能小步推进、可验证、可交接。

## 标准闭环

```text
读上下文 -> 复述理解 -> 明确任务 -> 小步修改 -> 运行验证 -> 更新交接 -> 总结下一步
```

## 角色分工

| 角色 | 主要职责 | 不应做 |
| --- | --- | --- |
| 用户 | 明确目标、确认高风险操作、验收关键结果 | 把密钥或未脱敏数据发给 AI |
| AI | 阅读上下文、执行任务、验证结果、更新交接 | 擅自扩大范围或执行高风险操作 |
| 接手者 | 先读交接文档，复述理解后继续 | 忽略已有状态重新猜测项目 |

## 任务开始前

AI 开始修改前，应先确认：

1. 本次目标是什么。
2. 本次明确不做什么。
3. 预计涉及哪些文件或模块。
4. 使用什么验证方式。
5. 是否触及 `SECURITY_AND_PRIVACY.md` 中的确认边界。
6. 是否需要更新 `MODEL_AND_EVAL.md`、`QUALITY_GATE.md` 或其它交接文档。

## 开发中

1. 优先做最小可验证改动。
2. 发现未知改动时，先判断是否和当前任务相关。
3. 遇到缺失上下文时，优先查项目文件，再向用户确认。
4. 如果任务变大，先停下来拆分任务并更新 `NEXT_ACTIONS.md`。
5. 如果发现长期风险，记录到 `RISK_REGISTER.md`。

## 验证分级

验证强度按 `QUALITY_GATE.md` 执行：

1. 小改动使用 Quick Check。
2. 功能改动使用 Standard Check。
3. 发布、迁移、数据或安全相关改动使用 Release Check。

无法执行的检查必须写明原因，并记录补救任务。

## 会话收尾

每次阶段性结束时，AI 应完成：

1. 总结本次目标和实际完成内容。
2. 列出改动文件。
3. 记录验证结果和未验证原因。
4. 更新必要的交接文档。
5. 按 `RECORDING_PROTOCOL.md` 将问题调查、方案讨论、决策或发布证据写入对应专项记录。
6. 写出遗留问题、风险和下一步建议。
7. 如果适合提交，给出建议提交信息。

## 中断与恢复

当会话被打断或迁移到新 AI 时：

1. 新 AI 先阅读 `AGENTS.md` 和 `docs/00-handoff/`。
2. 复述当前状态、最高优先级任务、质量门禁和安全边界。
3. 在用户确认前不修改文件。
4. 从 `NEXT_ACTIONS.md` 或 `SESSION_LOG.md` 的最新记录继续。

## 完成定义

一个任务只有在同时满足以下条件时，才算完成：

1. 需求中的验收标准已满足。
2. 相关验证已运行或明确记录无法运行的原因。
3. 改动范围没有混入无关内容。
4. 必要文档已更新。
5. 下一步或遗留问题已写清楚。
