# 决策记录

## DEC-0005：发货事实单一来源，客户版与内部留档版分受众输出

- 日期：2026-09-07
- 状态：已接受
- 背景：原“打印”走通用业务单据渲染器，“下载发货单 PDF”走销售专用渲染器；同一发货单因此出现版式、二维码/包裹信息、状态门禁、数据范围、归档和响应头不一致的两份 PDF。
- 决策：Shipment 只保留一条业务事实和一套发货 PDF 服务；按受众生成 `customer` 客户发货单和 `internal` 内部留档两种明确文档类型。客户版用于交接、签收和对账；内部版增加库位、批次、出库成本、欠库/冲销和操作字段。预览与下载只改变响应处置方式，必须复用同一受众归档字节。
- 规则：客户版与内部版分别归档，归档键包含受众、打印格式和 Shipment `updatedAt` 源版本；源数据变化生成新历史版本，不静默返回旧快照。旧 `/api/shipments/:id/delivery-note` 地址保留为客户版兼容包装。系统生成 PDF 不混入用户原始附件列表。
- 边界：Office/CAD 附件派生预览 PDF、SOP/用户手册静态 PDF和二维码标签打印属于不同输出用途，继续使用各自管线；本决策只消除运行时业务发货单的重复实现。
- 证据：`modules/sales/server/shipment-document-service.ts`、`verify:business-document-print` 发货双受众回归。

## DEC-0003：生产执行冻结 BOM、工艺路线和标准成本快照

- 日期：2026-09-06
- 状态：已接受
- 背景：BOM、工艺路线、工序参数和工作中心费率会继续变化；只保存 ID 会让历史订单成本和执行条件漂移，锯切成本对象还可能与锯切工序重复计费。
- 决策：成本运行保存路线及工序/工作中心快照；订单创建时冻结匹配 BOM、路线和成本运行；生产实绩及快捷日报复制快照；物料全景按 BOM 映射成本运行；已由成本对象覆盖的同名工序只保留零成本追踪行。
- 原因：把“标准转换关系”和“实际执行事实”连接起来，同时保持标准成本与库存实际成本分离，并避免重复计费。
- 边界：当前默认使用物料默认路线和最近匹配成本运行；显式选择多套成本假设列为后续 P2。旧记录无快照时只读兼容当前路线，不回写历史。
- 证据：ADR-0050、`20260905150000_freeze_production_route_and_cost_snapshots`、生产/BOM 定向回归。

## DEC-0004：工作中心提供工序成本默认费率

- 日期：2026-09-06
- 状态：已接受
- 背景：工序需要能够按工作中心的人工、机时和能源能力区域统一核价，同时允许特殊工序覆盖默认费率。
- 决策：`WorkCenter` 保存三类默认费率；有效费率按工序正值 > 工作中心默认 > 本次成本计算页面费率回退，能源费率统一按台·小时计。成本运行、生产订单、实绩和日报保存路线快照中的实际采用值，后续修改工作中心只影响新计算。旧成本对象没有工序外键时，仅允许编码/名称精确匹配，不能用名称包含关系静默跳过工序。
- 原因：让工作中心真正参与 BOM/工艺成本，又不破坏既有工序级明细和历史冻结语义。
- 边界：费率为 0 表示未配置，暂不支持显式“零费率覆盖”；能源费按机时小时计入机时成本，避免另起重复成本行。
- 证据：`20260906100000_add_work_center_cost_rates`、`verify:bom-cost-module`、`verify:bom-process-cost-link`、`verify:equipment`。

## DEC-0002：只有发货可形成受控负库存

- 日期：2026-09-04
- 状态：已接受
- 背景：用户需要先填并确认发货单、后补入库，但批次、成本和冲销仍必须可追溯。
- 决策：发货可形成与明细唯一关联的欠库；后续同物料、同库位可用批次按时间自动补齐。其他出库不放宽，退货须等待欠库补齐。
- 原因：满足现场单据时序，同时避免全局关闭库存约束造成无来源负数、批次断链和成本失真。
- 影响：新增两张欠库表及迁移；库存一致性检查理解有效欠库额度；发货详情新增待补状态。
- 替代方案：全局允许负库存会把生产领料和调拨一并放宽；仅取消前端校验会导致后端仍失败或形成无批次成本的黑箱。
- 证据：ADR-0049 与 `verify:shipment-negative-stock`。

## DEC-0001：锯切方案保留来源，物料与 BOM 分别建立关系

- 日期：2026-09-04
- 状态：已接受
- 背景：锯切成本既要作为物料加工成本在全景展示，也可能参与 BOM 成本计算。
- 决策：`SawingCostScenario` 保存完整参数和结果；`CostObject` 以方案 ID 作为来源，保留可追溯性。已有物料通过 `SawingCostScenario.materialId` 关联，物料全景沿此关系解析成本对象。BOM 关联保持可选，通过 `BOMItem` 同时引用成本对象与锯切方案。
- 原因：不覆盖成本对象来源，不强迫每项加工成本都进入 BOM，同时允许标准生产成本组合。
- 影响：无数据库迁移；查询逻辑必须理解锯切方案到物料的间接关系。选择 BOM 时只写草稿或复制新草稿版本。
- 替代方案：把成本对象来源改成 `MATERIAL` 会丢失锯切方案来源；新增成本对象到物料直接外键会重复现有关系并需要迁移。
- 证据：用户要求锯切成本对应物料并在全景展示，随后确认希望与 BOM 关联。
