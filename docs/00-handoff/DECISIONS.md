# 决策记录

## DEC-0002：只有发货可形成受控负库存

- 日期：2026-09-04
- 状态：已接受
- 背景：用户需要先填并确认发货单、后补入库，但批次、成本和冲销仍必须可追溯。
- 决策：发货可形成与明细唯一关联的欠库；后续同物料、同库位可用批次按时间自动补齐。其他出库不放宽，退货须等待欠库补齐。
- 原因：满足现场单据时序，同时避免全局关闭库存约束造成无来源负数、批次断链和成本失真。
- 影响：新增两张欠库表及迁移；库存一致性检查理解有效欠库额度；发货详情新增待补状态。
- 替代方案：全局允许负库存会把生产领料和调拨一并放宽；仅取消前端校验会导致后端仍失败或形成无批次成本的黑箱。
- 证据：ADR-0049 与 `verify:shipment-negative-stock`。

## DEC-0001：锯切方案保留来源，物料与 BOM 分别建立关系

- 日期：2026-09-04
- 状态：已接受
- 背景：锯切成本既要作为物料加工成本在全景展示，也可能参与 BOM 成本计算。
- 决策：`SawingCostScenario` 保存完整参数和结果；`CostObject` 以方案 ID 作为来源，保留可追溯性。已有物料通过 `SawingCostScenario.materialId` 关联，物料全景沿此关系解析成本对象。BOM 关联保持可选，通过 `BOMItem` 同时引用成本对象与锯切方案。
- 原因：不覆盖成本对象来源，不强迫每项加工成本都进入 BOM，同时允许标准生产成本组合。
- 影响：无数据库迁移；查询逻辑必须理解锯切方案到物料的间接关系。选择 BOM 时只写草稿或复制新草稿版本。
- 替代方案：把成本对象来源改成 `MATERIAL` 会丢失锯切方案来源；新增成本对象到物料直接外键会重复现有关系并需要迁移。
- 证据：用户要求锯切成本对应物料并在全景展示，随后确认希望与 BOM 关联。
