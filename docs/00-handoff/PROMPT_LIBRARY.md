# 常用提示词库

本文件收集 AI 协作开发中最常用的提示词。使用时先替换 `TODO`，并让 AI 优先阅读 `AGENTS.md` 与 `docs/00-handoff/` 下的相关文档。

## 使用原则

1. 先说明目标、约束和验收标准，再要求 AI 执行。
2. 涉及代码修改时，要求 AI 先阅读项目上下文并确认影响范围。
3. 涉及高风险操作时，要求 AI 先等待确认。
4. 每次任务结束时，要求 AI 总结改动、验证结果和下一步。
5. 不在提示词里粘贴密钥、生产凭证或未脱敏数据。

## 项目接手

### 只读接手

```text
你正在接手一个已有软件项目。请先阅读项目根目录的 AGENTS.md，然后阅读 docs/00-handoff/CURRENT_STATE.md、NEXT_ACTIONS.md、RUNBOOK.md、MODEL_AND_EVAL.md、QUALITY_GATE.md、SECURITY_AND_PRIVACY.md、CONTEXT_INDEX.md。

请完成以下事项：

1. 用不超过 10 条要点复述你对项目目标、当前状态、运行方式、AI 能力、质量门禁、安全边界、下一步任务和风险的理解。
2. 列出你认为需要优先确认的 3 个问题。
3. 在我确认前，不要修改任何文件。
```

### 开发接手

```text
请先阅读 AGENTS.md 和 docs/00-handoff/ 下的交接文档。

接下来请从 NEXT_ACTIONS.md 中选择最高优先级、当前最适合执行的任务，并按以下流程工作：

1. 先说明你准备修改哪些文件以及为什么。
2. 修改前确认现有运行和测试方式。
3. 保持改动范围小，沿用项目现有风格。
4. 完成后按 QUALITY_GATE.md 运行相关测试或手动验证。
5. 更新 docs/00-handoff/CURRENT_STATE.md 和 SESSION_LOG.md。
6. 最后总结改动、验证结果、遗留问题和下一步建议。
```

## 需求澄清

### 把想法整理成需求

```text
我想做：TODO。

请帮我把这个想法整理成可开发需求，输出：

1. 一句话目标。
2. 目标用户和使用场景。
3. 核心功能列表。
4. 暂不包含的范围。
5. 验收标准。
6. 需要我确认的问题。

请保持简洁，先不要写代码。
```

### 拆分任务

```text
请基于当前需求和项目状态，把 TODO 拆分成适合 AI 执行的小任务。

每个任务请包含：

1. 任务标题。
2. 背景。
3. 涉及文件或模块。
4. 验收标准。
5. 验证方式。
6. 风险和回滚方式。

请按优先级排序，并标出第一个建议执行的任务。
```

## 开发实现

### 任务开始前检查

```text
在开始修改前，请先完成任务开始前检查。

请输出：

1. 你理解的本次目标。
2. 本次明确不做的内容。
3. 预计涉及的文件或模块。
4. 需要先阅读的上下文文件。
5. 建议执行的质量门禁级别：Quick / Standard / Release。
6. 是否触及 SECURITY_AND_PRIVACY.md 中需要确认的边界。
7. 完成后需要更新哪些交接文档。

在我确认前，不要修改文件。
```

### 小范围实现

```text
请实现 TODO。

要求：

1. 先阅读相关文件和现有测试。
2. 保持改动范围尽量小，沿用项目现有风格。
3. 不引入新依赖，除非先说明原因并等待确认。
4. 完成后运行相关测试或说明无法测试的原因。
5. 总结改动文件、验证结果和遗留风险。
```

### 按工作流执行任务

```text
请按照 docs/00-handoff/WORKFLOW.md 执行任务：TODO。

要求：

1. 先完成任务开始前检查。
2. 小步修改，避免扩大范围。
3. 按 QUALITY_GATE.md 选择合适验证级别。
4. 如果发现长期风险，记录到 RISK_REGISTER.md。
5. 收尾时更新必要的交接文档，并总结下一步。
```

### 按现有风格补功能

```text
请参考项目中已有的相似实现，为 TODO 补充同风格功能。

请先找出 1-3 个最相关的现有实现，说明你会复用哪些模式，然后再修改代码。
完成后请给出验证方式和结果。
```

### 重构

```text
请重构 TODO。

边界：

1. 不改变外部行为。
2. 不做无关格式化。
3. 不移动无关文件。
4. 先说明重构目标、影响范围和回滚方式。
5. 完成后运行现有测试，并指出仍需人工确认的部分。
```

## 调试排错

### 分析报错

```text
这里是报错信息：

TODO

请先判断最可能的 3 个原因，并说明如何验证每个原因。
在没有足够证据前，不要直接大改代码。
如果需要修改，请优先给出最小修复方案。
```

### 定位回归

```text
功能 TODO 之前可以工作，现在出现 TODO。

请帮我定位可能的回归来源：

1. 阅读相关代码和最近改动。
2. 找出最可能导致问题的文件和逻辑。
3. 给出最小复现步骤。
4. 提出修复方案和验证方式。
```

## 代码审查

### 风险优先审查

```text
请以代码审查方式检查当前改动。

优先关注：

1. 可能导致 bug、数据丢失、安全问题、性能问题或回归的问题。
2. 测试遗漏。
3. 与项目约定不一致的地方。

请把问题按严重程度排序，给出文件位置、影响和建议修复方式。
如果没有发现高风险问题，请明确说明。
```

### 合并前检查

```text
请检查当前改动是否适合合并。

请确认：

1. 需求是否完成。
2. 是否有无关改动。
3. 测试和构建是否足够。
4. 文档和交接文件是否需要更新。
5. 是否存在安全、隐私或成本风险。

请输出“可以合并 / 暂不建议合并”，并说明原因。
```

## 测试与验收

### 生成测试计划

```text
请为 TODO 生成测试计划。

请覆盖：

1. 正常路径。
2. 边界输入。
3. 错误和空状态。
4. 权限或安全场景。
5. 回归风险。

请区分自动化测试和手动验收，并给出优先级。
```

### 补测试

```text
请为 TODO 补充测试。

要求：

1. 先阅读现有测试风格。
2. 优先覆盖真实风险，不追求无意义覆盖率。
3. 测试名称要描述行为。
4. 完成后运行相关测试，并总结覆盖了哪些场景。
```

## 文档与交接

### 更新交接文档

```text
请根据本次改动更新 docs/00-handoff/ 下的交接文档。

至少检查：

1. CURRENT_STATE.md 是否需要更新最近改动和验证结果。
2. NEXT_ACTIONS.md 是否需要更新下一步任务。
3. SESSION_LOG.md 是否需要追加会话记录。
4. RUNBOOK.md 是否有命令或环境变化。
5. MODEL_AND_EVAL.md、QUALITY_GATE.md、SECURITY_AND_PRIVACY.md 是否受影响。

请只更新确实需要变化的内容。
```

### 写 README

```text
请根据当前项目状态更新 README。

目标读者是第一次打开项目的人。请让 README 包含：

1. 项目是什么。
2. 如何安装和运行。
3. 如何测试和构建。
4. 核心目录说明。
5. 常见问题或限制。

请保持简洁，不要写营销文案。
```

## Git 与发布

### 整理提交信息

```text
请根据当前改动建议一条清晰的提交信息。

要求：

1. 使用 Conventional Commits 风格。
2. 标题不超过 72 个字符。
3. 如果改动较多，请给出简短正文。
4. 说明为什么这样归类。
```

### 发布前检查

```text
请根据 QUALITY_GATE.md 和当前改动做发布前检查。

请输出：

1. 已通过的检查。
2. 未执行的检查及原因。
3. 发布风险。
4. 回滚步骤。
5. 发布后的冒烟验证步骤。
```

## 安全与隐私

### 安全边界审查

```text
请检查当前需求或改动是否涉及安全和隐私风险。

请重点关注：

1. 密钥、令牌、生产凭证。
2. 用户数据和日志脱敏。
3. 外部服务调用和数据出境。
4. 权限、鉴权和越权访问。
5. 高风险操作的确认与回滚。

请参考 SECURITY_AND_PRIVACY.md，并给出必须修复项和建议优化项。
```

### 环境变量梳理

```text
请梳理项目中使用到的环境变量。

请输出：

1. 变量名。
2. 是否必需。
3. 敏感级别。
4. 示例占位值。
5. 使用位置。
6. 是否需要写入 SECURITY_AND_PRIVACY.md 或 RUNBOOK.md。

不要输出真实密钥或凭证。
```

## AI 能力与评测

### 设计 AI 功能

```text
我要实现 AI 功能：TODO。

请帮我设计实现方案，包含：

1. 用户输入和预期输出。
2. 模型或服务选择建议。
3. 提示词结构。
4. 失败、超时、限流和降级策略。
5. 评测集设计。
6. 成本和安全风险。

请先给方案，不要直接写代码。
```

### 评估 AI 输出质量

```text
请为 AI 能力 TODO 设计评测标准。

请包含：

1. 评测维度。
2. 代表性测试样例。
3. 通过标准。
4. 失败案例分类。
5. 人工验收方式。
6. 需要记录到 MODEL_AND_EVAL.md 的内容。
```

## 迁移到新 AI

### 迁移提示

```text
你正在接手一个已有项目。请先阅读 AGENTS.md 和 docs/00-handoff/ 下的交接文档。

请不要直接改文件。先输出：

1. 你理解的项目目标。
2. 当前状态和可运行能力。
3. 当前最高优先级任务。
4. 质量门禁和安全边界。
5. 你建议下一步怎么做。
6. 你需要我确认的问题。
```

### 会话收尾

```text
请为本次会话做收尾。

请完成：

1. 总结本次目标和实际完成内容。
2. 列出改动文件。
3. 记录本次执行的质量门禁级别和验证结果。
4. 写出遗留问题、风险和下一步建议。
5. 判断是否需要更新 RISK_REGISTER.md。
6. 更新必要的 docs/00-handoff/ 交接文档。
7. 如果适合提交，建议一条提交信息。
```
