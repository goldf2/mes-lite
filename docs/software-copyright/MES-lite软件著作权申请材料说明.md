# MES-lite 软件著作权申请材料说明

文档版本：1.0
更新日期：2026-08-05

## 1. 文档目的

本文档用于指导 MES-lite 在中国大陆申请计算机软件著作权登记，列明必交材料、项目专项证据、AI 辅助开发风险控制和提交前检查项。

本文档是项目内部办理指南，不替代中国版权保护中心当期系统提示或专业法律意见。申请界面、实名认证和电子材料格式如有变化，以官方平台最新要求为准。

## 2. 申请前先确定的事项

### 2.1 著作权人

申请前必须先确定软件著作权归属：

- 个人独立开发：由自然人作为著作权人。
- 公司组织开发并承担责任：可由公司作为著作权人。
- 合作开发：必须有书面协议明确各方权利、登记代表和收益分配。
- 委托或外包开发：必须由书面合同明确软件著作权归属。未明确时不应自行推定委托方拥有全部权利。
- 员工职务开发：应保留劳动合同、岗位说明、项目任务书和知识产权归属条款。

AI 工具不作为著作权人、作者或合作开发者填写。申请人必须是对项目进行实际组织、创造性设计、选择修改、验收并承担责任的自然人、法人或其他组织。

### 2.2 申请版本

建议从主分支冻结一个稳定、可构建、可演示的版本，并为该版本创建 Git Tag。

MES-lite 当前仍使用 `0.1.x` 开发版本号。申请时可选择：

1. 按真实冻结版本填写，例如 `V0.1.xxx`；或
2. 完成第一个正式稳定版后统一升级为 `V1.0.0` 再申请。

不得在申请表、源代码页眉、说明书、系统界面和发布记录中使用互相矛盾的版本号。

### 2.3 软件名称建议

候选名称：

- 软件全称：`MES-lite 轻量化制造执行与库存管理系统`
- 软件简称：`MES-lite`
- 版本号：以最终冻结版本为准

正式申请前应检索近似名称，并确认名称未冒用他人商标、企业名称或在先软件标识。

## 3. 法定核心材料

### 3.1 软件著作权登记申请表

申请表通常需要准备以下信息，具体字段以官方申报系统为准：

- 软件全称、简称和版本号。
- 软件类别、主要用途和技术特点。
- 开发完成日期。
- 是否发表；已发表时填写首次发表日期和地点。
- 开发方式：独立、合作、委托或任务开发。
- 权利取得方式和权利范围。
- 硬件环境、软件环境、开发工具、编程语言和源程序量。
- 主要功能和技术特点的简明说明。
- 著作权人、联系人和代理人信息。

申请表应使用中文，申请人签名或单位盖章。

### 3.2 源程序鉴别材料

普通交存要求：

- 提交源程序前、后各连续 30 页，合计 60 页。
- 整个源程序不足 60 页时，提交全部源程序。
- 除规定的例外情形外，程序每页不少于 50 行。
- 纸张或导出页面按 A4 规格编排。
- 页眉建议统一标注软件全称和版本，页脚连续编号。
- 前 30 页和后 30 页必须在各自部分内连续，不得为了展示功能而任意拼接不连续片段。

MES-lite 源程序材料应优先包含项目自有的业务实现，例如：

- `app/` 下的页面、API 和公共组件。
- `lib/` 下的库存、权限、附件、成本和数据完整性逻辑。
- `prisma/schema.prisma` 及必要的数据模型说明。
- 必要的构建、验证和部署脚本。

不应将以下内容当作自有源程序主体提交：

- `node_modules/`、`.next/` 和其他第三方或生成文件。
- 数据库文件、缓存、日志和用户上传文件。
- 密钥、口令、Token、真实个人信息或生产数据。
- 来源不明或未确认许可证的第三方代码。

如源程序含商业秘密，可依法考虑例外交存或封存，但应在申请前让专业代理人或律师确认具体方式。

### 3.3 文档鉴别材料

可从用户手册、操作手册、设计说明书等文档中选择一种提交。普通交存要求为：

- 文档前、后各连续 30 页，合计 60 页。
- 整份文档不足 60 页时，提交全部文档。
- 除规定的例外情形外，文档每页不少于 30 行；带必要界面截图的操作手册应以官方平台实际审查格式为准。
- 文档中的软件名称、版本、功能和截图必须与冻结版本一致。

MES-lite 建议使用《MES-lite 轻量化制造执行与库存管理系统操作说明书》，至少包含：

1. 软件概述与适用对象。
2. 部署和运行环境。
3. 登录、账号与权限。
4. 工作台与所有功能入口。
5. 物料管理、物料图片和双单位参数。
6. BOM 设置与 BOM 全览，说明整组投入与整组产出。
7. 来料单、多物料来料与入库。
8. 生产订单、多产品工单和生产日报。
9. 库存、库位、发货、退货与流程转移。
10. 产品文档、附件、PDF 预览与搜索。
11. 成本计算、统计报表与销售/生产测算。
12. 系统配置、数据工具、归档与操作记录。
13. 数据备份、恢复和安全注意事项。

### 3.4 申请人身份证明

按申请主体准备：

- 自然人：有效身份证明及官方系统要求的实名认证材料。
- 企业法人：营业执照、经办人信息、盖章或电子签署材料。
- 其他组织：相应的合法主体证明。
- 委托代理：代理委托书和代理人身份证明。

### 3.5 权利归属证明

存在相应情形时提交：

- 合作开发协议。
- 委托开发合同。
- 项目任务书或职务开发归属文件。
- 在原软件上修改开发时的原著作权人许可证明。
- 软件著作权受让、继承或承受证明。

## 4. MES-lite 项目建议额外留存的证据

以下材料不一定全部随首次申请提交，但应内部完整归档，用于补正、交易尽调或侵权争议：

- 需求记录、页面草图、功能规划和用户验收记录。
- Git 仓库完整历史、版本 Tag、发布说明和提交者信息。
- `docs/minierp/` 下的业务模型、交互规范、数据模型和架构决策。
- 构建、类型检查、测试、部署和故障修复记录。
- 核心功能的视频或截图，截图应隐去真实客户和个人数据。
- 员工、合作者和外包方的书面权属文件。
- 开源依赖清单、版本、用途和许可证审查结果。

软件登记证书是登记事项的初步证明，不能代替开发过程和权属链证据。

## 5. AI 辅助开发专项说明

### 5.1 基本原则

MES-lite 使用 AI 辅助完成部分代码实现、调试和文档整理。这不等于 AI 是软件开发者或著作权人。项目应能证明自然人或申请单位在以下方面进行了实质性投入：

- 确定产品目标、用户群体和业务范围。
- 定义物料、BOM、双单位库存、来料、生产、发货和退货等业务规则。
- 提供草图、交互反馈、功能取舍和验收意见。
- 对 AI 产出进行选择、重组、修改、删除、测试和发布确认。
- 对最终软件质量、安全和合法性承担责任。

### 5.2 建议内部编写《AI 辅助开发与人工贡献说明》

该说明建议包含：

1. 使用的 AI 工具名称和用途。
2. 申请人自主完成的需求、草图、业务规则和架构决策。
3. AI 主要承担的代码转换、重复实现、检查和文档工作。
4. 申请人对生成结果的选择、修改、反复验收和否决记录。
5. 关键模块与人工贡献之间的对应表。
6. 最终版本的人工审查和批准结论。

该说明原则上作为内部证据留存，不在官方表格未要求的字段中自行添加不实信息；登记机构补正、交易尽调或司法程序要求时，应如实提供。

## 6. 开源与第三方代码审查

申请前建议完成一次代码来源审查：

- 从 `package-lock.json` 生成完整依赖清单。
- 记录直接依赖和重要间接依赖的许可证。
- 确认 MIT、Apache-2.0、BSD 等许可证的保留通知要求。
- GPL、AGPL、SSPL 或自定义商业许可证必须单独评估。
- 检查从论坛、博客、GitHub 或 AI 输出中引入的大段相似代码。
- 删除无法说明来源或无法满足许可条件的代码。
- 保留项目中已有的许可证文件和第三方声明。

软件著作权登记不会自动消除第三方代码侵权或开源许可证违约风险。

## 7. 建议办理流程

1. 确定申请主体和权利归属。
2. 确定软件全称、简称和申请版本。
3. 冻结 Git 提交，创建版本 Tag，完成构建和功能验收。
4. 完成开源依赖和代码来源审查。
5. 生成连续的源程序鉴别材料。
6. 编写与冻结版本一致的操作说明书。
7. 准备身份、合同、任务书和其他权属证明。
8. 在中国版权保护中心指定系统完成账号和实名认证。
9. 按当期系统要求在线填报、签章并提交电子材料。
10. 保存受理号，跟踪补正通知；收到补正后在指定期限内处理。
11. 取得证书后，将证书、提交版源代码、说明书、申请表和权属证明整套归档。

## 8. 提交前一致性检查表

### 主体与权属

- [ ] 申请人确实是著作权人或合法权利承受人。
- [ ] 合作、委托、外包和职务开发已有书面权属文件。
- [ ] 申请表、合同、源代码和说明书中的著作权人一致。

### 软件信息

- [ ] 软件全称、简称和版本号已冻结。
- [ ] 开发完成日期、首次发表日期和 Git 记录不矛盾。
- [ ] 软件名称、版本和著作权人署名在全部材料中一致。

### 源代码

- [ ] 提交的前后 30 页分别连续，或在不足 60 页时提交了全部代码。
- [ ] 每页行数、A4 格式、页眉和页码符合要求。
- [ ] 不包含密钥、个人信息、真实生产数据、缓存和第三方生成文件。
- [ ] 提交代码与冻结版本相同，能在 Git 中追溯。

### 说明文档

- [ ] 说明书截图来自冻结版本。
- [ ] 功能说明与实际已实现功能一致，未把规划功能当成已实现功能。
- [ ] 截图中已隐去真实客户、员工、联系方式和业务数据。
- [ ] 文档页数、连续性和行数符合当期要求。

### AI 与第三方合规

- [ ] 已归档人工需求、草图、业务决策、修改和验收证据。
- [ ] 已编写或准备《AI 辅助开发与人工贡献说明》。
- [ ] 已完成开源依赖和代码来源审查。
- [ ] 不存在来源不明的大段复制代码。

## 11. 重要提醒

- 不得将他人软件或开源项目整体改名后作为独立开发软件登记。
- 不得为了通过形式审查伪造开发日期、作者、版本、源代码或权属文件。
- 软件著作权登记不保护抽象思想、业务方法、处理过程或数学概念，主要保护具体的程序和文档表达。
- 如软著将用于融资、招投标、技术出资、许可交易或诉讼，应在申请前由知识产权律师审查权属链、AI 证据和开源许可证。
