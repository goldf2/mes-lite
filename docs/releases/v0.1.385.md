# v0.1.385 GitHub CI 失败子检查定位

日期：2026-08-15

## 更新内容

- 为 `verify:ci` 的 40 个串行子检查记录单项用时。
- 任一子检查失败时，终端明确输出检查名、退出码和用时。
- 在 GitHub Actions 中额外写入 workflow command annotation，让公开 check-run annotation 能直接指向失败子检查，不再只显示笼统的 exit code 1。

## 影响范围

- 页面、API、权限、Prisma Schema 和迁移：无变化。
- 车间业务流程与 SOP 步骤：无变化，只重生成当前版本 Markdown 同源文档。
- 运行镜像：应用逻辑不变；变更仅在仓库 CI 基线调度脚本。
- 版本递增的目的是在不降低门禁范围的前提下，定位 GitHub Ubuntu/Node 20 与本机之间的稳定差异。

## 验证结果

- v0.1.384 在本机 Node 24 和临时 Node 20.19.4 下均通过相同 `SOP_DIFF_BASE=HEAD^` 的 40 项完整基线；GitHub Ubuntu 运行器连续两个版本只返回第 8 步 exit code 1，无法从公开状态定位子检查。
- 临时 Node 20.19.4 下的完整 `verify:ci` 已通过，共 40 项；`node --check scripts/verify-ci-baseline.mjs`、`verify:sop`、`verify:release-notes` 和 `verify:development-docs` 也已分别通过。
- 现用生产域名 `mes.szxiangshu.com` 在本次调查期间持续返回 readiness 200；旧域名 `mes.xiangshu.me` 不作为生产验收入口。

## 回滚

本版本没有数据库迁移或业务数据变更，可直接回退到 `v0.1.384`。回滚只会失去 CI 失败子检查 annotation，不影响在线帮助、OSS 下载契约、站内 SOP 文档库或业务数据。
