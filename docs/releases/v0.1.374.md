# v0.1.374 来料收货与红冲命令分权

发布日期：2026-08-14

## 更新内容

- 新增 `materialInReceive` 与 `materialInReverse` 两个权限资源，使来料草稿编辑、收货/拒收和整单红冲不再共用 `materialIn.update`。
- 来料页面按新建、编辑、收货/拒收和红冲四类有效权限显示动作；仪表盘“待收货”只对具有收货命令的账号显示。
- 新安装仓库作业组可收货/拒收但不能红冲，仓库主管组另有有原因红冲；质量岗位读取来料不再意味着能执行仓库命令。
- 既有安装的角色、自定义组、已修改内置组和个人覆盖默认不获得两个高风险命令，维护窗口须按岗位审批显式授予。
- 作业指导书隔离演示库为仓库主管补齐全库位数据范围，使待收货、已收货待检和可红冲单据可在真实岗位账号下完整复核。
- SOP 新增命令授权与岗位操作边界 2 个流程，扩展到 171 个流程并同步站内帮助、Markdown、DOCX、PDF 与离线 Web。

## 影响范围

- 数据库：不修改 Prisma Schema，仍为 91 个模型和 81 个迁移；运行时只补齐缺失权限设置。
- 页面/API：仍为 44 个页面模块和 149 条 Route Handler；收货/拒收 API 改用 `materialInReceive.update`，红冲 API 改用 `materialInReverse.update`，运行时权限资源由 52 个增至 54 个。
- 领域边界：继续复用 `MaterialInPage`、`MaterialInCollectionView`、应用壳权限控制和 `modules/receiving` 状态服务，没有复制页面、库存账或质量台账。
- 不包含：发货、退货和流程转移命令进一步拆分，部门/班组范围或生产岗位审批。

## 验证结果

- 隔离 SQLite 回归覆盖新安装岗位预置、旧角色/自定义组/内置组/个人例外安全升级、岗位任务和页面/API 静态映射。
- 真实 HTTP 回归覆盖仅编辑账号收货/拒收/红冲 403、普通仓管收货成功与红冲 403、仓库主管红冲成功、仓管质量任务 403、质检库位范围和判定。
- 来料领域、类型检查、Lint、CI、生产构建、SOP 与开发文档验证通过。

## 部署与回滚

1. 固定本版本精确提交，执行数据库与附件一致备份并确认维护窗口。
2. 部署后先由权限管理员按仓储负责人签字，为真实仓管授予 `materialInReceive.update`，仅为仓库主管授予 `materialInReverse.update`；不要把旧 `materialIn.update` 当作命令授权。
3. 分别用仅编辑、普通仓管、仓库主管和质检账号验证按钮、HTTP 403、库位范围、收货质量交接和有原因红冲。
4. 回滚应用时固定到上一个已验证提交并暂停来料写入；权限设置可保留，不执行数据库降级或删除库存/质量事实。
