# v0.1.502 — 待发货单可继续增删商品与货箱

日期：2026-10-21。状态：本地专项与桌面/手机验收通过，完整门禁、精确提交 CI 与独立测试站验收待登记；未发布生产。

## 更新内容

原先保存发货单后仅能补填价格。现在保存后仍处于可编辑的待发货阶段，可在详情点击“编辑发货内容”，重新增删商品、调整散货数量和库位、增删已有货箱，以及修改客户、凭证号、物流和备注；“保存修改”后整单生效。纯散货、纯货箱及混合发货继续支持，客户发货单仍按具体产品汇总箱内量与散货量。

确认发货后冻结产品、数量、库位及选箱内容。原“补填 / 修改发货价格”继续按既有权限、状态与原因规则使用，确认、签收、取消、冲销和退货仍分别授权。

## 影响范围

- 复用原发货详情和 `ShipmentCreateDialog`，共用客户字段、散货关系清单、货箱选择、公共弹窗/按钮/搜索及暂存附件。成功保存后再绑定本次附件；取消不改原单及原附件。
- 已有单的编辑回填区分真实散货与本单所选箱，不把箱内量再次作为散货。箱内产品和数量保持只读，沿用现有产品行价格。
- `PATCH /api/shipments/:id` 增加明确的 `mode: "draft"` 与读取版本 `updatedAt`，保留原价格修正请求。草稿更新使用 `shipment.update`，并复检原/新明细库位范围和客户物料归属。
- 单头、明细/来源及箱占用在同一事务保存。保留箱不重新占用；移除箱释放，新箱原子占用；陈旧版本、非待发货或任一选箱失败使整单回滚。草稿修改不产生库存、批次或成本过账。编辑已移除的箱不再显示于当前单构成；取消/归档释放占用时保留最后保存的箱构成，兼顾历史追溯与箱重新可发。
- 保留旧发货现场箱及明细引用；有效现场箱所对应的行不能直接删除或减少至已装数量以下；只有已归档旧箱引用的行可解除可选明细关联，但保留其产品/数量快照。

本版不增加数据库表、迁移、状态枚举、权限资源或空间模型。标签身份、唯一货物位置及后续立体仓库边界保持。
