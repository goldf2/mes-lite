# v0.1.375 物流状态命令分权与审计

发布日期：2026-08-14

## 更新内容

- 新增 `shipmentDispatch`、`shipmentDeliver`、`shipmentCancel`、`returnReceive`、`returnReject`、`flowTransferConfirm` 与 `flowTransferReverse` 七个权限资源，使单据维护、仓库正向执行、销售确认和高风险取消/冲销不再共用通用更新。
- 发货、退货和流程转移页面按新建、编辑及每个状态命令的有效权限显示动作；仪表盘“待发货”和“退货待收货”只对具有正向执行命令的账号显示。
- 新安装普通仓管可发货、接收入库退货和确认移库但不能签收、取消、拒绝或冲销；仓库主管另获高风险仓库命令；销售跟单可确认签收、取消待发货和拒绝退货但不能执行仓库出入库。
- 既有角色、内置/自定义组和个人例外默认不获得七个命令，维护窗口须按仓储、销售和生产负责人签字显式授予。
- 发货、签收、取消、退货收货和拒绝补齐请求级操作记录；取消、拒绝和移库冲销必须填写原因并保存前后快照。
- SOP 新增 8 个物流命令流程，扩展到 179 个流程并同步站内帮助、Markdown、DOCX、PDF 与离线 Web。

## 影响范围

- 数据库：不修改 Prisma Schema，仍为 91 个模型和 81 个迁移；运行时只补齐缺失权限设置。
- 页面/API：仍为 44 个页面模块和 149 条 Route Handler；七条状态 API 改用独立命令资源，运行时权限资源由 54 个增至 61 个。
- 领域边界：继续复用销售履约、流程转移、岗位任务、公共按钮/弹窗和应用壳权限注入；库存、成本、批次和状态机仍由既有领域服务原子维护。
- 不包含：部门/班组数据范围、真实生产岗位审批、Product→Material 生产回填、异地对象存储、自动采集/OEE 或 SPC。

## 验证结果

- 隔离 SQLite 回归覆盖新安装岗位预置、旧角色/自定义组/内置组/个人例外安全升级、岗位任务和页面/API 静态映射。
- 真实 HTTP 回归覆盖通用编辑账号七条命令 403、普通仓管正向执行成功且高风险动作 403、仓库主管取消/拒绝/冲销成功、销售跟单签收/取消/拒绝成功及原因审计。
- 销售履约、流程转移、类型检查、Lint、CI、生产构建、SOP 与开发文档验证通过。

## 部署与回滚

1. 固定本版本精确提交，执行数据库与附件一致备份并确认维护窗口。
2. 部署后由权限管理员按岗位签字显式授予七个新命令；不要把 `shipment.update`、`return.update` 或 `flowTransfers.update` 当作状态命令授权。
3. 分别使用通用编辑、普通仓管、仓库主管、销售跟单和生产主管账号验证按钮、HTTP 403、库位范围、库存/批次结果和操作记录原因。
4. 回滚应用时固定到上一个已验证提交并暂停物流写入；权限设置可保留，不执行数据库降级，也不删除已经产生的库存、批次或审计事实。
