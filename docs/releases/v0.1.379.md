# v0.1.379 统一库存事务账本与冲销不变式

发布日期：2026-08-15

## 更新内容

- 保留 `StockLog` 作为唯一库存事务事实源，不创建与现有库存流水平行的 `InventoryAdjustment` 或 `InventoryTransaction` 表。
- 新增统一库存冲销服务；来料红冲、生产实绩冲销、历史生产冲销、流程转移冲销和旧工单取消退料均建立原流水与冲销流水的双向关系。
- 新增第 83 个迁移：同一原流水只能指向一个精确冲销；SQLite 触发器校验同一库存对象及数量、核算数量、成本金额守恒，并锁定已建立关系，禁止解绑、关键值篡改或删除。
- 库存调整请求不再接收浏览器提供的操作人；服务器会话操作人、库存余额、库存流水与审计日志在同一事务提交，库存调整成为第 15 个强制事务审计命令。
- 库存流水页面新增账本关系列，区分“已由流水冲销”“冲销原流水”和普通“关联来源流水”，并支持使用关联流水 ID 搜索。
- 站内帮助的库存调整与库存流水流程同步说明可信操作人、事务审计和双向冲销核对方法，并从同一内容源生成 Markdown、DOCX、PDF 与离线 Web。

## 影响范围

- 影响库存账本公共服务、来料/生产/流程转移冲销、旧工单取消退料、库存调整、库存流水查询和展示、SQLite 迁移、验证脚本、CI 与受影响文档。
- 不新增页面、API、权限资源或 Prisma 模型；库存流水仍使用 `stocks.read`，库存调整仍使用 `stocks.update`。
- 客户部分退货等一对多业务回流继续只使用 `sourceMovementId` 表达来源，不设置 `reversalMovementId`，因此不会被误报为整笔精确冲销。

## 验证结果

- `verify:inventory-transaction-ledger` 验证双向关联、数量/核算量/成本守恒、重复冲销拒绝、跨库存拒绝和数据库关系锁定。
- 来料、生产实绩、历史生产、流程转移和旧工单取消退料回归均验证原流水与冲销流水成对；库存调整回归验证服务器身份、事务审计、失败不留孤立日志和库位预留保护。
- 写接口覆盖保持 134 个处理器、129 个已审计和 5 个具体豁免，高风险事务上下文由 14 个增加为 15 个；CI 基线由 35 项增加为 36 项。
- 对两个本地生产审计副本只读预检，均为 3 条库存流水、0 条既有精确冲销和 0 条不合法关系。结构收敛恢复副本成功追加至第 83 个迁移；原始运行库副本仍被既有失败迁移 `20260812223000_add_material_projections_for_product_exit` 以 Prisma `P3009` 阻断，未修改原副本。

## 部署与回滚

1. 部署前生成最新数据库与附件一致备份；对实际部署库运行生产 Schema 漂移审计，并确认不存在失败迁移和非法既有冲销关系。
2. 只有迁移状态为可继续时，固定 `v0.1.379` 精确提交并应用迁移；原始运行库若仍有 `P3009`，必须先按 v0.1.377 的非覆盖收敛流程生成零漂移候选，不能强行继续。
3. 部署后抽查库存调整、来料红冲、生产冲销和流程转移冲销，确认库存结果、双向账本关系和操作日志同时存在。
4. 如应用行为异常，可停止写入并把应用回滚到 `v0.1.378` 精确提交；本迁移只增加索引和约束，旧版现有成对冲销写法仍兼容，因此默认保留已应用迁移，不删除合法账本关系。
5. 如迁移本身失败，不修改迁移历史或在线数据库；保留失败证据，使用部署前一致备份生成新的非覆盖恢复候选后再处理。
