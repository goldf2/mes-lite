# MES-lite v0.1.356

日期：2026-08-13

## 更新内容

- 已发货/已签收发货单按出库库位可用批次 FIFO 分配客户发货批次；历史无批次库存使用显式 `LEGACY-*` 兼容批次，不伪造来料或生产来源。
- 发货详情增加客户发货批次、已退数量和库存谱系入口；批次追溯增加客户发货与退货回流区，可从原批次反查客户、发货单和退货后代。
- 新建退货单必须选择仍有可退数量的原发货单，系统锁定客户与物料并限制累计退货数量，避免退货脱离客户履约事实。
- 退货收货按原发货批次分摊来源，建立独立 `RT-*` 隔离批次、待检库存、质检任务和审计流水；退货批次支持整批合格放行或不合格冻结。
- 增加发货/退货批次迁移、领域契约、查询/命令服务、详情页、统一质量批次卡、追溯界面和专项回归脚本。
- 使用全新临时演示库完成真实浏览器操作，新增 10 张客户履约与退货质检截图；全流程作业指导书扩展为 88 个流程、90 页 Markdown/DOCX/PDF 交付物。

## 影响范围

- 迁移 `20260813203000_add_shipment_return_lot_trace` 为可加性迁移，新增发货批次分配、退货批次分配、发货追溯状态和退货批次关联，不自动重写历史库存。
- 历史已发货库存继续可追溯为兼容批次，但不会被标记成真实来料或生产批次；新发货将记录实际可用批次分配。
- 当前闭环为“供应商/来料内部批次 → 生产投入/产出 → 质量状态 → 客户发货 → 退货隔离 → 退货质检 → 放行/冻结”。部分放行、复检、让步、返工、报废和解冻仍属于后续治理范围。
- 本地临时数据、截图和测试不等于真实 Coolify 部署完成；生产迁移、持久卷备份和真实业务验收仍需服务器维护窗口。

## 回滚

新表无业务数据时，可回退应用代码并保留加性结构。只要已经产生发货批次分配、退货批次、质检任务或状态流水，就不能删除新增结构或直接运行不能识别这些关系的旧应用。需要停止相关写入，保留客户、批次、质量和审计证据并以前滚方式修复。生产部署前必须创建数据库与附件一致备份；恢复只能生成非覆盖候选，经迁移状态、`PRAGMA quick_check`、数量和附件清单验证后再切换。
