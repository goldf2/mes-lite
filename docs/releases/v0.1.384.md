# v0.1.384 SOP 站内文档库受控发布

日期：2026-08-15

## 更新内容

- 新增 `sop:publish:library`：默认执行零写入预检，可从本地冻结清单或单一 OSS 地址读取当前应用的精确版本 PDF/DOCX。
- 生产镜像内置 `scripts/sop-library-publication.mjs`，Coolify Terminal 不需要 TypeScript、`tsx` 或完整开发依赖即可运行。
- 强制校验应用版本、精确文件名/对象路径、PDF+DOCX 唯一性、单文件 50MB 上限、实际大小和 SHA-256；生产 OSS 来源必须为无凭据、无查询参数的 HTTPS 地址，跨域重定向会被拒绝。
- 写入必须显式提供启用的文控账号、`--apply` 和一致备份引用。账号须拥有文档类别新增、产品文档新增/修改和附件新增权限；只读预检不会补写默认权限。
- 当前版先保存为“不关联物料”的“系统教学 / SOP”草稿。中断后可补齐缺失附件；全部复核通过后才原子启用当前版、归档旧受控版本并记录 `SYSTEM_SOP/PUBLISH` 审计。
- 相同版本和成品指纹重复执行完全幂等；人工同名文档、额外附件、重复记录、归档同版本或内容漂移均阻断，不静默覆盖。
- 将纯数据库审计写入从 Next.js 请求上下文拆到 `lib/audit-core.ts`，使维护包无需加载 HTTP 运行时，同时保持现有 API 审计契约不变。

## 影响范围

- 页面与 API：不新增页面或 HTTP 路由，不改变帮助中心、快捷帮助和车间操作流程。
- 权限：不新增权限资源；维护命令复用既有文档类别、产品文档和附件动作语义。
- 数据库：不修改 Prisma Schema，不新增迁移。只有人工确认后的 `--apply` 才会写文档类别、产品文档、附件和审计；自动部署和容器启动不会执行。
- 文件：站内副本进入现有持久附件目录；OSS 成品和本地 `output/` 继续不进入 Git、GitHub Actions checkout 或 Docker 构建上下文。
- 交付：真实 OSS、最终 PDF/DOCX、最新生产一致备份和真实文控账号仍未提供，因此本版本交付的是受控能力和临时环境回归证据，不宣称生产成品已经登记。

- 全迁移临时 SQLite、临时附件目录和本地 HTTP OSS 模拟覆盖：预检零写入、停用/无权账号拒绝、精确版本下载、路径逃逸拒绝、生产 HTTP 拒绝、备份引用门禁、草稿续传、双附件内容哈希、旧版归档、重复发布幂等和文件篡改阻断。
- 独立 ESM 维护包完成构建并可直接运行 `--help`，Dockerfile 明确复制到生产镜像。
- `verify:sop-library-publication` 纳入第 40 项 CI 领域/治理基线；当前共有 116 个 `verify:*` 命令。
- `npx prisma validate`、`npx tsc --noEmit`、`npm run lint` 和 `npm run build` 全部通过；生产构建同时生成 173.9 KiB 独立维护包。
- 40 项 CI 领域/治理基线全部通过；发布树为 1,589 个文件、58.8 MiB，最终 SOP 二进制仍未进入 Git/Docker 发布树。
- 应用级恢复演练验证通过：非覆盖候选、迁移、readiness、登录、业务/附件抽查、账号清理和证据脱敏符合预期。
- 2026-08-15 20:13 CST 推送前核验：现用生产域名 `mes.szxiangshu.com` 的 TLS 正常，`/api/health/live`、`/api/health/ready`、`/api/health` 和 `/help` 均返回 200；readiness 显示 84 个迁移、SQLite、数据/附件目录及备份时效全部通过。旧域名 `mes.xiangshu.me` 仍指向 `cool-al01` 并返回 Traefik 默认证书与 `503 no available server`，不再作为生产验收入口。本项证据只证明推送前基线健康，v0.1.384 仍须在自动部署后另行核对运行版本和 readiness。

## 回滚

代码可回退到 `v0.1.383`，本版本没有数据库迁移。尚未执行 `--apply` 时不会产生业务数据。已经执行时，新版和旧版文档、附件仍保留：由文控人员在产品文档页把当前版改为 `ARCHIVED`，把上一版改回 `ACTIVE` 并记录原因；不要删除附件或用 Git 回滚覆盖 SQLite。仅需停用外部下载时，可删除 `SOP_PUBLIC_BASE_URL` 并重新部署，在线帮助继续可用。
