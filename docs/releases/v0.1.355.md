# MES-lite v0.1.355

日期：2026-08-13

## 更新内容

- 已收货来料明细自动生成唯一内部批次，保留供应批号、供应商、来料单、库位、数量和成本来源。
- 流程转移确认与冲销同步移动同一内部批次的库位余额；同批次分布在多个库位时，追溯页逐库位展示余额。
- 生产实绩确认时按库位可用库存 FIFO 分配投入批次；历史无批次库存仅在需要时生成显式 `LEGACY-*` 兼容批次。
- 生产投入与每项产出建立不可变谱系关系，支持从成品反查原料/供应批号，也支持从来料正查所有下游生产产出。
- 来料详情和生产实绩增加批次明细及“查看谱系”入口；冲销同步恢复批次余额并保留反向交易证据。
- 增加谱系 API、领域契约与回归脚本，扩展库存一致性和归档清理守卫。
- 使用全新临时演示库完成实际浏览器操作，新增 6 张来料到生产谱系截图，并更新全流程 Markdown、DOCX、PDF 作业指导书。

## 影响范围

- 迁移 `20260813150000_add_receipt_lots_and_production_genealogy` 为可加性迁移，新增来料批次关联、投入分配和谱系表，不自动改写历史库存。
- 历史库存仍可继续使用；首次参与生产或流程转移时会建立可识别的兼容批次，避免伪造供应来源。
- 本版本完成“供应商批号 → 来料内部批次 → 生产投入 → 产出批次 → 质量状态”的闭环。发货、客户签收和退货批次尚未接入端到端谱系。
- 本地临时数据与截图验证不等于真实 Coolify 部署完成；生产迁移、持久卷备份和实际业务验收仍需维护窗口执行。

## 回滚

新表无业务数据时，可回退应用代码并保留加性结构。只要已经生成来料内部批次、投入分配或谱系关系，就不能删除新表或直接运行不能识别这些关系的旧应用。需要停止相关写入、保留批次交易与审计证据并前滚修复。生产部署前必须创建数据库与附件一致备份；恢复只能生成非覆盖候选，经迁移状态、`PRAGMA quick_check`、数量和附件清单验证后再切换。
