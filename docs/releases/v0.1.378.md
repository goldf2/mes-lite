# v0.1.378 写接口审计覆盖与事务一致性

发布日期：2026-08-15

## 更新内容

- 新增基于 TypeScript AST 的写接口审计覆盖守卫，枚举全部 `POST / PUT / PATCH / DELETE` Route Handler；每个处理器必须记录审计、明确委托已审计服务，或说明无业务写入的豁免原因。
- 补齐附件上传/封面/归档与草稿清理、登录/退出/注册、生产订单创建/取消、派工状态、生产成本、兼容报工/入库、扫码/撤销/完成以及人员审批的审计记录。
- 生产订单、派工、成本、兼容报工/入库、扫码盘点、注册和人员审批将业务写入与审计写入放入同一数据库事务；失败和幂等重放不产生虚假审计。
- 将审计覆盖守卫接入 CI，并为上述高风险命令增加临时 SQLite 事务回归。
- 站内“查看操作记录”SOP 同步增加关键写操作、前后快照和交叉核对要求，并从同一内容源生成四种交付格式。

## 影响范围

- 影响写接口审计适配、身份权限、生产、扫码盘点、附件横切能力、验证脚本、CI、交付文档和 SOP。
- 不新增页面、权限资源、Prisma 模型或迁移，不改变既有业务状态机、库存数量、成本计算或批次规则。
- 5 个无业务数据写入的接口保持显式豁免：固定 501/410/405 兼容响应、个人界面偏好和匿名使用统计。

## 验证结果

- 写接口覆盖守卫识别 134 个写处理器：129 个已审计、5 个显式豁免；14 个高风险命令强制传递事务审计上下文。
- 派工、生产订单、生产成本、扫码打印、历史工单收尾、身份注册与人员审批的临时 SQLite 回归均通过，并验证前后快照、失败分支和幂等分支。
- 最终发布门禁已通过：CI 编排内 35 项基线均通过（数据库结构文档版本遗漏修正后定点复核通过），TypeScript、ESLint 和 Next.js 生产构建通过；SOP 17 章、181 个流程同步通过，DOCX/PDF 共 183 页完整性、版式抽查和逐页像素一致性检查通过。

## 部署与回滚

1. 本版本没有数据库迁移，正常发布只需固定并部署 `v0.1.378` 对应精确提交。
2. 部署后抽查订单创建/取消、派工状态、扫码完成和人员审批，确认业务结果与操作记录同时存在。
3. 若新增事务审计导致关键写操作失败，停止继续操作并回滚到 `v0.1.377` 精确提交；无需回滚数据库 Schema。
4. 回滚只撤销新增审计覆盖行为，不删除已经形成的合法操作记录；生产数据恢复仍遵守一致备份和非覆盖候选流程。
