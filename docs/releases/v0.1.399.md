# v0.1.399 账号资料维护与停用恢复

日期：2026-08-17

## 更新内容

- 人员管理的列表和卡片视图增加“编辑资料”入口，管理员可修改登录账号、姓名和手机号；原有角色调整继续保留。
- 登录账号沿用注册时的长度和字符规则，并继续由数据库唯一约束阻止重复账号；手机号留空会清除原手机号。
- 已停用账号增加“恢复”入口，恢复后状态回到 `ACTIVE`，重新记录批准人和批准时间，原密码和权限配置不变。
- 账号资料、角色和状态修改统一保留审计前后快照；停用仍会撤销现有会话，恢复不会创建新会话。
- 只有管理员可以修改账号资料；已有 `operators.update` 授权规则继续保护人员状态动作。

## 影响范围

- 变更人员管理页面、identity-access 输入契约与领域服务、身份权限回归及人员管理 SOP。
- 继续复用 `PATCH /api/operators` 和既有 `operators.update` 权限，不增加 API、权限资源或数据库模型。
- 不修改 Prisma Schema，不新增数据库迁移，不改变员工、生产、库存、质量或成本数据。

## 验证结果

- 覆盖资料字段清理、非法账号格式、管理员修改、重复账号冲突、停用后恢复及再次停用删除。
- 身份认证回归确认资料和状态变化持久化，登录账号重复返回明确冲突，删除审计使用修改后的账号快照。
- 执行身份认证与身份权限模块回归、全量 CI 基线、类型检查、Lint 和生产构建。

## 回滚

代码可回退到 `v0.1.398`，无需数据库迁移回滚。已经保存的登录账号、姓名和手机号修改不会因代码回滚自动撤销；需要恢复旧值时应由管理员按审计记录人工修改。已恢复账号在回滚后仍保持启用状态。
