# v0.1.463 — 备份启动窗口与滚动更新稳定性

日期：2026-09-06

## 背景

Con01 上 v0.1.462 的代码已经成功完成 Prisma 迁移并启动应用，但在启用迁移前备份后，Coolify 仍按 15 秒启动窗口执行 readiness 健康检查。备份快照与 Prisma 启动尚未完成时，六次检查全部失败，Coolify 因而回滚到旧容器。旧容器继续健康，数据未丢失，但备份开关没有进入运行容器。

## 更新内容

- 保持 readiness 作为容器健康检查目标，避免把迁移未完成的容器提前切入流量。
- 将 Docker `HEALTHCHECK` 的 `start-period` 从 15 秒延长到 120 秒，给持久化数据库备份、迁移检查和 Next.js 启动留出明确窗口。
- 在运维基线中锁定 120 秒门槛，并在恢复/部署文档中记录启用备份后的启动语义。

## 影响范围

仅影响 Docker 镜像健康检查的启动等待时间、运维回归和部署文档；不改变业务接口、数据库结构、库存数量或已发布 BOM。Coolify 的生产环境变量仍由部署配置管理，启动窗口变更不会关闭健康检查，也不会跳过迁移。

## 数据与回滚

本版本无数据库迁移、无业务数据改写。Coolify 生产环境的 `MES_LITE_PRE_MIGRATION_BACKUP_ENABLED=true` 配置已保存；重试部署前必须确认最近备份存在且可验证。若新容器仍未通过健康检查，保留 Coolify 自动回滚的旧容器，不手动删除旧镜像或持久卷。

## 验证结果

本地通过 `verify:runtime-operations`、TypeScript、生产构建和完整 CI 后，才允许推送候选并重试 Con01 滚动更新。生产验收必须同时记录：新容器精确 `SOURCE_COMMIT`、备份归档与 SHA-256、`/api/health`、`/api/health/ready`、迁移计数以及三条持久卷。
