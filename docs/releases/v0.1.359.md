# MES-lite v0.1.359

日期：2026-08-13

## 更新内容

- 仪表盘首屏新增岗位任务工作台，由服务端按当前账号的有效权限生成生产、质量、仓储和系统待办；任务卡直达对应业务页并自动应用状态筛选。
- 生产订单发布、生产实绩草稿登记、生产实绩确认过账和生产实绩冲销拆为四个独立权限资源，页面按钮与 API 使用同一门禁。
- 新增基础访问、生产执行、生产管理、仓库作业、质量检验/处置/授权放行、生产计划和系统管理预置组；初始化只补齐缺失资源，不覆盖企业已有权限设置。
- 质量任务、来料、发货、退货和生产订单页面读取稳定 `task` 参数，分别进入待检、待处置、待收货、待发货、待退货、待发布、实绩登记或确认视图。
- 没有实绩登记权限的岗位只看到“详情”，避免质检员和计划员被无权操作文案误导；质量任务搜索统一进入公共顶部工具栏。
- 演示种子增加计划员、质检员、仓管员和生产主管账号与岗位组；使用真实浏览器新增 8 张桌面/移动端截图，全流程作业指导书扩展到 120 个流程、122 页 Markdown/DOCX/PDF。

## 影响范围

- 本版本无 Prisma Schema 变更，迁移仍为 74 个；权限资源写入既有 `PermissionSetting` / `PermissionGroupSetting` 表。
- 页面注册表仍为 41 个页面模块定义，API Route Handler 仍为 129 个，权限资源由 26 个增加为 30 个，验证命令由 85 个增加为 87 个。
- 预置权限组不会自动为既有人员分组，也不会覆盖管理员已经修改的权限。正式部署前仍需按企业岗位审批分配组并逐账号验收。
- 当前岗位任务数量是单厂全局口径，尚未实现本人、班组/工作中心或仓库/库位数据范围；不能把页面可见性解释为数据范围隔离。
- 本地隔离数据库和截图不等于真实 Coolify 已部署。本版本不操作本地不存在的 Coolify 服务或服务器生产数据。

## 回滚

本版本没有数据库结构变化。应用回滚到 `v0.1.358` 后，岗位任务区、四类生产命令资源和新增预置岗位组不再由代码读取；数据库中已补齐的权限资源与组设置会成为无引用记录，不影响旧版 `orders.update` 行为。回滚前仍应保留数据库与附件一致备份，并记录回滚期间生产发布、实绩确认和冲销恢复为旧宽权限的风险；恢复旧版后用生产执行、计划员和主管账号重新验证菜单、按钮及关键 API。
