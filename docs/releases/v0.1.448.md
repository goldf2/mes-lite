# MES-lite v0.1.448

发布日期：2026-08-29

## 更新内容

- 生产日报确认在正式库存扣料的同一事务内，按来源库位的可用批次 FIFO 扣减 `InventoryLotBalance`，并为每条 `DailyProductionConsumption` 写入关联正式 `StockLog` 的批次耗用事务。
- 生产日报冲销按原耗用批次事务精确恢复原批次、原库位及数量/核算量/金额，不按冲销时的当前 FIFO 重新分配。
- 原批次事务缺失、批次状态异常或未关联对应正式耗用流水时，拒绝冲销并回滚产出、投入、库位、成本层、正式流水和批次余额的全部临时变更。

## 安全边界

- 本次不修改 Prisma Schema，不包含数据库迁移，也不自动改写已修复的生产 SQLite 数据。
- 确认与冲销仍使用原有权限、状态、幂等键、库位数据范围和下游消耗阻断规则。
- 对没有可信原批次依据的历史日报，系统不猜测批次、不伪造恢复流水，而是明确阻断并要求先修复数据。

## 影响范围

- 影响生产日报/快捷生产的确认与冲销事务，以及通用批次库存服务的指定业务来源恢复能力。
- 不改变 BOM 编辑、生产订单/派工/报工、来料、发货、退货或库位转移业务流程。

## 验证结果

- 临时全新 SQLite 回归覆盖两个原料、三个来料批次的 FIFO 耗用，并核对批次事务的数量、核算量、金额和正式 `StockLog` 关联。
- 冲销前插入更早的空批次，回归仍只恢复原先耗用的批次，证明未重跑当前 FIFO。
- 人为删除原耗用批次事务后，冲销被阻断，且状态、总库存、库位余额、批次余额、成本层、正式流水和批次事务计数均保持不变。

## 回滚说明

- 代码可通过正常 Coolify 发布回滚到 v0.1.447；本次无数据库迁移需要回退。
- 上线前仍必须保留生产一致备份，部署后使用新建日报验证批次耗用与冲销恢复，不以源码或 CI 通过代替生产验收。
