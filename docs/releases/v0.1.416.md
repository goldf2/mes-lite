# MES-lite v0.1.416

发布日期：2026-08-20

## 更新内容

- LibreDWG 容器只编译核心库与命令行工具，关闭未使用的 JSON 转换和项目文档模块，并跳过与服务无关的示例程序。
- 增加结构门禁，防止后续改动重新引入部署服务器不需要的耗时编译目标。
- 候选 CI 在镜像失败时把末尾构建日志写入检查注解，避免公共仓库只能看到无上下文的 `exit code 1`。
- 更新独立 CAD 预览服务的镜像示例和 Coolify 配置手册适用版本。

## 影响范围

- `v0.1.415` 在 Coolify 实机连续两次停留于 LibreDWG `in_json.lo` 编译；第一次在约 10 分钟无新输出后由远程部署命令以 `exit code 255` 中断，第二次复现后人工停止。
- 首轮 v0.1.416 候选进一步确认：LibreDWG 0.14 在关闭 JSON 后，其示例程序 `dwgadd.c` 仍调用 `dwg_read_json` 并因 `-Werror` 失败；生产服务不使用这些示例，因此构建边界收敛为 `src` 与 `programs`。
- MES-lite 当前转换链路只使用 `dwg2dxf` 和 `dxf2dwg`，不调用 LibreDWG JSON 程序，也不需要在运行镜像中交付上游文档，因此关闭这两个目标不改变 CAD 预览接口、原文件、PDF 派生文件或下载降级行为。
- 不修改 Prisma Schema、业务流程、权限、页面结构和附件存储；本次无需更新建模/流程文档。

## 验证结果

- `npm run verify:libredwg-cad-preview` 与 `npm run verify:cad-preview` 通过。
- 本机未安装 Docker CLI，镜像级构建由候选 GitHub Actions 执行；通过后才允许合入 `main`。
- 合入后仍须在 Coolify 确认构建不再进入 `in_json.lo`，容器健康后再配置双方同值令牌并进行真实图纸验收。
