# v0.1.401 GitHub Actions 远端生产构建门禁

日期：2026-08-17

## 更新内容

- 标准生产构建由 GitHub Actions 执行，普通改动不再在开发机重复运行完整 `npm run build`。
- CI 新增 `ci/**` 候选分支和手动触发入口；待发布提交先在候选分支完成远端构建，再以同一 SHA 进入 `main`。
- 应用恢复演练明确在远端生产构建后执行，因为验收需要使用 `.next` 产物启动隔离应用；该依赖关系由候选分支首次运行验证。
- 项目规则、README 和 Coolify 部署文档统一记录开发机、Actions 与 Coolify 的职责边界。

## 影响范围

- 仅修改 CI 和发布协作流程，不改变页面、API、业务状态、权限、数据库 Schema、迁移或 SOP 操作步骤。
- 当前 GitHub Actions 只验证源码生产构建，不发布 Docker 镜像；Coolify 仍在 `main` 到达后执行 Docker BuildKit 构建和部署。
- `Dockerfile`、容器入口、Docker 依赖或系统依赖变更仍需要镜像级验证，不能只凭 Next.js 构建判定可发布。

## 验证结果

- 本机仅执行工作流语法/结构、发布记录、开发文档和 SOP 一致性验证，没有执行 `npm run build`。
- 候选分支首次运行正确拦截了构建前误放的恢复演练；修正步骤顺序后重新运行，失败提交没有进入 `main` 或触发生产部署。
- v0.1.401 精确提交先推送到 `ci/v0.1.401`，以对应 GitHub Actions run 的远端生产构建结果作为进入 `main` 的门禁。

## 回滚

代码可回退到 `v0.1.400`，无需数据库迁移回滚。回滚只恢复原工作流触发范围和文档，不影响生产数据或持久挂载。
