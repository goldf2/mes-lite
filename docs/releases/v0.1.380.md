# v0.1.380 库存所有者数据库不变式

日期：2026-08-15

## 更新内容

- 增加第 84 个迁移 `20260815234500_enforce_stock_owner_invariant`：迁移前扫描 `Stock`，只要存在“Material/Product 都为空”或“两者同时存在”的记录就停止，不自动猜测或修复生产数据。
- 增加 SQLite 新建/更新触发器，保证每条库存必须且只能归属一个 `Material` 或一个待迁移的旧 `Product`。
- 旧 Product-only 库存继续合法；Product→Material 维护命令仍可在一个原子更新中把归属从旧 Product 切换到目标 Material。
- 新增 `verify:stock-owner-invariant` 并纳入 CI，覆盖历史异常迁移阻断、新建/更新旁路阻断和 Product→Material 原子切换。
- 生产 Schema 漂移回归固定从当前 `HEAD` 提取 Schema 与迁移建立测试基线，未提交工作树新增迁移不再被误判为已发布精确提交的一部分。

## 影响范围

- 数据库：新增两个 `Stock` 归属触发器，不新增模型、字段或业务数据。
- 业务：正常 Material 库存和旧 Product-only 库存不变；非法无归属/双归属写入会在数据库层失败。
- 页面/API/权限：不新增页面、接口、权限资源或操作步骤，181 个站内 SOP 流程内容不变。
- 生产门禁：原始运行库如果仍有既有 `P3009`，必须先使用 v0.1.377 非覆盖 Schema 收敛候选；本迁移不能绕过失败迁移继续部署。

## 验证结果

- Prisma Schema 校验及专项库存归属回归通过；历史异常迁移预检、四类非法写入和原子所有者切换均按预期执行。
- 在 v0.1.376 零漂移生产恢复候选的隔离副本顺序应用第 83、84 个迁移成功，`PRAGMA quick_check=ok`，两个触发器存在。
- 候选迁移前后业务统计一致：46 条 Material、16 条 Product、62 条 Stock、3 条 StockLog、1 张生产订单和 90 条附件记录均未变化；库存数量汇总仍为 18,600，成本汇总仍为 0。
- 候选迁移后库存归属为 Material-only 46、Product-only 16、无归属 0、双归属 0。该旧候选只证明迁移兼容性，不替代最新在线生产备份、Schema 审计或业务签字。

## 部署与回滚

1. 部署前执行数据库与附件一致备份，并在最新只读生产副本确认无归属/双归属库存均为 0。
2. 只有生产迁移状态可继续、物理 Schema 为零漂移时，才固定本版本精确提交并执行第 84 个迁移。
3. 如果迁移被归属门禁阻断，停止部署并由业务人员处理异常；不得删除门禁或自动选择 Material/Product。
4. 代码回退到 v0.1.379 与这两个触发器兼容，正常情况下保留触发器即可。只有经备份和审批确认必须撤销数据库约束时，才单独执行 `DROP TRIGGER "Stock_owner_insert_guard"` 与 `DROP TRIGGER "Stock_owner_update_guard"`；该动作不会恢复或改写任何库存数据。
