# MES-lite v0.1.431

发布日期：2026-08-22

## 更新内容

- 销售订单与发货单完全解耦：销售订单只记录客户需求，发货单只记录一个客户和一至多条实际发货物料，不保存销售订单或订单明细 ID，也不回写订单数量与状态。
- 新建发货单改为多明细整单编辑，可连续加入、编辑和移除物料明细后一次保存；每条明细独立保存物料、库位、数量和单价，确认发货时逐项扣减库存、批次和成本。
- 按“客户 + 物料”动态汇总销售需求、待发、已发、未发和超发数量，在发货录入与仪表盘中提供参考；参考不形成订单履约关系，也不限制超发。
- 销售订单和发货列表可选显示物料图片，并允许用户分别选择凭据、日期、状态、金额、库位、数量、附件等显示项；显示偏好保存在当前浏览器。
- 产品文档移除工作中心字段和关系；生产实绩的作业文件候选只按订单物料或通用文档筛选，不再按文档工作中心过滤。
- 业务弹窗默认禁止点击遮罩空白关闭，只保留明确的关闭、取消和 `Esc`；临时菜单与搜索浮层仍可点击外部收起。

## 数据模型与迁移

- 新增 `ShipmentItem`，一张 `Shipment` 可拥有一至多条发货明细；货箱明细、发货批次和退货明细改为引用具体发货明细。
- 迁移 `20260822093000_add_shipment_items` 把历史单行发货映射为一条 `ShipmentItem`，并迁移货箱、批次和退货引用；单头旧字段暂保留为兼容投影。
- 迁移 `20260822090000_unbind_documents_from_work_centers` 删除产品文档与工作中心关联表，现有文档、正文、附件和物料关系不变。
- 未发与超发不落库，不写回销售订单；页面和仪表盘始终从当前订单需求与发货事实重新汇总。

## 影响范围

- 影响销售订单查询、发货新增/查询/确认/送达/取消、货箱、退货、送货单 PDF、仪表盘交付参考、产品文档维护和生产实绩作业文件候选。
- 销售订单与发货单不再提供来源订单关系；既有历史关系通过迁移转换为独立发货事实后不再参与运行逻辑。
- 物料图片来自物料的主图片附件；没有图片时列表保持原有文字展示，不阻断订单或发货操作。
- 允许超发，但发货确认仍受实际库位可用量、批次和库存事务规则约束。

## 页面与权限

- 发货新增、修改、确认、送达、取消、退货和货箱继续使用原有权限资源；没有新增平行权限。
- 发货弹窗使用“添加本项并继续”“本单已加入”“保存整单”区分当前明细与整单提交，保存按钮显示明细数量。
- 销售订单与发货页面的“显示项”由页面实际字段目录生成，至少保留一个显示项，图片默认关闭以避免改变现有阅读密度。
- 仪表盘交付参考遵循当前操作者的数据范围，只显示其可见客户、销售需求与发货事实。

## 验证结果

- 全新 SQLite 数据库 90 个迁移部署通过，历史单行发货迁移、销售订单/发货无外键与多明细数据一致性回归通过。
- 销售订单、发货多明细、定价边界、货箱、退货批次、送货单打印、文档元数据、生产实绩上下文和仪表盘定向回归通过。
- TypeScript、ESLint、模块边界、数据完整性、动态搜索字段、SOP、开发文档和发布说明门禁通过。
- 本地浏览器实测仪表盘交付参考、销售/发货显示项、多明细发货弹窗及业务弹窗遮罩行为；标准生产构建和部署后验证由候选提交及生产版本门禁执行。

## 回滚说明

- 应用代码可回滚，但旧版本不认识 `ShipmentItem`，会按兼容单头字段读取每张发货单的首项或汇总值，不应在回滚窗口继续创建多明细发货。
- 回滚前必须备份数据库；不要删除 `ShipmentItem` 或已迁移的明细引用。若需长期回退，应另行编写受控的多明细降级迁移，并明确如何处理无法无损压回单行的发货单。
- 文档与工作中心关系删除后不自动恢复；旧版本即使回滚也不能重新推断原关联。
