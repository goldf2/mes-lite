# MES-lite v0.1.347

日期：2026-08-12

## 更新内容

- Git 停止跟踪 `prisma/mes_lite.db` 和 `tsconfig.tsbuildinfo`，并忽略 SQLite journal/WAL/SHM、构建缓存和运行时备份；本地已有数据库文件保留不变。
- 新增运行时备份命令：使用 SQLite `VACUUM INTO` 生成一致快照，复制附件后逐条核对数据库附件引用，生成清单与逐文件 SHA-256，并在保留前自动解包复验。
- 新增备份验证和非覆盖恢复候选命令；恢复目标必须不存在，不会改写当前数据库和 uploads。
- 容器新增 `/app/backups` 持久化目录；挂载就绪并显式开启后，旧数据库在每次 Prisma 迁移前自动备份，备份失败则中止迁移。默认保留最多 30 份且最长 14 天。
- 新增 `/api/health/live` 和 `/api/health/ready`。readiness 检查 SQLite、Prisma 迁移、数据/附件目录读写性；备份过期作为可监控警告，不引发容器重启循环。
- Docker HEALTHCHECK 和 Coolify 配置切换到 readiness，Compose 与环境变量示例同步数据、附件、备份三类持久化路径。
- 运行镜像在现有 BuildKit APT 缓存、镜像源和有限重试层显式安装并校验 `tar`，不依赖 Debian slim 的偶然预装内容。

## 影响范围

- 不修改 Prisma 业务 Schema，不改写现有 SQLite 数据和附件。
- Coolify 必须新增 `/opt/mes-lite/backups -> /app/backups` 持久化挂载，并建立每日备份调度；否则迁移前备份可能只留在容器可写层。
- 当前仓库的历史 commit 仍含旧 SQLite 快照。历史清理、远程强制推送和密钥/账号轮换必须在单独维护窗口执行，本版本不做破坏性历史重写。
- 异地副本需要由主机级备份或对象存储任务提供；仓库不保存任何云存储凭据。

## 验证结果

- 临时完整迁移 SQLite 验证了备份创建、归档复验、附件引用、篡改 SHA-256 拒绝、非覆盖恢复候选及恢复库再查询。
- readiness 在数据库、迁移和持久目录正常时通过，附件目录缺失时稳定返回未就绪。
- TypeScript、ESLint、Prisma Schema、模块边界、开发文档、发布记录和 Next.js 生产构建已通过。
- 本机无 Docker CLI，未构建运行镜像；已校验 Dockerfile/Compose 契约、启动脚本和 standalone 中的 Prisma 运行依赖。最终镜像仍需以 Coolify 详细构建日志验收。

## 回滚

- 代码可回滚到 `v0.1.346`；无需数据库反向迁移。
- 回滚时保留 `/app/data`、`/app/public/uploads` 和 `/app/backups` 挂载，并保留 `.gitignore` 对运行时数据的排除，不应重新把生产 SQLite 加回 Git。
- 如 readiness 误判阻断启动，可在维护窗口暂时将 Coolify 健康路径切回 `/api/health`，但不得跳过已失败的 Prisma 迁移或不可写持久目录继续对外服务。
