# v0.1.496 MES 内部任务协同与冻结资料发放

## 问题与结果

任务的执行要求、物料清单、图纸版本、进度备注和资料发放记录原先缺少统一的协同入口。本版在现有 MES 内新增任务协同模块，完成草稿、任务 BOM、文件引用、派工关联、进度、资料预览与冻结发布、人工发放登记、历史查询和归档恢复。关联已有生产订单或派工时，实际完成量、报废量和执行状态仍由 MES 生产领域提供，协同备注不重复报工，也不产生库存或财务过账。

本版是准备推送的发布候选，基于已核对的 `origin/main` 提交 `f8be0d85cf6c4907061f15c9a60c19fe191c3d9a`（v0.1.495）隔离集成。原 v0.1.493 独立候选已有本地完整验收证据；本发布 worktree 的检查仍在进行，尚无本版精确提交的远端 CI、main 合入或生产部署结论。用户已授权推送后试用，执行顺序仍须遵守候选 CI 门禁。

## 更新内容与复用边界

- `modules/task-collaboration` 拥有任务契约、客户端、领域服务、薄 HTTP 处理器与界面。任务可引用已有销售订单、生产订单、派工、员工、供应商和工作中心；任务 BOM 引用现有 `Material`，不建立平行物料、联系人、生产 BOM 或派工引擎。模板只复制固定说明、BOM 与资料引用，新任务数量、行身份、执行关系及历史保持独立。
- 协同状态为 `DRAFT → ASSIGNED → IN_PROGRESS → COMPLETED`，允许从已分派或进行中取消；MES 关联任务仅追加备注或异常，由现有生产接口提供实绩。内容修改、分派、协同状态和归档恢复使用 `expectedRevision`，陈旧写入返回 409；归档保留原状态与历史，不提供永久删除。
- 发布前核对来源权限、版本及真实文件字节，返回绑定任务、收件对象和来源资料的 `previewToken`。发布时原样提交 token 与稳定 `operationId`，复制精确文件字节并冻结资料清单；来源变化须重新预览。操作 ID 与任务版本唯一约束、事务及不可变触发器防止重复有效发布或历史覆盖。
- 冻结清单保存任务、BOM、收件对象、文件来源、业务版本、文件名、MIME、大小、旋转和 SHA-256；文件访问使用冻结副本 ID。后续源图修改或归档不改变已发放资料。清单只保存 MES 来源 ID，不冻结实时生产数量或状态；当前 `execution` 另按生产范围过滤。
- 发放记录支持 `MANUAL/EXPORT/EMAIL/WECHAT` 与记录、导出、失败状态。EMAIL/WECHAT 仅登记人工凭证，本版不发送真实消息；供应商是已有资料引用，没有新增供应商自助登录或外部账号体系。
- 列表支持搜索、状态/归档筛选与服务端分页，关联选项按资源远程检索；详情汇集 BOM、文件、执行来源、进度及发布历史。1440px 桌面与 390px 手机复用公共资源工作区、工具栏、列表/卡片、弹窗、关联编辑、`AttachmentPanel` 和 `DocumentFileViewer`。修正嵌套 DTO、缺失权限默认拒绝、表单隔离、交期 UTC/本地往返、预览失效、失败重试、归档文件保护及窄列可读性。
- 公共 `AttachmentPanel` 增加可选上传、更新、归档动作权限及兼容别名；旧调用不传时保持原默认行为，`readOnly` 优先。任务适配器分别检查任务与附件动作，服务端仍执行来源、owner 和数据范围鉴权。不可用文件只返回受限元数据标记，不暴露存储路径。

v0.1.494/495 已进入主线的宇峰紧凑首页、功能矩阵、收藏/高频与操作规范保留；按用户截图取消整条平台标题横栏，任务入口与公共工具栏继续复用现有组件。用户确认 MES、客户管理、宇峰平台分别使用 mes.csyufeng.com、crm.csyufeng.com、work.csyufeng.com；客户管理入口默认指向新前缀，现有数据平台部署的域名与登录配置另按实际状态核实。MES 与宇峰平台当前仍共用既有 Web 部署，客户管理沿用独立部署，不新建应用、迁移数据库或修改 DNS。

## 影响范围

新增五个模型/表：`TaskCollaboration`、`TaskCollaborationLine`、`TaskCollaborationProgress`、`TaskCollaborationRelease`、`TaskCollaborationDelivery`。复用既有业务外键与 `DocumentAttachment`，增加 `TASK_COLLABORATION` 附件 owner 和 `SYSTEM_GENERATED_TASK_RELEASE` 只读副本语义。

新增资源 `taskCollaboration` 与 `taskCollaborationPublish`。非管理员的新权限默认关闭，不从旧生产或附件权限隐式继承，不修改真实账号授权。任务所有接口要求任务 read；预览、发布及发放还要求发布资源 update。附件操作继续叠加原 `attachments` 动作与来源资源权限，引用选择也分别检查对应资源 read。

任务范围沿用 `ALL/SELF/WORK_CENTERS`：SELF 仅绑定员工为负责人的任务，工作中心模式仅允许指定中心。订单/派工实绩还须独立满足生产范围，范围外实时数据返回空投影；创建人或供应商引用不扩大任务范围。归档历史详情及清单按任务权限读取，归档任务文件拒绝访问，恢复后重新授权读取。

API 根路径为 `/api/task-collaboration`，新增 11 个路由文件、13 个 HTTP 处理器：

| 接口 | 行为 |
| --- | --- |
| `GET/POST /`、`GET/PATCH /:id` | 查询、草稿/模板创建、详情与内容更新 |
| `GET /options` | 按既有资源权限查询物料、员工、供应商、订单、派工、工作中心及当前任务附件 |
| `POST /:id/assign`、`/:id/progress` | 分派关联校验、进度/异常与允许的协同状态命令 |
| `POST /:id/release-preview`、`/:id/releases` | 只读预览、token 校验、幂等冻结发布 |
| `GET /:id/releases/:releaseId/manifest` | 读取和导出不可变 JSON 清单 |
| `POST /:id/releases/:releaseId/deliveries` | 沿冻结收件对象登记人工发放凭证 |
| `POST /:id/archive`、`/:id/restore` | 乐观版本校验后的归档与恢复 |

文件继续通过现有附件预览、缩略图和下载接口。严格输入拒绝额外产量字段；未登录 401、资源/任务范围拒绝 403、非法数量/引用/状态 400、失效文件 404、版本/幂等冲突 409。原附件 owner 的范围拒绝保留既有 404 语义。

## 迁移、备份与回退

新增迁移 `prisma/migrations/20261020093000_task_collaboration/migration.sql`，为第 100 个迁移。仅新增五张表、外键、索引、唯一约束和不可变保护触发器；不回填现有单据、不改写库存成本、不删除旧结构，也不执行人员赋权。触发器保护进度、发布、发放记录不可改删，并保护冻结附件的内容身份字段及删除。

实际运行迁移前，须按现有备份流程取得可恢复的数据库与上传文件一致备份，核对完整性、备份位置和恢复入口；保留既有持久卷及迁移前备份门禁。发布候选只在临时合成库验证，不将本地结果当作生产迁移已完成。

出现问题时先停止任务写入和新资料发放，记录待回退提交与备份。增量结构允许评估回退至上一应用版本并保留新增表、触发器和冻结附件，旧版不提供任务功能；执行前仍须核验旧版关键路径与附件清理兼容性。不得用自动 DROP 表、解除不可变保护或删除冻结文件完成回退。只有在单独确认恢复范围与新增任务/附件处置后，才按既有恢复流程恢复一致备份；本版不附带破坏性 down migration。
