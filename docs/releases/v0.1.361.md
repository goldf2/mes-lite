# MES-lite v0.1.361

日期：2026-08-13

## 更新内容

- 新增账号级生产数据范围：`ALL / SELF / WORK_CENTERS`。本人范围使用账号绑定员工，工作中心范围使用工序与工作中心稳定外键。
- 新增账号级库存数据范围：`ALL / LOCATIONS`。来料、发货、退货、流程转移、库存、流水、批次追溯和质量任务按获批库位过滤。
- 生产订单、派工、生产实绩、旧生产报表、仪表盘统计和岗位任务同时应用动作权限与数据范围；状态命令在领域服务再次断言范围，跨范围请求返回 403。
- 附件读取、上传、修改和归档除原业务资源权限外，再校验所属生产或履约对象的数据范围；来料历史换算样本只读取授权库位。
- 个人权限覆盖升级为临时授权，必须记录业务原因、授权人、开始和失效时间；到期后自动退出有效权限，新增、修改和删除均保存审计快照。
- 旧账号缺少数据范围记录时保持原 `ALL / ALL` 行为并显式标记“继承旧版默认”；新注册和首次微信登录账号默认使用本人生产范围及空的指定库位集合。
- 旧个人覆盖迁移为 `legacyPermanent` 兼容记录，标记“历史个人覆盖兼容（需重新审批）”，避免升级时突然失权，同时要求生产上线前逐项审批收窄。
- 使用隔离本地演示库新增 3 张真实浏览器截图，全流程作业指导书扩展到 132 个流程、134 页 Markdown/DOCX/PDF。
- 增加生产库 P3009 只读审计、非覆盖恢复候选生成和回归工具；恢复事实、哈希证据、Coolify 固定提交和回滚边界写入运维文档与独立修复报告。

## 影响范围

- Prisma 模型由 74 个增加为 77 个，迁移由 74 个增加为 76 个；新增 `OperatorDataScope`、`OperatorWorkCenterScope`、`OperatorInventoryLocationScope`，并为 `ProcessStep` 增加 `workCenterId`、为 `Dispatch` 增加 `employeeId`。
- `OperatorPermissionOverride` 新增 `reason`、`grantedBy`、`startsAt`、`expiresAt`、`legacyPermanent` 和失效时间索引。迁移只增加字段、表、索引和可确定的历史外键回填，不删除业务数据。
- 页面模块和 Route Handler 数量不变，仍为 41 个页面模块定义和 129 条 Route Handler；验证命令增加到 92 个。
- 管理员固定全厂范围。非管理员只有在资源动作权限和数据范围同时满足时才能读取或修改业务对象，前端隐藏不作为安全边界。
- 历史库存批次只要曾在授权库位有过余额即可保留追溯可见性；质量判定和处置只接受当前正余额位于授权库位的批次。
- 部门/班组范围尚未独立建模；旧账号的全厂兼容范围和历史永久个人覆盖不是最终最小授权，必须在生产岗位审批中清理。
- 本次代码推送不会自动部署：Coolify Git Source 继续固定在已恢复的 v0.1.360 提交 `be7e18f653bd684cb2367985c1f8c072801d79ec`。

## 生产部署门禁

生产环境当前保持“v0.1.360 固定提交 + 已恢复数据库”的健康基线。升级 v0.1.361 前必须同时完成：

1. 持久挂载 `/app/backups` 并用内建工具生成、校验一次数据库与附件一致备份；
2. 建立每日调度和异地副本，并在非覆盖目录完成恢复演练，记录真实 RPO/RTO；
3. 在生产数据库副本顺序应用第 75、76 个迁移并执行数据范围专项回归；
4. 逐人审批旧版默认全厂范围和历史永久个人覆盖；
5. 在维护窗口显式修改 Coolify Commit SHA，部署后验证首页、live、ready、登录、岗位任务、越权 403、附件和关键业务闭环。

## 回滚

本版包含可加性数据库迁移，不能只回退镜像。迁移后的数据库保留新增表、列和索引；旧 v0.1.360 代码不会读取它们，但旧代码会恢复单厂全局数据口径和历史个人覆盖语义。

若部署验收失败，应停止应用，使用升级前经验证的一致备份在非覆盖目录生成恢复候选，校验后再成对切换回 v0.1.360 代码与数据库。禁止删除已部署迁移目录、手工删除 `_prisma_migrations` 记录或把旧 journal/WAL/SHM 与恢复候选混用。若仅撤销功能而保留新版数据库，应使用新的前向补偿迁移，不能修改已发布迁移 SQL。
