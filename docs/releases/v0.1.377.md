# v0.1.377 生产 Schema 漂移审计与非覆盖收敛候选

发布日期：2026-08-15

## 更新内容

- 新增生产 Schema 只读审计：从指定 Git 提交完整迁移构建空库基线，区分额外、缺失、语义变更和等价 SQL 定义差异。
- 新增非覆盖 Schema 收敛候选：将退役表和旧列数据归档后，只在新候选上执行审计绑定的 diff SQL，并强制后置零漂移。
- 回归脚本同时覆盖源哈希不变、报告不可覆盖、有数据退役表归档、旧列移除、候选完整性和后置零漂移。
- 在实际生产恢复候选上完成审计、非覆盖收敛和隔离应用恢复；保留备份过旧导致的 RPO 失败，不将技术抽查通过冒充为可生产切换。
- 应用恢复 SOP 同步增加 Schema 审计、历史数据审批、收敛候选和 RPO 门禁，并重生成 Markdown、DOCX、PDF 和离线 Web。

## 影响范围

- 运维脚本、CI 编排、恢复 SOP、运维/架构/交付文档与版本号。
- 不修改 Prisma Schema、迁移数量、业务 API、页面、权限、在线生产数据库或 Coolify 运行状态。
- 归档和收敛仅已在本地隔离候选执行；它们不授权直接切换生产。

## 验证结果

- 专用 Schema 漂移回归已通过：清洁库为零漂移，合成漂移能被准确分类，并能在保存历史数据后生成零漂移候选。
- 生产恢复候选收敛后，迁移、SQLite、附件哈希、readiness、登录和关键只读 API 全部通过；完整应用 RTO 2.287 秒通过，RPO 约 46.9 小时失败。
- 最终验收已通过：CI 领域基线 34 项、`tsc --noEmit`、ESLint、Next.js 生产构建和 SOP 同步均为绿色；DOCX/PDF 均为 183 页，更新后的第 181 页已复核无裁切、重叠或旧截图残留。

## 部署与回滚

1. 此版本可先正常部署运维工具，但不得因为代码部署成功就执行生产数据切换。
2. 生产维护窗口必须用最新一致备份重做审计、收敛候选和应用演练，并取得退役数据与 Product→Material 映射签字。
3. 实际切换时保留旧 `data/uploads` 挂载。验收失败则停止新容器并切回旧挂载；不在运行中覆盖 SQLite。
