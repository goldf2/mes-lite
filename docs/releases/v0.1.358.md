# MES-lite v0.1.358

日期：2026-08-13

## 更新内容

- 新增 MES > 库存 > 批次追溯页面，可按供应批号、内部批号、物料、供应商、客户及来料/生产/检验/发货/退货单搜索内部批次。
- 新增多跳正反向全景，从任意起点展开有效生产投入/产出和客户退货回流关系，并按上游、当前、下游层级显示批次、库存状态、检验记录和业务单据。
- 全景汇总关联批次、转换关系、供应批次、客户和质量检验；客户发货区显示来源批次、发出与已退数量。
- 搜索最多返回 100 条、全景最多展开 300 个批次；只读取 `ACTIVE` 关系，切换搜索词立即清空旧全景，避免将旧结果误认为新条件结果。
- 页面、搜索 API、全景 API 与相邻追溯弹窗统一复用 `stocks.read`，没有创建重复权限资源。
- 指导书演示种子改为由合格生产批次发货，并增加已处理退货与独立待检批次，使全新隔离数据库可复现完整供应到客户再回流链路。
- 使用真实浏览器新增 6 张批次追溯截图；全流程作业指导书扩展到 112 个流程、114 页 Markdown/DOCX/PDF 交付物。

## 影响范围

- 本版本无 Prisma Schema 变更，迁移仍为 74 个；只新增查询服务、两个只读 Route Handler、一个页面入口和演示/文档资产。
- 页面注册表现为 41 个页面模块定义，API Route Handler 为 129 个，验证命令为 85 个。
- 搜索与全景是只读能力，不修改批次、库存、质量、发货或退货事实；原有相邻追溯入口继续兼容。
- 本地隔离数据库和截图不等于真实 Coolify 已部署。生产只允许在一致备份和维护窗口后升级，再用只读账号验证搜索和反向退货追溯。

## 回滚

本版本没有数据库结构或写入协议变化。应用回滚到 `v0.1.357` 时，新“批次追溯”页面和两个只读 API 消失，既有批次数据、质量处置、发货与退货关系不需转换。回滚前仍应保留数据库与附件一致备份；如生产已通过新页面形成导出或外部操作记录，应一并保留其审计证据。恢复后执行 `PRAGMA quick_check`、迁移账本核对、相邻批次追溯和库存状态合计检查。
