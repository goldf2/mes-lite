# v0.1.381 轻量发布树与分阶段 SOP 验收

日期：2026-08-15

## 更新内容

- 将版本化 DOCX、PDF 与离线 Web 从当前 Git 发布树移除，本地文件保留在被忽略的 `output/`。
- Git 与 Docker 构建上下文统一忽略 `output/`；新增 `verify:release-tree`，阻止生成成品再次入库，并把当前发布树限制在 128 MiB 内。
- GitHub Actions 从完整历史改为验证所需的浅历史，避免每次 CI 拉取旧二进制成品。
- 新增 `sop:build:source`，开发期只生成 Markdown；`verify:sop` 只验证清单、权限、截图和 Markdown。最终冻结后才运行 `sop:build` 与 `verify:sop:artifacts`。
- 修正运维文档事实：2026-08-15 真实 Coolify 只读审计确认 main Webhook 自动部署当前开启，不再把“自动部署关闭”写成现状。

## 根因与效果

- v0.1.380 当前树含 2,803 个 `output/` 文件、约 2,106.3 MiB；除生成物外的发布树约 58.5 MiB。
- 真实 Coolify 上一部署 `be036af` 在 `git clone --depth=1` 阶段运行约 58 分钟后以退出码 255 失败，尚未进入依赖安装、Next.js 构建或数据库迁移。
- v0.1.381 的目标是让下一次浅克隆只获取代码、迁移、SOP 源文件与截图源资产；历史旧提交仍保留原二进制，不宣称完成 Git 历史瘦身。

## 影响范围

- 页面/API/权限/数据库：无变化；84 个迁移保持不变。
- 在线帮助：181 个流程、操作步骤和截图不变。
- 本地交付：已有 v0.1.380 DOCX/PDF/Web 文件不删除；v0.1.381 不在开发期重复生成全部成品。
- 自动部署：推送会触发真实 Coolify Webhook；是否上线仍以部署结果、健康检查和迁移门禁为准。

## 验证结果

1. `verify:release-tree` 必须报告当前 Git 发布树不超过 128 MiB且没有跟踪 `output/`。
2. `verify:sop`、类型检查、Lint、生产构建与 38 项 CI 基线必须通过。
3. 最终商业交付版本冻结后运行 `npm run sop:build` 和 `npm run verify:sop:artifacts`，再执行一次人工全页验收。

## 回滚

本版本不改数据库。若应用需要回滚，使用已验证运行镜像或代码提交；不要把旧二进制成品重新加入当前发布树。
