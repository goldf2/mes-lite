# MES-lite v0.1.468

## 更新内容

- 发货单收敛到唯一文档服务：客户发货单的在线预览、浏览器打印、直接下载和旧下载 URL 复用同一份已归档 PDF，不再由两个渲染器生成不同版式。
- 明确区分“客户发货单”和“内部留档”。客户版保留双方资料、物料、数量、金额、货箱、物流号、二维码与签收栏；内部版增加库位、批次、欠库、出库成本、操作人和冲销信息。
- 两种受众使用独立的系统生成文档类型，源单版本、打印密度、页边距和企业抬头资料组成归档匹配条件；变化后追加新版本，不覆盖历史文件。
- 发货 PDF 统一执行已发货/已签收状态门禁和有效库位数据范围；系统生成 PDF 不再混入用户上传的原始附件列表。
- 完成仓库 PDF 输出盘点：来料、销售订单、销售退货、流程转移、生产订单和派工继续使用通用业务单据模板；Office/CAD 派生预览、SOP 静态 PDF 和标签画布保持用途隔离。

## 影响范围

- 发货管理的卡片、表格和详情操作改为明确显示“客户发货单 / 内部留档”；待发货、已取消和已冲销单据不提供正式发货 PDF。
- 旧 `/api/shipments/:id/delivery-note` 地址继续可用，但仅作为客户版下载兼容包装；不会删除旧 `SYSTEM_GENERATED_PDF` 数据，也不会把旧版通用发货文件误作客户新版本。
- 本版本无 Prisma 迁移、库存改写或业务状态改写。现有 Office/CAD 在线预览、原始附件下载和 SOP 发布流程不变。

## 验证结果

本地验证已通过：

- `npm run verify:business-document-print`
- `npm run verify:module-boundaries`
- `npm run verify:sales-module`
- `npm run verify:attachment-management`
- `npm run verify:attachment-file-types`
- `npm run verify:document-server`
- `npx tsc --noEmit`
- `git diff --check`

客户版和内部版均使用真实 PDFKit 输出进行 A4 渲染检查；客户预览与下载字节一致，内部版与客户版按受众不同，打印设置、企业抬头或发货源数据变化会追加归档版本。

候选 CI、main CI 与 Con01 生产验收待补充。只操作 Con01，不访问 AL02。

## 回滚边界

本版本无数据库迁移。若发布失败，回滚代码并保留 Shipment、附件记录和附件存储文件；不删除已经生成的 PDF 历史快照。旧兼容 URL 仍可由上一版本处理。
