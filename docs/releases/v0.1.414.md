# MES-lite v0.1.414

发布日期：2026-08-20

## 更新内容

- 增加独立的 `services/cad-preview/` CAD 转换服务，不把 DWG 解析器和原生依赖装入 MES-lite Web 进程。
- DXF 由 ezdxf/PyMuPDF 直接转换为只读 PDF；DWG 先由 GNU LibreDWG 0.14 转为 DXF，再复用同一渲染链路。
- 保持 v0.1.412 已发布的内部 HTTP 契约不变，现有附件权限、派生缓存、全屏 PDF 查看与下载原文件降级无需新增页面分支。
- 镜像固定源码版本和 SHA-256，使用非 root 用户、上传上限、命令超时和自动清理的临时目录；构建期间真实覆盖 DXF 直转和 DWG 往返转换。
- GitHub Actions 增加 CAD 镜像构建门禁，Coolify 文档补充私网第二应用、健康检查、资源约束、回滚和真实图纸验收步骤。

## 影响范围

- 不修改 Prisma Schema、业务状态、权限资源、用户操作流程或 MES-lite 主容器运行依赖。
- 新增一个可选内部容器；未部署或离线时，MES-lite readiness 继续只返回警告，用户仍可下载原始 DWG/DXF。
- 该引擎是 2D 试用方案，不承诺所有 DWG 版本、垂直产品实体、外部参照、字体和布局的像素级兼容。原文件始终是唯一事实源。
- LibreDWG、ezdxf 和 PyMuPDF 的许可证及镜像分发义务与 Web 应用分开管理；向客户分发转换器镜像前必须完成开源合规复核。

## 验证结果

- 本机使用真实生成的 DXF 完成 PDF 渲染，并通过 Bearer 错误令牌拒绝、正确令牌放行和 multipart 上传协议验证。
- `python3 -m py_compile services/cad-preview/server.py services/cad-preview/smoke_test.py` 通过。
- `npm run verify:cad-preview` 与 `npm run verify:libredwg-cad-preview` 用于锁定 MES 客户端契约和转换服务边界。
- 本机没有 Docker CLI，无法在开发机完成 LibreDWG 镜像构建；候选分支 GitHub Actions 必须成功执行 `docker build` 及镜像内 DXF/DWG 冒烟后，才允许同一提交进入 `main`。
