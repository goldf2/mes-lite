# v0.1.455 — 发货受控负库存与后补入库闭环

日期：2026-09-04。

## 更新内容

- 新建发货单不再因所选库位库存不足而拒绝保存，并显示确认后的预计欠库数量。
- 确认发货允许形成受控负库存：已有可用量仍按真实批次和成本发出，差额记录为发货欠库。
- 后续同物料、同库位的可用入库或质量放行按时间顺序自动补齐发货批次和成本；发货详情显示待补数量。
- 欠库未补齐时阻止客户退货；发货冲销同时恢复原发货、已执行的欠库补账、批次和成本。
- 数据一致性检查只接受有开放发货欠库支撑的负库存，生产领料、调拨、普通调整及非可用状态库存继续禁止超量或负数。

## 影响范围

- 页面：新建发货数量参考和发货详情批次状态。
- 领域服务：销售发货/退货状态、库存收发过账、内部批次分配、状态转换和库存一致性检查。
- 数据库：新增两张只追加的欠库关系表及一个迁移；既有业务数据不被改写。
- 不改变销售订单、生产领料、调拨、库存冻结、权限资源或 API URL。

## 数据变更

- 新增 `ShipmentStockShortage`，保存发货明细、物料、库位、欠库量、已补量及状态。
- 新增 `ShipmentStockShortageSettlement`，连接欠库、后补批次、成本层、库存流水和发货批次分配。
- 迁移：`20260904143000_add_shipment_stock_shortages`；只新增表、索引和外键，不改写既有库存数据。

## 验证结果

- 新增端到端验证覆盖：零库存发货、分两次后补入库、批次/成本补齐、非发货负库存阻断、欠库期间退货阻断及整单冲销。
- 既有多明细发货、发货冲销、发货退货批次、统一库存事务账本、数据一致性和来料模块回归均通过。
- TypeScript、Prisma Schema、迁移、Lint、SOP、研发文档和版本说明门禁在候选提交前执行；生产构建由精确 SHA 的 GitHub Actions 候选分支完成。

## 风险与边界

- 发货欠库只由后续“同物料、同库位”的可用批次自动补齐；其他库位库存不会被隐式挪用。
- 欠库补齐前的发货成本并非最终完整成本，详情会持续显示待补状态。
- 本版不放宽生产领料、调拨、冻结库存或普通库存调整规则。

## 回滚

- 未产生欠库记录前，可重新发布上一个已验证提交。
- 已产生欠库记录后，禁止直接降级旧应用；应先暂停相关写入、备份数据库并补齐或冲销开放欠库。
