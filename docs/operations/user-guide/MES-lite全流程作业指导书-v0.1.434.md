## 推荐业务顺序

单位/库位/员工/供应商/客户/工作中心 → 物料 → 检验标准 → BOM/工艺路线 → 生产订单/销售订单 → 派工/来料/发货 → 收货转待检 → 质量判定/处置/复检 → 生产日报 → 库存盘点与审计复核。

## 1. 登录与功能导航

### 使用站内帮助中心

目的：按当前账号权限搜索并阅读当前版本的作业指导书。

1. 在任一页面展开“工作台”功能区。
2. 点击“帮助中心”。
3. 需要独立全屏查看时，在快捷帮助中点击“打开完整帮助中心”，系统会新开页面且保留当前业务页面。
4. 使用搜索框输入页面、单据、岗位或操作关键字。
5. 视频教程按既有 SOP 章节显示；点击视频可直接播放，或在新页面打开原始视频。
6. 展开目标流程，逐步操作并核对结果检查。
7. 商业交付环境若已配置外部文档下载地址，可在页头下载与当前系统版本一致的 PDF 或 DOCX；没有下载按钮时继续使用在线帮助并联系管理员完成成品发布。

结果检查：独立帮助页面显示系统版本、可读流程数、视频数和章节；视频与流程按同一章节、权限和当前页面关系显示，无权限内容不会出现；只有配置了只读发布地址时才显示当前版本 PDF/DOCX 下载和已登记的视频文件。

![使用站内帮助中心](screenshots/v0.1.370/150-fullscreen-help-page.png)

### 查看当前页面操作帮助

目的：不离开当前业务页面即可查看与该页面关联的操作流程。

2. 点击顶部问号按钮。
3. 在右侧抽屉播放当前页面相关视频，或展开相关流程查看步骤、结果和截图。
4. 点击“新页面全屏查看”只查看当前功能，或点击“打开完整帮助中心”在新页面检索全部流程。

结果检查：抽屉只显示当前页面且当前账号有权读取的 SOP 流程和视频；两个底部入口均在新页面打开，不中断当前业务操作。

![查看当前页面操作帮助](screenshots/v0.1.370/149-context-help-new-page.png)

4. 发现红色或橙色预警时进入对应功能核查。

## 2. 物料与 BOM 主数据

### 查询物料

目的：查询物料编码、规格、单位和库存概况。

1. 展开“物料”功能区，进入“物料管理”。
2. 使用顶部搜索框输入编码、名称或规格。
3. 需要时切换列表/卡片视图并打开详情。

结果检查：目标物料及库存单位正确显示。

![查询物料](screenshots/v0.1.350/04-material-list.png)

### 新建物料

目的：建立可用于库存和生产的统一 Material 主数据。

1. 点击“新建物料”。
2. 填写编码、名称、规格、分类、库存单位和主要计量方式。
3. 按需要填写默认价格、安全库存和客户。
4. 保存后返回列表复核。

结果检查：新物料可被 BOM、订单、收发货等业务选择。

![新建物料](screenshots/v0.1.350/05-material-create.png)

### 进入 BOM 工作区

目的：查找物料并维护 BOM 版本。

1. 展开“物料”功能区，进入“BOM 设置”。
2. 搜索并选择目标产出物料。
3. 查看当前版本、状态、输入项和输出项。

结果检查：BOM 工作区显示目标物料和版本状态。

![进入 BOM 工作区](screenshots/v0.1.350/06-bom-workspace.png)

### 维护并发布 BOM

目的：定义整批投入、主产出和副产出。

1. 新建或打开草稿 BOM。
2. 填写基准产量、投入物料、数量和单位。
3. 维护主产出与副产出比例。
4. 校验无误后发布，生产只能引用已发布版本。

结果检查：发布版本显示“已发布”，投入单位与物料计量方式一致。

![维护并发布 BOM](screenshots/v0.1.350/07-bom-detail.png)

## 3. 生产订单与班后实绩

### 查看生产订单

目的：查看生产计划及统一状态。

1. 展开“生产”功能区，进入“生产订单”。
2. 按订单号、物料或状态搜索。
3. 关注草稿、已发布、生产中、已完成和已取消状态。

结果检查：列表显示计划数量、日期、BOM 和当前状态。

![查看生产订单](screenshots/v0.1.350/08-production-order-list.png)

### 新建生产订单

目的：建立物料化生产计划。

1. 点击“新建生产订单”。
2. 选择产出物料、已发布 BOM、计划数量和计划日期。
3. 填写班组或备注后保存。
4. 需要纸质单据时，保存后在生产订单清单点击“打印”。

结果检查：订单以“草稿”创建，此时不可登记实绩。

![新建生产订单](screenshots/v0.1.350/09-production-order-create.png)

### 发布生产订单

目的：将已复核计划转为可执行任务。

1. 打开草稿订单详情。
2. 核对物料、数量、日期和 BOM。
3. 点击“发布订单”并确认。

结果检查：状态由“草稿”变为“已发布”。

![发布生产订单](screenshots/v0.1.350/10-production-order-release.png)

### 确认订单可执行

目的：确认发布后实绩入口已经解锁。

1. 发布完成后重新查看订单详情。
2. 确认状态为“已发布”。
3. 确认“登记班后产量”按钮可用。

结果检查：发布状态与操作按钮保持一致。

![确认订单可执行](screenshots/v0.1.350/11-production-order-released.png)

### 登记班后生产实绩

目的：按人员、设备、作业文件、投入和产出记录可回放的班后实绩。

1. 点击“登记班后产量”。
2. 填写实际日期并从启用员工中选择一人或多人。
3. 从订单工作中心范围内选择本次实际使用的设备。
4. 选择适用于订单物料或通用的已生效作业文件；工作中心由派工或路线决定。
5. 按现场记录填写实际投入、主产出、副产出及库位。
6. 保存后先核对实绩草稿中的人员、设备和文件版本快照，再执行确认。

结果检查：实绩草稿保存成功；确认前必须同时具备设备和作业文件快照，或分别填写明确的例外原因。

![登记班后生产实绩](screenshots/v0.1.376/183-production-actual-context-entry.png)

### 核对生产实绩执行上下文快照

目的：确认班后实绩保存的是当时实际设备和作业文件版本，而不是可漂移的主数据引用。

1. 打开生产订单详情并找到目标班后实绩。
2. 在“实际设备”中核对设备编码、名称、型号、状态和所属工作中心快照。
3. 在“作业文件”中核对标题、版本、状态、类别和适用物料快照；实际工作中心在实绩字段中单独核对。
4. 主数据后续调整时，以实绩卡片保存的历史快照解释当时执行条件。

结果检查：实绩卡片独立显示人、机、法证据；来源设备或文件后续修改不会改写既有快照。

![核对生产实绩执行上下文快照](screenshots/v0.1.376/182-production-actual-context-snapshot.png)

### 登记无设备或无作业文件的例外

目的：在合法的无设备或无文件场景保留可审计原因，避免用空值伪装完整执行记录。

1. 在登记实绩时确认本次确实没有可选择的实际设备或适用作业文件。
2. 对应选择保持为空，并在其例外原因中填写 2 到 200 个字符的具体说明。
3. 继续核对人员、投入、产出和库位后保存草稿。
4. 确认前再次核对例外原因；确认后原因与上下文快照均不可修改或删除。

结果检查：每一类缺失上下文都有明确原因；手机端保持单列滚动和底部保存操作，不遮挡最后一项。

![登记无设备或无作业文件的例外](screenshots/v0.1.376/184-production-actual-context-mobile.png)

## 4. 生产产出批次与质检

### 查看产出批次与质量状态

目的：从生产实绩核对内部批次、检验单和当前库存状态。

1. 进入生产订单详情并展开已确认实绩。
2. 在每项产出下查看内部批次号和检验单号。
3. 区分待检、已放行和冻结状态。

结果检查：每项新产出具有唯一内部批次，待检任务只允许判定一次。

![查看产出批次与质量状态](screenshots/v0.1.354/66-production-quality-lots.png)

### 填写合格判定

目的：记录抽样结果并准备整批放行。

1. 在待检批次点击“合格放行”。
2. 录入抽检数量、合格数量和不合格数量。
3. 填写检验结论说明并核对批次号。

结果检查：合格数量与不合格数量之和等于抽检数量，整批合格时不合格数为 0。

![填写合格判定](screenshots/v0.1.354/67-quality-pass-form.png)

### 确认整批放行

目的：把检验合格的整批产出从待检转为可用。

1. 点击“确认整批放行”。
2. 等待保存成功并刷新订单详情。
3. 核对批次状态、判定人和抽样结果。

结果检查：批次显示“已放行”，待检库存减少、可用库存增加。

![确认整批放行](screenshots/v0.1.354/68-quality-pass-result.png)

### 填写不合格判定

目的：记录不合格样本和冻结原因。

1. 在另一待检批次点击“不合格冻结”。
2. 录入抽检、合格和不合格数量。
3. 在说明中写清不合格现象和冻结原因。

结果检查：抽样关系校验通过，说明可供后续处置人员理解。

![填写不合格判定](screenshots/v0.1.354/69-quality-fail-form.png)

### 确认整批冻结

目的：阻止不合格产出进入领料或发货可用量。

1. 点击“确认整批冻结”。
2. 等待保存成功并刷新订单详情。
3. 核对批次状态、判定人和抽样结果。

结果检查：批次显示“冻结”，待检库存减少、冻结库存增加。

![确认整批冻结](screenshots/v0.1.354/70-quality-fail-result.png)

### 核对库存状态

目的：在库存总账复核质量判定后的可用、待检和冻结数量。

1. 展开“库存”功能区，进入“库存管理”。
2. 搜索质检涉及的产出物料。
3. 核对总量、可用、待检、冻结及库位余额。

结果检查：总库存等于可用、待检和冻结之和，质量判定不改变总量或总成本。

![核对库存状态](screenshots/v0.1.354/71-inventory-status-review.png)

### 核对质量状态流水

目的：确认放行或冻结可以从统一库存流水回放。

1. 展开“库存”功能区，进入“库存流水”。
2. 搜索产出物料或质量来源。
3. 核对 QUALITY RELEASE / QUALITY HOLD、批次、状态方向、操作人和时间。

结果检查：状态转换流水数量变化为 0，但明确记录待检到可用或冻结的转换。

![核对质量状态流水](screenshots/v0.1.354/72-inventory-quality-movements.png)

## 5. 质量任务与不合格处置

### 启用来料检验标准

目的：只为需要来料质量控制的物料显式启用入库待检。

1. 展开“生产”功能区，进入“质量任务”，点击“检验标准”。
2. 新建或复制标准，选择物料和“来料入库待检”来源。
3. 配置抽样方式、最低/最高数量和逐项接收标准。
4. 完成质量审批后发布标准。

结果检查：已发布标准显示“来料入库”；只有该物料后续收货会自动转待检，未启用标准的物料保持直接可用。

![启用来料检验标准](screenshots/v0.1.373/164-incoming-quality-standard.png)

### 接收来料检验任务

目的：由质检岗位接收仓管收货后自动生成的来料检验任务。

1. 展开“生产”功能区，进入“质量任务”。
2. 在“待检任务”中按内部批号、物料或来料单搜索。
3. 核对来源显示“来料入库”、检验单号、标准快照和建议抽样数。
4. 展开检验项目快照，确认接收标准与来料检验计划一致。

结果检查：质检员可读取授权库位的任务；仓管员只能完成收货，不能代替质量判定。

![接收来料检验任务](screenshots/v0.1.373/167-incoming-quality-task.png)

### 逐项判定来料质量

目的：按生效标准和建议抽样数完成来料逐项检验。

1. 在来料待检任务点击“合格放行”“不合格冻结”或“部分判定”。
2. 进入全屏表单，核对抽检、合格和不合格样本数量。
3. 逐项选择结果，填写实测值、项目备注和检验结论。
4. 确认总判定与逐项结果一致后提交。

结果检查：系统拒绝低于标准建议抽样数、项目缺失或总判定矛盾的提交。

![逐项判定来料质量](screenshots/v0.1.373/168-incoming-quality-decision.png)

### 核对来料合格放行

目的：确认来料库存由待检转为可用并保留完整检验事实。

1. 切换质量任务“全部记录”。
2. 按来料内部批号搜索已完成检验。
3. 核对“已放行”数量、标准快照、抽样和判定人。
4. 在库存或批次谱系复核同批次可用余额。

结果检查：同一批次待检余额归零、可用余额增加，总数量和总成本不变。

![核对来料合格放行](screenshots/v0.1.373/169-incoming-quality-released.png)

### 查看来料质量趋势

目的：单独分析供应来料的批次和样本质量表现。

1. 点击“质量趋势”。
2. 选择日期范围，并把来源切换为“来料入库”。
3. 点击“刷新统计”。
4. 核对完成批次、批次合格率、样本合格率、不合格项目和物料排名。

结果检查：趋势只统计已完成来料检验，不把待检或已随红冲取消的任务计入分母。

![查看来料质量趋势](screenshots/v0.1.373/170-incoming-quality-trend.png)

### 查看检验标准版本

目的：按物料和任务来源查看草稿、已发布和已停用标准。

1. 展开“生产”功能区，进入“质量任务”。
2. 点击页内“检验标准”。

## 10. 文档与设备台账

### 查看受控文档

目的：按标题、正文、类别、产品和扩展字段查找受控文件。

1. 展开“文档”功能区，进入“产品文档”。
2. 使用智能搜索覆盖标题、正文、产品、类别、备注和当前类别扩展字段；需要精确组合时打开高级搜索，字段列表会随类别字段定义更新。
3. 表格视图在常规桌面固定保留可读的文档标题宽度，适用产品使用紧凑摘要；文档不显示工作中心列，宽表只在自身容器横向滚动。
4. 需要共同维护元数据时，在卡片或表格勾选同一类别的多篇文档，点击“批量修改”，逐项勾选要应用的基础或扩展字段后保存；不同类别不能混合提交。
5. 需要调整某类文件的字段时，点击“字段设置”并选择类别；基础字段不可删除。扩展字段点击“编辑”：未使用时可修改名称、类型和选项，已使用时只能改名；只有未被任何文档使用的扩展字段可以删除。
6. 点击“全屏预览”直接阅读在线正文或首个附件，并可继续切换其他附件；点击“详情”查看版本、适用范围并管理附件。进入编辑后，基础信息在预览上方按可用宽度排列，标签不得逐字换行。XLS/XLSX/ODS 使用自托管 LibreOffice 核心查看器直接打开。DWG/DXF 通过内部 CAD 服务排队生成只读 PDF；具备维护权限时可点击“重新生成预览”重建 PDF 与缩略图，原图保持不变。图纸异常时由管理员进入“系统设置 > 文件预览”，检查 LibreDWG、ACadSharp、QCAD 可用状态并切换自动或指定引擎后重新生成；QCAD 只有服务器已合法安装和配置时可用。缺字时把已授权字体放入转换器外挂目录并重启；服务会受控修正目录权限、立即降权，并在健康检查显示路径所有者和有效权限。随后重新生成旧预览；预览服务异常时下载原文件。

结果检查：文档标题和编辑字段保持可读宽度；同类别文档可只覆盖明确选择的共同字段，类别扩展字段可安全编辑并受使用保护；全屏预览与详情职责分离，CAD 派生预览按引擎隔离缓存、可由获权人员手动重建且不改原图。

![查看受控文档](screenshots/v0.1.350/33-document-list.png)

### 新建受控文档

目的：上传原文件、批量导入同类文件或创建在线作业正文。

1. 单篇建档点击“新建文档”；同类图纸批量建档点击“批量导入”，一次选择最多 50 个文件。
2. 关联物料、类别、版本、工作中心，并按所选类别填写扩展字段；可搜索选择器既可点击输入框输入筛选，也可点击右侧箭头展开或收起；普通新增也可填写在线正文。
3. 确认批量导入中的每个文件会独立创建一篇文档并保留原始附件，再提交。
4. 保存后在列表逐篇复核状态；CAD 缩略图会延迟加载并按受控并发排队转换，不要连续重复刷新。批量导入存在部分失败时按文件名处理失败项。

结果检查：单篇文档和批量导入的每篇文档均可独立检索、维护分类字段并保留原始附件。

![新建受控文档](screenshots/v0.1.350/34-document-create.png)

### 查看设备台账

目的：核对设备基础资料、当前状态和运行事件入口。

1. 展开“设备”功能区，进入“设备台账”。
2. 搜索设备编码、名称、型号或工作中心。
3. 核对设备当前状态、现场位置和事件数量。

结果检查：台账显示可用、使用中、故障、维护中或停机状态；状态不能在基础资料中直接改写。

![查看设备台账](screenshots/v0.1.369/35-equipment-list.png)

### 新建设备

目的：建立设备基础台账。

1. 点击“新建设备”。
2. 填写编码、名称、类型和工作中心。
3. 填写位置、厂商、型号、参数和备注；不要在基础资料中设置运行状态。
4. 保存后复核列表。

结果检查：设备以“可用”作为初始状态，可用于后续运行事件、派工和产能关联。

![新建设备](screenshots/v0.1.369/36-equipment-create.png)

### 上报设备故障

目的：把现场故障作为可审计事件登记并立即改变设备状态。

1. 进入设备台账，在目标设备点击“事件”。
2. 点击“报告故障”。
3. 填写现场可核对的故障原因和已采取的安全措施。
4. 确认设备编码、当前状态和原因后点击“确认记录事件”。

结果检查：设备转为“故障”，时间线保留原状态、原因、操作人和发生时间。

![上报设备故障](screenshots/v0.1.369/143-equipment-fault-command.png)

### 恢复设备并回放事件时间线

目的：恢复设备前完成试运行，并核对故障持续时间与完整状态链。

1. 在故障设备的事件弹窗点击“恢复可用”。
2. 填写维修结果、试运行结论和复核说明。
3. 确认记录后重新打开“事件”。
4. 核对恢复、故障、开机事件的状态链、人员、原因和故障持续时间。

结果检查：设备回到“可用”；故障事件记录从故障发生到恢复的持续时间，恢复事件不重复计算。

![恢复设备并回放事件时间线](screenshots/v0.1.369/144-equipment-event-timeline.png)

### 查看到期设备点检任务

目的：按到期、逾期和异常状态找到当前工作中心需要处理的点检任务。

1. 展开 MES 的“设备”菜单并进入“设备点检”。
2. 先查看到期、逾期和异常记录计数。
3. 使用“到期任务”筛选；智能搜索覆盖计划、设备、工作中心、检查项、记录和人员，需要精确组合时打开高级搜索。
4. 核对设备、周期、下次到期时间和完整检查清单。

结果检查：页面只显示当前账号工作中心范围内的点检计划，到期任务可直接执行。

![查看到期设备点检任务](screenshots/v0.1.370/145-equipment-inspection-due-tasks.png)

### 新建设备点检计划

目的：为一台设备建立不可直接改写的周期点检标准和完整项目清单。

1. 在设备点检页面点击“新建点检计划”。
2. 填写唯一计划编码、名称、周期和首次到期时间。
3. 搜索并选择当前工作中心范围内的设备。
4. 逐项添加项目名称、检查标准和可选单位，一次保存计划。

结果检查：新计划进入到期任务或全部计划；项目清单保存后只能暂停或恢复计划，不能覆盖历史标准。

![新建设备点检计划](screenshots/v0.1.370/146-equipment-inspection-create-plan.png)

### 逐项完成设备点检

目的：按计划快照完整提交实测值、结果、人员和整次说明。

1. 在到期任务卡片点击“执行点检”。
2. 核对实际点检时间和每一项标准。
3. 逐项选择正常或异常，并填写实测值；异常项必须填写异常说明。
4. 填写整次说明后点击“确认完成点检”。

结果检查：系统一次保存全部项目、点检人、到期周期与审计记录，并把下次到期时间推进一个周期。

![逐项完成设备点检](screenshots/v0.1.370/147-equipment-inspection-complete.png)

### 复核异常点检与现场附件

目的：从异常记录回看点检事实，并保留现场照片或报告。

1. 切换到“异常记录”筛选。
2. 核对异常记录号、点检时间、点检人和异常说明。
3. 确认原设备已进入故障状态，并在设备事件时间线中存在对应故障事件。
4. 按需要在该次记录下上传现场照片、测量报告或维修凭证。

结果检查：异常点检记录不可改写；设备原为可用或运行中时，同一事务生成故障事件，附件继承点检与工作中心权限。

![复核异常点检与现场附件](screenshots/v0.1.370/148-equipment-inspection-abnormal-history.png)

### 查看到期设备保养计划

目的：按到期和逾期状态找到当前工作中心需要生成工单的周期保养任务。

1. 展开 MES 的“设备”菜单并进入“设备维保”。
2. 查看到期保养、逾期、维修中和待处理计数。
3. 切换到“到期计划”；智能搜索覆盖计划、工单、设备、负责人、备件和记录，需要精确组合时打开高级搜索。
4. 核对计划周期、下次到期时间、完整项目清单以及是否已生成工单。

结果检查：页面只显示当前账号工作中心范围内的保养计划；同一计划和到期周期不会重复生成活动工单。

![查看到期设备保养计划](screenshots/v0.1.371/151-equipment-maintenance-due-plans.png)

### 新建设备保养计划

目的：为一台设备建立不可直接覆盖的周期保养标准和项目清单。

1. 在设备维保页面点击“新建保养计划”。
2. 填写唯一计划编码、名称、周期、首次到期时间和说明。
3. 搜索并选择当前工作中心范围内的设备。
4. 逐项添加项目名称和作业标准，一次保存计划。

结果检查：计划进入到期或全部计划；项目清单保存后只能暂停或恢复计划，不能覆盖历史工单标准。

![新建设备保养计划](screenshots/v0.1.371/152-equipment-maintenance-create-plan.png)

### 登记设备故障维修工单

目的：把真实故障现象登记为可执行、可追溯的纠正性维修工单。

1. 在设备维保页面点击“新建维修工单”。
2. 搜索并选择发生故障的设备。
3. 填写维修主题、优先级、要求完成时间、负责人和客观故障现象。
4. 核对信息后点击“创建维修工单”。

结果检查：系统创建待处理维修工单；原为可用或运行中的设备同时进入故障状态并保留故障事件。

![登记设备故障维修工单](screenshots/v0.1.371/153-equipment-maintenance-create-repair.png)

### 开始设备维修或保养工单

目的：明确现场作业开始时点，并阻止设备在维修期间被视为可生产。

1. 切换到“待办工单”并核对工单、设备、负责人和故障现象或保养来源。
2. 在待处理工单点击“开始维修”。
3. 确认工单状态由“待处理”变为“维修中”。
4. 到设备台账核对同一设备状态已经同步变为“维修中”。

结果检查：工单记录开始人和开始时间，设备事件链增加进入维修状态的事件。

![开始设备维修或保养工单](screenshots/v0.1.371/154-equipment-maintenance-start-work-order.png)

### 完成维修并领用备件

目的：一次提交真实作业结果和备件领用，让设备、库存、成本与批次保持原子一致。

1. 在维修中工单点击“完成并领料”。
2. 计划保养工单须逐项确认全部清单达标；故障维修填写故障原因。
3. 按“搜索—选择物料—选择库位—填写数量—添加”录入全部备件。
4. 填写维修或保养内容、完成时间并点击“确认完成并过账”。

结果检查：工单完成、设备恢复可用；备件按可用批次扣减库存并形成库存流水、成本金额和批次分配。

![完成维修并领用备件](screenshots/v0.1.371/155-equipment-maintenance-complete-with-spare.png)

### 复核维保历史与备件批次

目的：从完成事实回看工单、作业结果、设备恢复、备件成本和实际消耗批次。

1. 在设备维保页面切换到“完成记录”。
2. 核对工单号、设备、负责人、故障现象和实际作业结果。
3. 在“备件领用”中核对物料、数量、库位和实际批次。
4. 按需要上传维修照片、校准报告或外协凭证，并到库存流水反查同一业务来源。

结果检查：完成工单、设备恢复事件、备件库存流水、成本和批次分配可相互追溯，完成事实不可覆盖。

![复核维保历史与备件批次](screenshots/v0.1.371/156-equipment-maintenance-completed-history.png)

### 执行应用级恢复演练

目的：在不改写在线生产和源候选的前提下，先收敛恢复候选的 Schema 漂移，再证明它能启动隔离应用并通过关键业务抽查。

1. 准备已验证的恢复候选数据库和附件目录，固定目标 Git 提交，并确认所有输出路径不存在。
2. 执行 npm run audit:production-schema-drift，核对源证据哈希未变、目标迁移基线正确，并保存不可覆盖的 JSON 报告。
3. 如审计返回漂移，先审批历史数据处置，再执行 npm run prepare:production-schema-reconciliation，生成退役结构归档和非覆盖收敛候选。
4. 只有候选后置审计为 NO_SCHEMA_DRIFT时，才执行 npm run storage:drill:application，填写数据库、附件、目标、报告、环境、备份创建时间和操作人。
5. 等待全附件哈希、迁移、readiness、临时管理员登录、物料/库存/生产单和附件原文件抽查完成。
6. 核对 Schema 和应用报告：所有技术检查为 PASS、RPO/RTO 分别判定，临时管理员已清理，且源候选 SHA-256 全程未变。

结果检查：Schema 收敛候选的后置审计为零漂移，隔离应用检查全部通过，且在线生产和源候选未被改写。备份超过 24 小时时 RPO 必须判定失败；异地副本与真实 Coolify 挂载切换仍单独验收。

### 预检 Product 到 Material 映射

目的：在进入生产维护窗口前，只读验证人工映射签字、引用一致性、库存风险和数据漂移。

1. 在停止写入的生产恢复候选上先执行 audit 和 plan，并将映射文件交给熟悉业务数据的负责人逐行核对。
2. 为每个 Product 填写 materialId、materialCode、库存处置和非空 decision.note，最后填写真实确认人及确认时间。
3. 执行 product-material-migration.mjs preflight，并把输出写入不存在的新报告文件。
4. 只有报告为 PASS、readyForApply=true 且 databaseSha256Before 与 databaseSha256After 相同时，才允许安排备份和维护窗口 apply。
5. 若报告为 FAILED，按错误修正；如提示签字后数据变化，废弃旧映射并重新生成，禁止绕过预检。

结果检查：未签字、缺少核对依据、引用冲突、非零库存或签字后漂移都会在写数据前被拒绝并留档；预检本身不创建备份、不回填数据库。

## 暂不作为现行 SOP 的治理项

- 生产、退货和显式启用标准的来料质量闭环与岗位动作权限已贯通；正式上线前仍须按企业审批制度配置岗位权限、数据范围并使用真实不合格评审单验收。
- 供应商、来料待检、生产投入产出、发货和退货回流已形成可搜索全景；未发布来料检验标准的物料仍直接入可用库存，跨工厂或供应商系统集成不在本阶段。
- 岗位任务、生产命令、来料收货/拒收与红冲命令、本人/工作中心生产范围与库位库存范围已经分层；已有安装须按岗位审批显式授予新来料命令，部门/班组范围尚未独立建模。
- 设备开机、停机、故障和恢复已形成事件时间线，周期点检、保养、维修工单、备件批次成本和现场附件已贯通；真实产量采集与 OEE 口径仍待企业确认。
- 生产实绩已冻结实际设备和作业文件版本；没有设备或文件时必须分别保存例外原因。文件快照只保存正文和附件元数据清单，法规级原件固化仍需内容哈希与保留策略。
- 精确库存冲销已建立原流水与冲销流水双向关系并校验数量、核算量和成本守恒；部分退货等一对多回流只表示一般来源关系，不能据此认定原流水已整笔冲销。
- 每条库存余额必须且只能归属 Material 或待迁移的旧 Product；无归属和双归属写入由数据库拒绝，旧 Product-only 库存仍须按人工确认计划迁移。
- DOCX、PDF、离线 Web 与视频成品保存在本地 output 目录，不进入 Git 或 Docker 发布树；PDF/DOCX 和自托管视频可发布到同一个只读对象存储地址，视频通过 sop/videos.json 关联现有 SOP 章节与流程。
- 最终 PDF/DOCX 登记到站内产品文档库时必须先做零写入预检和一致备份，再由启用的文控账号显式执行；版本、路径、大小或 SHA-256 不一致时不得生效。
- 旧 Product 与 Material 仍需分阶段迁移，禁止继续扩展旧模型写入口。
