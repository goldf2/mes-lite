# 设备维保与备件领用操作与回滚

适用版本：`v0.1.371`

## 1. 操作入口与权限

- 页面：MES → 设备 → 设备维保。
- 查看：`equipmentMaintenance.read`。
- 新建计划或维修工单：`equipmentMaintenance.create`。
- 暂停/恢复计划、开始、完成或取消工单：`equipmentMaintenance.update`。
- 现场附件：还需对应 `attachments` 动作权限。
- 非管理员同时受工作中心数据范围限制；备件物料只显示授权库位中存在可用库存的候选。

## 2. 周期保养计划

1. 点击“新建保养计划”。
2. 填写唯一计划编码、名称、周期、首次到期时间和说明。
3. 搜索并选择当前工作中心范围内的设备。
4. 逐项添加保养项目名称和可核对的作业标准，一次保存。
5. 到期后点击“生成保养工单”；同一计划和同一到期时点只允许一张活动工单。

计划和项目保存后不能原地覆盖。标准变化时新建新编码计划，确认新计划后暂停旧计划。只有对应周期工单完成，系统才推进下一次到期时间。

## 3. 故障维修与开始作业

1. 点击“新建维修工单”，选择故障设备。
2. 填写维修主题、优先级、要求完成时间、负责人和客观故障现象。
3. 创建后核对设备故障事件；设备原为可用或运行中时会同步进入故障状态。
4. 现场具备维修条件后点击“开始维修”。
5. 核对工单为“维修中”、设备为 `MAINTENANCE`，并确认开始人和开始时间。

不要把尚未开始的工单提前切为维修中，也不要绕过工单直接把设备恢复可用。

## 4. 完成工单与备件领用

1. 在维修中工单点击“完成并领料”。
2. 计划保养须逐项确认全部项目达标；故障维修须填写可复核的故障原因。
3. 备件按“搜索—选择物料—选择库位—填写数量—添加”形成已选列表，可添加多项后一次提交。
4. 填写实际维修/保养内容和完成时间，确认试运行合格后提交。
5. 核对工单已完成、设备恢复可用、备件数量/库位/批次和成本金额完整。

完成命令同时提交工单、设备恢复事件、保养结果、计划下次到期、库存流水、成本和批次分配；任何一步失败均不得形成部分事实。库存不足、库位越权或保养项目不完整会拒绝提交。

## 5. 完成记录与附件

- 在“完成记录”核对工单号、设备、故障现象、作业结果、备件数量、库位和实际批次。
- 到库存流水按工单业务来源反查数量与金额，到设备台账事件时间线核对故障—维修—恢复链。
- 维修照片、校准报告或外协凭证上传到对应工单；附件继承维保资源和工作中心范围。
- 完成事实不可修改或删除。误录不能直接覆盖，应保留审计记录，并由授权人员通过新业务事实解释或冲销库存影响。

## 6. 部署与回滚

### 部署前

1. 固定 `v0.1.371` 精确提交，暂停未审批的自动部署。
2. 对 SQLite 数据库和附件目录执行一致备份并完成校验。
3. 执行第 79 个迁移，确认六张维保表、索引和触发器存在。
4. 用设备维护员账号验证：工作中心隔离、到期计划、计划/维修工单、开始、完整保养结果、备件批次领用和附件。
5. 用仓库受限账号复核未授权库位不会出现在备件候选中。

### 应用回滚

1. 暂停新的保养、维修、设备事件和库存写入并记录回滚时点。
2. 将 Coolify 固定到上一个已验证提交并重新部署。
3. 保留新增表、设备事件、库存流水和批次分配，不删除表、不反向改写完成工单；旧版本会忽略维保表。
4. 验证登录、设备台账、库存余额、库存流水、批次追溯、质量和生产闭环。
5. 修复后重新部署 `v0.1.371` 或更高版本，核对计划、工单、设备事件、备件流水与批次分配仍连续。

### 数据恢复

只有数据库损坏或迁移失败且应用回滚无法恢复服务时，才从部署前一致备份恢复数据库与附件目录。恢复会丢失备份后的所有业务写入，必须由业务负责人确认恢复点、记录 RPO/RTO，并重新核对设备和库存实物。
