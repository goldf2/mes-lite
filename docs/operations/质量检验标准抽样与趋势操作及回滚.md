# MES-lite 质量检验标准、抽样与趋势操作及回滚

适用版本：`v0.1.373`

## 1. 上线前准备

1. 固定本版本精确 Git 提交，确认 Coolify 自动部署保持关闭。
2. 对 SQLite 数据库与附件目录创建同一时点一致备份，完成清单和 SHA-256 校验。
3. 确认质量工程师拥有 `qualityStandards:RCU`、质检员拥有 `qualityStandards:R`、`quality:RU`、`qualityDecision:U` 和所需附件权限；按真实岗位审批收窄库位范围。
4. 准备至少一个未归档物料，并确定生产入库、来料入库或退货入库的检验项目、方法、接收标准和抽样规则。来料标准发布后会改变该物料的新收货库存状态，必须先完成仓库与质量岗位确认。

## 2. 建立与发布标准

1. 进入“生产 → 质量任务 → 检验标准”，点击“新建检验标准”。
2. 填写唯一标准编码、名称、适用物料和任务来源。
3. 选择全检、固定数量或按比例抽样；需要时填写最低和最高抽样数。
4. 逐项添加项目名称、检验方法和接收标准，填写建立原因并保存草稿。
5. 草稿复核完成后点击“发布”。同一物料同一来源的旧发布版本会自动停用。
6. 标准变更时从原版本“复制新版本”，修改草稿并重新发布；不得覆盖已发布版本。

## 3. 执行标准化检验

1. 确认生产实绩、接收客户退货，或接收存在已发布来料标准的物料后，进入“质量任务”搜索新待检批次。
2. 核对标准编码/版本、标准名称、建议抽样数和任务建立时的检验项目快照。
3. 打开质量判定，填写实际抽样数、合格数、不合格数和结论说明。
4. 对每个项目选择合格或不合格，并按现场要求填写实测值和备注。
5. 提交后复核检验结论、批次库存状态、库存流水和处置入口；逐项结果与整单结论必须一致。
6. 现场原始记录、图片或报告通过任务上的“质量附件”上传；附件读写继续受公共附件权限和库位数据范围保护。

## 4. 查看质量趋势

1. 进入“质量任务 → 质量趋势”。
2. 选择起止日期，可按物料或任务来源筛选。
3. 分别核对已完成检验数、检验批次通过率、样本通过率、按日/物料汇总和失败项目排行。
4. 趋势只统计已完成且当前账号有权读取的质量任务；显示“结果已截断”时必须缩短日期范围后再用于分析。
5. 当前趋势不替代 SPC、过程能力分析或企业正式质量报表签署。

## 5. 部署验收

1. 应用启动执行到第 81 个迁移，确认三张标准/项目表、标准/任务快照字段、`MATERIAL_IN` 来源、索引与触发器存在。
2. 质量工程师创建草稿、复制和发布新版本；质检员能读取标准但创建请求返回 403。
3. 新建生产、来料与退货待检任务，确认使用当时生效标准；无来料标准的收货保持直接可用，发布新版后旧任务仍保留旧版快照。
4. 提交逐项判定，确认漏项或项目结果与整单结论不一致会被拒绝。
5. 复核质量附件、库位范围、趋势筛选、库存状态、批次交易和审计日志。

## 6. 应用回滚

1. 暂停新的标准、检验、处置和相关库存写入。
2. 在 Coolify 固定到上一个已验证提交并重新部署，不点击会拉取最新主分支的普通 Redeploy。
3. 保留 `QualityInspectionStandard`、`QualityInspectionStandardItem`、`QualityInspectionCheckItem` 及质量任务快照字段，不手工删表或回写历史标准。
4. 验证旧版登录、质量任务读取、原有判定/处置、批次库存和附件仍可用；旧应用忽略新增标准功能。

## 7. 数据恢复

只有迁移失败或数据库损坏且应用回滚不能恢复服务时，才执行部署前一致备份恢复：先生成非覆盖恢复候选，校验数据库与附件清单，再切换持久挂载。恢复后必须重验登录、标准版本、待检任务、逐项结果、库存/成本/批次守恒和附件原文件；不得在未确认业务写入损失前覆盖当前生产数据。
