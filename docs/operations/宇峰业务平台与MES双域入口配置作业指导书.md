# 宇峰业务平台与 MES 双域入口配置作业指导书

适用版本：v0.1.493。编制日期：2026-10-19。

当前状态：方案和本地隔离验证已完成；正式域名、部署、Casdoor 回调和普通账号现场验收尚待记录，不能据此认定已经上线。文末验收表由执行人员在取得实际证据后更新。

本指导书只说明两个入口的配置、日常使用、验收和回退，不重复整本业务操作手册。原业务流程继续参考[全流程作业指导书](user-guide/MES-lite全流程作业指导书-v0.1.490.md)，其中旧平台入口说明由本专项替代；技术依据为[平台结构](../architecture/business-workbench.md)、[认证设计](../architecture/casdoor-login.md)及[Coolify 部署说明](../deployment/coolify.md)。

## 1. 配置后的两个入口

| 地址 | 用途 | 应看到的内容 |
| --- | --- | --- |
| `https://work.csyufeng.com/` | 宇峰业务平台 | MES Lite、客户管理两个应用入口，全局功能搜索和个人收藏 |
| `https://mes.csyufeng.com/` | 原 MES Lite | 原首页、岗位任务、经营统计和完整本地分类菜单 |

两个域绑定同一个现有 Web 部署，不复制容器、数据库或业务记录。平台域根路径由服务端精确改写到内部 `/platform`，浏览器仍可使用平台域根地址；MES 域根路径保持原首页。旧 `/workbench` 是兼容入口，会导向配置的平台地址。

MES Lite 实际包含生产、销售、物料、库存、收发和本厂设备，范围超过狭义生产 MES。客户管理连接独立数据平台的客户、联系人、地点、地图和客户设备服务。两个代码库和业务数据库继续独立；本次没有启用联系人共享或 MES 订单上图。

## 2. 三个地址配置分别负责什么

在现有 Web 资源的**服务端 Runtime 环境变量**中设置以下公开地址。它们不是密码，也不是客户端密钥。

```env
APP_ORIGIN=https://mes.csyufeng.com
PLATFORM_ORIGIN=https://work.csyufeng.com
APP_AUTH_CALLBACK_ORIGINS=https://work.csyufeng.com
```

| 变量 | 职责 | 本次操作 |
| --- | --- | --- |
| `APP_ORIGIN` | 原 MES 的 canonical 地址和原认证基础地址 | 保持原 MES 域，不能为了平台入口把它改成 work 域 |
| `PLATFORM_ORIGIN` | 平台公开导航地址、返回平台地址及平台根路径识别 | 设置为 work 域；只设置这一项不会开放新的认证回调 |
| `APP_AUTH_CALLBACK_ORIGINS` | 允许使用既有客户端完成登录的额外精确 origin | 新增 work 域；canonical MES 域仍由 `APP_ORIGIN` 保留 |

额外 origin 多个时用英文逗号分隔。填写协议、域名和必要端口，不填写路径、查询条件、片段或账号密码；生产只接受 HTTPS。不使用 `*.csyufeng.com` 等通配符。

保留现有登录模式、身份服务地址、客户端信息、现有密钥及人员绑定，不在本指导书或验收截图中记录其值。不创建新组织、客户端、账号或管理员，也不修改既有业务权限。

## 3. 配置前记录

1. 在 Con01 控制台确认目标是**当前提供 MES 的 Web 资源**，不是新建应用、CAD 服务或 AL03 身份服务。
2. 记录当前资源名称、公开域名列表、运行版本及精确提交；保留原域名列表，后续只能追加所需入口。
3. 记录三个公开地址变量的变更前值、当前已有回调地址，以及原部署的回退版本。凭据只保留在既有安全存储中，不复制进本记录。
4. 核对数据库、上传、备份三个现有持久挂载以及一致备份结果。不得新建空数据库替代原目录。
5. 选定一个**已有且有原业务权限的普通账号**用于只读验收；不通过管理员恢复登录或临时加权让测试通过。

## 4. DNS、HTTPS、回调与发布顺序

### 4.1 先通过候选 CI

1. 将本地验证后的精确提交推送至 `ci/0.1.493`。
2. 等待该 SHA 的完整 `MES-lite CI` 成功，记录 run ID、SHA 和结果。
3. CI 未成功时停止发布，修复后重新核对精确提交；不能人工 Redeploy 绕过门禁。

### 4.2 为同一 Web 资源准备新增域

1. 在 DNS 控制台新增 `work.csyufeng.com`，指向从现有部署核对的 Con01 实际入口；不要把代理服务显示的边缘 IP 当作源站地址。
2. 不修改、删除 MES 原 DNS 记录。
3. 在现有 Coolify Web 资源的域名配置中追加 `https://work.csyufeng.com`，保留原 MES 域及其他已有有效域名；不创建第二份业务应用。
4. 核对新增域的 DNS 生效、HTTPS 证书及反向代理路由。代理传递实际 HTTPS 协议和 Host，并覆盖客户端自带的转发头。
5. 发布前新域暂时能打开旧界面不代表完成；必须等候选版本生效后按第 6 节逐项核验。

### 4.3 在原 Casdoor 客户端追加精确回调

1. 使用现有管理入口打开**MES 当前正在使用的客户端**，按现有应用归属和客户端标识确认对象。
2. 找到 OIDC/OAuth 的重定向地址列表，保留所有现有有效地址，尤其保留原 MES 回调。
3. 确认同时存在以下两个完整地址并保存：

```text
https://mes.csyufeng.com/api/auth/casdoor/callback
https://work.csyufeng.com/api/auth/casdoor/callback
```

4. 重新读取已保存列表，逐字核对协议、域名与路径。不能只填 origin，不能使用通配回调，不能把 work 地址覆盖到原 MES 地址上。
5. 保留现有客户端密钥及身份配置，不重新生成密钥，不创建另一套账号或人员绑定。

#### 4.3.1 旧 yufeng-web 与现有 MES 客户端的命名迁移（待核实）

用户已选择沿用**现有 MES Lite 客户端**作为宇峰统一平台客户端，目标名称为 `yufeng`。截图中的旧 `admin/yufeng-web`（组织 `yufeng`）不是本次应继续配置的统一客户端；但“以后不使用”不等于可以在依赖核对前直接删除。

本节是迁移计划，尚未登记实际保存结果。最终内部名称、显示名称及生效配置必须由执行人员核对后填写，不把目标名称当作已经完成的事实。

1. 先核对现有 MES 和数据平台运行配置引用的客户端 ID、应用内部名称、组织及登录路径，确认截图旧对象还有哪些实际依赖。只记录对象关系与核验结果，不复制客户端密钥到文档、日志或截图。
2. 若数据平台仍使用旧 `yufeng-web`，保留该对象及其有效回调，不能直接删除、禁用或覆盖为 MES 客户端。任何后续迁移都先验证目标登录与原业务权限，不能让数据平台因本次命名整理失去登录。
3. 在原 MES Lite 客户端上执行命名调整，目标为 `yufeng`；保留原客户端 ID、现有密钥、`oaktechz-saas` 组织和原账号到 MES 人员的映射。不得为实现名称统一新建账号、移动人员组织、合并业务库或授予额外权限。
4. 区分“显示名称”和 Casdoor 应用“内部名称”：仅改显示名称不应被记录为内部名称已变更。若内部名称需要变动，核对 `CASDOOR_APPLICATION`、依赖应用内部名称的登录 URL、默认应用引用及既有回调引用；同步实际需要的运行配置后再验收，不能只检查页面标题。
5. 在该既有 MES 客户端保留原 MES 回调，并确认平台域的精确回调与第 4.3 节一致；仍禁止通配符。旧客户端的业务依赖未迁移前，不移除其原有效回调。
6. `CASDOOR_APPLICATION` 属于原身份配置代际检查字段。如果内部名称变动要求修改该变量，应检查旧会话和在途挑战按既有代际规则失效，并由普通账号重新正常登录；不能套用“仅新增回调别名不旋转代际”的结论。回改旧名称也不能使已失效旧会话复活。
7. 保存后读取实际对象与 Runtime 配置，分别验收 MES 域、平台域以及仍依赖旧对象的数据平台。记录最终名称和依赖状态后，才能另行处理已无依赖的旧对象；当前先不删除旧客户端。

### 4.4 保存 Runtime 配置并发布已验证提交

1. 在同一 Web 资源保存第 2 节三个变量，其他认证、业务、持久化和服务配置保持原值。
2. 复核 `APP_ORIGIN` 仍为 MES 域，平台入口与额外认证 origin 均为 work 域。入口配置与回调允许清单必须分别核对。
3. 在完整候选 CI 成功后，将**同一 SHA**正常推进 main，由现有自动部署执行；不要同时启动重复构建。
4. 等待该部署终态，再核对实际运行版本、提交、健康状态、原挂载和启动前备份。若 main 同时触发 CAD 发布，也应完成其原发布核验。
5. 两域分别请求公开 health/ready，并确认返回页面来自同一目标版本。容器健康只说明运行基础，不能代替下面的真实登录与功能验收。

## 5. 日常使用与登录边界

1. 需要总览时打开 `work.csyufeng.com`，选择 MES Lite 或客户管理；也可以直接搜索“发货”“销售订单”“联系人”。
2. 选择 MES Lite 或本地业务搜索结果后，浏览器完整进入 `mes.csyufeng.com` 的原首页或精确功能页。物料功能需保留对应 section，不应都落到物料首页。
3. 客户管理先在平台显示该应用的授权入口；打开具体数据平台功能后，仍由数据平台独立登录与校验权限。
4. 原 MES 用户仍可直接访问原 MES 地址，不必每次先经过平台。需要其他应用时，从顶部应用切换器返回 work 平台入口。
5. 收藏仍跟随当前人员，失去权限的旧收藏不显示；不因为菜单可见就认为已经获得目标应用权限。

两个域分别使用 host-only Cookie，各自通过正常登录建立会话。已在 MES 登录，不意味着浏览器自动拥有 work 域会话；现有 Casdoor 会话可能减少再次输入，但须以实际流程验证，不能转发另一域的 Cookie 或 Token。

“退出登录”只结束当前域的本站会话。退出 work 后，原 MES 可能仍保持有效会话；退出 MES 也不能声称 work、数据平台和 Casdoor 已一起退出。不配置跨子域 Cookie，不把局部退出描述成全局注销。

## 6. 普通账号现场验收

配置完成后使用既有普通账号执行；以读取、搜索和已有页面打开为主，不创建测试生产单、修改客户或执行真实发货。

| 检查 | 操作 | 通过标准 |
| --- | --- | --- |
| 原 MES 保留 | 打开 MES 根地址、dashboard 和已有业务书签 | 原首页、统计和本地完整菜单可用，原业务路径未被平台覆盖 |
| 平台总览 | 打开 work 根地址 | 按权限展示实际应用入口（有权账号看到两项）、搜索和收藏，无 MES 长侧栏及重复默认快捷目录 |
| MES 跳转 | 选择 MES 卡片；另搜索发货、销售订单和 BOM | 进入 MES 域对应真实页，业务参数/section 保留，原权限继续生效 |
| 返回平台 | 从 MES 顶部应用切换器返回 | 进入 work 域根入口，不绕回 MES 首页 |
| 客户入口 | 进入客户管理并打开已授权目标 | 授权范围内可见客户/联系人/地点/地图和客户设备服务，精确目的地不丢失 |
| 两域登录 | 分别从两域正常登录入口经 Casdoor 回调 | 各自回到原目的地并建立当前域会话，身份仍绑定原 MES 人员，未增加业务权限 |
| 权限边界 | 使用原受限账号查看目录、搜索、旧收藏和私有接口 | 未授权目标隐藏或被原服务端拒绝，不因平台卡片获得管理员或额外数据 |
| work 退出 | 在 work 退出，再刷新其私有业务接口 | 当前域旧会话被拒绝；另行检查 MES，不能把仍有效的另一域会话误报为全局退出成功 |
| MES 退出 | 在 MES 退出，再刷新其私有业务接口 | 当前域旧会话被拒绝；保持局部退出的准确说明 |
| 菜单和遮挡 | 桌面展开/收起、调宽、常驻/临时侧栏；390px 手机操作 | 可见侧栏不盖正文，收起恢复空间；手机无桌面留白，标题和搜索可读，主体/箭头操作仍有效 |
| 运行证据 | 核对两域 health/ready、版本、SHA、持久挂载和备份 | 与获准候选提交一致，原业务存储连续，没有空库替换或重复实例 |

回调登记错误、未允许 origin、挑战失效等应显示明确失败，不能改成密码模式、放宽允许清单、修改数据权限或清空生产库来使验收通过。

## 7. 未来更换平台域名

1. 保留 `APP_ORIGIN` 为原 MES 域；仅更换平台域名不需要移动业务数据库或修改 MES 身份归属。
2. 为新平台域准备 DNS、同一 Web 资源路由与 HTTPS。
3. 在原 Casdoor 客户端先追加新平台域的精确回调；在 `APP_AUTH_CALLBACK_ORIGINS` 中临时保留旧、新两个平台 origin，不能用通配符替代。
4. 将 `PLATFORM_ORIGIN` 改成新平台 origin，按配置发布流程生效。服务器传入的新入口决定卡片、返回平台和兼容入口的目的地。
5. 旧平台地址仍需提供明确的公开入口重定向；单一 `PLATFORM_ORIGIN` 的修改不会自动将旧域根路径继续识别为平台。认证回调和私有 API 不应跨域重定向，已有挑战必须在其原 origin 完成。
6. 使用普通账号验收新入口、精确回调、MES 跳转和局部退出；确认旧入口引用已处理后，再按计划移除旧额外回调、允许项和不再需要的路由。
7. 记录旧、新 origin、切换时间、回调清单及验收结果。改 `APP_ORIGIN` 属于 MES canonical 更换，还涉及原登录、打印与历史外链，需另作完整迁移评估，不能照搬仅平台改域步骤。

## 8. 回退步骤

1. 记录失败现象、当前精确版本及发生阶段，保留原 MES 域服务；不要反复启动构建或调整人员权限试错。
2. 恢复第 3 节记录的变更前 `PLATFORM_ORIGIN` 与额外回调允许项；`APP_ORIGIN` 保持原 MES canonical。若原变量为空，恢复为空，不编造替代地址。
3. 在原客户端移除本次新增且不再使用的平台精确回调，保留原 MES 回调及其他原有有效回调。
4. 如需代码回退，部署上一个已有验证证据的精确提交，保持原三条持久挂载；本轮没有数据库迁移，不恢复或清空生产数据库。
5. 核对原 MES 正常登录、原业务读取、原权限、health/ready 和版本。确认平台入口不再依赖新域后，再处理新增域路由/DNS，避免先删 DNS 导致无法完成检查。
6. 移除别名会阻断其在途登录，但不自动注销已经建立的所有会话；需要撤销会话时使用现有明确的会话管理流程，不擅自重置密码或扩大管理员权限。
7. 若命名迁移造成登录故障，恢复已记录的原应用内部名称、显示名称及对应 `CASDOOR_APPLICATION`/登录路径引用，保留客户端 ID、密钥、组织、身份映射和原回调。按代际规则重新登录，不尝试复活旧 Cookie；旧 `yufeng-web` 在依赖未清理前继续保留。
