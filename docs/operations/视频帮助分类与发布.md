# MES-lite 视频帮助分类与发布

事实基线：`v0.1.389`。

## 分类原则

视频不按 MP4、哔哩哔哩或 YouTube 分类，因为这些只是播放来源。视频沿用 `sop/manifest.json` 的业务章节和流程体系：

1. `chapterId`：唯一主章节，用于完整帮助中心归档。
2. `workflowIds`：关联一个或多个现有 SOP 流程，用于说明视频具体覆盖哪些任务。
3. `pageKey`：不重复填写，由关联流程自动推导；顶部问号只返回当前页面相关视频。
4. `resource`：沿用权限资源；没有读取权限的账号看不到视频。
5. `provider`：只表示 `file`、`bilibili` 或 `youtube` 播放来源。

推荐按任务粒度制作，而不是为每个按钮单独录制：系统入门、端到端业务流程、单页关键操作、管理配置、异常处理。一个视频只设一个主章节，但可以关联多个流程和页面。

## 与在线帮助的结合方式

- 完整帮助中心：视频出现在对应 SOP 章节内，并与流程共用搜索、权限和版本信息。
- 当前页面快捷帮助：系统根据关联流程的 `pageKey` 自动筛选视频，可在抽屉内直接播放。
- 独立页面：快捷帮助的两个入口仍可新开当前页帮助或完整帮助中心。
- 文件视频：使用浏览器原生播放器；只有配置合法的 `SOP_PUBLIC_BASE_URL` 时才显示。
- 平台视频：哔哩哔哩和 YouTube 播放器在用户点击后才加载，同时保留新页面打开原视频的入口。

视频目录由 `sop/videos.json` 管理。示例：

```json
{
  "id": "main-interface-tour-v0.1.388",
  "title": "MES-lite 主界面快速导览",
  "description": "介绍首页入口、统一导航和帮助中心。",
  "provider": "file",
  "version": "0.1.388",
  "chapterId": "01",
  "workflowIds": ["139-sop-help-center", "140-context-help-drawer", "02-dashboard"],
  "sortOrder": 10,
  "resource": "dashboard",
  "objectPath": "v0.1.388/videos/MES-lite主界面导览-v0.1.388-全同步版.mp4"
}
```

`chapterId` 或 `workflowIds` 引用不存在时，服务端不会发布该视频，验证命令也会失败。

## 文件与发布约定

文件名建议使用 `<系统>-<任务>-v<内容版本>.mp4`。同一个只读 OSS 地址同时保存离线文档和自托管视频：

```text
https://downloads.example.com/mes-lite/sop/
├── v0.1.389/
│   ├── MES-lite全流程作业指导书-v0.1.389.pdf
│   └── MES-lite全流程作业指导书-v0.1.389.docx
└── v0.1.388/videos/
    └── MES-lite主界面导览-v0.1.388-全同步版.mp4
```

对象存储应返回正确的 `Content-Type`，支持字节范围请求，且不要强制使用附件下载响应。生产环境的公开基地址必须是 HTTPS，不能包含账号、密钥或查询签名。

哔哩哔哩和 YouTube 条目不需要上传 OSS，分别登记 BV 号或 YouTube 视频 ID。平台视频可用性受访问网络和平台策略影响，关键岗位教程优先保留自托管 MP4。

## 更新流程

1. 确认受影响的现有章节、流程、页面和权限资源。
2. 生成并验收 MP4；自托管文件上传到版本化 OSS 路径。
3. 更新 `sop/videos.json`，不要把视频二进制放进 Git 或 Docker 发布树。
4. 更新受影响 SOP 流程及 `sop/change-impact.json`。
5. 执行 `npm run verify:sop-media`、`npm run verify:sop`、类型检查和生产构建。
6. 部署时在 Coolify 配置唯一公开基地址 `SOP_PUBLIC_BASE_URL`。

代码更新不会自动生成视频内容，但目录关系、在线入口和版本记录会随 Git 发布同步；视频二进制通过对象存储独立发布，避免扩大仓库和镜像。
