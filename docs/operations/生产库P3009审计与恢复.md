## 1. 已确认事实

- 2026-08-13 的 Coolify 部署成功拉取并构建提交 `be7e18f`，镜像构建不是失败点。
- 新容器启动时，Prisma 报 `P3009`：迁移 `20260812223000_add_material_projections_for_product_exit` 存在未完成且未回滚的失败记录。

## 2. 错误分级

| 现象 | 级别 | 处理 |
| --- | --- | --- |
| Prisma `P3009` | 致命 | 容器在 `server.js` 前退出，必须修复迁移状态与物理结构 |
| orphan 旧容器、回滚后公网 404 | 致命 | 旧容器没有重新承接路由；恢复后必须从公网验证三条 URL |

| Coolify 提示健康检查需 curl/wget | 中 | 本项目 Dockerfile 使用 Node `fetch` 自定义 HEALTHCHECK；警告不是本次根因，但需核验 Coolify 与 Docker 两层配置 |

## 5. 通用三类恢复路径

任何路径都必须先生成数据库与附件的一致性备份，并验证 SHA-256。不得直接删除 `_prisma_migrations` 记录。

### A. 结构完全未执行

条件：目标失败记录有效，六列和六索引均不存在，且没有其他活动失败迁移。

处理顺序：

1. `prisma migrate resolve --rolled-back 20260812223000_add_material_projections_for_product_exit`
2. `prisma migrate deploy`
3. Prisma 重新执行完整迁移。

### B. 结构部分执行

条件：六列或六索引只存在一部分。

处理顺序：

1. 根据报告逐项核对已有结构的类型、可空性、唯一性和列顺序；
2. 在一个受控事务内只补缺失结构；
3. 再次审计，结构必须与迁移 SQL 完全一致；
4. `prisma migrate resolve --applied 20260812223000_add_material_projections_for_product_exit`
5. `prisma migrate deploy`。

不得对部分执行状态直接使用 `--rolled-back` 后重跑，因为已经存在的列或索引会导致重复对象错误。

### C. 结构已全部完成，只有状态失败

条件：六列和六索引全部与迁移 SQL 一致，迁移校验和一致，且没有其他活动失败迁移。

处理顺序：

1. `prisma migrate resolve --applied 20260812223000_add_material_projections_for_product_exit`
2. `prisma migrate deploy`。

不得在结构不完整、校验和不一致或另有失败迁移时采用该路径。

## 9. 回滚边界

- Git/镜像回退不会自动回滚 SQLite 迁移状态。
- 只能使用修复前绑定的备份做数据回滚；先非覆盖 `stage-restore` 到候选目录，验证后再切换持久卷。
- Coolify 官方回滚依赖服务器本地仍存在的旧镜像；本次旧容器已成为 orphan 且公网无路由，不能假定 UI 回滚一定可用。
- 若候选库启动验收失败，立即停止应用，不在候选库上继续手工修改；将候选库移出持久卷，按相同属主和权限恢复第 7 节保存的原数据库及其配套 journal/WAL/SHM，然后重新审计。
