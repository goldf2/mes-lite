# 装箱、发货退货与批次追溯操作

适用版本：`v0.1.499` 实施候选（2026-10-21）。本地验证、精确提交 CI 与生产部署分别记录在正式版本说明；本文不是上线证明。

## 1. 业务关系

```text
已放行的真实内部批次
  → 可直接作为散货发货
  → 也可先建立装箱记录、贴箱签，再在发货单选择货箱
  → 同一发货单允许货箱 + 散货
  → 显式确认发货：扣实际批次、库位、库存和成本
  → 客户发货单显示具体产品与实际数量，箱号辅助追溯
  → 从原发货明细登记退货
  → 收货生成独立待检批次
  → 质量判定及受控处置
```

容器无状态：纸箱、金属网箱、塑料盒只是包装类型；装箱编号属于本次货物内容。原来的散货方式继续可用，不要求先装箱。

## 2. 仓库装箱与标签

1. 进入“库存 → 装箱记录”，新建装箱。
2. 选择真实可用批次及实际库位，核对产品、规格、批次和未装箱可用数量；首期每箱一种产品、一个批次。
3. 输入实装数量、包装类型、包装日期/人员和可选尺寸。生产及质检人员默认从真实来源记录带出，允许人工补录；人工姓名不是检验合格证明。
4. 保存后生成唯一 `BX-*` 装箱号，库存总量和成本不增加；系统为这箱建立唯一的正式库位位置。未测量的三维坐标保留未知。
5. 核对本箱产品和数量后打印货箱标签，选择与标签纸匹配的介质尺寸。标签来自本箱，不取整张发货单的第一项产品。
6. 补打使用原装箱号及内容版本。发起浏览器打印请求不表示打印机已经出纸，贴标前应核对实物、标签和数量。
7. 内容错误或重新装货时，有原因作废未占用/未发货的装箱记录，处理旧标签后重新装箱。已选入待发货单的箱先取消对应发货；已发货箱不能直接作废。保留过货箱分配或旧货箱的发货历史不能永久删除；无箱、无过账的归档散货草稿仍按原维护规则处理。

装箱记录 R/U 沿用 `stocks` 读取/修改权限和库位范围；标签打印另要求 `scanPrint.create`。看得到库存不等于能装箱、作废或打印。

## 3. 创建和确认发货

1. 进入“物流 → 发货管理”，独立选择客户。发货不保存销售订单或订单明细引用，也不占用/回写订单状态；客户物料需求、待发/已发及超发只作参考。
2. 按实际情况添加散货、选择已有货箱，或两者混合。搜索/扫描箱签带出产品、数量、批次和库位；箱内数量只读，不在发货录入中另改。
3. 核对具体产品与总量：例如两个各 200 件的箱加散货 50 件，产品行显示 450 件；箱号不能替代产品内容。不能重复添加同箱，已占用/已发/已作废/越权/旧内容版本的箱会被拒绝。
4. 保存待发货单。选中箱被该单占用，防止另一张待发货单再次选择；此时不扣库存。客户取消时按权限填写原因取消，货箱占用释放，库存保持。归档仍占用仓库箱的待发单时，系统同步取消并释放；以后恢复只恢复历史记录，不能再次确认出库，需要重新新建选箱发货单。
5. 实际出货前点击“确认发货”。服务端重新核对状态、库位、产品归属、箱内容版本和真实批次可用状态；选箱部分按箱内实际批次与成本出库，散货部分按未装箱可用来源处理。
6. 散货保留原有受控欠库功能；已实物装箱的部分不允许用其他批次替代或形成虚拟欠库。后补可用入库只按现有欠库规则补批次和成本，未补齐前不能登记客户退货。
7. 详情核对“客户发货批次”中的内部批号、数量、成本和谱系。`TRACKED` 有实际批次来源，`SHORTAGE` 尚有欠库，`LEGACY` 仅为历史兼容，不能当成真实生产来源证据。
8. 确认发货后选择客户连续纸或 A4 发货单；两版均显示产品、规格及实际数量，保留箱摘要。内部留档另外提供库位和批次追溯，不以客户单替代内部审计。

确认发货、签收、取消、冲销分别沿用 `shipmentDispatch`、`shipmentDeliver`、`shipmentCancel`、`shipmentReverse` 独立动作权限。创建发货可选择范围内可发箱，不授予库存维护权。

## 4. 签收和错误过账冲销

确认签收只更新履约责任与时间，不重复扣库存。已发货但尚未签收、没有退货依赖时，授权仓库主管可填写原因冲销，恢复原库存、库位、实际批次及成本；仓库独立箱释放发货关联并回到可用装箱状态，历史发货现场箱仍保留原冲销状态。原单、原流水及箱身份不删除，追加反向流水和追溯关系。

已签收或有退货依赖的单据不能直接冲销，真实回流必须走客户退货。不得把改单据状态当作库存冲销。

## 5. 客户退货和质量

1. 新建退货时选择原发货单及具体发货产品行，输入不超过剩余可退量的数量、退回库位和原因。
2. 核对实物后按权限确认接收，生成独立 `RT-*` 退货批次并连接原发货来源。新增量先进入 `QUARANTINE`，总库存增加但可用量不增加。
3. 质量人员按现有检验任务记录客观结果，由对应判定/处置/授权放行权限执行；质量状态转换保留批次、库存、成本与审计，不能用库位名称或标签人员文字代替。
4. 退货不自动恢复原整箱身份。箱内实物已经变化，需要重新核实、装箱和贴标。

## 6. 追溯和数据保护

- 从装箱详情查询真实批次、当前库位和本箱内容；从发货批次查看生产/来料来源、客户去向及退货回流。
- 一个真实追溯发货单的有效批次分配与明细数量一致；有效装箱分配加未装箱散货构成同一库存事实，不能重复求和或扣减。
- 已装箱的物料不能被普通散货、生产领料或整库位移库绕过包装分配消耗；先核实拆包/作废或使用受控货物移动能力。
- 参与装箱/发货/退货追溯的来源记录不能随意删除，标签、分配与历史证据保留。
- 二维仓库全景仍是视图；本期没有三维编辑、布局发布或拖动搬货过账。

## 7. 验证、迁移与回退

本地使用临时 SQLite 与合成业务运行装箱/混合发货、批次、成本、冲销、欠库、领料/移库和权限回归，不连接生产数据库。关键案例为两批不同成本产品：选择后批货箱必须消耗后批，散货不得误扣箱内数量，冲销恢复原成本和批次。

部署前遵守数据库及附件一致备份和恢复检查。新模型采用加性迁移，保留历史箱号、发货引用和照片，不为旧箱补造批次或坐标。新装箱/分配写入后，不可运行不能识别包装分配的旧库存写入代码；故障时停止相关写入、保留证据并前滚修复，不能靠删表回退。

具体命令、候选 CI、迁移、真实打印及生产验收结果在本版正式说明中记录。物理打印和真实仓库测量结果不能由自动回归代替。
