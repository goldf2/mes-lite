# 发货退货批次追溯与质检操作

适用版本：`v0.1.356`

## 1. 当前闭环

```text
已放行成品内部批次
  → 确认发货时按库位 FIFO 分配
  → 客户 / 发货单 / 实际批次数量
  → 从原发货单登记客户退货
  → 确认收货生成独立退货待检批次
  → 连接原发货批次
  → 整批合格放行或不合格冻结
```

## 2. 发货操作

1. 进入“销售 → 发货管理”，独立选择客户与物料，或关联已确认销售订单明细。
2. 选择发货库位并创建待发货单；创建只占用订单可发量，不扣库存。
3. 点击“发货”。服务端复检可用库存，并按该库位开放 `AVAILABLE` 批次的接收时间 FIFO 自动分配。
4. 打开发货详情，在“客户发货批次”核对内部批号、发出数量、已退数量、库位和追溯状态。
5. `TRACKED` 表示本次确认时保存了真实内部批次；`LEGACY` 表示迁移前历史发货兼容记录，不能作为真实炉批或生产来源证据。

## 3. 客户退货收货

1. 进入“销售 → 退货管理”，点击“新建退货单”。
2. 先选择原发货单。列表只显示已发货/已签收且仍有剩余可退数量的单据，物料自动带出。
3. 输入不超过剩余可退量的数量、退回库位和原因，保存退货单。
4. 对实物核对无误后点击“处理”。系统把状态改为“已收货”，并在所选库位建立独立 `RT-<退货单号>` 待检批次。
5. 此时总库存增加，但可用库存不增加；新增数量全部进入 `QUARANTINE`，普通发货、领料和库存调整不可消费。

## 4. 退货质量判定

1. 打开已收货退货详情，在“退货待检批次”核对批号、待检数量和检验单。
2. 具有 `quality.update` 权限的人员录入抽检、合格、不合格数量和结论。
3. “确认整批放行”把整批从 `QUARANTINE` 转 `AVAILABLE`；“确认整批冻结”转 `HOLD`。
4. 判定不改变总数量、核算量或总成本，只改变状态，并写批次交易、库存流水和审计操作人。

## 5. 正反向追溯

- 从发货详情的内部批次点击“查看谱系”，可向上查看来料/生产来源，并在“客户履约追溯”查看该批次发给哪些客户、哪些退货批次已回流。
- 从退货待检批次点击“查看谱系”，可查看原发货单、客户和原发货内部批次，再沿生产谱系回到原料和供应商批号。
- 当前是相邻节点导航，不是跨全部批次的搜索全景；批次可继续点击切换。

## 6. 数据与删除保护

- 一个真实追溯发货单的有效批次分配合计必须等于发货数量。
- 一个已收货退货单的有效来源分配合计必须等于退货数量，且必须拥有唯一独立退货批次。
- 原发货分配累计退回量不能超过发出量；新建和处理时服务端均复检。
- 参与发货或退货谱系的发货单、退货单和来源批次不得永久删除；维护工具会显示批次引用阻止原因。

## 7. 部署与回滚

1. 生产部署前创建数据库与附件一致备份并验证恢复候选。
2. 应用迁移 `20260813203000_add_shipment_return_lot_trace`，再运行 `npm run verify:shipment-return-lots` 和库存/销售完整性验证。
3. 上线后用受控测试发货和退货核对批次、库存状态、成本、流水、审计和追溯。
4. 尚无新写入时可回退应用并保留加性表列；一旦写入发货/退货分配，不得删除新表或运行不能识别这些关系的旧应用，只能停止相关写入并前滚修复。
5. 本地临时库验证不等于真实 Coolify 已部署；服务器迁移、持久卷备份和真实业务验收仍需维护窗口执行。

## 8. 当前停止线

- 不支持人工指定发货批次、逐件序列号、部分放行、复检、让步、返工、报废和解冻。
- 迁移前历史发货无法恢复未保存的真实内部批次，只能明确标记兼容来源。
