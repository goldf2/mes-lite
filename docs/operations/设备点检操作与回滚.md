# 设备点检操作与回滚

适用版本：`v0.1.370`

## 1. 操作入口与权限

- 页面：MES → 设备 → 设备点检。
- 查看：`equipmentInspections.read`。
- 新建计划：`equipmentInspections.create`。
- 执行、暂停和恢复：`equipmentInspections.update`。
- 现场附件：还需对应 `attachments` 动作权限。
- 非管理员同时受工作中心数据范围限制；任务、设备候选、执行和附件必须属于授权工作中心。

## 2. 建立点检计划

1. 点击“新建点检计划”。
2. 填写唯一计划编码、计划名称、周期和首次到期时间。
3. 搜索并选择当前数据范围内的设备。
4. 逐项添加名称、检查标准和可选单位，一次保存。
5. 在“全部计划”核对设备、周期、到期时间和项目顺序。

计划主体和项目保存后不能原地修改或删除。标准需要变化时，新建新编码计划，确认新计划后暂停旧计划，避免覆盖历史口径。

## 3. 执行到期点检

1. 在“到期任务”选择计划并点击“执行点检”。
2. 核对实际点检时间；系统禁止尚未到期的计划提前重置周期。
3. 逐项填写实测值并选择正常/异常。异常项必须说明具体现象，不使用“有问题”等不可核对描述。
4. 填写整次说明，确认所有项目完整后提交。
5. 核对最近记录号、点检人、结果和下次到期时间。

一次提交具有幂等标识。网络重试不会重复创建记录、重复推进周期或重复上报故障。

## 4. 异常与附件

- 任一项目异常时，整次结果为“异常”。
- 设备原为可用或运行中时，系统在同一事务创建故障事件并把设备切为故障；到设备台账的事件时间线核对来源状态、原因、人员和时间。
- 设备已经停机、维护或故障时，只保存本次异常事实，不强行生成不合法事件。
- 在最近记录中上传现场照片、测量报告或维修凭证；附件访问继承点检资源和工作中心范围。
- 点检事实不可修改。误录不能直接删除，应在现场记录、操作日志和后续维修/复检证据中解释，并由授权人员建立下一次可信记录。

## 5. 暂停与恢复

- 长期停用、待迁移或计划被新标准替代时，暂停旧计划。
- 恢复已过期计划时，系统把下次到期时间重置到恢复时刻，避免恢复后积累多个虚假历史周期。
- 暂停/恢复均写审计记录，不修改既有点检事实。

## 6. 部署与回滚

### 部署前

1. 固定 `v0.1.370` 精确提交，关闭未审批的自动部署。
2. 对 SQLite 数据库和附件目录执行一致备份并完成校验。
3. 执行第 78 个迁移，确认四张点检表、索引和触发器存在。
4. 用设备维护员账号验证：授权工作中心可见，未授权工作中心不可见；可建计划、执行正常/异常点检并上传附件。

### 应用回滚

1. 暂停点检写入并记录回滚时间。
2. 将 Coolify 固定到上一个已验证提交并重新部署。
3. 保留新增表和数据，不执行删除表或回写设备状态的降级脚本；旧版本会忽略这些表。
4. 验证登录、设备台账、运行事件和原业务闭环。
5. 修复后重新部署 `v0.1.370` 或更高版本，核对原计划、记录、故障关联和下次到期时间仍连续。

### 数据恢复

只有数据库损坏或迁移失败且应用回滚无法恢复服务时，才从部署前一致备份恢复数据库与附件目录。恢复会丢失备份后的所有业务写入，必须由业务负责人确认恢复点并记录 RPO/RTO。
