# 来料到生产批次谱系操作与回滚

适用版本：`v0.1.355`

## 1. 当前闭环

```text
供应商批号
  → 来料单明细
  → 收货生成内部原料批次
  → 流程转移同步批次库位余额
  → 生产实绩按库位先进先出分配投入批次
  → 产出内部批次
  → 父子谱系
  → 待检 / 放行 / 冻结
```

本页记录 v0.1.355 的来料到生产基线。`v0.1.356` 已继续把产出批次连接到客户发货和退货回流，可从客户发货单反查生产与原料；操作见[发货退货批次追溯与质检操作](./发货退货批次追溯与质检操作.md)。

## 2. 仓管收货

1. 进入 `MES → 物流 → 来料管理`。
2. 新建来料单，每行填写物料、数量、库位和供应商批号/炉批号。
3. 保存后由有 `materialIn.update` 权限的人员执行“整单收货”。
4. 在来料详情中核对：供应批号、内部批次 `RM-<来料行号>`、可用数量和来源来料单。
5. 点击“查看谱系”。刚收货的原料批次没有上游，未投入生产时也没有下游。

## 3. 批次配送

1. 在 `MES → 生产 → 流程转移` 新建配送单。
2. 选择原料来源库位、生产目标库位、数量和操作员工。
3. 确认后，总库存和总成本不变，批次余额按先进先出同步移到目标库位。
4. 冲销会按相同批次和数量移回原库位。

## 4. 生产确认和追溯

1. 在已发布生产订单详情登记班后实绩，投入行选择真实来源库位。
2. 点击“确认并生成批次谱系”。系统先核对可用库存，再按批次先进先出分配投入。
3. 在已确认实绩的“投入物料”中核对每个内部批次、供应批号和分配数量。
4. 在“产出物料”点击“查看谱系”：中间是当前产出批次，左侧是上游投入批次，右侧是下游产出批次。
5. 点击任一相邻批次可继续沿谱系导航。

## 5. 红冲和冲销

- 来料内部批次尚未使用且余额仍等于原收货数量时，允许来料整单红冲；系统同时冲销库存、成本层、批次余额和批次交易。
- 来料批次已用于生产或发生其他余额变化时，拒绝整单红冲，避免破坏谱系。
- 生产实绩冲销先撤销未被后续使用的产出批次，再恢复总库存、成本层和每个投入父批次余额；投入分配和谱系边保留但标记为已冲销。
- 已放行产出若已进入后续业务，仍按现有保护拒绝直接冲销。

## 6. 历史库存

历史升级前的库存没有真实供应商批次。首次进入流程转移或生产领用时，系统建立 `LEGACY-...` 兼容批次并明确显示“历史未追踪库存”。该批次只用于保持数量闭环，不能作为真实炉号、供应商或收货单证据。

## 7. 部署与回滚

1. 部署前备份 SQLite 数据库和附件目录，并执行备份校验。
2. 应用迁移 `20260813150000_add_receipt_lots_and_production_genealogy`。
3. 在临时副本运行 `npm run verify:inventory-lot-genealogy`、`npm run verify:data-integrity` 和库存/生产/来料专项验证。
4. 上线后用一张测试来料单和一张测试生产实绩验证批次正反查。
5. 尚无新写入时可回退应用并保留空表；已有谱系写入后只允许业务冲销或向前修复，不删除新表。

## 8. 当前停止线

- `v0.1.356` 已自动分配发货批次并保留原发货退货批次；本页自身停止在生产产出节点。
- 不支持部分放行、批次拆分合并、让步、返工、报废和解冻。
- 本地验证不代表真实 Coolify 已部署；真实服务器仍需单独执行备份、迁移、健康检查和恢复演练。
