# 设备运行事件操作与回滚

适用版本：`v0.1.369`

## 1. 能力边界

本切片只管理设备的基础运行状态：开机、停机、故障、恢复和归档。事件保留来源/目标状态、原因、补充说明、可信操作人和发生时间；恢复会把持续时间写回最近一条未结束的故障、停机或维护事件。

点检、保养、维修工单、备件、设备协议、自动产量采集和 OEE 尚未实现，不得把当前时间线当作完整设备管理系统。

## 2. 状态命令

| 当前状态 | 允许命令 | 目标状态 |
| --- | --- | --- |
| `AVAILABLE` 可用 | 开始运行、停机、报告故障 | `IN_USE`、`STOPPED`、`FAULT` |
| `IN_USE` 使用中 | 停机、报告故障 | `STOPPED`、`FAULT` |
| `STOPPED` 停机 | 恢复可用 | `AVAILABLE` |
| `FAULT` 故障 | 恢复可用 | `AVAILABLE` |
| `MAINTENANCE` 维护中（历史兼容） | 恢复可用 | `AVAILABLE` |

基础资料新增/编辑严格拒绝 `status`；新设备固定从可用开始。非法状态转换返回 HTTP 409，前端按钮隐藏不是安全边界。

## 3. 现场操作

1. 进入“设备 → 设备台账”，核对设备编码和当前状态。
2. 点击目标设备的“事件”。设备只读岗位可以查看时间线。
3. 具有 `equipmentEvents.update` 的设备维护员选择开机、停机、报告故障或恢复可用。
4. 填写现场可核对的原因；故障时补充挂牌、断电、通知等安全措施，恢复时补充维修和试运行结论。
5. 提交后重新打开时间线，核对状态链、原因、操作人和时间。恢复故障/停机后，持续时间只显示在被关闭事件上。

## 4. 权限与审计

- 列表和时间线：`equipment.read`。
- 新建/编辑/归档设备资料：`equipment.create/update/delete`。
- 开机、停机、故障和恢复：`equipmentEvents.update`。
- 新安装设备维护组：`equipment:RCUA + equipmentEvents:RU`。
- 升级安装首次补齐新资源时从原 `equipment` 复制五项设置，部署后必须按岗位复核并收窄。
- 每个事件命令写 `AuditLog` 前后快照与原因；归档同时写 `ARCHIVE` 事件。

## 5. 数据迁移与部署

迁移 `20260815090000_add_equipment_events` 只新增 `EquipmentEvent` 表和索引，不改写既有设备状态。维护窗口流程：

1. 固定批准提交并停止生产写入。
2. 生成 SQLite 与附件一致备份，记录 SHA-256。
3. 在生产副本执行 `prisma migrate deploy`，确认迁移清单由 76 增至 77。
4. 启动应用，验证 readiness、登录、设备读取、只读账号命令 403、设备维护账号故障/恢复和时间线。
5. 完成真实岗位签字后再恢复写入。

## 6. 回滚

代码可以回退到 `v0.1.368`，新增表保留不影响旧代码；不要删除已写入的事件表或从迁移历史移除本迁移。若部署后出现故障：

1. 停止写入，记录失败提交、容器日志和数据库 SHA-256。
2. 优先回退应用代码到批准的 `v0.1.368`，保留 `EquipmentEvent` 表待后续重启用。
3. 只有数据库本身损坏或迁移执行异常时，才从部署前一致备份生成非覆盖恢复候选并切换挂载。
4. 不得用手工 `UPDATE Equipment.status` 纠正业务状态；恢复新版本后应通过受控事件或经审计的数据维护方案修正。
