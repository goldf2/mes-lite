# 生产实绩执行上下文操作与回滚

适用版本：v0.1.376

## 1. 操作目标

班后实绩除人员、投入和产出外，还要回答“实际使用了哪台设备、按哪份作业文件执行”。系统保存当时设备与文件版本快照，来源主数据后续变化不回写历史。合法无设备或无适用文件时，必须分别填写明确例外原因。

## 2. 上线前准备

1. 暂停生产实绩写入并完成数据库、附件目录一致备份。
2. 在隔离恢复副本执行全部 82 个迁移，确认新增两张快照表、两个例外原因字段、索引和保护触发器存在。
3. 核对订单默认路线或派工已关联正确工作中心；核对现场设备归属、状态和归档状态。
4. 核对作业文件已经生效，并关联订单主产出物料或适用工作中心。
5. 由生产、工艺和质量负责人确认哪些场景允许填写例外原因，禁止用“无”“临时”等无法审计的模糊文字。

## 3. 现场登记

1. 打开已发布生产订单，点击“登记班后产量”。
2. 填写实际日期并选择一名或多名启用员工。
3. 在“实际设备”搜索并加入本次设备；候选只显示订单工作中心内可用或运行中的设备。
4. 在“作业文件”搜索并加入本次实际执行版本；候选只显示已生效且适用于订单物料或工作中心的文档。
5. 若某一类确实为空，在对应例外原因填写 2 到 200 个字符的具体说明。
6. 填写实际投入、来源库位、实际产出和去向库位，保存草稿。
7. 在实绩卡片核对员工、设备编码/名称/型号/工作中心、文件标题/版本/类别、投入与产出，然后再确认。

## 4. 验收检查

- 不属于订单工作中心、已故障/停机、已归档设备不进入候选。
- 草稿、停用、已归档或与订单物料/工作中心无关的文件不进入候选。
- 同一设备或文件不能重复加入；伪造 ID 由服务端拒绝。
- 两类上下文都不得静默为空；没有快照时必须有对应原因。
- 修改来源设备名称、工作中心或文件正文/版本后，旧实绩卡片保持原快照。
- 已确认或已冲销实绩的设备快照、文件快照与例外原因不能更新或删除。
- 确认、质量批次、投入 FIFO 分配、库存成本和冲销回归仍通过。

## 5. 部署顺序

1. 固定 v0.1.376 的精确 Git 提交，关闭自动部署。
2. 完成备份并在隔离候选验证迁移与应用启动。
3. 在维护窗口部署应用并执行第 82 个迁移。
4. 使用一张试点订单完成“登记草稿 - 修改来源主数据 - 核对快照不漂移 - 确认 - 冲销”验收。
5. 由生产和工艺负责人签署设备/文件候选及例外原因规则，再恢复全量写入。

## 6. 回滚

本迁移为加性结构，旧应用会忽略新增表和字段。需要回滚时：

1. 立即暂停生产实绩写入并重新完成数据库/附件一致备份。
2. 将应用固定到上一个已验证提交；不执行数据库降级。
3. 保留新增快照表、例外原因和触发器，不删除已经产生的历史事实。
4. 若回滚期间旧应用产生新实绩，重新升级前必须先停止写入并审计这些记录；不得用虚构设备或文件补历史。

## 7. 已知边界

文件快照包含正文和附件元数据清单，不复制附件二进制。当前附件原件依赖持久目录、备份和恢复策略；需要法规级原件固化时，应另行增加内容哈希和受控保留。自动采集、设备节拍、停机原因与 OEE 不属于本版本。
