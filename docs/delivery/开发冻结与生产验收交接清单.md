# MES-lite 开发冻结与生产验收交接清单

状态：`v0.1.401` 已将标准生产构建迁移到 GitHub Actions 候选分支并再次冻结；生产与商业验收继续转交人工跟进

适用范围：当前单厂、单实例 SQLite、人工/扫码为主的 MES-lite 商业交付基线。本文只收敛已经批准的阶段 0–4 目标，不把 OEE、SPC、完整 MRP/ERP 等未来功能加入当前完成条件。

## 1. 完成结论如何判定

“本地开发完成”“生产上线完成”和“全局治理完成”是三个不同状态：

| 状态 | 判定条件 | 当前结论 |
| --- | --- | --- |
| 仓库开发任务 | 当前版本、锁文件、发布记录、文档和 SOP 一致；CI、类型检查、Lint、构建及领域回归通过 | `v0.1.401` 以候选分支远端构建替代本机完整构建后再次冻结；不重新纳入人工生产验收项 |
| 生产基础运行 | 最新版本部署、三个持久挂载、live/ready、迁移和一致备份均留下证据 | `v0.1.396` 已通过基础运行核验 |
| 商业验收 | Schema/映射、真实岗位、关键闭环、回切、OSS 和异地灾备均有签字证据 | 未完成，转交人工跟进 |

只有“仓库开发冻结候选”可以由代码和自动检查证明。涉及生产数据、真实账号、对象存储、维护窗口和企业签字的项目，不得由本地测试代替。

人工责任、优先级和登记表见[开发结束与人工跟进事项清单](./开发结束与人工跟进事项清单.md)。本文保留门禁及操作顺序，供后续人工执行；这些项目不再作为当前开发任务待办。

## 2. 人工跟进门禁

治理计划中的历史切片保留原始待办以便追溯；实际交接只按以下七个门禁推进，避免把同一个生产验收问题重复计算多次。

| 门禁 | 当前状态 | 负责人 | 必须形成的证据 | 失败时停止线 |
| --- | --- | --- | --- | --- |
| G0 仓库冻结 | 技术通过；最终交接版本待远端 CI | 开发/运维 | 精确版本和提交、绿色 CI、发布记录、`verify:release-tree`、生产构建日志 | 任一检查失败不得部署 |
| G1 最新生产一致备份 | 技术通过，待运维签字 | 运维负责人 | 数据库+附件归档、SHA-256、`quick_check=ok`、附件一致性、创建时间和 RPO | 备份过期、不可取回或校验失败立即停止 |
| G2 Schema 与 Product→Material 收敛 | 待生产只读审计和业务签字 | 数据负责人、生产负责人 | 零漂移审计或批准的非覆盖候选、人工签字映射、PASS 的 `preflight`、数据库前后哈希一致；若应用则保存迁移结果和回滚包 | 不允许猜测映射，不允许直接覆盖运行库 |
| G3 真实岗位与权限 | 待企业审批 | 企业负责人、权限管理员及各业务负责人 | 岗位权限表、数据范围、临时授权、正常用例与 HTTP 403 反例、签字日期 | 管理员代测不能替代最小权限验收 |
| G4 Coolify 部署与回切 | 部署与基础运行通过；业务抽查和回切待人工 | 运维负责人 | 三个真实挂载、目标提交、部署日志、live/ready、登录、关键业务抽查、旧挂载回滚点和回切记录 | readiness 或关键闭环失败即停止写入并回切 |
| G5 OSS 文档与视频发布 | 待 Bucket、域名、凭据和人工视频审核 | 文控、运维 | `sop:release` 成品清单、下载回读大小/SHA-256、HTTPS 播放、文控账号预检/登记审计、7 个视频终版确认 | 未上传对象不得写入 `sop/videos.json` |
| G6 异地灾备与历史安全清理 | 待外部存储及独立维护安排 | 运维、仓库管理员 | 异地上传与取回恢复证据；旧 SQLite Git 历史清理通知、受控历史重写记录、账号/密钥轮换记录 | 不与普通代码发布混合，不在无协作者通知时强推历史 |

## 3. 生产维护窗口执行顺序

以下顺序是依赖关系，不可任意互换：

1. 锁定目标版本和精确提交，确认远端 CI 绿色；维护窗口期间暂停自动合入。
2. 使用运行容器实际挂载创建最新一致备份并立即验证，复制到异地后再取回校验。
3. 在最新生产副本上执行 Schema 只读审计；需要收敛时只生成非覆盖候选并做应用级恢复演练。
4. 导出 Product→Material 计划，由业务负责人逐项签字；运行只读 `preflight`，未 PASS 不进入回填。
5. 审批并配置真实岗位权限，用真实岗位账号验证正常路径、数据范围和越权 403。
6. 在 Coolify 核对 `/app/data`、`/app/public/uploads`、`/app/backups` 三个真实挂载和回滚目录，再部署目标提交。
7. 验证 `/api/health/live`、`/api/health/ready`、登录，以及来料→质量、生产→产出、发货→退货、设备故障→恢复的代表性闭环。
8. 生成最终 DOCX/PDF/离线 Web，上传并回读 OSS；人工确认视频终版后再登记在线帮助和站内文档库。
9. 汇总本页证据，完成《单厂 MES 商业交付验收基线》签字；开发任务已经结束，但只有所有 G0–G6 通过后才能由人工把商业验收标记为完成。

## 6. 当前范围之外

以下能力需要新的业务口径、接口或合同范围，不阻挡当前轻量 MES 基线冻结，也不能表述为已经交付：

- 实时开工/暂停、自动产量、停机原因、节拍、能源、MTBF/MTTR 和 OEE。
- SPC、过程能力、实验室仪器采集、缺陷/原因主数据和多级质量评审。
- 逐件序列号、专业 WMS 波次/立库、完整 MRP/APS、财务和多租户 SaaS。

如果企业决定加入上述能力，应单独确认范围、验收口径和优先级，不能在本交接清单中默认扩张。
