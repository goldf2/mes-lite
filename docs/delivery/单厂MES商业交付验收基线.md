# MES-lite 单厂商业交付验收基线

状态：`v0.1.381` 可执行基线

适用范围：单工厂、单应用实例、SQLite 持久数据库、文件附件持久目录。MRP-lite 与 ERP-lite 是生产履约辅助能力，不等同于完整 APS、财务或采购系统。

## 1. 交付范围

### 1.1 本次可验收

- 物料、版本化 BOM、工艺、工作中心、设备和受控作业文档。
- 生产订单、派工、带人员/实际设备/作业文件版本快照的班后实绩、来料、库位、库存和业务流水。
- 来料内部批次、生产投入/产出谱系、待检/可用/冻结/返工库存、质量判定与不合格处置。
- 销售订单、客户发货批次、退货回流与退货质检。
- 61 项细粒度权限、岗位任务、生产命令、来料收货/红冲与发货/退货/流程转移命令、设备运行/点检/维保任务、本人/工作中心和库位数据范围、个人临时授权。
- 设备开机、停机、故障、恢复事件时间线，以及周期点检、保养/维修工单、设备恢复和备件库存/成本/批次领用。
- 生产、退货和按已发布标准启用的来料检验：标准版本、收货隔离、自动任务、抽样建议、任务项目快照、逐项判定、质量附件、描述性趋势和安全红冲联动。
- 归档记录按归档入口、原业务资源和人员数据范围三重校验，恢复和永久删除继续保留审计。
- SQLite 与附件一致备份、迁移前备份、非覆盖恢复候选、隔离应用恢复演练、健康检查和审计记录。
- 按精确 Git 提交的全迁移基线审计生产物理 Schema；对退役结构先归档和批准处置，再生成非覆盖收敛候选并强制后置零漂移。
- Product→Material 映射只读审计、人工确认和维护窗口前预检；未签字或预检失败不允许执行回填。
- 134 个写处理器审计覆盖清单和 CI 守卫；15 个高风险命令将业务结果与审计写入同一事务。
- `StockLog` 统一库存事务账本；精确冲销双向关联且数量、核算量、成本守恒，库存调整只使用服务器会话身份。

### 1.2 不在本次承诺

- 多工厂、多租户、多实例高可用。
- APS 高级排程、完整 MRP、财务总账、应收应付、税务和完整采购。
- 逐件序列号、设备协议全覆盖、自动产量/停机采集、节拍和 OEE 完整闭环。
- 在未配置独立存储前承诺异地容灾；本机隔离应用 RTO 不等于真实 Coolify 挂载切换 RTO。

## 2. 交付物清单

| 类别 | 必须交付 |
| --- | --- |
| 软件 | 精确 Git 提交、版本号、Dockerfile、迁移目录和依赖锁文件 |
| 配置 | 环境变量清单、域名、健康检查、三个持久挂载、固定提交和自动部署策略 |
| 数据 | 初始化/迁移报告、数据范围审批表、备份归档 SHA-256、恢复候选及应用级演练记录 |
| 文档 | 当前事实手册、全流程截图 SOP、部署/备份/回滚手册、版本记录；DOCX/PDF/Web 由批准提交在最终交付时生成，不进入应用发布树 |
| 验证 | CI 结果、类型检查、Lint、生产构建、领域回归、生产健康与业务抽查 |

## 3. 环境准入

- HTTPS 域名、可信 Origin 和 Secure Cookie 正常。
- 生产公开注册关闭；初始管理员令牌已删除；不存在共享默认密码。
- `/app/data`、`/app/public/uploads`、`/app/backups` 分别持久挂载且可写。
- SQLite 只允许一个在线写实例；需要滚动多实例时先迁移 PostgreSQL 与共享对象存储。
- 目标提交必须通过 CI、备份和迁移门禁。当前 Coolify main Webhook 自动部署已开启，因此不能继续把“自动部署关闭”写成现行事实；涉及生产迁移的提交仍须先安排维护窗口和回滚点。
- 每日一致备份、失败通知和备份新鲜度已验证；异地副本必须记录目标、账号和取回验证。

## 4. 业务验收矩阵

| 流程 | 输入 | 处理 | 输出与闭环证据 |
| --- | --- | --- | --- |
| 来料 | 供应商、物料、数量、供应批号、库位 | 收货并生成内部批次 | 库存、成本层、流水和供应批号可追溯 |
| 生产 | 已发布订单/BOM、投入批次、人员、工作中心 | 登记并确认实绩 | 产出待检批次、投入谱系、库存与成本守恒 |
| 质量 | 已发布标准、待检/冻结批次、抽样、逐项结果、结论和审批依据 | 标准快照、放行、冻结、复检、返工、报废、让步/解冻 | 标准版本、项目事实、附件、趋势、状态库存、处置记录和操作人可回放 |
| 发货 | 客户、发货单、库位和可用批次 | FIFO 分配并确认出库 | 客户去向、批次余额、成本和流水一致 |
| 退货 | 原发货、剩余可退量、回库库位 | 生成隔离退货批次并送检 | 可反查客户、原发货、生产和供应来源 |
| 设备异常 | 设备当前状态、故障原因、安全措施、维修/试运行结果 | 上报故障并在修复后恢复 | 状态链、操作人、时间和故障持续时间可回放 |
| 冲销 | 原业务单据、权限、原因 | 在统一库存账本中事务化逆操作 | 数量/成本/状态恢复，原流水与冲销流水双向对应且保留审计 |

每条流程至少用一个正常用例和一个越权/异常用例验收；不能只检查页面存在或成功提示。

## 5. 权限与岗位签署

- 企业负责人批准岗位职责和高风险动作分离。
- 权限管理员配置组权限、人员数据范围和临时授权有效期；来料登记/编辑、收货/拒收和红冲分别签署，旧 `materialIn.update` 不视为拥有库存过账或冲销权。
- 计划、生产、仓储、质量、销售、人事和运维分别使用真实岗位账号验收菜单、按钮、列表范围和 HTTP 403。
- 自定义委派归档时，分别验收无入口、无原业务权限和跨数据范围三类 403，不能用管理员账号代替最小权限验收。
- 旧全厂兼容范围和历史永久个人覆盖逐项复核；未审批项不得视为最小权限完成。

## 6. 发布与回滚门禁

1. CI、写接口审计覆盖守卫、类型检查、Lint、生产构建和受影响领域回归全部通过。
2. 版本号、发布记录、当前事实文档和 SOP 同步。
3. 生成并验证迁移前数据库+附件一致备份，记录归档、SHA-256 和备份创建时间。
4. 对生产副本执行全迁移基线 Schema 审计；只有 `NO_SCHEMA_DRIFT`，或退役数据已归档/审批且非覆盖收敛候选后置为零漂移时，才能继续。
5. 涉及 Product→Material 时，在最终零漂移候选上重新生成计划、完成映射签字和 `preflight`；报告须为 PASS 且数据库前后 SHA-256 一致。
6. 执行应用级恢复演练；确认迁移、readiness、登录、业务/附件抽查、RPO 和 RTO 全部通过。
7. 在维护窗口固定目标提交并部署；验证首页、live、ready、登录和关键闭环。
8. 失败时停止写入，保留新候选证据并将 Coolify 挂载切回旧回滚点；不在运行中覆盖 SQLite。

当前生产候选已在本机完成 Schema 收敛、readiness、管理员登录、物料/库存/生产单只读抽查和附件原文件 SHA-256 抽查，完整应用 RTO 为 2.287 秒；但原备份 RPO 约 46.9 小时已超标。真实交付须在最新生产一致备份上全流程复跑，并在目标 Coolify 主机执行可回切的挂载切换；不能直接照搬本机 RTO。
