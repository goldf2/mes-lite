## 4. 建议执行顺序

1. 先完成 M-01，确认可用且新鲜的一致备份。
2. 在隔离副本完成 M-02；没有零漂移证据时不得执行数据回填。
3. 完成 M-03 的业务逐行确认和只读预检，再决定是否安排生产回填。
4. 并行准备 M-04；随后在维护窗口执行 M-05 和 M-06。
5. 文档和视频终审后执行 M-07；再用同一外部存储能力完成 M-08。
6. M-09 单独安排，不与应用发布或生产数据迁移混合。

## 6. 安全边界

- 不把生产数据库、附件、备份归档、账号、Cookie、访问令牌、密钥或对象存储凭据提交到 Git。
- Schema 审计、Product→Material 回填和恢复演练必须使用当前手册命令；禁止从旧聊天或截图复制命令。
- 所有数据库变化先备份、再预检、再事务执行；失败时停止写入并使用报告绑定的回滚包。
- 任一人工项缺少证据时保持“待人工”或“有条件验收”，不得默认标记为完成。
