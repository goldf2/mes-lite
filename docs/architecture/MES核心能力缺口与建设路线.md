# MES-lite 核心能力缺口与建设路线

状态：当前代码审计 + 分阶段建设基线
日期：2026-08-14

## 1. 审计结论

MES-lite 已经不是只有主数据和表单的原型。现有代码具备物料、BOM、工艺路线、工作中心、设备台账、生产订单、派工、班后实绩、来料、库位库存、成本层、流程转移、发货退货、附件、权限和审计等基础链路。

当前最主要的问题不是再增加 ERP 页面，而是让现场事实形成可查询、可判定、可追溯、可冲销的 MES 闭环。按生产风险排序如下：

| 优先级 | 能力 | 当前代码事实 | 缺口 | 建设停止线 |
| --- | --- | --- | --- | --- |
| P0 | 库存流水查询 | `StockLog` 已记录数量、核算数量、成本、库位、来源和操作人 | 过去没有独立页面，查账需要跨表或看局部详情 | **本版本完成**：统一页面、权限、智能搜索、字段搜索、卡片/列表、分页和来源展示 |
| P0 | 质量判定闭环 | `v0.1.374` 已形成生产/退货标准化检验、按标准启用的来料隔离/判定/红冲，并拆分来料收货与红冲命令 | 尚无 SPC/过程能力、原因分类主数据和复杂审批流 | **当前完成批次级标准化检验闭环**；标准版本、项目事实、处置、命令权限和最终库存去向可追溯 |
| P0 | 批次/序列追溯 | `v0.1.358` 已建立来料、生产、发货、客户和退货回流的可搜索批次级正反向全景 | 尚无逐件序列号和客户指定批次拣货 | 先稳定批次级追溯；逐件序列号和人工指定批次按真实需求扩展 |
| P1 | 不合格处置 | `v0.1.372` 已有独立处置记录、返工/报废/让步/解冻、复检轮次和任务附件 | 尚无原因分类主数据和多级评审工作流 | 先使用原因/审批依据文本和分层权限稳定现场闭环，再按真实审批需求扩展 |
| P1 | 设备事件与维护 | `v0.1.371` 已有运行事件、周期点检、保养计划、维修工单、设备恢复、备件库存/成本/批次过账、附件和独立权限 | 自动采集、停机原因采集、节拍和 OEE 尚未贯通 | 先固定采集接口、时间同步和 OEE 口径，再接真实设备；不做财务资产折旧 |
| P1 | 仓库与库存状态 | 已有库位；`v0.1.357` 使用 `AVAILABLE / QUARANTINE / HOLD / REWORK` 同步汇总、库位、批次和成本层 | 尚无仓库层级和独立于质量处置的受控状态调整 | 在不复制库存账的前提下补齐仓库；所有变化继续写流水 |
| P2 | 工序级执行深化 | 有工艺路线、派工、生产订单实绩 | 当前实绩偏班后汇总，暂停、异常、人工/机时和工序级产量仍弱 | 只在现场确有采集需求时增加事件，不先建设复杂 APS |

## 2. 本版本完成的第一条闭环

新增“库存 → 库存流水”页面，继续复用 `stocks` 读取权限和公共页面框架：

- 默认按发生时间倒序展示流水类型、库存对象、库位、数量变化、库存前后值、核算数量、成本变化、来源单据、操作人和备注。
- 顶部智能搜索使用空格拆分关键词，并允许关键词分别命中物料编码/名称/规格、流水类型、来源、库位、操作人或备注。
- 高级搜索逐字段提供物料编码、物料名称、流水类型、收发方向、库位、来源类型、来源 ID、操作人、备注和发生日期。
- 卡片和列表共用同一接口、筛选和分页；页面偏好通过公共视图控件保存。
- API 只做 `stocks:read` 权限、参数解析和 HTTP 映射；查询与选项装配位于 `modules/inventory/server`。
- 不修改 `StockLog`、库存过账、成本层或正式数据库，不把查询页面误当作新的库存账本。

## 3. v0.1.354 已交付的第一条质量批次闭环

1. 确认新生产实绩时，每项产出自动生成唯一内部批次、待检批次余额、批次入账交易和待检任务。
2. 总库存与库位库存显式拆分为可用、待检、冻结数量；成本层同步保存批次和状态。
3. 具有 `quality.update` 权限的人员可在生产订单详情整批判定：合格转换为 `AVAILABLE`，不合格转换为 `HOLD`。
4. 状态转换在一个服务端事务内更新检验、批次余额、汇总/库位库存、成本层、批次交易和库存流水；总数量和总成本保持不变。
5. FIFO 领料、发货和普通库存调整只使用可用库存，不能消耗待检或冻结库存。
6. 当前切片没有增加独立质量一级页面；7 张真实浏览器截图和操作步骤已纳入 v0.1.354 作业指导书。

## 4. 当前与下一阶段垂直切片

### 4.0 v0.1.355 已交付代码：来料到生产谱系

1. 来料收货一行一个内部批次，内部批号与供应商批号分开保存。
2. 流程转移按 FIFO 同步移动批次库位余额，历史未追踪库存显式进入兼容批次。
3. 生产实绩确认按来源库位可用批次 FIFO 分配，为每个产出保存所有投入父批次。
4. 来料详情、生产投入和产出质量卡都能打开追溯弹窗，在相邻父/子批次间继续导航。
5. 生产冲销恢复投入批次余额并撤销谱系；来料红冲阻止已消耗或余额已变动的来源批次。

### 4.0A v0.1.356 已交付代码：发货到客户与退货回流

1. 确认发货按来源库位可用内部批次 FIFO 自动分配，保存客户、发货单、批次、数量和成本。
2. 新退货单必须选择原发货单，服务端校验状态、物料和剩余可退数量。
3. 退货确认收货后生成独立待检批次，原发货批次通过 `ReturnLotAllocation` 连接到退货批次。
4. 统一追溯弹窗显示生产上下游、客户发货去向、退货来源和退货回流批次。
5. 历史发货仅建立明确兼容批次；不把迁移后构造的数据描述为真实历史来源。

### 4.1 v0.1.357 已交付：质量任务与不合格处置

1. 在现有 `QualityInspection` 上增加轮次和父子关系，不恢复旧 `QCRecord` 为新主流程。
2. 增加部分放行/冻结、复检、让步接收、返工、报废和解冻；每次状态与数量变化都写批次交易、库存流水和独立 `QualityDisposition`。
3. 建立跨工单质量待办工作区，并细分质量查看、判定、处置与授权放行权限。
4. 增加 `REWORK` 库存状态和成本拆分；返工完成只能回到待检，报废按批次比例扣减库存与成本。
5. `v0.1.373` 已补齐生产/退货检验标准，并按已发布标准启用来料自动送检、隔离、判定、趋势和红冲联动；SPC/过程能力、原因分类和复杂审批仍作为后续按需切片。

### 4.2 P0-3 批次追溯

1. 已完成来料、流程转移、生产投入/产出、发货、客户和退货回流的批次链。
2. `v0.1.358` 已将相邻节点追溯扩展为可搜索的批次全景，支持按客户、发货/退货/检验/生产/来料单、供应批号和内部批号检索。
3. 需要客户指定炉批或先到期先出时，在现有分配模型上增加受控人工拣批，不改变库存事实源。
4. 继续以批次为默认追溯单位，序列号作为可选扩展。

### 4.3 P1 设备与异常

1. **已完成 `v0.1.369`**：开机、停机、故障、恢复及原因形成不可直接改写的事件时间线；恢复关闭最近故障/停机并计算持续时间，基础资料不能直接写状态。
2. **已完成 `v0.1.369`**：设备事件使用独立 `equipmentEvents.update`，设备只读岗位可回放，越权命令返回 403；升级安装从旧设备权限继承后必须复核收窄。
3. **已完成 `v0.1.370`**：点检计划、到期/逾期任务、完整项目清单、实测/结果/人员、异常故障联动和现场附件使用独立 `equipmentInspections` 资源；记录与项目快照不可覆盖。
4. **已完成 `v0.1.371`**：周期保养计划、到期/逾期任务、计划与故障维修工单、开始/完成状态机、设备维护/恢复事件、完整保养结果，以及备件库存、成本和 FIFO 批次原子过账使用独立 `equipmentMaintenance` 资源。
5. **下一切片**：先定义边缘采集输入合同、设备时钟/班次映射、停机原因和数据质量指标；产量采集与 OEE 只在真实现场接口和口径签字后建设。

## 5. 明确不扩张的边界

- 不建设总账、应收应付、税务、工资和财务凭证。
- 不在本系统实现复杂 APS、全局最优排程或专业 WMS 波次。
- MRP-lite 只在质量与追溯闭环稳定后建设“需求 → BOM 展开 → 可用量 → 缺料 → 建议”。
- ERP-lite 继续只保留独立运行需要的客商、销售、参考价格、发货和退货。

## 6. 每个后续切片的验收门槛

1. 页面、API、权限、数据模型和文档同时更新。
2. 状态变化必须在服务端校验；前端禁用按钮不算安全边界。
3. 数量、成本、批次或库存状态变化必须可通过库存流水和审计回放。
4. 确认后的业务优先冲销，不直接删除；冲销必须成对、幂等并保留原因。
5. 宽屏、窄屏、卡片、列表和高级搜索使用公共组件，不新增平行骨架。
6. 完成临时数据库回归、类型检查、结构校验、构建和本机浏览器验证后才进入主线。
