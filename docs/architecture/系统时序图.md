# MES-lite 系统时序图

本文记录 `v0.1.434` 的关键交互与业务时序。系统定位为 MES 主体、有限 MRP/ERP 支持，不在当前阶段实现跨域自动编排；当前已实现链路见《MES 当前功能流程与泳道》，模块功能和缺口见《系统功能全景与完备性审查》。

阅读方法：流程图说明角色和单据怎样前后衔接；本文件说明一次高风险命令在 HTTP、领域服务、数据库事务、库存和审计之间怎样执行。带人员字段的旧生产日报通用入口仍只属于兼容时序；当前前端使用专用 BOM 快捷接口。

## 1. 页面打开与形态切换

```mermaid
sequenceDiagram
  actor U as 操作人员
  participant N as 主导航
  participant H as 页面注册与应用壳
  participant P as 主显示区
  participant D as 公共 ModalDialog

  U->>N: 选择一级功能页面
  N->>H: navigate(pageKey)
  H->>P: 以页面模式渲染

  U->>P: 点击详情、新建或编辑
  P->>H: open(content, source=content)
  H->>D: 默认以弹窗模式渲染
  U->>D: 点击全屏图标
  D->>D: 同一业务组件占满可视窗口
  U->>D: 再次点击全屏图标或按 Esc
  D->>D: 还原原弹窗并保留上下文
```

规则：主导航始终进入主显示区；页内资源操作默认弹窗；公共弹窗只保留一个可逆的全屏图标，不再提供“在主页面打开”平行形态。命令型操作在当前上下文执行。复杂工作区可以在页面注册中声明例外，不在每个页面重复实现打开逻辑。

### 1.1 销售订单查看关联物料

```mermaid
sequenceDiagram
  actor U as 销售人员
  participant SO as 销售订单详情
  participant R as MaterialReferenceButton
  participant M as 物料详情控制器
  participant API as GET /api/materials
  participant D as MaterialDetailDialog

  U->>R: 点击物料名称或编码
  R->>SO: 保存当前订单上下文并选择物料引用
  SO->>SO: 暂时隐藏订单弹窗，避免同层遮罩叠加
  SO->>M: 传入 id/code/name/spec 轻量引用
  M->>API: 按 code 查询完整物料
  API-->>M: 返回物料档案
  M-->>D: 只读显示详情与附件
  U->>D: 关闭
  D->>SO: 清除物料选择并恢复原订单详情
```

销售模块只持有轻量物料引用，查询和详情展示由 `modules/materials` 公开入口负责；在销售上下文中不传入编辑或全景命令，避免跨域写入。

## 2. 生产订单创建与查询服务

```mermaid
sequenceDiagram
  actor U as 计划或现场人员
  participant UI as 生产订单页面
  participant API as Orders HTTP Adapter
  participant C as Production Order Command Service
  participant Q as Production Order Query Service
  participant S as Production Order Status Service
  participant DB as Prisma Transaction

  U->>UI: 选择目标产出、可选已发布 BOM 和计划数量
  UI->>API: POST 创建请求
  API->>API: 校验权限与请求 Schema
  API->>C: 已校验的创建输入
  C->>DB: 原子计算当日组号并解析全部订单行
  DB->>DB: 映射兼容 Product；有 BOM 时校验已发布版本与唯一主产出
  DB->>DB: 可选冻结 BOM 快照并写入组号和行号
  DB-->>C: 全部订单行
  C-->>API: 首行、明细、数量和可选组号
  API-->>UI: 201 Created

  U->>UI: 状态、客户或多个关键词查询
  UI->>API: GET 查询参数
  API->>Q: 已解析的过滤和分页条件
  Q->>DB: 查询订单及物料、客户、BOM 和实绩计数
  DB-->>Q: 订单和总数
  Q-->>API: 列表与分页
  API-->>UI: 查询结果

  U->>UI: 打开详情或确认/取消订单
  alt 打开详情
    UI->>API: GET /orders/:id
    API->>Q: 查询详情
    Q->>DB: 装配同组行、BOM、默认路线和当前工序
    DB-->>UI: 订单详情
  else 确认订单
    UI->>API: PATCH confirm
    API->>S: 确认命令
    S->>DB: 校验草稿状态并写入开始状态
    DB-->>UI: 已确认订单
  else 取消订单
    UI->>API: PATCH cancel + 原因
    API->>S: 取消命令
    S->>DB: 原子退回已领料或释放预留，作废报工并取消订单
    DB-->>UI: 取消结果
  end
```

Route Handler 只负责 HTTP、权限和请求级审计；生产订单编号、BOM 结构校验、快照、详情装配、确认和取消事务属于 `modules/production`。验证使用临时独立 SQLite，不连接本机测试库或服务器正式库。

## 3. 生产实绩登记、确认与冲销

```mermaid
sequenceDiagram
  actor U as 现场人员
  participant UI as 生产订单实绩面板
  participant API as Actual HTTP Adapter
  participant C as Execution Context Service
  participant D as Actual Draft Service
  participant S as Actual Status Service
  participant I as Inventory Service
  participant DB as Prisma Transaction

  U->>UI: 填写日期、员工、实际设备、作业文件、投入、产出和库位
  UI->>API: POST /orders/:id/actuals
  API->>D: 已校验草稿输入
  D->>C: 按来源 ID 重新解析设备/文件或例外原因
  C->>DB: 校验订单工作中心、设备状态和文件适用范围
  D->>DB: 冻结执行上下文和 BOM、检查库位库存、生成当日最大序号+1
  DB-->>UI: 草稿实绩

  U->>UI: 确认实绩
  UI->>API: PATCH confirm
  API->>S: 确认命令 + 操作人
  S->>DB: 锁定草稿并复检设备/文件快照或例外原因
  S->>I: 投入出库并保存成本层消耗快照
  S->>I: 主产出带成本、副产出按规则入库
  S->>DB: 确认实绩并重算完工/废料/订单状态
  DB-->>UI: 已确认实绩

  U->>UI: 填写原因并冲销
  UI->>API: PATCH reverse
  API->>S: 冲销命令 + 操作人
  S->>DB: 校验产出未被下游消耗
  S->>I: 扣回全部产出并恢复投入及历史成本层
  S->>DB: 写反向流水、冲销状态并重算订单
  DB-->>UI: 已冲销实绩
```

四条实绩 Route Handler 不访问 Prisma；请求契约、设备/作业文件候选与快照、BOM 快照、日期编号、共同投入、多产出、库存成本过账、冲销恢复和订单累计均由 `modules/production` 所有。确认不能绕过每类“快照或原因”的服务/数据库双重约束；冲销不能绕过产出可用库存和成本层未被消费校验。

## 3.5 通用附件上传、草稿绑定与归档

```mermaid
sequenceDiagram
  actor U as 操作人员
  participant UI as 业务页面或公共附件面板
  participant C as Attachment Client
  participant API as Attachment HTTP Adapter
  participant S as Attachment Service
  participant DB as Prisma
  participant FS as 持久化文件目录

  U->>UI: 选择文件或拖放上传
  UI->>C: uploadAttachment(ownerType, ownerId, file)
  C->>API: POST multipart/form-data
  API->>API: 权限与 Schema 校验
  API->>S: uploadManagedAttachment
  S->>FS: 保存原文件并按需生成预览派生文件
  S->>DB: 写入附件元数据与首张物料封面状态
  DB-->>UI: 带统一预览/下载 URL 的附件

  alt 新建单据暂存附件
    UI->>S: finalize draft + 正式单据 ID
    S->>DB: 批量切换 ownerType / ownerId
  else 取消新建
    UI->>S: discard draft
    S->>DB: 删除暂存元数据
    S->>FS: 删除暂存原文件与派生文件
  else 归档当前物料封面
    UI->>S: archive attachment
    S->>DB: 标记归档并原子提升下一张有效封面
  end
```

页面与其他领域不得自行实现附件 CRUD。附件 Route Handler 只承担权限、HTTP 文件流、审计和错误映射；上传、封面、旋转、归档与草稿生命周期统一由 `modules/attachments` 所有。

## 3.5.1 文档批量导入、分类字段与批量修改

```mermaid
sequenceDiagram
  actor U as 文控人员
  participant UI as 产品文档页
  participant API as Document HTTP Adapter
  participant D as Documents Service
  participant A as Attachments Service
  participant DB as Prisma

  U->>UI: 选择同类文件并填写共同元数据
  UI->>API: POST batch-import(files, metadata)
  API->>API: 校验文档新增 + 附件新增权限
  loop 每个文件
    API->>D: 创建独立 WorkInstruction
    D->>DB: 校验类别、关系和扩展字段后写入
    API->>A: 保存该文档的原始附件
  end
  API-->>UI: 逐文件成功/失败结果

  U->>UI: 勾选同类别文档并选择要应用的字段
  UI->>API: PATCH bulk(ids, selected fields)
  API->>D: 校验同一类别与字段归属
  D->>DB: 事务更新所选基础/扩展字段
  DB-->>UI: 更新后的文档集合
```

字段定义由类别拥有，基础字段不进入动态定义。扩展字段只有使用计数为零时才能删除；批量修改未选择的字段不会随空值提交，跨类别选择整批拒绝。

## 3.6 来料登记、收货与整单红冲

```mermaid
sequenceDiagram
  actor U as 仓管人员
  participant UI as 来料页面
  participant API as Material In HTTP Adapter
  participant D as Detail Service
  participant S as Status Service
  participant DB as Prisma Transaction

  U->>UI: 创建一项或多项来料明细
  UI->>API: POST /api/material-ins
  API->>D: 已校验输入
  D->>DB: 读取当日最大序号并原子写入全部明细
  DB-->>UI: 待收货来料单

  U->>UI: 确认收货
  UI->>API: PATCH receive
  API->>S: receiveManagedMaterialIn
  S->>DB: 校验待收货状态
  DB->>DB: 增加总库存与目标库位余额
  DB->>DB: 创建成本层、库存流水和来料内部批次
  DB->>DB: 状态改为 RECEIVED
  DB-->>UI: 收货结果

  alt 整单错误且成本层/批次余额未被消费或改变
    U->>API: PATCH reverse + 原因
    API->>S: reverseManagedMaterialIn
    S->>DB: 原子恢复库存、库位、成本层和批次，并写反向流水
    DB-->>UI: REVERSED
  else 成本层已有下游变化
    S-->>UI: 拒绝红冲并保留当前账实
  end
```

5 条来料 Route Handler 均不访问 Prisma。编号、详情装配、状态约束与来料事务由 `modules/receiving` 所有；内部批次余额和批次交易由 `modules/inventory` 所有。新收货行将供应商批号写入内部批次；已被生产消耗或余额变动的来源批次会阻断红冲。

## 3.7 生产投入批次分配与谱系

```mermaid
sequenceDiagram
  actor U as 生产确认人
  participant UI as 生产实绩面板
  participant P as Production Status Service
  participant I as Inventory Lot Service
  participant DB as Prisma Transaction

  U->>UI: 确认班后生产实绩
  UI->>P: confirmProductionOrderActual
  P->>DB: 校验状态和可用库存，扣减投入
  P->>I: allocateAvailableInventoryLots
  I->>DB: 按库位 AVAILABLE 批次 FIFO 分配
  P->>DB: 产出入 QUARANTINE，创建产出批次和待检任务
  P->>I: createProductionLotGenealogies
  I->>DB: 每个投入分配连接到每个产出批次
  DB-->>UI: 返回投入批次和产出谱系

  opt 冲销生产实绩
    U->>P: reverseProductionOrderActual + 原因
    P->>I: reverseProductionLotAllocations
    I->>DB: 恢复投入批次余额，分配/谱系标记 REVERSED
  end
```

批次分配是库存出库的实物追溯投影，不取代成本层核算。当历史可用库存没有批次记录时，事务先计算未追踪差额并建立 `LEGACY_INVENTORY` 兼容批次；该来源不被展示为供应商批号。

## 3.8 派工创建与五态流转

```mermaid
sequenceDiagram
  actor U as 生产管理人员
  participant UI as 派工页面
  participant API as Dispatch HTTP Adapter
  participant C as Dispatch Command Service
  participant S as Dispatch Status Service
  participant DB as Prisma Transaction

  U->>UI: 选择可派工订单、工序、人员和计划数量
  UI->>API: POST /api/dispatches
  API->>C: 已校验创建输入
  C->>DB: 校验 Material 订单为 RELEASED/IN_PROGRESS
  C->>DB: 历史无 materialId 工单兼容 PICKED/RUNNING
  C->>DB: 校验工序属于订单产品路线
  C->>DB: 读取当日最大序号并创建 PENDING 派工单
  DB-->>UI: 新派工单

  U->>API: PATCH dispatch
  API->>S: PENDING → DISPATCHED
  U->>API: PATCH start
  API->>S: DISPATCHED → IN_PROGRESS
  U->>API: PATCH complete
  API->>S: IN_PROGRESS → COMPLETED
  S->>DB: 每次在事务中重新校验当前状态并更新时间戳
  DB-->>UI: 最新状态

  opt 尚未开工
    U->>API: PATCH cancel
    API->>S: PENDING/DISPATCHED → CANCELLED
  end
```

6 条派工 Route Handler 均不访问 Prisma；组合查询、编号、工序归属和状态流转由 `modules/production` 所有。非法重复流转在领域层拒绝，临时 SQLite 回归不接触本机或服务器正式数据。

## 3.8 流程转移确认与冲销

```mermaid
sequenceDiagram
  actor U as 现场人员
  participant UI as 流程转移页面
  participant API as Flow Transfer HTTP Adapter
  participant C as Flow Transfer Command Service
  participant S as Flow Transfer Status Service
  participant I as Inventory Location Transfer
  participant DB as Prisma Transaction

  U->>UI: 选择业务日期、员工、物料和来源/目标库位
  UI->>API: POST 草稿
  API->>C: 已校验输入
  C->>DB: 校验来源可用量并读取业务日期最大序号
  DB-->>UI: DRAFT 转移单

  U->>API: PATCH confirm
  API->>API: 校验 flowTransferConfirm.update
  API->>S: 确认命令 + 操作人
  S->>DB: 重新校验 DRAFT 状态
  S->>I: 来源库位扣减、目标库位增加
  I->>DB: 写一出一入流水，成本变动为零
  S->>DB: 状态改为 CONFIRMED
  DB-->>UI: 已确认转移

  U->>API: PATCH reverse + 原因
  API->>API: 校验 flowTransferReverse.update
  API->>S: 冲销命令
  S->>DB: 校验 CONFIRMED 和原目标库位可用量
  S->>I: 按相反方向恢复库位并写反向流水
  S->>DB: 状态改为 REVERSED
  DB-->>UI: 已冲销转移
```

4 条流程转移 Route Handler 均不访问 Prisma。草稿维护、确认与冲销分别使用通用页面资源和两个独立命令资源，只有冲销要求保存原因。总库存、计价数量、成本和成本层在确认与冲销前后保持不变；失败事务不能留下单边库位变化。

## 3.9 库存流水查询

```mermaid
sequenceDiagram
```

## 4. 销售订单与默认销售价

```mermaid
sequenceDiagram

  participant API as Sales Order API
  participant C as Sales Command Service
  participant M as Material

  API->>C: 调用已校验创建命令
```

## 5. 独立发货与可选来源关系

```mermaid
sequenceDiagram
  actor U as 仓库人员
  participant UI as 发货管理
  participant API as Shipment API
  participant C as Fulfillment Command Service
  participant R as 客户物料交付参考
  participant I as Inventory Service
  participant S as Shipment
  participant F as 附件与 PDF

  U->>UI: 新建发货单
  U->>UI: 选择一个客户，连续加入多条物料、库位、数量和价格
  UI->>R: 查看客户＋物料的需求、待发、已发、未发或超发参考
  Note over UI,R: 参考不形成订单关系，也不限制超发
  UI->>API: customerId、items[]、物流与备注
  API->>C: 调用多明细发货命令
  C->>I: 逐明细校验库位可用量
  C->>S: 原子创建单头与 ShipmentItem[]
  U->>F: 上传附件或调用 AI 识别
  F-->>S: 绑定附件
  API-->>UI: 返回待发货单
  U->>API: 确认发货
  API->>API: 校验 shipmentDispatch.update
  API->>C: 调用发货状态事务
  C->>S: 若存在货箱，复检有效货箱合计等于发货数量
  C->>I: 原子扣减总库存、库位余额和成本
```

```mermaid
  PROD->>DB: 确认 DailyProductionReport + CONFIRM 审计
  DB-->>UI: 全部成功或全部回滚，不留下草稿
```

该时序不创建生产订单、派工或报工；省略的是复杂生产组织流程，不是 BOM、库存、成本、审计和可选质量控制。选择待检时复用统一质量任务与处置流程。库存盘点已移到库存菜单的独立页面，仍沿用 `daily-count` 事务且不能代替 BOM 转换。

## 18. Coolify 启动、迁移前备份与就绪检查

```mermaid
sequenceDiagram
  participant C as Coolify
  participant Container as MES-lite Container
  participant Backup as Verified Backup Script
  participant Volume as data/uploads/backups 持久目录
  participant Prisma as Prisma Migrate
  participant Next as Next.js Standalone
  participant Health as /api/health/ready

  C->>Container: 部署指定 Git 提交并启动
  Container->>Volume: 检查明确挂载和可写性
  opt 旧数据库存在且启用迁移前备份
    Container->>Backup: 创建 SQLite 一致性快照
    Backup->>Volume: 写数据库+附件清单及 SHA-256 校验
  end
  Container->>Prisma: migrate deploy
  Prisma->>Volume: 只对持久数据库应用待执行迁移
  Container->>Next: 启动 server.js
  C->>Health: 轮询就绪状态

  Health-->>C: ready / unhealthy + 明确原因
```

Docker 镜像本身不保存业务数据。Coolify 的正常停止、重启和重新部署必须继续使用同一组明确持久目录；删除应用或改挂载前必须先生成并验证可恢复备份。
