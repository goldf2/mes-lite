# MES-lite 系统时序图

本文记录 v0.1.316 的关键交互与业务时序。系统定位为 MES 主体、有限 MRP/ERP 支持，不在当前阶段实现跨域自动编排。

## 1. 页面打开与形态切换

```mermaid
sequenceDiagram
  actor U as 操作人员
  participant N as 主导航
  participant H as 页面注册与应用壳
  participant P as 主显示区
  participant D as 公共 ModalDialog

  U->>N: 选择一级功能页面
  N->>H: navigate(pageKey)
  H->>P: 以页面模式渲染

  U->>P: 点击详情、新建或编辑
  P->>H: open(content, source=content)
  H->>D: 默认以弹窗模式渲染
  U->>D: 点击全屏图标
  D->>D: 同一业务组件占满可视窗口
  U->>D: 再次点击全屏图标或按 Esc
  D->>D: 还原原弹窗并保留上下文
```

规则：主导航始终进入主显示区；页内资源操作默认弹窗；公共弹窗只保留一个可逆的全屏图标，不再提供“在主页面打开”平行形态。命令型操作在当前上下文执行。复杂工作区可以在页面注册中声明例外，不在每个页面重复实现打开逻辑。

## 2. 生产订单创建与查询服务

```mermaid
sequenceDiagram
  actor U as 计划或现场人员
  participant UI as 生产订单页面
  participant API as Orders HTTP Adapter
  participant C as Production Order Command Service
  participant Q as Production Order Query Service
  participant S as Production Order Status Service
  participant DB as Prisma Transaction

  U->>UI: 选择一项或多项物料、BOM 和计划数量
  UI->>API: POST 创建请求
  API->>API: 校验权限与请求 Schema
  API->>C: 已校验的创建输入
  C->>DB: 原子计算当日组号并解析全部订单行
  DB->>DB: 映射兼容 Product、校验启用 BOM 与唯一主产出
  DB->>DB: 冻结 BOM 快照并写入组号和行号
  DB-->>C: 全部订单行
  C-->>API: 首行、明细、数量和可选组号
  API-->>UI: 201 Created

  U->>UI: 状态、客户或多个关键词查询
  UI->>API: GET 查询参数
  API->>Q: 已解析的过滤和分页条件
  Q->>DB: 查询订单及物料、客户、BOM 和实绩计数
  DB-->>Q: 订单和总数
  Q-->>API: 列表与分页
  API-->>UI: 查询结果

  U->>UI: 打开详情或确认/取消订单
  alt 打开详情
    UI->>API: GET /orders/:id
    API->>Q: 查询详情
    Q->>DB: 装配同组行、BOM、默认路线和当前工序
    DB-->>UI: 订单详情
  else 确认订单
    UI->>API: PATCH confirm
    API->>S: 确认命令
    S->>DB: 校验草稿状态并写入开始状态
    DB-->>UI: 已确认订单
  else 取消订单
    UI->>API: PATCH cancel + 原因
    API->>S: 取消命令
    S->>DB: 原子退回已领料或释放预留，作废报工并取消订单
    DB-->>UI: 取消结果
  end
```

Route Handler 只负责 HTTP、权限和请求级审计；生产订单编号、BOM 结构校验、快照、详情装配、确认和取消事务属于 `modules/production`。验证使用临时独立 SQLite，不连接本机测试库或服务器正式库。

## 3. 生产实绩登记、确认与冲销

```mermaid
sequenceDiagram
  actor U as 现场人员
  participant UI as 生产订单实绩面板
  participant API as Actual HTTP Adapter
  participant D as Actual Draft Service
  participant S as Actual Status Service
  participant I as Inventory Service
  participant DB as Prisma Transaction

  U->>UI: 填写日期、员工、投入、产出和库位
  UI->>API: POST /orders/:id/actuals
  API->>D: 已校验草稿输入
  D->>DB: 解析冻结 BOM、检查库位库存、生成当日最大序号+1
  DB-->>UI: 草稿实绩

  U->>UI: 确认实绩
  UI->>API: PATCH confirm
  API->>S: 确认命令 + 操作人
  S->>DB: 锁定草稿与投入/全部产出
  S->>I: 投入出库并保存成本层消耗快照
  S->>I: 主产出带成本、副产出按规则入库
  S->>DB: 确认实绩并重算完工/废料/订单状态
  DB-->>UI: 已确认实绩

  U->>UI: 填写原因并冲销
  UI->>API: PATCH reverse
  API->>S: 冲销命令 + 操作人
  S->>DB: 校验产出未被下游消耗
  S->>I: 扣回全部产出并恢复投入及历史成本层
  S->>DB: 写反向流水、冲销状态并重算订单
  DB-->>UI: 已冲销实绩
```

四条实绩 Route Handler 不访问 Prisma；请求契约、冻结快照、日期编号、共同投入、多产出、库存成本过账、冲销恢复和订单累计均由 `modules/production` 所有。冲销不能绕过产出可用库存和成本层未被消费校验。

## 3.5 通用附件上传、草稿绑定与归档

```mermaid
sequenceDiagram
  actor U as 操作人员
  participant UI as 业务页面或公共附件面板
  participant C as Attachment Client
  participant API as Attachment HTTP Adapter
  participant S as Attachment Service
  participant DB as Prisma
  participant FS as 持久化文件目录

  U->>UI: 选择文件或拖放上传
  UI->>C: uploadAttachment(ownerType, ownerId, file)
  C->>API: POST multipart/form-data
  API->>API: 权限与 Schema 校验
  API->>S: uploadManagedAttachment
  S->>FS: 保存原文件并按需生成预览派生文件
  S->>DB: 写入附件元数据与首张物料封面状态
  DB-->>UI: 带统一预览/下载 URL 的附件

  alt 新建单据暂存附件
    UI->>S: finalize draft + 正式单据 ID
    S->>DB: 批量切换 ownerType / ownerId
  else 取消新建
    UI->>S: discard draft
    S->>DB: 删除暂存元数据
    S->>FS: 删除暂存原文件与派生文件
  else 归档当前物料封面
    UI->>S: archive attachment
    S->>DB: 标记归档并原子提升下一张有效封面
  end
```

页面与其他领域不得自行实现附件 CRUD。附件 Route Handler 只承担权限、HTTP 文件流、审计和错误映射；上传、封面、旋转、归档与草稿生命周期统一由 `modules/attachments` 所有。

## 3.6 来料登记、收货与整单红冲

```mermaid
sequenceDiagram
  actor U as 仓管人员
  participant UI as 来料页面
  participant API as Material In HTTP Adapter
  participant D as Detail Service
  participant S as Status Service
  participant DB as Prisma Transaction

  U->>UI: 创建一项或多项来料明细
  UI->>API: POST /api/material-ins
  API->>D: 已校验输入
  D->>DB: 读取当日最大序号并原子写入全部明细
  DB-->>UI: 待收货来料单

  U->>UI: 确认收货
  UI->>API: PATCH receive
  API->>S: receiveManagedMaterialIn
  S->>DB: 校验待收货状态
  DB->>DB: 增加总库存与目标库位余额
  DB->>DB: 创建成本层和库存流水
  DB->>DB: 状态改为 RECEIVED
  DB-->>UI: 收货结果

  alt 整单错误且成本层未被消费或改变
    U->>API: PATCH reverse + 原因
    API->>S: reverseManagedMaterialIn
    S->>DB: 原子恢复库存、库位和成本层并写反向流水
    DB-->>UI: REVERSED
  else 成本层已有下游变化
    S-->>UI: 拒绝红冲并保留当前账实
  end
```

5 条来料 Route Handler 均不访问 Prisma。编号、详情装配、状态约束、库存/库位/成本层过账和红冲恢复由 `modules/receiving` 所有；临时 SQLite 回归不读写本机测试数据或服务器正式数据。

## 4. 销售订单与默认销售价

```mermaid
sequenceDiagram
  actor U as 销售人员
  participant UI as 销售订单页面
  participant API as Sales Order API
  participant C as Sales Command Service
  participant M as Material
  participant SO as Prisma Transaction
  participant A as AuditLog

  U->>UI: 新建销售订单并选择物料
  UI->>M: 读取默认销售价与币种
  M-->>UI: defaultSalePrice, salesCurrency
  UI->>UI: 自动带入价格，允许手工覆盖
  U->>UI: 保存订单
  UI->>API: 客户、日期、物料、数量、可选单价
  API->>C: 调用已校验创建命令
  C->>M: 再次读取当前默认价
  C->>SO: 原子写入订单、单价、默认价快照、价格来源
  API->>A: 记录创建审计
  API-->>UI: 返回订单

  opt 尚未产生发货记录时调整价格
    U->>UI: 调整价格并填写原因
    UI->>API: PATCH prices
    API->>C: 调用受控调价命令
    C->>SO: 校验状态与发货关系并更新金额
    C->>A: 在同一事务写入调价前后快照与原因
    API-->>UI: 刷新订单
  end
```

价格是销售快照，不是动态引用。物料只保存默认销售价；成本继续由 BOM、来料成本层或手工成本流程计算，不在物料主数据增加成本字段。

## 5. 独立发货与可选来源关系

```mermaid
sequenceDiagram
  actor U as 仓库人员
  participant UI as 发货管理
  participant API as Shipment API
  participant C as Fulfillment Command Service
  participant SO as SalesOrder Item
  participant I as Inventory Service
  participant S as Shipment
  participant F as 附件与 PDF

  U->>UI: 新建发货单
  alt 关联销售订单
    U->>UI: 选择未发完的订单明细
    UI->>API: salesOrderItemId、库位、数量
    API->>C: 调用关联发货命令
    C->>SO: 校验订单状态、待发占用和剩余数量
    C->>I: 校验库位可用量
    C->>S: 冻结订单客户、物料和单价快照
  else 独立发货
    U->>UI: 选择客户、物料、库位并可填凭证和单价
    UI->>API: customerId、materialId、locationId、数量
    API->>C: 调用独立发货命令
    C->>I: 校验库位可用量
    C->>S: 创建无销售来源的发货单
  end
  U->>F: 上传附件或调用 AI 识别
  F-->>S: 绑定附件
  API-->>UI: 返回待发货单
  U->>API: 确认发货
  API->>C: 调用发货状态事务
  C->>I: 原子扣减总库存、库位余额和成本
  C->>SO: 仅关联订单时累计已发数量并更新状态
  U->>F: 下载由领域 PDF 服务生成的送货单

  Note over S,SO: 只有显式关联时才更新订单进度；独立发货不自动创建或修改销售订单
```

退货登记先校验原发货状态、物料和累计可退量；处理时由销售履约状态服务按原发货成本比例恢复总库存与所选库位并写幂等库存流水，拒绝退货不改变库存。16 条销售履约 Route Handler 均不直接访问 Prisma。

## 6. MES、MRP、ERP 当前协作边界

```mermaid
sequenceDiagram
  participant ERP as ERP 轻量能力
  participant MRP as MRP 轻量能力
  participant MES as MES 核心
  participant DB as 统一业务数据库

  ERP->>DB: 客户、销售订单、默认销售价
  MRP->>DB: BOM、需求和生产订单基础数据
  MES->>DB: 实绩、库位、库存流水、质量、设备
  Note over ERP,MES: 当前仅共享主数据和显式业务关系
  Note over ERP,MES: 不自动执行销售转计划、计划转工单、工单转发货
```

## 7. 权限组与人员授权

```mermaid
sequenceDiagram
  actor A as 权限管理员
  participant UI as 人员/组权限页面
  participant API as Permissions HTTP Adapter
  participant S as Identity Access Service
  participant DB as Prisma Transaction
  participant Audit as AuditLog

  A->>UI: 修改权限组或人员分组
  UI->>API: 提交字段化权限契约
  API->>S: 当前操作人 + 已校验输入
  S->>S: 校验资源 grant 与权限组可分配范围
  S->>DB: 原子替换权限组设置/人员分组
  DB-->>S: 变更前后快照
  S-->>API: 审计数据
  API->>Audit: 写入请求级操作审计
  API-->>UI: 权限已保存
```

权限 API 只处理 HTTP、会话入口、审计和错误映射；权限契约、授权规则与事务归 `modules/identity-access`，避免页面、API 和数据库写入各自维护一套授权逻辑。
