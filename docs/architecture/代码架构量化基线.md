# MES-lite 代码架构量化基线

事实基线：`v0.1.452` / 2026-09-02。

本文把模块化与代码冗余从一次性人工判断变成可重复度量。它描述代码结构，不代表业务流程、生产数据或生产部署已经验收。

## 1. 执行方式

```bash
npm run audit:architecture
npm run audit:architecture -- --json
npm run verify:architecture-baseline
```

- 第一条输出适合人工阅读的摘要。
- 第二条输出完整 JSON，可交给趋势图、CI 或外部分析工具。
- 第三条对照 [`code-architecture-baseline.json`](./code-architecture-baseline.json) 执行非回退检查。

度量只读取 `app/`、`modules/`、`lib/`、`prisma/schema.prisma` 和 Git 提交信息，不连接数据库，也不写业务数据。

## 3. 依赖图事实

当前没有越过 `modules/<domain>/index.ts` 的深层导入，但存在三组直接双向依赖：

- `bom <-> materials`
- `configuration <-> equipment`
- `inventory <-> production`

沿其他单向依赖继续追踪后，以下七个模块属于同一个强连通分量：

```text
bom <-> configuration <-> equipment <-> inventory <-> materials <-> production <-> quality
```

所以“三组双向依赖”不等于“三座隔离的小环”。长期目标是先打断直接双向边，再让整个强连通分量消失；仅把导入换到公开出口不能解决循环依赖。

## 5. 治理顺序

1. **库存内聚**：已将收货建批、可用批次 FIFO 消耗/恢复和生产投入分配提取到 `inventory-lot-issue-service.ts`，并将发货分配/冲销、历史发货兼容和退货回批次提取到 `inventory-shipment-lot-service.ts`；`inventory-status-service.ts` 已由 1,237 行递减到 556 行。下一步处理生产谱系、调拨/状态/处置，并将 `lib/inventory.ts` 收归库存领域，同时保持公开事务入口和冲销不变式稳定。
2. **切断直接双向依赖**：跨领域页面组合上移到应用/工作区组合层，通用选择器和排序规则明确唯一所有者。
3. **高变化 UI 协调器**：优先处理来料、物料和生产页面，通过业务 Hook、任务面板和稳定动作契约降低主协调器复杂度。
4. **低风险精确重复**：先统一日期条件、成本公式和相同查询投影；短小 Route Handler 样板保持显式，避免用通用处理器隐藏权限和审计差异。
5. **模型收敛专项**：Product/Material 双轨必须基于生产数据预检、映射、备份和回滚证据单独推进，不与普通前端拆分混合。

## 6. 基线维护规则

- 普通功能提交不得调高 JSON 预算来绕过失败。
- 文件、克隆、依赖环或双轨模型减少后，应在同一提交下调对应预算。
- 新增超过 600 行的 UI 或超过 700 行的核心文件直接失败；确需例外时必须在架构文档中说明不可拆分的事务边界。
- 依赖环按完整强连通分量和直接双向边同时检查，避免在既有大环内悄悄增加新反向依赖。
- 当前度量与 `verify:module-boundaries`、`verify:structural-goal` 互补：前者提供趋势预算，后两者继续负责不可突破的结构底线。
