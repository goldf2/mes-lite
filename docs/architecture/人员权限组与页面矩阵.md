# MES-lite 人员权限组、页面与操作矩阵

状态：规划基线，尚未作为系统预置权限写入数据库。

本文用于统一回答三个问题：人员应该加入哪些权限组、权限组可以进入哪些页面、进入页面后可以执行哪些操作。矩阵以当前页面注册表和后端权限资源为依据，但同时标出需要拆分的过粗权限资源，避免把页面可见性误当成完整授权。

## 1. 权限动作

| 代码 | 系统字段 | 含义 |
| --- | --- | --- |
| `R` | `canRead` | 查看页面、列表和详情 |
| `C` | `canCreate` | 新建记录或业务单据 |
| `U` | `canUpdate` | 修改、提交或执行状态动作 |
| `A` | `canDelete` | 归档；业务页面不直接物理删除 |
| `G` | `canGrant` | 将对应权限授予其他人员或权限组 |

`RCU` 表示同时具有查看、新建和修改权限；空白表示没有入口和操作权限。业务状态动作未来应继续拆成独立命令权限，不能长期把审核、确认、冲销都等同于普通 `U`。

## 2. 建议权限组

| 组代码 | 权限组 | 典型人员 | 边界 |
| --- | --- | --- | --- |
| `BASE` | 基础访问组 | 所有正式账号 | 只提供通用只读入口，不包含业务写入 |
| `PROD_EXEC` | 生产执行组 | 操作工 | 查看任务、报工、扫码和流程转移，不建立生产计划 |
| `PROD_LEAD` | 生产管理组 | 班组长、生产主管 | 生产订单、派工和现场异常处理 |
| `WH_EXEC` | 仓库作业组 | 仓管员 | 来料、收发、移库和库存执行 |
| `WH_LEAD` | 仓库管理组 | 仓库主管 | 在仓库作业基础上维护库位并处理归档 |
| `QUALITY` | 质量检验组 | 质检员 | 使用质量任务工作台和 `qualityDecision` 记录客观检验结果，不自动获得不合格处置或授权放行 |
| `QUALITY_DISPOSITION` | 质量处置组 | 质量工程师、处置协调人 | 使用 `qualityDisposition` 执行复检、返工和报废，不自动获得让步/解冻放行 |
| `QUALITY_RELEASE` | 质量授权放行组 | 质量负责人 | 使用 `qualityRelease` 执行让步与解冻，应限制为少量经批准人员 |
| `PROCESS` | 工艺技术组 | 工艺、BOM 工程师 | 物料、BOM、工艺、单位和作业文件维护 |
| `PLANNING` | 生产计划组 | 计划员 | 生产计划、派工计划和跨模块只读信息 |
| `EQUIP` | 设备维护组 | 设备管理员、维修员 | 设备台账与维护资料 |
| `DOC` | 文档管理组 | 文控人员 | 文档、类别、版本、附件和归档 |
| `SALES` | 销售发运组 | 销售、跟单、发运人员 | 客户、销售订单、发货和退货 |
| `PERSONNEL` | 人员管理组 | 人事、账号审核人员 | 员工档案和账号启停，不授予业务权限 |
| `PERMISSION` | 权限管理员组 | 指定安全管理员 | 权限组和人员赋权，不自动拥有系统维护能力 |
| `SYS_ADMIN` | 系统管理员组 | 系统负责人 | 全部页面和动作；控制在一至两人 |

分配规则：除 `SYS_ADMIN` 外，正式账号先加入 `BASE`，再按岗位叠加一个或多个业务组。不要按人员姓名创建权限组，也不要使用“综合权限组”复制多个岗位权限。

## 5. 跨页面能力

| 能力 | 当前资源 | 目标规则 |
| --- | --- | --- |
| AI 协作助手 | `aiAssistant` | `BASE:R` 只允许打开助手；实际工具继续按目标业务资源二次过滤 |
| 附件 | `attachments` | 全局附件动作与所属单据权限必须同时满足；查看继承所属单据 `R`，上传继承 `C/U`，归档继承所属单据维护权限；暂存附件还按登录账号隔离，不授予脱离业务对象的附件访问 |
| 权限总入口 | `permissions` | 逐步停用这个宽泛资源，统一使用 `permissionUsers` 和 `permissionGroups` |
| 个人权限覆盖 | `OperatorPermissionOverride` | 只处理例外，必须记录原因、授权人、开始时间和失效时间；不作为日常分配方式 |

## 6. 当前实现与落地顺序

当前有效权限算法为：管理员全权；非管理员无权限组时使用角色默认权限；一旦加入权限组，只合并所有权限组，不再叠加角色默认权限；个人覆盖最后替换对应资源。这意味着现阶段给人员分配岗位组时必须同时分配 `BASE`。

建议实施顺序：

1. 先拆分表中使用 `system`、`stats` 和复合 BOM 的权限资源，并让页面、API、AI 工具读取同一资源声明。
2. 将 `BASE` 和岗位组写为系统预置权限组；已有三组保留并提供迁移映射，不直接覆盖用户自定义组。
3. 把权限计算调整为“角色基础权限 + 权限组并集 + 有期限的个人例外”，并明确是否需要显式拒绝。
4. 增加部门、工作中心、仓库/库位、本人/本班组等数据范围权限；没有数据范围前，不把“可进入页面”等同于“可查看全部数据”。
5. 增加矩阵覆盖校验，确保每个页面键、API 资源和 AI 工具都能追溯到稳定权限资源。

本文只定义目标矩阵，不修改当前账号、权限组、数据库预置数据或接口行为。
