# MES-lite 系统功能全景与完备性审查

状态：当前代码事实 + 产品复盘清单
事实基线：`v0.1.431` / 2026-08-22

## 1. 审查方法

本审查不以“有页面、有按钮”为完成标准。每个业务能力按以下闭环检查：

```mermaid
flowchart LR
  Input["输入<br/>主档、数量、人员、来源"] --> Process["处理<br/>校验、状态机、事务"]
  Process --> Output["输出<br/>单据、任务、批次、结果"]
  Output --> Ledger["库存 / 成本<br/>余额、成本层、流水"]
  Ledger --> Trace["追溯<br/>来源、快照、附件、审计"]
  Trace --> Reverse["逆向<br/>冲销、退货、处置、恢复"]
  Reverse -.安全条件满足.-> Input
```

状态定义：

- **当前闭环**：在当前单厂、人工/扫码操作范围内，主路径与安全逆操作均有事实记录。
- **基础可用**：可完成主要任务，但实时性、异常颗粒度、自动化或管理深度不足。
- **横切支撑**：为多个业务域提供一致能力，不单独产生制造结果。
- **兼容过渡**：仅服务历史数据或迁移，不应继续扩张。

## 2. 17 个模块功能全景

| 模块 | 面向角色与入口 | 主要输入与处理 | 输出、账务与追溯 | 当前判断 | 主要缺口或停止线 |
| --- | --- | --- | --- | --- | --- |
| `workspace` | 全员；工作台、待办和统计 | 汇总订单、质量、库存、设备等只读事实 | 指标、任务入口、跨页导航；不另建业务账 | 横切支撑 | 只做事实聚合，不把复杂分析逻辑塞进仪表盘 |
| `materials` | 工程、计划、仓库；物料管理/全景 | 物料编码、单位、分类、图片、兼容映射 | 唯一物料主档、关联 BOM/库存/订单的全景 | 基础可用 | `Product` 历史兼容仍需最终收敛；不把物料页变成万能业务页 |
| `bom` | 工程、计划；BOM 设置/全览 | 草稿结构、用量、损耗、主产出、版本命令 | 发布版本、订单快照、成本输入；发布后不可修改 | 当前闭环 | 自动替代料、复杂工程变更审批和完整 MRP 展开未建设 |
| `production` | 计划、班组、生产主管；订单、派工、实绩、转移 | 订单+BOM 快照、人员、实际设备、作业文件、投入/产出 | FIFO 投入、产出批次、谱系、库存/成本流水、进度和安全冲销 | 基础可用 | 偏班后实绩；缺少实时开工/暂停、工时机时、异常原因和 APS |
| `receiving` | 仓库、质量；来料登记 | 供应商、物料、数量、价格、批号、库位、检验标准 | 收货批次、成本层、库存流水、按标准自动送检和安全红冲 | 当前闭环 | 缺少采购订单/到货预约/复杂收货差异审批；这些属后续 ERP 协同 |
| `quality` | 检验员、质量主管；质量标准、任务、趋势 | 版本化标准、抽样、逐项结果、附件、判定和处置 | 快照、合格/冻结/返工/报废状态、处置历史及库存去向 | 当前闭环 | SPC/过程能力、原因分类主数据、多级评审和实验室仪器采集未建设 |
| `inventory` | 仓库、计划、审计；库存、批次、流水 | 来料/生产/发货/退货/转移的统一过账命令 | 总量、库位、状态、批次、成本层、流水、正反向谱系和冲销关联 | 当前闭环 | 缺仓库层级、波次/拣配、序列号、客户指定批次和独立受控状态调整 |
| `sales` | 销售、仓库、质量；销售订单、发货、货箱、退货 | 客户需求；独立的客户＋多条实际发货物料；货箱内容物、打包人/时间/照片、物流号和发货批次 | 客户物料交付参考、装箱完整性、唯一箱码/发货单码、发货扣账、客户去向、剩余可退数量、独立退货待检批次 | 当前闭环 | 销售订单与发货不绑定；缺信用、应收、开票和复杂履约编排 |
| `equipment` | 设备、生产、维修；设备、工作中心、点检、维保 | 台账、受控事件、点检项、计划/工单、备件领用 | 设备状态时间线、不可覆盖点检事实、维修恢复、备件库存/成本批次 | 基础可用 | 缺 PLC/边缘采集、停机原因、节拍、能源、MTBF/MTTR 和 OEE |
| `documents` | 工程、现场；作业文档与类别 | 文件、类别、基础/分类扩展字段、版本、适用范围、批量导入/修改和归档命令 | 独立受控文件、分类元数据、生产实绩文件快照、预览与引用 | 基础可用 | 缺完整电子签审、变更审批和培训签收；不替代通用 Wiki/DMS |
| `configuration` | 管理员；企业、客户/供应商、单位、库位、员工等配置 | 公共资料 CRUD、唯一性、默认值和引用保护 | 可归档主档与公共选项 | 横切支撑 | 只承载同构配置；工作中心、文档类别等仍由各自领域拥有 |
| `identity-access` | 管理员、主管；账号、人员、权限组 | 登录身份、审核、角色、资源动作、数据范围、临时授权 | 会话、授权结果、人员绑定和变更审计 | 横切支撑 | 部门/班组组织范围和更复杂职责分离仍有限；前端隐藏不等于授权 |
| `attachments` | 所有业务角色；详情附件 | 上传、草稿绑定、业务归属、预览、归档 | 原文件、派生预览、关联事实和生命周期记录 | 横切支撑 | 外部对象存储是后续候选；原文件与数据库必须同周期备份 |
| `business-documents` | 业务人员；打印、归档和扫码解析 | 受支持单据的投影、模板、附件、`BX-/SH-` 单据码 | PDF、打印链接、二维码、单据定位和归档缓存 | 横切支撑 | 当前不是通用报表设计器；模板扩展需按单据契约验证 |
| `sop` | 全员；快捷帮助、完整帮助、文档库 | 页面键、角色、前置条件、步骤、结果检查、截图、媒体清单 | 站内帮助、Markdown、可生成 DOCX/PDF/离线 Web、视频关联 | 横切支撑 | 需随工作流变化更新；视频按跨页典型流程组织，不按每个按钮拆分 |
| `system-settings` | 管理员；显示、导航、文件预览、AI 设置 | 品牌、模块入口、导航顺序、CAD 引擎选择与状态、AI 提供方安全配置 | 统一应用壳偏好和受控设置 | 横切支撑 | CAD 引擎只影响派生预览，不修改原附件或设计事实；密钥只可服务端加密保存 |
| `operations-tools` | 管理员、运维、工程/仓库；数据/审计/扫码/成本工具 | 备份、恢复、归档、审计、数据检查、单据扫码、扫码计数、标签和专项计算 | 维护证据、恢复候选、审计查询、货箱/发货单定位和辅助结果 | 横切支撑 | 数据维护不是日常业务入口；危险动作必须显式授权、确认并保留审计 |

## 3. 关键业务闭环审查

| 业务链 | 输入 | 核心处理 | 输出/账务 | 追溯与逆向 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 来料入库 | 供应商、物料、数量、价格、批号、库位 | 接收/拒收；按已发布 `MATERIAL_IN` 标准决定直接可用或待检 | 内部批次、库存、成本层、流水、质量任务 | 供应商批号可追溯；未被下游使用时整单红冲 | 当前闭环 |
| 生产执行 | 生产订单、BOM 快照、员工、实际设备、作业文件、投入/产出 | 草稿→确认；投入 FIFO；产出建批；质量任务；订单进度重算 | 投入扣减、产出待检、成本结转、父子批次谱系 | 冻结执行快照；安全条件下恢复投入并冲销产出 | 基础可用，实时执行不足 |
| 质量处置 | 已发布标准、抽样、逐项结果、批次 | 判定 PASS/FAIL；复检、返工、报废、让步、解冻 | `AVAILABLE / HOLD / REWORK / QUARANTINE` 及库存/成本变化 | 标准与任务快照、附件、处置历史；处置动作可复盘 | 当前批次级闭环 |
| 销售履约 | 客户需求；独立的多明细发货；可用批次、货箱内容物与打包照片 | 客户物料交付量动态参考；发货单关联多货箱；已开始装箱时校验数量完整；发货确认并按明细和批次扣减；限制超量退货 | 唯一箱码/发货单码、物流号、客户去向、发货流水、退货独立待检批次 | 销售需求与发货事实不绑定；扫码返回货箱或发货单；原发货明细→退货→质量结果可追溯 | 当前闭环 |
| 库内转移 | 来源/目标库位、数量、批次 | 校验可用余额并同步总量、库位和批次状态余额 | 统一库存流水和新库位余额 | 精确来源/冲销关系；安全条件下逆转 | 当前闭环 |
| 设备维保 | 设备状态、点检结果、计划/故障、备件 | 状态机、点检异常触发故障、工单开始/完成、备件 FIFO | 设备恢复、时间线、备件库存/成本流水 | 事件、点检、工单、附件与领用批次关联 | 基础闭环，自动采集不足 |

## 4. 明确尚未完备的能力

### 4.1 优先补齐

1. **现场实时执行颗粒度**：开工、暂停、恢复、异常原因、人工工时和设备工时，而不只记录班后汇总。
2. **质量分析**：缺陷/原因主数据、SPC、过程能力和按真实需要设计的评审流。
3. **设备自动化**：独立边缘采集器、时间同步、停机原因与 OEE 口径；不能把 PLC 协议直接耦合进 Web 请求。
4. **仓储深度**：仓库层级、序列号、指定批次、拣配与复核，仅在真实业务需要时扩展。
5. **历史模型收敛**：完成 `Product` 映射与旧生产日报盘点后，制定可回滚迁移和下线路线。

### 4.2 明确不应被按钮误导为已交付

- 完整 MRP 净需求、采购建议、产能平衡与 APS。
- 财务总账、应收应付、税务、工资、固定资产。
- 专业 WMS 波次、立库控制和全自动拣选。
- 多组织、多租户 SaaS 和离线冲突同步。

这些能力可以通过预留的 MRP/ERP 模块入口逐步接入，但当前不能作为 MES-lite 已完备功能对外承诺。

## 5. 功能复盘问题模板

对每项功能都回答以下问题；任何一项没有答案，就不能仅凭页面存在判定“完成”。

1. 谁在什么事件发生后启动它？
2. 必填输入来自哪里，是否冻结版本或快照？
3. 哪些状态转换被允许，谁有权限执行？
4. 成功后产生什么单据、任务、批次、库存或成本事实？
5. 失败、部分成功和重复提交怎样处理？
6. 能否从结果追到来源、人员、时间、附件和理由？
7. 误操作如何冲销、退货、处置或恢复，哪些下游事实会阻断逆操作？
8. 当前页面和 SOP 是否能让对应岗位独立完成？

## 6. 视频与功能介绍的拆分方式

不建议“一页一个视频”，也不建议“一按钮一个视频”。视频应按可产生业务结果的跨页工作流组织：

| 视频系列 | 建议覆盖页面 | 完成结果 |
| --- | --- | --- |
| 新物料投产准备 | 物料 → BOM → 工艺路线 → 作业文档 | 可创建带有效快照的生产订单 |
| 来料接收与质量放行 | 来料 → 质量任务 → 批次/库存流水 | 原料批次可用或受控冻结 |
| 生产订单到产出放行 | 生产订单 → 派工 → 实绩 → 质量任务 → 批次全景 | 产出批次可用且投入谱系可追 |
| 库内转移与查账 | 库存 → 流程转移 → 库存流水 → 批次全景 | 数量、库位和来源一致 |
| 销售发货与退货处置 | 销售订单 → 发货 → 退货 → 质量任务 | 客户去向和退货回流闭环 |
| 设备异常到恢复 | 设备事件/点检 → 维保工单 → 备件领用 → 恢复 | 状态、维修证据和备件成本可追 |
| 权限与岗位上线 | 人员 → 权限组 → 数据范围 → 临时授权 → 审计 | 岗位能做且只能做授权动作 |
| 备份与恢复演练 | 数据工具/服务器配置 → 备份 → 校验 → 隔离恢复 | 可证明数据库与附件能恢复 |

每个视频内部再用章节标记页面和动作；文字 SOP 继续保留细颗粒度步骤，视频负责解释业务目的、角色交接和跨页结果。

## 7. 审查结论

MES-lite 已形成单厂人工/扫码场景下的基础业务骨架，并在 BOM、来料、批次库存、质量处置、销售退货和受控逆操作上建立了可验证事实。当前短板集中在实时执行、质量统计、设备采集和更深的仓储/计划能力，而不是“再增加更多一级菜单”。下一轮产品决策应优先验证这些缺口是否来自真实车间，再决定扩展顺序。
