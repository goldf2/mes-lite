# 宇峰业务工作台：真实功能接入

v0.1.487（含485接入及486逐项修正）。统一平台入口为 `https://mes.csyufeng.com/workbench`，规范化为 `/?page=businessWorkbench`。原 MES 独立首页 `/?page=dashboard` 保留；其常用功能和搜索只包含原 MES 目录，并提供返回统一平台入口。工作台属于现有 MES Web 应用壳，两个业务代码库、数据库、登录会话和发布流程继续独立；不是把先前 HTML 草图作为业务系统部署。

## 入口与真实页面

统一平台、全部功能和侧栏使用原生页面与已核对外部入口合成的可用功能目录，原生项目从 `lib/page-registry.ts` 派生，经当前人员读取权限、管理员限制和已启用工作区筛选；各自的搜索与收藏继续使用相同过滤结果。原 MES 首页仅消费原生目录，保留返回统一平台的原生入口。点击调用既有 `openWorkspaceFunction`，由页面渲染注册表装配原有业务 UI、API 和事务服务。

| 功能 | 真实入口 | 原有 API |
| --- | --- | --- |
| 统一平台首页 | `/workbench` → `/?page=businessWorkbench` | 真实功能目录及当前人员偏好 |
| MES 独立首页 | `/?page=dashboard` | `/api/stats/dashboard` |
| 全部功能 | `/?page=allFunctions` | 权限过滤的实际目录 |
| 销售订单 | `/?page=salesOrders` | `/api/sales-orders` |
| 生产订单及进度 | `/?page=orders` | `/api/orders`、订单详情及实绩接口 |
| 生产日报 | `/?page=dailyInventory` | `/api/daily-production-shortcut` |
| 库存管理 | `/?page=stocks` | `/api/stocks` |
| 发货管理 | `/?page=shipment` | `/api/shipments` |

`orders` 只表示生产订单，销售必须使用 `salesOrders`。没有新增“生产任务”“各工序进度”“订单明细”“按订单交付查询”等占位页面。生产进展仍以实际订单的计划、完成、报废、状态与实绩为准；销售交付参考仍是既有客户＋物料动态统计。

原生页面继续复用原列表、卡片、详情、新增表单、校验与写操作权限。未授予的业务页面不出现在目录、搜索或收藏；私有 API 继续服务端拒绝。收藏使用当前操作人员已有的工作台偏好服务，不新建共享角色或权限。

## 数据平台真实入口

`modules/workspace/domain/data-platform-functions.ts` 仅描述已核对的跨应用页面：客户、联系人、客户地点、客户设备、型号、安装及客户/设备地图。不复制页面或联系人，不创建代理业务数据，也不把本地地图订单图层宣传为 MES 订单统计。

非秘密构建变量 `NEXT_PUBLIC_DATA_PLATFORM_WORKSPACE_URL` 默认 `https://fix.xiangshu.me/workspaces/local/default`，未来域名/工作区可替换。Docker builder 已声明同名 ARG，构建时可传入；Next.js 将公开目标嵌入客户端，域名修改后需重建。显式空值关闭外部入口；非 HTTPS、带账号密码/查询/片段或非工作区路径的值不产生链接。

每个目标使用目标应用 `/login?next=<精确本地业务路径>`，避免其未登录工作区布局把目的地降为首页。导航只传本地 `next`；不转发 MES Cookie、Token 或用户自报身份。当前 MES 需有对应客户/设备读取权限才显示入口，目标仍独立完成 Casdoor 登录与本地业务授权；菜单可见不是目标应用授权证明。

数据平台顶栏返回入口通过其既有 `APP_PORTAL_URL` 设置为 `https://mes.csyufeng.com/workbench`；此项属于部署配置，不要求合并代码库。没有更改 Casdoor 源、客户端、账号归属或真实权限。

## 个人首页与异常

独立统一平台显示跨应用的真实快捷入口、我的收藏和功能搜索。原 MES 首页继续保留实际岗位待办、生产/库存/交付统计及原生常用入口。全部功能和两个首页复用同一套偏好服务，保存调用 `/api/workspace-preferences`；首次偏好加载和跨页保存期间禁用偏好操作，避免完整 PUT 覆盖未读或尚未保存的状态。权限撤销后，保存过的功能键也必须先与当前可用目录交集，不恢复已撤销入口。

原 MES 首页的统计接口失败时显示错误与重试，仍保留功能入口；不能把失败转成全零业务统计。独立统一平台不依赖该统计请求。外部应用不可用时不制造本地替代联系人，也不宣称共享数据接入完成。

## 验收和发布边界

本次基于生产 main v0.1.481，不合入未启用的 v0.1.484 联系人数据迁移。无 Prisma 模型、迁移、业务记录改写或生产测试造单；历史打印不受影响。

必须验证：真实本地账号登录；首页/全部功能点击进入销售、生产、库存及发货原页面，读取可辨认的隔离样本并能打开原新增表单；收藏保存后重载保持；受限账号目录/搜索/旧收藏过滤且业务 API 403；外链精确目的地；390px 无溢出。合成账号和数据库只用于隔离验收，不能充当生产 Casdoor 证据。

精确候选 SHA 的完整 GitHub CI 通过后才推进 main。生产验收另核对发布 SHA/版本、原持久卷、启动前一致备份、公开 ready，以及已有真实账号下的页面和只读接口。部署记录保留当前事实，不把健康检查或入口配置当作完整业务验收。

帮助中心也属于逐项入口验收：应用内使用公共 ResourceToolbar 顶部搜索，独立 `/help` 使用相同控件内联显示；加载和失败状态仍挂载工具栏。

冷启动的 Casdoor 登录按钮携带当前本站路径和查询条件；统一平台和原 MES 首页各自返回原处。服务端继续执行原 safeLoginReturn/OIDC/人员绑定验证，不通过客户端参数授予任何权限。

## v0.1.488 手机功能搜索

仅统一平台和全部功能在小于 1024px 时把 `SearchFieldWithPresets` 放到标题下方整行展示；手机顶栏放大镜定位并聚焦该输入框，高级搜索、页内选项和二维码仍使用原公共页面工具。桌面继续原 `TopBarPortal`，原 MES 首页默认不启用新布局。关键词、条件和快捷搜索继续使用同一份受控状态与原存储键；手机不同时挂载顶栏与内容区两套快捷搜索。无全局 CSS、注册路由、权限、业务 API 或数据模型变化。
