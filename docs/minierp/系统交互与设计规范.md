# MES-lite 系统交互与设计规范

本文是 MES-lite 界面与交互设计的主规范，是产品设计、前端开发、评审和验收的共同依据。目标不是让所有页面长得完全相同，而是让相同语义使用相同组件、相同操作得到相同反馈、相同设备采用稳定的布局模型。

## 1. 文档定位

### 1.1 适用范围

本规范适用于：

- Web 桌面端和移动端的应用壳、导航、列表、卡片、表单、弹窗、菜单、文件查看和反馈状态。
- 新建页面、改造旧页面、公共组件开发、视觉评审、响应式验收和无障碍检查。
- 业务功能中的浏览器偏好、显式保存、危险操作、权限呈现和审计反馈。

打印标签、扫码设备、PDF 渲染等领域能力仍遵循各自业务文档；只要出现在 Web 界面中，其操作入口和反馈仍受本规范约束。

### 1.2 规范层级

发生冲突时按以下顺序处理：

1. 本文定义系统级交互语义、设计令牌、组件选型和验收底线。
2. `桌面端界面开发规范.md`、`移动端界面开发规范.md`定义设备专项布局。
3. `响应式断点与验收矩阵.md`定义实际视口验证要求。
4. `layout-architecture.md`定义应用壳、导航和工作区结构。
5. `界面开发规则.md`作为开发阶段的详细实现清单。

`现代化连续工作区体验参考.md`补充用户强感知的产品体验目标和连续任务验收方式；它不改变本文的保存、权限、危险操作和响应式底线。

业务页面不得自行发明与上述规范冲突的新交互。确需例外时，应在相关业务文档记录原因、范围和退出条件；影响多个模块或难以回退的例外写入 ADR。

### 1.3 多平台边界

- 当前规范中的桌面端和移动端首先指同一 Web 应用的响应式设备形态，不代表维护两套业务页面。
- 未来桌面 App 使用 Tauri 薄壳，移动 App 使用 Capacitor 薄壳；两者复用当前 Web 前端、API、账号、权限和数据模型。
- 平台壳只增加窗口、导航、签名、自动更新及扫码、拍照、打印、文件等原生适配，不复制业务流程和页面。
- 原生能力通过适配接口提供给共享组件；能力不可用时显示明确状态或使用 Web 降级路径，不能让共享页面静默失效。
- 正式发布其他平台前，先确认 Web 的来料、生产日报、库存、发货、退货和 BOM 核心闭环稳定。详细决策见 `docs/adr/0017-single-web-core-and-thin-platform-shells.md`。

## 2. 设计原则

### 2.1 一致而可预期

- 相同动作使用相同文案、颜色、位置和关闭方式。
- 相同数据对象使用相同选择器、格式和状态颜色。
- 同一功能在桌面端和移动端可以改变布局，但不能改变业务含义和结果。

### 2.2 业务优先

- 页面先帮助用户完成查找、录入、核对和追溯，再考虑装饰。
- 高频操作直接可见；低频、批量或危险操作进入“工具”或“更多”。
- 关键业务数据不能只靠颜色、图标、悬停或隐藏菜单表达。

### 2.3 防错且可恢复

- 输入就近校验，失败保留已填内容，并将焦点移到首个错误字段。
- 业务数据默认显式保存；避免用户不知情的静默写入。
- 归档、冲销、永久删除等动作明确区分，并在服务端再次校验权限和状态。

### 2.4 渐进展示

- 列表只展示判断所需的核心字段，详情承载完整信息。
- 手机端缩减同屏信息，不删除核心能力；低频操作进入页面工具抽屉。
- 空状态、加载和错误都必须可辨认，不能用空白页面代替。

### 2.5 键盘、触控和无障碍同等可用

- 可点击元素必须可聚焦并有明显焦点态。
- 弹窗、菜单、搜索选择器和排序表头支持键盘操作。
- 图标按钮必须提供可访问名称；颜色不是唯一状态提示。

### 2.6 连续而低打扰

- 查看、编辑、关联和继续处理优先在同一工作区完成，避免为了简单动作整页跳转。
- 从列表打开详情、切换编辑态或保存数据时，必须保持搜索、筛选、选中对象和滚动位置。
- 保存成功后停留在当前对象上下文；失败保留输入和已选关系，并给出可继续处理的说明。
- 即时反馈优先采用局部状态和轻量提示，不用多层弹窗或全屏加载打断连续任务。
- 连续工作区的产品体验和验收方法见 `现代化连续工作区体验参考.md`。

## 3. 信息架构与导航

### 3.0 层级上限

- 系统采用“一级业务入口 + 最多两级页面”的结构：一级入口负责业务分组，一级页面承载列表/工作区，二级页面承载详情或稳定子页；不得再新增第三级业务页面。
- 从工作台常用入口或“所有功能”页进入任一一级页面只需一次操作；从应用入口到终端业务功能不超过三次跳转。
- 高频功能直接出现在工作台；完整但低频的入口统一进入“所有功能”页，不通过继续嵌套菜单解决。

### 3.1 只维护两种设备形态

- 桌面端：视口宽度 `>= 1024px`。
- 移动端：视口宽度 `< 1024px`，包括手机、折叠屏和平板竖屏。

设备形态只决定布局，不改变权限、字段定义和业务规则。具体宽度模拟见 `响应式断点与验收矩阵.md`。

### 3.2 桌面端结构

- 顶部应用栏是基础控制区，保留品牌、当前页面的搜索/筛选/视图/主操作、全局工具和账户入口，不再承载一级业务导航。
- 左侧导航区统一显示一级业务域；当前业务域在原位展开所属页面，存在稳定父子关系时最多展开一层。
- 中央区域是主工作区。
- 右侧辅助区只在详情、BOM 或当前选择的上下文确有需要时出现，并允许调宽；无内容时收起。
- 左侧辅助区已经明确选中当前页面时，桌面工具栏只承载搜索、筛选、视图切换和页面操作，不重复显示“业务功能/页面名称”；没有工具栏操作的仪表盘不渲染空标题栏。移动端仍在顶部应用栏显示当前页标题。

### 3.3 移动端结构

- 顶部第一行固定为菜单按钮、当前页标题、账户入口。
- 顶部第二行按需展示搜索、筛选和“工具”，无内容时不占高度。
- 底部导航只放用户配置的常用入口，不设置与顶部菜单重复的“更多”。
- 菜单按钮打开左侧全高功能抽屉，按工作台、物料、生产、文档、设备、物流、销售、库存、业务配置、系统设置、工具分组；系统设置下先提供显示设置和 AI 服务，不预置没有正文能力的空入口。
- 页面工具抽屉承载新增、导入、导出、类别管理和视图切换等页面级操作。

### 3.4 工作台与所有功能

- 工作台包含仪表盘和个人常用功能区；常用功能只显示当前账号有权访问的页面。
- 常用功能支持“系统默认”“智能排序”“自定义”三种模式。智能排序按当前账号主动打开页面的次数、最近使用时间排序，并允许固定常用项；刷新、后台重新请求和系统跳转不得增加次数。
- 自定义模式允许选择、拖动、上移、下移和移除快捷入口；设置保存在服务端并跟随账号。
- “所有功能”作为工作台下的独立一级页面，按业务入口分组并支持关键词搜索，是完整功能目录而不是新的导航层级。
- 工作台常用功能使用紧凑快捷卡片：图标、名称、描述和使用/固定状态不得形成大面积留白；普通桌面按 5 列、超宽桌面按 8–10 列自适应，优先让经营指标进入首屏。

### 3.5 滚动规则

- 应用栏、桌面侧栏和页面标题/工具栏不随业务内容滚动。
- 普通页面只有一个纵向内容滚动区；桌面端由标题/工具栏下方的主内容区统一承载，并在内容超出视口时始终显示最右侧滚动轨道，禁止父层隐藏滚动后又没有子层接管。
- 桌面主从双区允许左右各一个独立纵向滚动区；除此之外禁止无理由嵌套纵向滚动。
- 宽表只在表格容器内横向滚动，页面本身不得横向滚动。
- 移动端固定底栏必须预留实际高度、安全区和页尾间距，不能遮挡分页、保存栏或最后一条内容。

### 3.6 全局 AI 协作入口

- 桌面端在顶部页面工具区右侧、页面选项与账号入口左侧显示专用 AI 助手图标；悬停或键盘聚焦时必须提示“打开 AI 助手”。移动端固定在底部导航并保留“问 AI”文字，不能只依赖图标。
- AI 图标静止时使用缓慢匀速旋转和轻微呼吸动效；悬停或键盘聚焦时暂停旋转，只保留轻微放大反馈，按压时短促收拢。动效不得造成布局位移，并必须遵循系统的“减少动态效果”偏好。
- AI 使用右侧全高协作面板，背景遮罩阻止底层误操作；移动端占满可用宽度。面板内部独立滚动，输入区固定在底部并避让安全区。
- 面板必须显示当前页面、只读状态、权限边界和回答数据来源。服务未配置、停用、超时、限流或无权限时显示明确状态。
- 管理员可从 AI 面板直接进入“系统设置 → AI 服务”，维护提供商、兼容接口地址、模型、API Key、超时和工具轮次并测试已保存配置。API Key 输入不得回填，页面只显示配置来源、保存状态和脱敏提示。
- AI 首屏直接提供可提问示例，不再叠加单独的首次使用教学弹窗。AI 可以承接大段操作说明，但字段标签、校验错误、状态和危险确认仍由页面负责。
- 详细能力和安全边界见 `docs/ai-agent/MES-Agent规范.md`。

## 4. 设计令牌

设计令牌由公共组件实现。业务页面使用语义名称，不直接复制颜色和尺寸。

### 4.1 颜色语义

| 语义 | Tailwind 基准 | 用途 |
| --- | --- | --- |
| 主操作 | `blue-600`，悬停 `blue-700` | 保存、提交、确认、当前选中 |
| 新建/成功 | `emerald-600`，悬停 `emerald-700` | 新建对象、成功状态 |
| 普通操作 | 白底、`gray-300` 边框、`gray-700` 文字 | 取消、详情、导入、导出 |
| 提醒/归档 | `amber-500` 到 `amber-600` | 归档、待处理、警告 |
| 危险/错误 | `red-600` 到 `red-700` | 冲销、永久删除、校验错误 |
| 页面与分隔 | `gray-50/100/200` | 页面底色、卡片、边框、禁用态 |

状态必须同时显示文字；禁止只用红绿颜色区分。状态色统一由状态样式映射维护。

### 4.2 间距与密度

- 以 4px 为基础步进，常用间距为 4、8、12、16、20、24、32px。
- 控件内部常用水平间距 12–16px，表单字段间距 16–24px，页面区块间距 24px。
- 页面不能通过大量空白制造“高级感”；桌面业务清单优先信息密度和扫描效率。
- 同一分组内间距小于分组之间的间距，清楚表达层级。

### 4.3 圆角、边框和阴影

- 输入框、按钮、菜单项使用 8px 圆角。
- 普通弹窗使用 12px 圆角。
- 表格、卡片和表单分组使用 1px `gray-200/300` 边框。
- 阴影只用于浮层、弹窗、菜单和需要与背景分离的卡片；页面区块不层层叠加阴影。

### 4.4 字体与文字层级

- 页面标题：20–24px，半粗体。
- 区块标题：16–18px，半粗体。
- 正文和控件：14px。
- 辅助说明和表格次要信息：12px。
- 编码、单号和适合逐字符比较的数据使用等宽字体。
- 文案优先简短动词和业务名词，不使用含糊的“处理一下”“确定操作”等表达。

### 4.5 控件尺寸

| 场景 | 高度 |
| --- | --- |
| 紧凑/行内按钮 | 32px |
| 标准输入框、按钮 | 40px |
| 移动端主按钮 | 44px |
| 标准图标按钮 | 40 × 40px |

移动端触控目标推荐不小于 44px，最低不得小于 36px。同行控件必须同高、同圆角、同字号。

## 5. 公共组件与使用边界

已有公共组件能够覆盖的交互，业务页面不得重新手写同类结构。

| 交互语义 | 公共组件 | 强制规则 |
| --- | --- | --- |
| 按钮 | `app/components/AppButton.tsx` | 只通过 `primary/create/secondary/warning/danger/ghost` 表达语义 |
| 表单字段 | `FormField.tsx` | 统一标签、必填、提示、错误和输入样式 |
| 数值字段 | `NumberInputField.tsx` | 统一最小值、步长、非负约束和单位后缀 |
| 指标卡片 | `MetricCard.tsx` | 统一常规/紧凑密度和主值、成功、警告、危险语义色 |
| 遮罩 | `ModalOverlay.tsx` | 统一遮罩、滚动锁定、焦点恢复、Esc 和点击空白关闭 |
| 普通弹窗 | `ModalDialog.tsx` | 统一标题、正文滚动、固定底部操作区和响应式宽度 |
| 弹窗操作 | `ModalActions` | 取消在前，保存/提交在后；处理中禁止重复提交 |
| 动态数据选择 | `SearchableSelect.tsx` | 可输入筛选、键盘选择、清除、点击外部和 Esc 收起，靠近视口底部时向上展开 |
| 物料选择 | `MaterialChoiceSearch.tsx` | 物料编码、名称、规格的业务搜索，复用统一弹层方向计算 |
| 可排序表头 | `SortableTableHeader.tsx` | 显示方向并设置 `aria-sort` |
| 响应式工具栏 | `ResponsiveToolbarActions.tsx` | 桌面展开操作，移动端收进工具抽屉 |
| 视图切换 | `ViewModeToggle.tsx` | 卡片/列表语义和浏览器偏好保持一致 |
| 快捷搜索 | `SavedSearchPresets.tsx` | 保存当前浏览器的页面搜索预置 |
| 页面排序状态 | `useClientTableSort.ts` | 统一升序/降序切换和稳定排序 |

文件查看、状态标签、数据表格、详情面板继续向公共组件收敛。若公共组件暂不支持合理场景，应先扩展公共组件，再在业务页面使用；不得用大段局部样式绕过组件。

### 5.1 公共骨架与独立实现准入

- 所有前端页面必须建立在公共应用壳和资源工作区之上，并使用公共语义组件完成工具栏、字段、列表、卡片、弹窗、详情、状态反馈和响应式布局。页面不得拥有平行的基础框架实现。
- 新功能开发前先搜索现有组件、Hooks、服务和相邻页面；评审时必须能够说明复用了什么，不能以重新手写作为默认起点。
- 常规资料页面必须复用资源工作区骨架，由配置声明字段、筛选、排序、权限、接口、归档策略和关系；查询、新增、修改、归档与恢复不得按模块复制整套页面。
- 多对象关联统一复用关联编辑骨架：搜索添加、已选列表、防重复、附加字段、移除和未保存提示保持一致。不同业务只通过适配器补充数量、单位、页码、章节、角色等领域字段。
- 公共框架不能满足合理需求时，先修改公共模块或增加稳定扩展点，再由业务页面调用；不得在页面内放置只服务当前页面的框架补丁。公共模块变化必须保持兼容，或同步迁移所有调用方。
- 公共骨架负责布局、视觉、键盘、触控、加载/空/错状态和响应式行为；领域适配器负责显示差异；领域服务负责权限、校验、事务、审计和状态流转。三层不得相互复制职责。
- 同一交互出现两次或已有明确的第二调用方时，必须提取公共模块。只有本文“允许的例外”所列领域主体可专用实现，并应在相关设计文档和提交说明中记录标准组件不能满足的具体约束。
- 公共组件变更视为全局变更，必须检查所有调用方并按影响范围回归；业务页面不得依赖公共组件未声明的内部 DOM 或样式细节。
- 通用化不得牺牲领域约束。库存过账、成本层、生产确认/冲销和 BOM 数量计算继续使用专用服务，只复用页面及关联编辑骨架。

## 6. 标准页面模式

### 6.1 资源列表页

推荐顺序：

1. 页面标题和简短说明。
2. 关键词搜索与快捷搜索。
3. 高级搜索、视图切换、页内选项和页面操作。
4. 列表或卡片主体。
5. 空/错/加载状态。
6. 分页和每页条数。

桌面默认以表格提高扫描效率；移动默认以卡片提高可读性，但用户仍可切换视图。卡片和列表必须覆盖相同核心字段。

### 6.2 新增与编辑表单

- 桌面使用 2–3 列网格；有关联的字段同组，无关字段不强行并排。
- 移动端使用单列；长表单按业务阶段分区，而不是嵌套多个小弹窗。
- 标题区说明动作和对象；正文只放字段；底部只放取消与保存/提交。
- 普通表单使用 `ModalDialog`；高密度录入可以使用 `wide`，但不能无限拉长阅读宽度。

### 6.3 详情与主从工作区

- 详情固定顺序：身份信息、业务信息、附件/凭证、审计记录。
- 桌面需要持续对照时使用主从双区，否则使用大弹窗。
- 编辑态优先在同一详情容器切换，避免再打开第二个风格不同的弹窗。
- 小于 1280px 的主从工作区降级为单区、抽屉或上下排列。

### 6.4 文件与文档

- 图片、PDF、文本和 Office 文件使用统一查看器；列表使用服务器持久化缩略图，详情使用适配容器尺寸的展示或只读 PDF 预览，明确下载时才读取原始文件。
- 物料图片派生 URL 使用内容版本和私有长缓存；浏览器缓存允许自动淘汰，不承担备份职责。
- 文件默认全屏打开；PDF 初始适合整页，不强制按宽度放大。
- 旋转、缩放、复位和方向校正使用相同操作顺序；方向校正写入附件记录而不改原文件。
- 文档允许上传常见办公文件和其他业务附件，单个文件默认不超过 50 MB；图片、PDF、文本以及 Word、Excel、PowerPoint、OpenDocument 文件必须支持系统内预览。Office 文件由服务器转换为只读 PDF 预览并保留原文件，无法安全预览的其他格式仍允许下载；禁止把企业内部文件提交给公网第三方预览服务。

### 6.5 确认与危险操作

- 普通保存不二次确认，依靠校验和明确按钮文案。
- 归档、冲销、永久删除等高风险动作使用独立确认弹窗，说明影响对象和能否恢复。
- 永久删除要求输入确认文字，并由后端校验归档状态、业务引用和权限。

## 7. 搜索、筛选与选择器

### 7.1 主搜索

- 物料、来料、工单、库存、销售订单、发货、退货、产品文档等列表必须提供关键词搜索；产品文档搜索覆盖独立标题、服务器提取的正文纯文本、关联产品、类别和备注。
- 搜索编码、名称和业务关键词时忽略拉丁字母大小写。
- 列表主搜索默认按空格拆分多个关键词，在资源声明的字段范围内执行 AND 组合模糊匹配。高级搜索负责结构化精确条件；快捷搜索分为关键词搜索和条件搜索，最多 20 项并支持单项删除。
- 高级搜索、常用分类、客户和状态条件共用统一查询表达式，不再另建与高级搜索重复的筛选系统。
- 列表刷新后保留搜索词、筛选、排序、页码和滚动位置，除非业务结果已使页码失效。
- 浏览器按账号保存当前一级页面、物料子页面和各页面纵向滚动位置；刷新后回到原浏览断点。恢复前必须校验入口仍存在且账号仍有读取权限，否则回退到默认可访问页。

### 7.2 高级搜索与页内选项

- 首层展示高频关键词；分类、状态、客户和日期等精确条件进入同一搜索组合中的“高级搜索”。
- 高级搜索入口显示生效条件数，关键词和精确条件都可以保存为快捷搜索。
- 排序、字段显示、摘要可见性和列宽等个人查看偏好进入“页内选项”，不与业务搜索条件混合。
- 页内选项可以保存在当前浏览器，但必须明确其不修改业务数据或其他终端。
- 顶部工具栏固定保留关键词搜索、高级搜索、视图方式和页内选项四个槽位；不适用能力显示禁用态，保证跨页面的位置稳定。
- 页内选项入口只显示公共图标，并允许按当前页面调整顶部工具组顺序和是否显示不可用占位；设置与其他个人查看偏好一样按页面保存在当前浏览器。

### 7.3 动态选择器

- 物料、客户、供应商、库位、工单、工序、单位、文档类别和模板统一可输入筛选。
- 输入匹配名称、编码和业务关键词，并忽略拉丁字母大小写。
- 支持聚焦展开、上下键移动、回车确认、Esc 收起、点击外部收起和清除已选项。
- 大数据量选项必须调用后端搜索，不得仅过滤前端已加载的少量数据。
- 状态、优先级、排序方向、每页条数等固定小枚举可以使用普通下拉。

## 8. 表格与卡片

### 8.1 表格

- 列顺序固定为：身份字段、业务字段、状态/数量、时间、操作。
- 可比较的文字、编码、状态、时间、数量和金额列均可点击表头排序；第一次升序，第二次降序。
- 配置类列表默认按服务器保存的人工顺序展示；“手动排序”保存后对所有终端生效并写入操作日志。点击表头只改变当前页面的查看顺序，不覆盖人工默认顺序。
- 单位配置只能在相同计量类别内手动排序，长度、重量、数量和其他单位不得跨类别混排。
- 图片、附件、操作、可编辑明细、权限矩阵和横向指标对比不排序。
- 操作列固定在最右侧；编码和单号使用等宽字体。
- 长文本默认最多显示两行，超出截断；完整内容进入详情或通过可访问提示查看。
- 桌面列宽自动分配；内容差异大时支持拖动调整和恢复自动宽度，个人列宽保存到浏览器本地。
- 金额、数量、日期和单位使用集中格式化方法，禁止页面分别拼接。

### 8.2 卡片

- 信息顺序固定为编码/状态、名称、关键属性、数量/金额、附件/凭证、操作。
- 只展示完成判断所需字段，低频字段进入详情。
- 移动端主操作直接显示 1–2 个，其余进入“更多”；不得出现多排按钮。
- 卡片操作顺序和表格行内操作一致。

### 8.3 操作顺序

同一对象的常用顺序为：全屏打开、详情、编辑、上传、打印/导出、归档。危险操作与普通操作分隔，并放在末尾。

## 9. 表单与保存

### 9.1 保存模型

- 业务数据使用显式保存：用户编辑后点击“保存”或“提交”，系统统一校验并一次提交。
- 视图模式、列宽、快捷搜索、常用入口等浏览器偏好可以自动保存。
- 可编辑表格和 BOM 明细仍应有一个明确的最终保存按钮，避免部分字段已写入、部分字段未写入。
- BOM 方案名、基准产出数量、默认状态和组成明细属于同一个编辑事务，由工作区标题栏单一“保存 BOM”按钮一次提交。
- BOM 编辑的最终保存按钮必须随工作区标题显示，不使用覆盖内容的悬浮或粘性定位；表单末尾只显示未保存状态，不再放第二个保存入口。
- 物料管理在有 BOM 权限时显示可隐藏的 BOM 简况，并在统一筛选面板提供“未建立产出 BOM / 有 BOM 但无启用方案 / 有启用方案但无默认方案 / 已有可用默认 BOM”状态筛选。每行和卡片操作区提供“创建 BOM”，点击后在当前页打开宽模态窗口并预选当前物料为主产出；保存成功关闭窗口并刷新简况。“完整 BOM 设置”仅用于多版本和复杂关系的后续维护。
- BOM 设置使用“BOM 列表 + 创建/修改区”的主从工作区。左侧只显示已建立的 BOM，每张卡片以 BOM 名称/版本为主信息，主产出和投入物料仅作为摘要；顶部搜索同时匹配投入、产出、BOM 和版本。右侧上半区固定为左“输入”、右“输出”，两侧均可搜索添加多项物料并填写每批数量。长度和重量行的单位后缀可从同量纲单位目录选择，切换时同步换算数值；新行长度默认 `mm`、重量默认 `g`。全部输入组成整体消耗并共同对应全部输出，不显示逐输出关系或跨量纲转换模型。首项输出是主产出，后续项为其他输出；废料、废屑和可回收料也作为输出表达。下方只保留 BOM 方案名称、默认开关、版本状态和唯一保存按钮。投入允许原材料、半成品和已有产品，未选完整时仍保留禁用的保存按钮并说明原因。
- BOM 全览以物料而不是产品为查询主体。左侧物料列表支持名称、编码和规格搜索，并显示双向 BOM 数量；右侧分别显示该物料作为产出和作为投入的直接关联。一个 BOM 在同一分区只显示一次，内部再列出针对各产出的批量关系。全览不提供修改字段，点击“打开编辑”后必须进入 BOM 设置并自动选中目标 BOM。
- 创建生产订单时用两个连续的可搜索字段选择主产出和启用 BOM，保存基本信息后进入订单详情。班后实绩在同一订单详情中展开，不另设独立生产记录一级入口。
- 班后实绩的“生产员工”从启用员工档案中多选并以标签显示；投入和产出左右分区，每一项使用可搜索库位选择器并显示物料编码、名称、数量和主单位。流程转移的“操作员工”从同一档案中单选。人员不允许继续使用自由文本输入。
- 员工新增表单不要求录入员工编码，编码位显示“保存后自动生成”；保存后显示 `EMP-000001` 格式编码并保持只读。新增/编辑表单可选绑定一个已注册账号，选项显示登录账号、姓名和审核状态；已绑定其他员工的账号必须置灰，解除绑定使用同一选择器的清除操作。
- 流程转移是独立整单保存表单；只提供一个物料选择器和一个数量字段，左右核对区必须展示同一物料和同一数量。
- 同一业务表单不能同时混用“字段自动保存”和“整单保存”。

### 9.2 字段与校验

- 每个字段有可见标签；必填项显示红色 `*`，并在语义上标记必填。
- 帮助说明在字段下方，错误信息在相同位置替换帮助说明。
- 数值字段明确单位、允许范围和小数精度；不得让用户根据占位符猜测单位。
- 业务单据在点击“保存/提交草稿”时即完成字段、关联对象、单位、数量和所选库位可用量校验；不允许先保存已知不合规数据，再把基础错误推迟到最终确认。
- 存货调整弹窗必须先通过可输入筛选控件选择启用库位，再录入该库位调整后数量；界面同时展示该库位当前数量和调整后的物料总库存，不允许隐式使用默认库位。
- 库存页的库位数量和包装穿透均为总账的可解释视图：库位数量合计必须等于物料真实库存；包装等效合计必须明确标注为分析结果，不与真实散件、整箱库存再次相加过账。
- 最终确认仍必须在同一事务中复检单据状态和库存等可能并发变化的数据，但复检是并发兜底，不是首次业务校验。
- 提交失败保留输入并聚焦首个错误；服务端业务错误转换成可操作的中文说明。
- 主按钮处理中显示“处理中…”并禁用重复提交。

### 9.3 关闭与未保存内容

- 未修改、只读或空表单可直接关闭。
- 有未保存修改的长表单关闭前提示。
- 保存成功后关闭弹窗并刷新相关数据；失败不关闭、不清空。

## 10. 弹窗、菜单与层级

### 10.1 普通弹窗

- 结构固定为标题/说明、可滚动正文、固定底部操作区。
- 可连续添加多条明细的录入弹窗，已加入列表不得插在当前明细选择区与输入区之间。宽屏将已加入明细放在右侧独立对照区，窄屏则放在完整录入表单之后；标题和底部提交区保持固定。
- 非处理中状态支持右上角关闭、点击遮罩空白、Esc 三种退出方式。
- 打开时锁定底层滚动并将焦点移入弹窗；Tab 焦点限制在弹窗内；关闭后返回原触发按钮。
- 点击弹窗内部不得关闭；保存处理中禁止关闭。
- 桌面建议宽度：`sm 448px`、`md 512px`、`lg 672px`、`xl 896px`、`wide 1152px`，最大高度不超过视口约 92%。
- 移动端弹窗接近全屏，底部操作区避开安全区和底部导航。
- 全局成功或错误提示通过 Portal 挂载到页面根节点，层级必须高于普通弹窗和模糊遮罩；弹窗打开时提示仍应清晰可读，不得留在后台内容区被遮挡或模糊。

### 10.2 菜单、筛选弹层和选择列表

- 点击触发按钮打开；点击外部或 Esc 关闭；关闭后焦点返回触发按钮。
- 内容超高只允许弹层自身滚动，弹层不得超出视口或被父容器裁切。
- 全局账号菜单必须高于页面标题、筛选和操作工具栏；移动端为承载账号菜单提升顶部栏层级时，不得同步提升桌面端主内容工具栏。
- 多层弹出应尽量避免；确需嵌套时只关闭最上层，焦点和遮罩层级必须清楚。
- 菜单选项触发动作后自动关闭；需要继续多选的筛选面板在点击“应用”后关闭。

## 11. 反馈、状态与数据格式

### 11.1 页面状态

每个数据区域至少覆盖：

- 初次加载：稳定骨架或明确加载文字，避免布局大幅跳动。
- 暂无数据：说明当前确实没有记录，并在有权限时提供新增入口。
- 筛选无结果：保留筛选上下文，提供清除筛选。
- 无权限：说明缺少权限，不展示不可执行的假按钮。
- 请求失败：说明失败原因并提供重试。
- 提交成功：刷新相关数据；仅在结果不明显时显示短暂成功提示。

页面连续性与业务草稿分开处理：导航位置和只读滚动断点可自动保存到当前浏览器；未提交的 BOM、单据、数量或金额不得因页面状态恢复而静默写入数据库。

### 11.2 数据显示

- 日期时间使用中文本地格式，列表和详情保持一致。
- 人民币显示 `¥` 和固定货币精度。
- 数量保留业务所需有效小数并去掉无意义尾零。
- 单位紧随数值，来源于单位目录；界面不得在未知量纲间擅自换算。
- 未知值显示“—”，零显示 `0`，两者不得混用。

## 12. 权限、审计与危险操作

- 无权限操作优先隐藏；需要解释能力边界时置灰并说明原因。
- 所有改变业务数据的操作由服务端校验权限并写入审计日志。
- 单位、库位、员工状态等基础配置发生变化时，保留变更前后值、操作人和时间；员工改名或停用不得覆盖历史单据的工号、姓名快照。
- 归档是可恢复的软删除；永久删除只能从归档记录进入。
- 冲销保留原单据和反向业务记录，不伪装成删除。

## 13. 无障碍与键盘规范

- 表单标签必须与输入控件关联；图标按钮提供 `aria-label` 或可见文字。
- 对话框使用 `role="dialog"`、`aria-modal`、标题关联和焦点圈定。
- 排序表头设置 `aria-sort`；搜索选择器使用组合框和列表框语义。
- 所有可操作元素支持 Tab；Enter/Space 执行，Esc 关闭当前最上层浮层。
- 焦点态使用清楚的蓝色描边，不能仅依赖浏览器不稳定的默认样式。
- 正文、按钮和状态文字保持可读对比度；颜色之外必须有文字或图标辅助。
- 不依赖 hover 才能发现关键功能；tooltip 只补充解释，不承载唯一信息。

## 14. 允许的例外

以下场景可不使用普通页面或普通弹窗结构，但仍需满足关闭、焦点、滚动和响应式底线：

- 沉浸式文件全屏查看器。
- 产品全景图和高密度主从工作区。
- 移动端全高功能抽屉、底部工具抽屉。
- 权限矩阵、BOM 可编辑明细、锯切横向比较等不适合表头排序的结构。

例外只豁免领域主体布局，不豁免公共应用壳、工具栏、按钮、弹窗、反馈和响应式底线。“开发方便”不是例外理由。新例外必须在相关业务文档说明为何标准组件不能满足、替代交互是什么、如何验收。

## 15. 页面完成定义（Definition of Done）

每个新增或改造页面交付前必须确认：

### 15.1 结构与视觉

- [ ] 使用规定的应用壳、标题栏和工作区，没有重复导航。
- [ ] 开发前已盘点现有公共组件、Hooks 和服务，并记录复用结果。
- [ ] 复用公共按钮、字段、弹窗、选择器、排序和工具栏组件。
- [ ] 页面使用公共应用壳和资源工作区；常规 CRUD 与多对象关联使用统一骨架。
- [ ] 公共框架能力不足时已先扩展公共模块，而不是在业务页面增加局部替代实现。
- [ ] 领域主体例外具有已记录的具体理由，且外围结构仍使用公共框架。
- [ ] 文案、颜色、尺寸、圆角、间距和操作顺序符合规范。
- [ ] 页面无整体横向滚动，滚动条不嵌套失控。

### 15.2 交互与数据

- [ ] 动态下拉可以输入筛选，并支持键盘、清除和点击外部关闭。
- [ ] 可比较表格列可以升降序，例外有明确理由。
- [ ] 表单有必填、单位、就近错误、处理中和重复提交保护。
- [ ] 业务表单显式保存；失败保留输入；成功刷新相关数据。
- [ ] 加载、空数据、筛选无结果、无权限和失败状态完整。
- [ ] 从列表打开、编辑、保存和切换对象时保留搜索、筛选、选中项与滚动位置。
- [ ] 保存后停留在当前对象上下文；失败时输入和已选关系不丢失。
- [ ] 权限、危险确认和审计由服务端兜底。

### 15.3 响应式与无障碍

- [ ] 完成受影响页面的桌面和移动视口模拟，而非只看一个尺寸。
- [ ] 固定顶部、底部导航、分页和弹窗操作区互不遮挡。
- [ ] 弹窗和菜单支持 Esc、点击外部、焦点恢复和滚动锁定。
- [ ] 图标、表头、输入和对话框具有必要的无障碍语义。
- [ ] 键盘可完成搜索、选择、排序、保存和关闭。

## 16. 规范治理

- 本文是系统交互和设计的单一主入口；设备细节保留在桌面、移动和响应式专项文档中，避免在多个文件复制同一规则。
- 公共交互变化必须在同一提交中更新组件、本规范和受影响专项文档。
- 新页面评审优先检查语义组件和完成定义，不以单张截图作为唯一验收依据。
- 可复用需求先扩展公共组件；一次性业务规则留在业务页面，但不能复制视觉原语。
- 代码评审必须把“是否已有实现、是否可扩展公共模块、是否形成第二份同类骨架”作为独立检查项；发现无准入理由的重复实现不得合并。
- 规范变更应记录日期、原因和影响面。难以回退的应用壳、保存模型或数据交互变更应新增 ADR。
- 文档与实现不一致时视为缺陷；修复时优先判断应改实现还是更新已过时规范，不能长期保留两套事实。
