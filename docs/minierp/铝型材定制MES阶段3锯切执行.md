# 铝型材定制 MES 阶段 3：锯切执行与余料闭环

## 本阶段目标

把阶段 2 的已确认排样方案变成可执行、可过账、可冲销的锯切任务，并让型材实体分账、库存总账、双单位核算和成本层保持一致。

本阶段不接扫码枪和标签打印联动，也不代替后续钻孔、质检和成品入库。

## 页面入口

顶部一级菜单选择“生产”，左侧选择“锯切执行”。

操作顺序：

1. 在“切割排样”确认方案，系统按实际参与切割的根数占用实体与汇总库存。
2. 在“锯切执行”从已确认方案下发任务，可填写设备、班次和备注。
3. 任务开工。
4. 逐根填写合格、不良、报废、实际锯缝、固定损耗、其他损耗、剩余长度和剩余去向。
5. 确认完工并过账。
6. 若实绩错误且余料尚未被继续使用，可冲销后重新执行或取消排样。

## 数量与长度校验

- 每一根计划原料都必须提交实绩，不能漏报或重复。
- 同一需求的 `合格 + 不良 + 报废` 必须等于该根原料上的计划切件数。
- 每根原料执行以下长度平衡：

```text
实际原料长度
= 全部切件数量 × 对应切长
+ 实际锯缝损耗
+ 实际首尾/夹持损耗
+ 实际其他损耗
+ 实际剩余长度
```

- 当前允许 1 mm 的测量与小数误差。
- 选择“余料回库”时，剩余长度必须大于 0；若配置了最小回库长度，还必须达到该阈值。
- 选择“废料”时只保存实际剩余长度和去向，不生成可用库存实体。

## 库存与成本事务

### 排样确认

- `ProfileStockEntity.availableQty → reservedQty`
- `Stock.availableQty → reservedQty`
- 同步移动 `availableValuationQty → reservedValuationQty`
- 写入 `RESERVE_FOR_CUTTING` 与 `CUTTING_RESERVE`

带切长并启用实体追踪的 BOM 行，在创建工单时跳过传统 `PickItem` 预留。这样不会把成品段数误当成原料根数，也不会与排样重复占用。

### 锯切完工

- 来源实体：`reservedQty → consumedQty`
- 汇总库存：总量与预留量扣减实际耗用根数
- 成本：按物料当前 FIFO 或加权平均方法出账
- 可复用余料：生成父子谱系实体，以一根余料回收入汇总库存
- 余料核算数量和成本：按 `实际余料长度 ÷ 本任务实际原料总长度` 分摊原料出账的核算数量与成本
- 写入不可改写的实体流水、库存流水和成本层消耗明细

任务页面显示原料耗用根数、余料回库根数和净耗用成本。净耗用成本等于原料出账成本减余料回收成本。

### 冲销

冲销按相反顺序执行：

1. 校验余料实体未被占用、拆分、耗用或继续产生子实体。
2. 冲销余料回库，作废余料实体及其成本层。
3. 将来源实体从已耗用恢复为排样占用。
4. 恢复原料库存、双单位核算和 FIFO 成本层。
5. 回退切割需求的合格完成量。
6. 排样方案恢复为“已确认”，可重新执行或取消。

历史实绩、冲销原因和反向流水保留，不物理删除。

## 数据对象

| 对象 | 作用 |
| --- | --- |
| `CuttingTask` | 锯切任务、设备/班次、开完工、原料出账和余料回收汇总 |
| `CuttingTaskSource` | 每根计划原料的实际长度、损耗、剩余长度、去向和余料关联 |
| `CuttingTaskOutput` | 每根原料按切割需求记录计划、合格、不良和报废 |
| `CuttingTaskCostLayerConsumption` | FIFO 成本层消耗快照，供合法冲销恢复 |
| `ProfileStockMovement` | 实体可用、占用、耗用、余料与冲销轨迹 |
| `StockLog` | 汇总库存预留、耗用、余料回收和反向流水 |

## 幂等与权限

- 下发任务使用 `clientRequestId`。
- 完工使用独立 `completeRequestId`。
- 库存与实体流水使用稳定业务键。
- 重复网络请求不会重复占用、耗用或回收余料。
- 新权限资源为 `cuttingTasks`；录入、审核和管理员默认可执行，删除历史任务不开放。

## 自动验证

执行：

```bash
npm run verify:cutting-tasks
```

验证脚本在回滚事务中覆盖排样预留、任务下发/开工、逐根实绩、余料谱系与成本、FIFO 耗用、冲销恢复以及冲销后取消排样。
