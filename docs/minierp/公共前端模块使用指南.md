# MES-lite 公共前端模块使用指南

本文说明资源型功能页面如何复用统一骨架。适用于物料、文档、设备、客户、供应商、员工、工艺、路线等以“查询、新增、修改、归档、关联”为主的页面。

## 1. 模块边界

```txt
app/components/page-modules/ 全系统六类页面边界
app/components/resource/    资源列表、卡片、详情、表单、筛选和页面骨架
app/components/relations/   一对一、一对多、多对一关系编辑与实体搜索
app/components/layout/      左右分区、窄屏模式和可移动边缘呼出按钮
app/components/navigation/ 桌面单列折叠与固定双列导航
app/components/             按钮、弹窗、搜索、工具栏等基础组件
lib/page-modules.ts         稳定页面键、模块类别和物料子页面映射
lib/contrast-modes.ts       系统级柔和、标准、高对比配色模式
```

业务页面负责数据请求、权限、状态流转和字段定义。页面框架、工具弹窗、响应式布局、关系行和视觉层级由公共模块负责。

全系统仅允许工作台、资源、主从、交易、设置和工具六类页面。完整页面覆盖及接入规则见《页面模块分类与接入清单》；新增页面必须先在 `lib/page-modules.ts` 注册模块类型和顶部工具栏策略，并通过 `npm run verify:page-modules`。`PageModuleBoundary` 只负责边界与契约，不能替代 `ResourcePage`、`ResourceToolbar` 等具体公共骨架。

## 2. 标准资源页面

从 `app/components/resource` 导入：

```tsx
import {
  ResourceDetailPanel,
  ResourcePage,
  type ResourceTableColumn,
} from '@/app/components/resource'
```

`ResourcePage<T>` 的最小调用需要：

- `resourceKey`：稳定且全局唯一，用于保存搜索与布局偏好。
- `items / getKey`：当前列表及稳定主键。
- `columns`：列表列定义。
- `searchValue / onSearchChange / searchPlaceholder`：统一文字搜索。
- `viewMode / onViewModeChange`：列表与卡片模式。
- `selectedKey / onSelect / detail`：连续列表—详情工作区。

页面可按需传入 `filters`、`filterCount`、`actions`、`onCreate`、加载、错误和空状态。不要在业务页重新实现工具栏或主从布局。

## 3. 详情与编辑

`ResourceDetailPanel` 统一处理：

- 标题、编码摘要、状态与编辑标记。
- 上一条、下一条连续浏览。
- 桌面关闭与窄屏返回语义。
- 更多操作菜单。
- 同容器编辑与固定底部保存操作。

新增和独立编辑使用 `ResourceFormDialog`。归档、永久删除等动作必须继续使用公共确认弹窗。

## 4. 主从工作区

`AdaptiveMasterDetailWorkspace` 自动提供：

- 宽屏左右分区及可拖动分隔线。
- 窄屏列表弹窗、上下分区、列表/详情切换三种模式。
- 布局比例、显示模式和边缘按钮位置的浏览器持久化。
- 左侧列表与右侧页面工具互斥，避免遮挡。

业务页面不得监听视口后复制另一套详情页面。紧凑布局必须继续复用相同的列表和详情内容节点。

## 5. 关系模块

所有关系编辑从 `app/components/relations` 导入：

```tsx
import {
  ManyToOneRelationField,
  OneToManyRelationField,
  OneToOneRelationField,
  RelationSearch,
} from '@/app/components/relations'
```

### 5.1 一对一

使用 `OneToOneRelationField<T>`。适用于设备与当前点检模板、员工与专属账号等最多一个目标的关系。

### 5.2 一对多

使用 `OneToManyRelationField<T>`。适用于文档关联多个物料、BOM 多项投入/产出、订单多条明细等关系。

### 5.3 多对一

使用 `ManyToOneRelationField<T>`。适用于多个物料属于一个类别、多个设备属于一个工作中心等“所属对象”关系。它复用单关系交互，但保留明确的领域调用名。

### 5.4 统一搜索

`RelationSearch<T>` 接收实体数组、主键、显示文本、搜索关键词和禁用项；物料关系使用已经封装的 `MaterialRelationSearch` 与 `MaterialRelationIdentity`。其他实体应在通用搜索上增加自己的薄适配器，不复制弹层、键盘导航和外部关闭逻辑。

## 6. 系统级对比度

页面中性色统一通过 Tailwind `gray-*` 调用，底层映射到 `--mes-color-neutral-50` 至 `--mes-color-neutral-950`。系统设置提供柔和、标准和高对比三种模式。

- 不在业务组件写新的固定灰阶。
- 需要领域层级时先增加语义令牌。
- 蓝、绿、琥珀、红继续表达主操作、成功/新增、提醒/归档和危险/错误，不随对比度模式换色。

## 7. 桌面导航布局

桌面侧栏统一由 `DesktopNavigation` 渲染，业务模块不得分别维护一套单列菜单和双列菜单。调用方只负责把公共菜单注册表转换成分组、子项、当前状态和导航动作。

- 单列折叠：适合希望为业务内容保留更多宽度的用户。
- 双列导航：一级功能固定在左列，当前一级功能的二级入口显示在右列；两列独立滚动。
- 公共侧栏搜索必须覆盖全部有权访问的功能；双列搜索时一级列保持稳定，匹配结果在二级列按分组显示。
- 搜索结果只负责快速导航，不允许在筛选状态下拖拽排序；按 `Esc` 或清空按钮恢复完整菜单。
- 一级菜单统一保持单行排列，并允许在页面选项中选择“图标”“图标＋文字”“文字”三种显示方式；默认使用图标＋文字。
- 双列一级菜单宽度按显示方式分别保存：仅图标默认 64px、图标＋文字默认 136px、仅文字默认 112px；内部一级列宽度与整个侧栏宽度必须分别保存。
- 1024–1279px 自动使用单列，1280px 及以上才显示双列，移动端继续使用底部常用入口与抽屉菜单。
- 两种模式分别保存侧栏宽度，切换后不覆盖另一模式的设置。
- 导航布局和一级菜单显示方式入口统一放在“页面选项”，不能在各业务页单独添加切换按钮。

## 8. 显示模式

页面显示模式统一使用 Finder 风格弹出按钮：收起时显示当前模式图标和下拉箭头，展开后使用“图标 + 中文名称 + 当前项标记”的菜单。所有页面必须复用 `ViewModeToggle` / `DisplayModeToggle`，不得在工具栏并排复制一组显示按钮。

`DisplayModeToggle` 按页面能力声明可用模式：

- 图标：Finder 风格对象网格，适合快速识别对象；公共资源页允许在 72–160px 内调节图标大小并按页面记忆。
- 列表：表格或高密度列表，适合比较字段和批量操作。
- 卡片：保留完整业务摘要、状态、操作和文档缩略图，适合在大屏直接浏览内容细节。
- 分栏：紧凑的单列主列表与更宽详情并列，适合连续浏览主从资源；分栏比例使用独立持久化键，不覆盖普通列表比例。
- 画廊：突出图片、PDF 或文档预览的大卡片，适合视觉资料。

公共 `ResourcePage` 已复用同一批数据、选择状态、卡片内容和详情节点实现五种模式；公共资源框架实验页启用全部五种模式作为集成样例。历史 `card` 偏好继续代表“卡片”，不得为了模仿 Finder 把卡片改名为图标。普通资源页继续使用 `ViewModeToggle`，默认只提供已经声明的模式。页面只有在正文骨架真正支持对应布局时，才允许声明图标、分栏或画廊；不得显示点击后没有布局变化的模式。

## 9. 完成定义

当前生产调用包括设备台账、员工资料两个标准资源页面，产品文档的工作中心一对多关系，以及员工账号多对一关系；其他复杂页面已统一经过所属模块边界和顶部工具栏契约，领域内核按垂直切片继续复用公共组件。经过模块边界只代表完成分类和契约校验，不代表正文列表、卡片或详情已经迁入 `ResourcePage`。

新的资源页面完成前至少验证：

1. 列表、卡片、详情、新增、编辑、归档、加载、空状态和错误状态。
2. 宽屏左右分区及刷新后分隔线不跳动。
3. 窄屏三种布局模式、左右呼出按钮移动和工具弹窗连续操作。
4. 键盘选择、焦点、可访问名称与 `Esc` 退出。
5. 柔和、标准、高对比三种页面效果。
6. 类型检查、lint、生产构建和目标浏览器验证。
