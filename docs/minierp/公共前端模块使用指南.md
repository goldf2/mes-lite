# MES-lite 公共前端模块使用指南

本文说明资源型功能页面如何复用统一骨架。适用于物料、文档、设备、客户、供应商、员工、工艺、路线等以“查询、新增、修改、归档、关联”为主的页面。

## 1. 模块边界

```txt
app/components/page-modules/ 全系统六类页面边界
app/components/resource/    资源列表、卡片、详情、表单、筛选和页面骨架
app/components/relations/   一对一、一对多、多对一关系编辑与实体搜索
app/components/layout/      左右分区、窄屏模式和可移动边缘呼出按钮
app/components/navigation/ 桌面单列折叠与固定双列导航
app/components/             按钮、弹窗、搜索、工具栏等基础组件
modules/<domain>/           拥有完整数据、交互状态和唯一公开入口的领域模块
app/HomeApp.tsx             鉴权后的公共应用壳、导航和页面装配
app/app-navigation.ts       导航分组、功能目录和页面连续性定义
app/page.tsx                只挂载应用入口，不承载业务状态或请求
lib/page-modules.ts         稳定页面键、模块类别和物料子页面映射
lib/contrast-modes.ts       系统级柔和、标准、高对比配色模式
lib/attachment-file-types.ts 附件类型识别、上传限制和预览能力
lib/document-source-credentials.ts 单据原始凭据与 AI 识别入口注册表
```

业务页面负责数据请求、权限、状态流转和字段定义。页面框架、工具弹窗、响应式布局、关系行和视觉层级由公共模块负责。

应用入口必须保持稳定：`app/page.tsx` 只导入并渲染 `HomeApp`；`HomeApp` 负责鉴权、全局权限、导航、URL 连续性、公共顶部工具栏和页面模块挂载，不得保存生产订单、库存等领域列表或表单状态。拥有独立查询、筛选、创建、详情或调整流程的页面放入 `modules/<domain>/`，由模块自己管理请求与局部 URL 参数，再通过模块根目录唯一 `index.ts` 接入公共应用壳。应用壳不得越过公开入口导入模块内部文件；模块 UI 继续调用现有公共页面骨架和控件，不建立第二套工具栏、搜索或视图组件。纯展示或已经稳定复用公共资源骨架的旧页面可以暂时留在 `app/components/`，在后续修改触及时按业务收益增量迁移。

文档和附件页面统一复用 `attachment-file-types`、`DocumentPreviewThumb` 与 `DocumentFileViewer`。上传层允许常见业务附件；预览层对图片、PDF、文本和 Office 文件分别使用原图、PDF.js、安全文本框架及服务器端 PDF 转换，其他格式降级为下载。业务页面禁止复制 MIME 白名单、文件大小或查看器判断。

来料、生产、派工、销售、发货和退货的原始凭据统一使用 `AttachmentPanel`，支持上传、查看和归档；允许 AI 凭据识别的单据类型只在 `lib/document-source-credentials.ts` 登记。新建表单统一嵌入 `DraftDocumentAttachmentPanel`：文件以表单专属草稿 ID 暂存，用户可在保存前预览和发起 AI 识别，业务记录创建成功后调用公共绑定接口，取消时调用公共清理接口。识别服务只把置信度不低于 0.7 的结构化建议回填到当前未保存表单，用户仍需核对并主动创建；模型不能直接保存、确认、过账或修改业务状态。

业务单据详情统一复用 `AttachmentPanel` 的完整“附件管理”模式，上传、预览、下载与归档不得散落在列表操作列。列表只允许使用 `compactMode="summary"` 展示附件数量；需要管理时进入详情。多个附件应允许用户指定某一个附件进入 `onAiRecognize(attachment)`，识别结果仍必须进入人工确认表单。

全系统仅允许工作台、资源、主从、交易、设置和工具六类页面。完整页面覆盖及接入规则见《页面模块分类与接入清单》；新增页面必须先在 `lib/page-modules.ts` 注册模块类型和顶部工具栏策略，并通过 `npm run verify:page-modules`。`PageModuleBoundary` 只负责边界与契约，不能替代 `ResourcePage`、`ResourceToolbar` 等具体公共骨架。

## 2. 标准资源页面

从 `app/components/resource` 导入：

```tsx
import {
  ResourceDetailPanel,
  ResourcePage,
  type ResourceTableColumn,
} from '@/app/components/resource'
```

`ResourcePage<T>` 的最小调用需要：

- `resourceKey`：稳定且全局唯一，用于保存搜索与布局偏好。
- `items / getKey`：当前列表及稳定主键。
- `columns`：列表列定义。
- `searchValue / onSearchChange / searchPlaceholder`：统一文字搜索。
- `viewMode / onViewModeChange`：列表与卡片模式。
- `selectedKey / onSelect / detail`：连续列表—详情工作区。

每个存在可搜索数据集合的页面必须传入 `advancedSearchFields`，并可按需传入 `actions`、`onCreate`、加载、错误和空状态。不要在业务页重新实现工具栏或主从布局。默认搜索按空格拆分多个关键词，关键词之间为 AND，每个关键词可命中该资源声明的任一字段；禁止自动扫描全部数据库字段。高级搜索必须使用公共 `ResourceAdvancedSearch`：入口固定在关键词搜索旁边，弹层一次列出当前资源声明的全部字段，由用户按字段选择运算符并输入精确条件。

业务资源必须集中声明关键词字段和高级搜索字段。列表、卡片、图标、分栏和画廊继承同一份搜索配置。快捷搜索按“关键词搜索”和“条件搜索”分组保存；存在结构化条件时归入条件搜索。历史 `filters` 接口和独立筛选面板已经停用，不得新增或恢复；常用分类、客户和状态应成为高级搜索字段。不存在可搜索数据集合的页面显示公共禁用占位，不得制造空白或伪高级搜索。

## 3. 详情与编辑

`ResourceDetailPanel` 统一处理：

- 标题、编码摘要、状态与编辑标记。
- 上一条、下一条连续浏览。
- 桌面关闭与窄屏返回语义。
- 更多操作菜单。
- 同容器编辑与固定底部保存操作。

新增和独立编辑使用 `ResourceFormDialog`。归档、永久删除等动作必须继续使用公共确认弹窗。

## 4. 主从工作区

`AdaptiveMasterDetailWorkspace` 自动提供：

- 宽屏左右分区及可拖动分隔线。
- 窄屏列表弹窗、上下分区、列表/详情切换三种模式。
- 布局比例、显示模式和边缘按钮位置的浏览器持久化。
- 左侧列表与右侧页面工具互斥，避免遮挡。

业务页面不得监听视口后复制另一套详情页面。紧凑布局必须继续复用相同的列表和详情内容节点。

## 5. 关系模块

所有关系编辑从 `app/components/relations` 导入：

```tsx
import {
  ManyToOneRelationField,
  OneToManyRelationField,
  OneToOneRelationField,
  RelationSearch,
} from '@/app/components/relations'
```

### 5.1 一对一

使用 `OneToOneRelationField<T>`。适用于设备与当前点检模板、员工与专属账号等最多一个目标的关系。

### 5.2 一对多

使用 `OneToManyRelationField<T>`。适用于文档关联多个物料、BOM 多项投入/产出、订单多条明细等关系。

### 5.3 多对一

使用 `ManyToOneRelationField<T>`。适用于多个物料属于一个类别、多个设备属于一个工作中心等“所属对象”关系。它复用单关系交互，但保留明确的领域调用名。

### 5.4 统一搜索

`RelationSearch<T>` 接收实体数组、主键、显示文本、搜索关键词和禁用项；物料关系使用已经封装的 `MaterialRelationSearch` 与 `MaterialRelationIdentity`。其他实体应在通用搜索上增加自己的薄适配器，不复制弹层、键盘导航和外部关闭逻辑。

## 6. 系统级对比度

页面中性色统一通过 Tailwind `gray-*` 调用，底层映射到 `--mes-color-neutral-50` 至 `--mes-color-neutral-950`。系统设置提供柔和、标准和高对比三种模式。

- 不在业务组件写新的固定灰阶。
- 需要领域层级时先增加语义令牌。
- 蓝、绿、琥珀、红继续表达主操作、成功/新增、提醒/归档和危险/错误，不随对比度模式换色。

## 7. 桌面工作区布局与导航

桌面应用壳统一提供两种工作区布局。两种布局必须读取同一份页面注册表、权限结果、当前页面状态和 `ResponsiveToolbarActions` 工具内容；业务页面只渲染一次正文，不得为不同布局复制页面、查询或操作按钮。

- 标准管理：左侧使用 `DesktopNavigation`，顶部承载当前页面工具，中央显示业务正文。适合跨模块频繁切换和高密度管理。
- 画布工作：顶部使用 `DesktopTopNavigation`，右侧常驻公共页面工具，中央主显示区获得连续画布。适合文档预览、图像资料和需要更大纵向空间的工作区。
- 全局形态切换按钮固定在应用壳，不进入业务页面或页内选项；“系统设置 → 显示设置”提供相同的持久化选择。
- 工作区切换只重排导航与公共工具容器，不改变 URL、选中记录、搜索条件、草稿、权限或业务数据。

标准管理布局的左侧导航继续由 `DesktopNavigation` 渲染，业务模块不得分别维护一套单列菜单和双列菜单。调用方只负责把公共菜单注册表转换成分组、子项、当前状态和导航动作。

- 单列折叠：适合希望为业务内容保留更多宽度的用户。
- 双列导航：一级功能固定在左列，当前一级功能的二级入口显示在右列；两列独立滚动。
- 常驻显示：左栏固定占位，正文左边距随已保存的侧栏宽度变化。
- 自动隐藏：左栏收起后只保留一个导航图标；鼠标进入左侧感应区或点击图标后以覆盖层呼出，移出后延时收回。覆盖层不得推动正文或造成布局跳动。
- 左栏固定/自动隐藏按钮属于导航本身的公共控制；固定状态变化才允许改变正文占位，临时呼出不得改变正文宽度。
- 公共侧栏搜索必须覆盖全部有权访问的功能；双列模式下搜索框横跨整个侧栏并位于两列上方，不能只放在二级列造成“仅搜索当前分类”的误解。搜索时一级列保持稳定，匹配结果在二级列按分组显示。
- 双列一级高亮已经表达当前分类，二级列直接显示功能入口，不再重复显示“功能菜单 / 当前分类”等伪层级标题。
- 搜索结果只负责快速导航，不允许在筛选状态下拖拽排序；按 `Esc` 或清空按钮恢复完整菜单。
- 一级菜单统一保持单行排列，并允许在“系统设置 → 显示设置”中选择“图标”“图标＋文字”“文字”三种显示方式；默认使用图标＋文字。
- 双列一级菜单宽度按显示方式分别保存：仅图标默认 64px、图标＋文字默认 136px、仅文字默认 112px；内部一级列宽度与整个侧栏宽度必须分别保存。
- 1024–1279px 自动使用单列，1280px 及以上才显示双列，移动端继续使用底部常用入口与抽屉菜单。
- 两种模式分别保存侧栏宽度，切换后不覆盖另一模式的设置。
- 工作区布局、左栏行为、导航布局、一级菜单显示方式、配色和弹窗效果统一放在“系统设置 → 显示设置”，不能在各业务页或页内选项重复提供入口。

画布工作布局的顶部导航必须保持单行；可用宽度不足时把低优先级一级入口收进“更多”，不能换行或挤压右侧全局按钮。右侧页面工具栏必须保持独立滚动，并继续呈现当前页面已声明的搜索、高级搜索、视图、页内选项、二维码和业务动作；它是公共工具栏的竖向呈现，不是第三套业务工具实现。

低于 `1024px` 时两种桌面布局统一降级为现有移动端应用壳，不显示桌面左栏行为或右侧常驻工具栏。

## 8. 配置页与页内选项

业务配置中的单位、库位、客户、供应商、工作中心、加工工艺和工艺路线必须复用 `ResourcePageShell` 或 `ResourcePage`。标题、说明、统计、工具栏、搜索、内容容器、空状态和响应式间距由公共骨架渲染；页面只声明资源字段、搜索范围、视图和领域动作。

- 创建独立业务对象统一使用“新建＋对象名称”，例如“新建物料”“新建 BOM”。
- 将已有对象加入关系或明细统一使用“添加”，例如“添加物料”“添加工序”。
- 页内选项只保存当前页面的顶部工具顺序、禁用占位显示、字段显示、排序和领域默认值；全局显示偏好不得进入页内选项。
- 所有页面通过 `ResponsiveToolbarActions` 固定输出关键词搜索、高级搜索、视图方式和页内选项四个公共槽位。页面只传入实际能力；缺失能力由公共组件渲染禁用占位，禁止业务页自行隐藏槽位或复制按钮。
- 公共工具栏只允许单行：搜索固定在左侧，其他工具靠右；紧凑桌面把高级搜索、视图、页内选项、二维码和业务操作收进“工具”，移动端继续复用同一工具抽屉和二维码弹窗。
- `ResponsiveToolbarActions` 的紧凑工具面板必须使用公共分组层级：筛选条件使用紧凑卡片，显示方式单独成行，页内选项与二维码归入页面功能，新增等业务动作固定在底部。业务页面只传入内容，不得自行复制弹层外壳。
- `advancedSearch`、`viewControl` 和 `onOpenPageOptions` 分别接入对应公共槽位；页内选项按钮始终为图标。若页面有专属页内选项窗口，必须在其中复用 `ToolbarOrderSettings`。
- 永久改变业务 `sortOrder` 的操作命名为“调整顺序”，不属于个人查看排序。

## 9. 显示模式

页面显示模式统一使用 Finder 风格弹出按钮：收起时显示当前模式图标和下拉箭头，展开后使用“图标 + 中文名称 + 当前项标记”的菜单。所有页面必须复用 `ViewModeToggle` / `DisplayModeToggle`，不得在工具栏并排复制一组显示按钮。

`DisplayModeToggle` 按页面能力声明可用模式：

- 图标：Finder 风格对象网格，适合快速识别对象；公共资源页允许在 72–160px 内调节图标大小并按页面记忆。
- 列表：表格或高密度列表，适合比较字段和批量操作。
- 卡片：保留完整业务摘要、状态、操作和文档缩略图，适合在大屏直接浏览内容细节。
- 分栏：紧凑的单列主列表与更宽详情并列，适合连续浏览主从资源；分栏比例使用独立持久化键，不覆盖普通列表比例。
- 画廊：突出图片、PDF 或文档预览的大卡片，适合视觉资料。

公共 `ResourcePage` 已复用同一批数据、选择状态、卡片内容和详情节点实现五种模式；公共资源框架实验页启用全部五种模式作为集成样例。历史 `card` 偏好继续代表“卡片”，不得为了模仿 Finder 把卡片改名为图标。普通资源页继续使用 `ViewModeToggle`，默认只提供已经声明的模式。页面只有在正文骨架真正支持对应布局时，才允许声明图标、分栏或画廊；不得显示点击后没有布局变化的模式。

## 10. 完成定义

当前生产调用包括设备台账、员工资料两个标准资源页面，产品文档的工作中心一对多关系，以及员工账号多对一关系；其他复杂页面已统一经过所属模块边界和顶部工具栏契约，领域内核按垂直切片继续复用公共组件。经过模块边界只代表完成分类和契约校验，不代表正文列表、卡片或详情已经迁入 `ResourcePage`。

新的资源页面完成前至少验证：

1. 列表、卡片、详情、新增、编辑、归档、加载、空状态和错误状态。
2. 宽屏左右分区及刷新后分隔线不跳动。
3. 窄屏三种布局模式、左右呼出按钮移动和工具弹窗连续操作。
4. 键盘选择、焦点、可访问名称与 `Esc` 退出。
5. 柔和、标准、高对比三种页面效果。
6. 类型检查、lint、生产构建和目标浏览器验证。
