# MES-lite 双单位全流程改造规划

> 历史说明：本文保留 2026-07-29 的初始改造方案作为过程记录。当前规则以 [ADR 0004](../adr/0004-material-primary-measure-and-batch-conversion.md) 和 [ADR 0005](../adr/0005-bom-unit-consumption-and-report-loss.md) 为准：物料按主计量方式记账，BOM 保存原料主库存单位下的每件成品单位消耗量，生产日报另行计算并保存本次损耗与实际耗用；本文中与这两项 ADR 冲突的旧方案不再作为实现依据。

## 实施状态

2026-07-29 已完成轻量主流程改造：

- 统一库存收入、发出试算与过账服务。
- 库存流水保存两套单位、换算率、换算来源、成本法和幂等键。
- 来料确认、生产日报、发货和退货接入统一过账。
- BOM 保存产出物料、对应原料和原料主库存单位下的单位消耗量。
- 生产日报按产量、单位消耗量和固定/百分比损耗计算，并可修正实际耗用。
- 发货、退货支持小数数量，FIFO 发货按成本层出库。
- 有库存、流水或 BOM 的物料禁止直接修改单位。
- FIFO 物料禁止普通直接盘点调整。
- 新增双批次 FIFO 全流程回归脚本。

后续扩展项：正式 FIFO 存货调整单、隐藏工单全部接入统一过账、批次根数和单根长度辅助信息。

## 1. 规划结论

当前系统已经具备双单位的部分基础：

- 物料有库存单位、核算单位和默认换算系数。
- 来料单可以记录本批库存数量、核算数量、实际换算率和两种计价方式。
- 库存余额同时保存库存数量、核算数量和成本。
- FIFO 成本层可以保存不同来料批次的实际换算关系。
- 生产、发货、退货和盘点的部分接口会同步修改两套库存。

但这些能力还没有形成完整闭环。主要原因不是缺少字段，而是每个业务模块分别计算双单位，没有共享统一的单位规则和库存过账机制。部分单据没有单位快照或换算来源，BOM 单位没有强校验，发货和退货仍限制为整数，生产成品和发货没有完整进入成本层，物料已有业务数据后仍可直接修改单位。

本次改造目标是：

```text
物料单位策略
  -> 来料双数量确认
  -> 库存双余额与批次成本层
  -> BOM 库存单位用量
  -> 生产双数量耗用与产出
  -> 发货双数量出库
  -> 退货按原业务恢复
  -> 盘点/冲销双数量校正
  -> 双单位对账
```

改造后，所有库存变化都必须通过同一个库存过账服务完成，一笔业务必须同时记录：

```text
库存数量 + 库存单位
核算数量 + 核算单位
实际换算率 + 换算来源
成本金额 + 成本来源
业务单据 + 原始/冲销关系
```

## 2. 成功标准

改造完成必须满足以下标准：

1. 任意库存流水都能回答“增加或减少了多少库存单位、多少核算单位、按什么换算率、金额是多少”。
2. 来料、生产、发货、退货、调整和冲销全部使用同一套过账服务。
3. BOM 数量始终以原料库存单位为口径，错误单位不能保存或确认生产。
4. 不同批次的实际换算率可以被 FIFO 正确继承和消耗。
5. 移动加权平均使用当前库存综合换算率，不回退到主数据默认值覆盖实际库存。
6. 原单冲销必须按原流水精确反向恢复，不能按冲销时的平均换算率重新估算。
7. 物料单位可以直接修改，但不换算任何业务数值；必须递增单位版本并记录审计，数据关系工具持续列出 BOM 与有效成本层的单位漂移。
8. 发货、退货和生产数量支持小数，不再被整数类型限制。
9. 库存汇总、成本层和库存流水可以自动对账，并能列出差异来源。
10. 历史数据迁移后保留原单据，无法确认来源的换算必须标记为历史估算。

## 3. 当前流程断点

| 环节 | 当前已有能力 | 主要断点 | 风险 |
| --- | --- | --- | --- |
| 物料主数据 | 保存两种单位和默认换算系数 | 有业务数据后仍可直接改单位；没有单位模式和版本 | 历史单据与当前单位口径不一致 |
| 来料 | 两套数量、本批换算率、双计价方式完整 | 表单允许用默认值补算，但缺少明确的换算来源字段 | 无法区分实测值和理论值 |
| 来料确认 | 同时增加两套库存并创建成本层 | 过账逻辑写在来料接口内 | 其他单据容易使用不同公式 |
| 库存 | 保存两套余额、预留量、成本 | `Stock` 被多个接口直接修改；没有统一原子校验 | 流程扩展后容易出现余额漂移 |
| BOM | 保存原料数量、单位和损耗 | 单位是普通字符串；后端没有验证它必须等于库存单位；基准产量被折算成每 1 件后丢失 | “米被当成根”仍可进入生产 |
| 生产日报 | 确认时同时扣两套原料库存并增加成品 | 草稿只保存部分单位快照；产出核算数量只能按物料默认系数；不能录入实测产出核算量 | 历史单位变化后难审计，产出辅助量可能失真 |
| 生产成本层 | 原料 FIFO 可以按来料层消耗 | 成品入库不创建成本层 | 后续成品发货无法真正执行 FIFO |
| 发货 | 同时扣减库存数量、核算数量和成本 | 数量为整数；无单位快照和换算来源；固定使用库存平均值；不走统一成本服务 | 小数单位无法发货，成本法不一致 |
| 退货 | 关联发货时按原发货比例恢复 | 数量为整数；退货单没有保存自身双单位快照和成本快照 | 部分退货和历史追踪不完整 |
| 存货调整 | 页面可输入两套数量和金额 | FIFO 物料也能直接调整余额，但没有同步成本层；没有正式调整单 | FIFO 层与库存汇总可能不一致 |
| 工单旧流程 | 预留、领料已经保存部分双单位数据 | 与生产日报使用两套相似但不同的逻辑 | 隐藏模块恢复时会再次产生口径分叉 |
| 库存流水 | 有前后两套余额和成本 | 没有单位快照、换算率、换算来源、原流水关系 | 流水不能独立解释历史业务 |
| 报表 | 部分页面显示核算库存 | 没有统一双单位流水和差异对账页面 | 只能看余额，不能核对来源 |

## 4. 统一业务规则

### 4.1 两个单位的职责

每个物料只保留两个正式库存维度：

```text
库存单位 stockUnit：
生产、领用、发货、盘点时必须准确增减的主单位

核算单位 valuationUnit：
采购计价、重量/长度辅助核算和成本计算使用的第二单位
```

选择原则：

- 生产按米消耗的棒料，库存单位必须配置为米。
- 整根领用的棒料，库存单位可以配置为根。
- 按重量采购时，核算单位配置为 kg。
- 普通成品配置为件/件，换算率为 1。

系统不允许 BOM 自行选择与物料库存单位不同的单位。

### 4.2 换算率定义

统一定义：

```text
换算率 = 核算数量 / 库存数量
1 库存单位 = 换算率 × 核算单位
```

换算来源使用固定枚举：

| 枚举 | 含义 | 使用场景 |
| --- | --- | --- |
| `MASTER_DEFAULT` | 物料主数据默认值 | 没有实测数量的新收入 |
| `DOCUMENT_ACTUAL` | 业务单据实际填写 | 来料实重、实测长度、生产实测产出 |
| `STOCK_AVERAGE` | 当前库存平均值 | 移动加权平均出库 |
| `FIFO_LAYER` | 实际成本层 | FIFO 出库 |
| `ORIGINAL_MOVEMENT` | 原业务流水 | 退货、冲销 |
| `LEGACY_ESTIMATE` | 历史迁移估算 | 无法还原来源的旧数据 |

### 4.3 数量来源优先级

收入业务：

```text
单据实测核算数量
  > 单据明确填写的换算率
  > 物料主数据默认换算率
```

发出业务：

```text
FIFO 物料：实际成本层换算率
移动平均物料：当前库存平均换算率
```

反向业务：

```text
原流水双数量和成本
  > 原单据快照
  > 当前库存平均值（只允许无来源的历史退货）
```

### 4.4 单位变更只修改主数据

系统允许操作员直接修改物料计量方式和单位：

- 只更新物料主数据并递增单位版本。
- 不换算库存、预留、成本、BOM 比例或任何业务数值。
- 不改写历史单据、库存流水、成本层或既有 BOM 中的单位快照。
- 审计日志必须记录修改前后设置，并明确标记未换算数值、未更新关联记录。

不同量纲之间无法由系统可靠推断换算关系，相关数值核对和业务调整由操作员负责。

## 5. 目标数据模型

### 5.1 物料单位策略

在 `Material` 中增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `unitMode` | String | `SINGLE` 或 `DUAL` |
| `unitVersion` | Int | 单位配置版本，初始为 1 |
| `quantityScale` | Int | 数量显示/输入精度，默认 6 |

保留现有：

- `stockUnit`
- `valuationUnit`
- `conversionRate`
- `conversionNote`
- `costingMethod`

`unit` 作为旧兼容字段逐步停用，业务代码统一读取 `stockUnit`。

### 5.2 统一库存流水

将 `StockLog` 升级为库存事实流水。至少增加：

| 字段 | 说明 |
| --- | --- |
| `stockUnitSnapshot` | 过账时库存单位 |
| `valuationUnitSnapshot` | 过账时核算单位 |
| `conversionRateUsed` | 本次实际换算率 |
| `conversionSource` | 换算来源枚举 |
| `costingMethodSnapshot` | 本次成本方法 |
| `sourceMovementId` | 原流水 ID，退货或冲销时使用 |
| `reversalMovementId` | 对应冲销流水 ID |
| `idempotencyKey` | 防止接口重试导致重复过账 |

现有字段继续记录：

- 库存数量变动及前后余额
- 核算数量变动及前后余额
- 成本变动及前后金额
- 业务类型和业务单据 ID

`StockLog` 是库存事实；`Stock` 是当前余额投影。余额异常时可以依据流水重建。

### 5.3 统一单据数量快照

所有会改变库存的业务行必须保存：

```text
stockQty
stockUnitSnapshot
valuationQty
valuationUnitSnapshot
conversionRateUsed
conversionSource
costAmount
```

不同单据可使用自己的字段名，但含义必须一致。确认后的快照不可修改。

### 5.4 BOM 基准数量

将 BOM 从“隐式每 1 件”改为明确的两端数量：

`BOM` 增加：

| 字段 | 说明 |
| --- | --- |
| `outputMaterialId` | BOM 对应产出物料，最终替代兼容 `Product` |
| `outputQty` | BOM 基准产出数量 |
| `outputUnitSnapshot` | 保存时的产出库存单位 |

`BOMItem` 调整：

| 字段 | 说明 |
| --- | --- |
| `inputQty` | 对应基准产出数量的原料库存数量 |
| `inputUnitSnapshot` | 原料库存单位快照 |
| `wastageRate` | 损耗率 |

计算公式：

```text
计划原料库存数量 =
实际加工数量 / BOM.outputQty
× BOMItem.inputQty
× (1 + 损耗率)
```

例如：

```text
100 件成品 = 35 米原料
```

系统直接保存 `outputQty = 100`、`inputQty = 35`，不再只保存折算后的 `0.35`。页面仍可显示每件用量，但不能丢失用户输入的原始比例。

### 5.5 正式存货调整单

新增 `StockAdjustment` 和 `StockAdjustmentLine`，替代直接修改余额：

- 调整前、调整后两套数量
- 调整前、调整后金额
- 差异数量和差异金额
- 单位和换算快照
- 原因、操作人、确认时间、冲销状态
- FIFO 成本层处理方式

FIFO 物料的调整规则：

- 盘盈：创建新的调整成本层。
- 盘亏：通过统一成本服务按 FIFO 消耗成本层。
- 只调整核算数量：需要指定影响哪个批次，或明确按现存层比例分摊。
- 不允许只改 `Stock` 而不改成本层。

## 6. 统一库存过账服务

新增领域服务，例如：

```text
lib/inventory/unit-policy.ts
lib/inventory/quote-movement.ts
lib/inventory/post-movement.ts
lib/inventory/reverse-movement.ts
lib/inventory/reconcile.ts
```

### 6.1 单位策略服务

职责：

- 读取并验证物料单位配置。
- 判断单单位或双单位。
- 校验业务输入单位必须等于物料库存单位。
- 根据数量来源生成核算数量、实际换算率和来源。
- 统一数量精度和容差。

### 6.2 移动试算服务

输入：

```text
物料
业务方向：收入或发出
库存数量
可选实测核算数量
可选原流水
成本方法
```

输出：

```text
库存数量
核算数量
换算率
换算来源
成本金额
成本层消耗或新增计划
```

试算只计算，不修改数据库，供页面预览和确认前校验使用。

### 6.3 库存过账服务

一笔过账必须在同一个数据库事务中：

1. 按 ID 重新读取库存余额。
2. 校验可用库存和预留数量。
3. 计算或验证双数量。
4. 处理成本层。
5. 更新 `Stock` 两套余额和成本。
6. 创建带单位快照的 `StockLog`。
7. 将快照写回业务单据。
8. 写入审计日志或返回审计数据。

所有业务接口禁止直接调用 `tx.stock.update()` 修改业务余额。

### 6.4 精确冲销服务

冲销必须引用原流水，并对原流水执行反向过账：

```text
冲销库存数量 = -原流水库存数量
冲销核算数量 = -原流水核算数量
冲销成本 = -原流水成本
换算来源 = ORIGINAL_MOVEMENT
```

FIFO 冲销恢复原成本层消耗；如果原成本层已经发生无法逆转的后续变化，则阻止冲销并提示先处理后续单据。

## 7. 完整业务流程

### 7.1 物料建立

1. 用户选择库存单位。
2. 用户选择是否启用双单位。
3. 双单位模式下填写核算单位、默认换算系数和说明。
4. 系统创建两套余额均为 0 的库存记录。
5. 首次确认业务后锁定单位配置。

### 7.2 来料

草稿阶段：

1. 输入库存数量。
2. 双单位物料可输入本批实测核算数量。
3. 未输入实测值时，页面显示“按物料默认换算率估算”。
4. 选择按库存单位或核算单位计价。
5. 页面实时显示实际换算率、两种单位成本和总金额。

确认阶段：

1. 固化两种单位和换算来源。
2. 统一服务增加两套库存。
3. 创建收入成本层。
4. 创建库存流水。
5. 来料单状态改为已收货。

来料冲销：

- 引用原收入流水。
- 要求对应成本层尚可恢复。
- 精确扣回原两套数量和成本。

### 7.3 库存查看

库存页同时显示：

- 库存数量、预留数量、可用数量和库存单位。
- 核算数量、预留核算数量、可用核算数量和核算单位。
- 当前实际平均换算率。
- 物料默认换算率。
- 两者差异。
- 库存总成本及两种单位成本。
- 批次层数量和换算率入口。

“默认换算率”和“当前实际平均换算率”必须分开显示，避免用户误以为库存余额按默认值计算。

### 7.4 BOM

1. 选择产出物料和基准产出数量。
2. 选择投入物料和投入数量。
3. 两侧单位由物料库存单位自动带出，不允许自由输入。
4. 填写损耗率。
5. 保存时验证产出和投入不能是同一物料、数量必须大于 0、单位版本必须有效。
6. BOM 发布后保存版本；生产日报引用发布版本快照。

BOM 只定义库存单位数量关系，不直接定义核算数量。核算数量在实际出库时，根据库存成本法和实际批次换算。

### 7.5 生产日报

草稿阶段：

1. 输入合格、不良和报废的产出库存数量。
2. 系统根据 BOM 基准比例计算原料库存数量。
3. 试算服务预览每项原料预计核算数量和成本。
4. 双单位成品可以选择输入本次合格品实测核算数量；不输入时使用主数据默认值。
5. 保存完整 BOM、单位、换算和成本试算快照。

确认阶段：

1. 按总加工数量消耗原料。
2. 每项原料通过统一服务按 FIFO 或移动平均出库。
3. 不良和报废消耗原料，但不增加合格库存。
4. 合格品通过统一服务收入库存。
5. FIFO 成品创建生产入库成本层。
6. 原料成本归集到合格品；后续再增加人工和制造费用。

冲销：

- 精确反向恢复原料流水和成本层。
- 精确撤销合格品收入层。
- 如果合格品已经发货或被后续生产消耗，阻止直接冲销。

### 7.6 发货

草稿阶段：

1. 发货数量改为小数。
2. 单位自动显示为物料库存单位。
3. 页面试算发货核算数量和成本。
4. 单据保存库存单位快照。

确认阶段：

1. 统一服务按物料成本方法出库。
2. FIFO 成品从生产/退货/调整收入层依次消耗。
3. 保存发货双数量、换算来源、成本和成本层快照。

### 7.7 客户退货

关联原发货时：

1. 退货数量不能超过原发货可退数量。
2. 按原发货流水比例恢复核算数量和成本。
3. 换算来源固定为 `ORIGINAL_MOVEMENT`。
4. 形成新的退货收入成本层，不改写原发货记录。

无原发货的历史退货：

1. 必须选择估算依据。
2. 可以填写实测核算数量。
3. 未填写时才使用当前平均换算率。
4. 单据明确标记为历史估算。

退货数量改为小数，并保存完整双单位快照。

### 7.8 存货调整

库存调整不再直接编辑 `Stock`：

1. 创建调整草稿。
2. 输入实盘库存数量和实盘核算数量。
3. 系统显示账面数、实盘数和两套差异。
4. 选择差异原因和成本处理方式。
5. 确认后通过统一服务过账。
6. 可以使用原调整流水冲销。

### 7.9 隐藏工单流程

虽然当前小微企业主流程不依赖工单，旧工单模块仍必须接入同一服务：

- 创建工单只形成双单位预留。
- 领料调用统一发出过账。
- 取消工单调用精确冲销。
- 成品入库调用统一收入过账并创建成本层。

这样未来重新显示工单时不会形成第二套库存算法。

## 8. 长短不一原料的落地口径

对于来料长短不一、生产按长度消耗的材料：

```text
库存单位 = 米或毫米
核算单位 = kg（按重量采购时）
来料库存数量 = 本批总长度
来料核算数量 = 本批实际总重量
BOM 投入数量 = 每个基准产量需要的长度
```

例如：

```text
20 根 × 6 米 = 120 米
10 根 × 4.5 米 = 45 米
库存汇总 = 165 米
```

根数和单根长度不是第三套正式库存余额。第一版将它们作为来料批次辅助信息：

- `pieceCount`：本批根数。
- `nominalLength`：标称单根长度。
- `lengthNote`：混合长度说明。

如果同一批包含多种长度，可拆成多个批次行。未来需要跟踪每根余料时，再增加条料/余料子系统，不把双单位扩展成任意多单位。

## 9. 数据迁移计划

### 9.1 迁移前审计

先生成只读报告：

- 物料单位配置缺失或换算率无效。
- BOM 单位与原料库存单位不一致。
- 库存双余额不满足可用量公式。
- FIFO 库存与开放成本层不一致。
- 发货、退货和生产记录缺少物料映射。
- 已有流水但库存单位可能被改过的物料。

发现异常时先列出，不自动猜测修复。

### 9.2 结构迁移

1. 增加物料单位模式和版本。
2. 增加库存流水的单位、换算和原流水字段。
3. 增加 BOM 基准产出数量和单位快照。
4. 增加生产、发货和退货的双单位快照。
5. 将发货、退货及旧工单入库数量由 `Int` 改为 `Float`。
6. 新增正式存货调整表。

SQLite 修改字段类型时使用建新表、复制数据、校验数量、替换旧表的迁移方式。

### 9.3 历史数据回填

- 来料：使用单据已保存的实际换算率，来源标记为 `DOCUMENT_ACTUAL` 或 `MASTER_DEFAULT`。
- 生产原料：使用已保存的消费核算数量和成本层快照。
- 生产成品：使用已保存的产出核算数量。
- 发货：使用 `shippedValuationQty` 和 `shippedCostAmount`。
- 退货：有关联发货的按原发货比例回填；无关联的标记 `LEGACY_ESTIMATE`。
- 旧库存流水：单位使用当时能够确定的单据快照；只能使用当前物料单位时标记为历史估算。
- BOM：单位与当前库存单位一致的直接回填；不一致的列入人工处理清单，禁止自动改数。

### 9.4 迁移后对账

必须同时验证：

```text
Stock 余额 = 库存流水累计
FIFO Stock 余额 = 开放成本层累计
业务单据确认数量 = 对应库存流水数量
冲销流水 = 原流水精确相反
```

迁移失败或有未处理差异时，部署不得继续。

## 10. 分阶段开发

### 第一阶段：单位规则和对账基础

范围：

- 增加单位模式、单位版本和单位锁定。
- 扩展库存流水快照字段。
- 建立统一数量精度、换算来源和试算函数。
- 建立只读库存对账 API 和页面。
- 生成历史异常清单。

完成标准：

- 不再允许有历史业务的物料直接改单位。
- 任意新增流水都携带单位和换算快照。
- 对账页面能指出现有数据差异。

### 第二阶段：来料到库存

范围：

- 来料草稿明确显示理论值或实测值来源。
- 来料确认和冲销改用统一过账服务。
- 成本层和库存流水由服务统一创建。
- 库存页显示默认换算率、实际平均换算率和批次明细。

完成标准：

- 两批不同换算率的来料能正确形成两层并汇总。
- 冲销任一未消耗批次能精确恢复。
- 移动平均和 FIFO 汇总均通过对账。

### 第三阶段：BOM 和生产日报

范围：

- BOM 保存两端基准数量和单位快照。
- BOM 单位只能使用原料库存单位。
- 生产日报草稿使用统一试算。
- 原料消耗和合格品入库使用统一过账。
- 生产成品创建成本层。

完成标准：

- 不同 BOM 基准比例计算一致。
- 合格、不良、报废全部正确消耗原料。
- 日报冲销能精确恢复两套数量和成本层。

### 第四阶段：发货和退货

范围：

- 数量改为小数。
- 保存双单位、换算和成本快照。
- 发货按物料成本法统一出库。
- 退货按原发货流水恢复。

完成标准：

- 支持按米、kg 等小数单位发货。
- 部分退货不会产生换算尾差。
- 发货和退货后库存、流水和成本层一致。

### 第五阶段：调整和隐藏工单

范围：

- 正式存货调整单。
- FIFO 盘盈、盘亏成本层处理。
- 旧工单预留、领料、取消和入库接入统一服务。
- 删除业务接口中剩余的直接库存更新代码。

完成标准：

- 全仓库业务代码只有库存领域服务可以修改库存余额。
- 工单显示或隐藏都不影响库存算法。
- 全流程对账无差异。

### 第六阶段：批次长度辅助信息

范围：

- 来料批次增加根数、标称长度和混合长度说明。
- 批次库存页面显示剩余总长度、重量和成本。
- 暂不跟踪单根余料。

该阶段不阻塞双单位库存闭环，可在前五阶段稳定后实施。

## 11. 验收场景

### 11.1 FIFO 不同批次换算率

物料配置：

```text
库存单位：米
核算单位：kg
成本方法：FIFO
```

来料：

```text
第一批：120 米，95 kg，760 元
第二批：45 米，34.5 kg，282.9 元
```

确认后：

```text
库存：165 米
核算库存：129.5 kg
金额：1042.9 元
成本层：2 层
```

生产消耗 36.75 米后：

```text
从第一层消耗 36.75 米
核算消耗：29.09375 kg
成本消耗：232.75 元
剩余库存：128.25 米
剩余核算库存：100.40625 kg
剩余金额：810.15 元
```

### 11.2 移动加权平均

使用相同两批来料，成本方法改为移动加权平均：

```text
当前平均换算率 = 129.5 / 165
当前核算单位成本 = 1042.9 / 129.5
```

发出数量必须使用这两个当前平均值，不能使用物料默认换算系数。

### 11.3 BOM 单位错误

原料库存单位为米时：

- BOM 输入单位为米：允许保存。
- BOM 输入单位为根：拒绝保存。
- 历史 BOM 单位为根：迁移报告列为待处理，禁止确认生产。

### 11.4 生产闭环

```text
合格 96 + 不良 3 + 报废 1 = 总加工 100
BOM：100 件产出需要 35 米，损耗 5%
原料消耗：36.75 米
合格品入库：96 件
```

不良和报废不增加成品库存，但原料消耗必须包含它们。

### 11.5 发货与部分退货

发货 20.5 件后退回 3.25 件：

- 发货和退货都允许小数。
- 退货两套数量和成本按原发货流水比例恢复。
- 发货剩余可退数量为 17.25 件。
- 重复退货不能超过原发货数量。

### 11.6 精确冲销

对来料、生产、发货和调整分别验证：

- 冲销流水的库存数量、核算数量和成本与原流水符号相反。
- 原流水和冲销流水互相引用。
- 重复冲销被拒绝。
- 存在后续消耗时，不允许破坏成本层顺序的直接冲销。

### 11.7 单位锁定

- 零库存且无流水：允许修改单位。
- 零库存但有历史流水：禁止直接修改单位。
- 有库存或有 BOM 引用：禁止直接修改单位。

### 11.8 接口幂等

同一个确认请求重复提交：

- 只产生一组库存流水。
- 库存余额只变化一次。
- 第二次请求返回原确认结果或“已经确认”，不能重复过账。

## 12. 实施顺序建议

推荐按以下顺序实施：

```text
第一阶段：统一规则、流水快照、单位锁定、对账
第二阶段：来料 -> 库存
第三阶段：库存 -> BOM -> 生产
第四阶段：成品库存 -> 发货 -> 退货
第五阶段：盘点、冲销、隐藏工单
第六阶段：批次长度辅助信息
```

不能先只修改页面显示。必须先建立统一过账服务和流水快照，否则后续每个页面仍会各自计算双单位，问题会再次出现。

第一阶段和第二阶段完成后，系统才算真正打通“来料到库存”；前四阶段完成后，才算打通小微企业使用的完整生产库存闭环。
