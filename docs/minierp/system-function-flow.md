# MES-lite 系统功能与流程总览

本文用于统一当前系统建模口径，并标出后续需要补齐的功能。

> `v0.1.357` 当前事实：来料、生产投入/产出、发货与客户退货已经形成批次级正反向链。独立质量任务工作台支持整批/部分判定、复检、返工、报废、让步和解冻，每个处置动作都保存独立记录并同步批次余额、流水、成本层和审计人。历史未保存批次的发货单仅建立显式兼容批次，不伪造真实来源。

## 核心建模原则

- 所有可库存、可采购、可生产、可销售、可报废、可回收的对象统一称为“物料”。
- 当前默认启用轻量生产业务模式：仪表盘、生产订单及班后实绩、流程转移、物料、来料、库存、发货、退货作为主线入口。
- BOM 设置和 BOM 全览保留在轻量主线中；BOM 以各投入物料主库存单位和主产出单位保存基准批量关系。投入不限制物料分类。派工暂时隐藏，待日常流转稳定后再逐步打开。
- 原材料、成品、辅材、废料、废品是物料分类，不是独立主数据体系。
- 当前轻量流程同时使用库位和显式库存状态：生产产出和客户退货先进入待检，质量人员可整批或部分放行/冻结；冻结批次可复检、返工、报废、让步或解冻，库存状态覆盖可用、待检、冻结、返工中和报废审计余额。
- 来料红冲保持整单冲销；非整单反向业务后续通过独立来料退货/冲销单处理。
- 普通数量、重量、金额尾差通过库存调整处理，并写入库存流水和操作记录。
- 库位由“配置 / 库位配置”维护；一张来料单的全部物料先进入同一待分库库位，再通过流程转移分配到实际原料或生产库位。班后实绩为每项投入选择来源库位、为每项产出选择去向库位，发货选择出库库位；质量状态不再由库位名称代替。
- 工序类型和是否派单分开配置；派单节点进入派工管理，不派单节点只随报工记录。
- 文档库保持通用：每篇文档有独立标题、结构化在线正文、可配置类别和版本状态，可选关联成品物料及多个工作中心，不保存具体工序实绩；未关联产品时表示跨产品通用文档。服务器从正文 JSON 提取搜索文本，产品全景图只展示明确关联该物料的文档。所有上传文件均保留原始附件，图片、PDF、文本和 Office 文件使用公共预览，方向校正按附件记录。
- BOM 继续只表达“料”；工作中心与设备表达“机”，产品文档中的工艺文件表达“法”。工艺文件可以关联多个适用工作中心，未关联时表示通用；具体设备不写入 BOM。
- 工作中心由“配置 / 工作中心”维护，设备在“设备 / 设备台账”维护并必须归属一个启用的工作中心。
- 员工档案由“业务配置 / 员工资料”维护，系统在新增时自动生成不可修改的业务员工编码；数据库内部 ID、员工编码和“账号与权限”中的登录账号三者分离。管理员可显式建立一对一账号绑定，但绑定不改变账号审核状态、角色或权限。业务单据只允许选择启用员工，并保存工号、姓名快照。
- 工作台提供账号级常用入口，支持系统默认、按主动访问次数智能排序和自定义摆放；“所有功能”页按一级业务域列出当前权限内全部页面。刷新和后台数据请求不计入使用频率。
- 页面层级上限为一级业务入口、一级页面和可选二级详情/稳定子页，不再增加第三级业务页面。
- 全局 AI 协作助手从桌面顶部和移动底部进入，按当前账号权限提供系统指导、物料、库存、BOM、生产订单和经营概览查询；第一阶段只读，不提供通用聊天、外网或任意数据库能力。

## 扫码计数与标签打印底座

当前阶段先验证硬件接入和通用能力，不与发货、库存或生产状态联动。

```mermaid
flowchart LR
  A["Honeywell 1900<br/>USB HID 键盘模式"] --> B["扫码输入适配器"]
  B --> C["独立计数会话"]
  C --> D["匹配 / 未识别 / 超量事件"]
  C --> E["完成计数"]

  F["通用标签数据"] --> G["选择介质尺寸<br/>默认 105×70 mm"]
  G --> H["自适应模板 + Code 128 SVG"]
  H --> I["浏览器打印"]
  I --> J["PC310T 203 dpi"]

  K["后续业务适配器"] -.-> C
  K -.-> F
  L["后续 QZ Tray / 打印桥"] -.-> J
```

边界：

- 扫码会话不修改发货单、库存或生产订单实绩。
- 标签打印不依赖扫码会话是否完成。
- 浏览器只能发起系统打印对话框；打印机 IP 不代表浏览器可以直接连接 RAW 9100 端口。
- 后续业务联动通过 `referenceType + referenceId` 接入，不修改设备适配器。
- 详细设备配置和验收方法见 `docs/minierp/hardware-print-scan.md`。

## 物料编码一次性规范化

“工具 / 数据工具”提供一次性物料编码转换，不作为持续运行的后台开关。

```mermaid
flowchart LR
  A["读取全部物料编码<br/>含已归档记录"] --> B["删除全部空白并转大写"]
  B --> C{"空编码或最终编码冲突？"}
  C -- 是 --> D["阻止执行并列出冲突"]
  C -- 否 --> E["事务更新 Material.code"]
  E --> F["同步 MAT-物料编码 / 历史同编码 Product.sku"]
  F --> G["写入操作记录"]
```

边界：

- 空白包括空格、制表符和换行，名称、规格、备注不转换。
- 已归档物料也参与预检和转换，避免后续恢复时占用规范化编码。
- 历史业务单据中的编码快照不追改。
- 若任何最终物料编码或关联产品编码重复，整批不执行。

## 物料编码数字自然排序

“配置 / 系统设置”提供持续生效的排序开关，和一次性编码规范化工具相互独立。

```mermaid
flowchart LR
  A["管理员开启数字自然排序"] --> B["SystemSetting 持久化"]
  B --> C["物料列表按编码排序"]
  B --> D["物料导出按编码排序"]
  C --> E["读取完整筛选结果"]
  E --> F["按数字片段排序"]
  F --> G["再执行分页"]
  D --> H["按相同规则输出"]
```

- 开启后所有客户端共享设置，`2` 排在 `12` 前，`A2` 排在 `A10` 前。
- 关闭后恢复原有数据库字符串排序。
- 该开关只影响排序结果，不会补零或改写物料编码。
- 非编码字段及用户选择的创建时间、库存等排序方式不受影响。

## 数据关系检查

“工具 / 数据工具”持续提供库存归属、物料、BOM、生产耗用和库存成本层关系检查。检查本身只读；管理员选择具体问题后，修复或删除在单个数据库事务中重新检查并写入操作记录。只有零余额、无库位、无流水的孤立库存允许安全清理；仍有余额或引用时只报警。

同一入口提供图片优化工具。第一阶段范围为物料图片：先扫描原图和两个派生规格的状态，再以最多 10 张为一批生成 WebP 缩略图及展示图并显示页面进度。处理失败不修改原图；新上传物料图片在上传流程中直接生成派生图。业务引用始终指向版本化派生图，只有操作员主动打开原图时读取原文件。

```mermaid
flowchart LR
  A["扫描关键数据关系"] --> B{"问题类型"}
  B --> C["BOM单位/产出单位漂移"]
  B --> D["BOM重复、自引用、无效投入物料"]
  B --> E["日报失效BOM明细指针"]
  B --> F["有效成本层使用旧单位"]
  B --> L["孤立库存归属异常"]
  C --> G["同步当前单位标签<br/>不换算数值"]
  D --> H["逐条确认后删除错误BOM明细"]
  E --> I["保留日报耗用快照<br/>仅清空失效指针"]
  F --> J["仅报警<br/>人工核对库存调整"]
  L --> M{"余额与引用均为空？"}
  M -->|是| N["事务复检后清理空记录"]
  M -->|否| J
  G --> K["写入操作记录"]
  H --> K
  I --> K
  N --> K
```

边界：

- 删除只开放给可独立移除的错误 `BOMItem`，不删除物料、库存流水、成本层或旧生产日报快照。
- 删除 BOM 明细时，引用该明细的日报只清空 `bomItemId`；`quantityPerUnit`、损耗、实际耗用、单位和成本快照继续保留。
- 仍有余额的成本层参与 FIFO 和库存成本运算，工具禁止直接修复或删除，只列出物料、旧单位和当前单位供人工处理。
- 所有处理都会重新扫描确认问题仍存在，避免对已经变化的数据执行过期操作。

## 归档记录永久删除

日常业务页面仍只提供归档。“工具 / 归档记录”提供受保护的永久删除，用于清理误建、未使用且持续占用唯一编码的记录。

```mermaid
flowchart LR
  A["选择归档记录"] --> B["输入“永久删除”确认"]
  B --> C["检查业务状态、库存净额和全部引用"]
  C -->|有有效库存/未冲销流水/下游业务引用| D["阻止并列出原因"]
  C -->|无引用或库存历史已完整红冲| E["事务永久删除主体及自有内容"]
  E --> F["释放唯一编码"]
  E --> G["写入操作记录"]
```

- 已确认、已收货、已发货、已完成或已处理的业务单据不能永久删除。
- 已完整红冲的来料单在库存数量、核算数量和成本金额净影响均为零，且成本层余额为零、没有成本消耗或其他下游引用时，可以永久删除；其成对库存流水和红冲成本层一并清理。
- 归档物料只有在库存余额为零、来料历史均已完整红冲或已拒收、且没有 BOM、领料、生产、发货等下游引用时，才可连同上述失效来料历史永久删除。
- 附件属于被删除记录的自有内容，不作为阻断引用；永久删除时同步删除附件记录和文件。日常读取和维护必须经过附件动作权限、所属业务对象权限与对象存在性校验，暂存附件按登录账号隔离，静态上传目录不直接对外提供文件。
- 未冲销库存流水、仍有效单据及其他业务引用继续禁止删除，不能通过级联破坏有效业务追溯。

## 统一物料模型

```mermaid
flowchart LR
  M["物料主数据"] --> C["物料分类"]
  C --> C1["原材料"]
  C --> C2["成品"]
  C --> C3["辅材"]
  C --> C4["废料"]
  C --> C5["废品"]

  M --> A["业务属性"]
  A --> A1["可采购"]
  A --> A2["可生产"]
  A --> A3["可销售"]
  A --> A4["可领料"]
  A --> A5["可回收"]

  M --> U["计量规则"]
  U --> U1["主计量方式"]
  U --> U2["主库存单位"]
  U --> U3["参考/计价单位"]
  U --> U4["默认参考换算"]

  M --> K["成本方法"]
  K --> K1["移动加权"]
  K --> K2["FIFO"]
```

当前用户侧统一使用 `Material` 作为唯一物品主数据。`Product` 仅作为旧 BOM、工单、发货、退货和成本表的待退出兼容投影，由后端按物料解析旧外键，不再作为独立产品资料入口，也不再创建或补齐 Product 库存。

物料主计量方式分为长度、重量、数量和其他。库存、领料与生产耗用只按主库存单位记账；每个物料最多再配置一个辅助/计价单位。物料的标准换算关系供 BOM 计划换算；来料行必须填写主单位实收量，辅助单位优先填写本批实测量。未填写辅助量时，系统只读取同物料、同单位版本、已收货且来源为本批实测的最近记录；至少 3 批后才按“辅助实测总量 ÷ 主实收总量”的加权率推算。推算行会冻结来源、样本数和换算率，但不会反向进入历史样本。采购计价可选择主单位或辅助单位，单价和总价格双向换算。

- 已有真正的单头/多物料明细、整单收货、拒收、整单红冲、附件和多行 PDF。
- 来料录入保存主单位实收量、可选辅助单位实测量、换算来源/样本数和总价格；辅助实测缺失时执行“至少 3 批实测历史加权推算”，推算记录不污染样本。
- 所有明细先进入同一待分库库位，分库复用现有流程转移；旧单行数据自动迁移为一单一行。
- 来料主路由、详情、收货、拒收和红冲路由均为薄 HTTP 层；`modules/receiving` 统一拥有编号、详情、状态约束以及总库存、库位、成本层和流水事务。
- 缺少独立来料退货/冲销单。

## 生产订单与班后实绩流程

生产统一从“生产订单”进入。订单可事前保存计划，也可在产后补录基本信息；创建时必须选择当前主产出物料的已发布 BOM，并冻结 BOM ID、名称、版本和全部投入/产出快照。草稿和已作废 BOM 不进入候选，已引用版本后续作废也不回算历史订单。BOM 投入可为原材料、半成品或已有产品，以支持二次加工。班后从订单详情登记一名或多名启用员工、全部实际投入、损耗、来源库位、全部实际产出和去向库位。

新生产订单统一执行 `DRAFT → RELEASED → IN_PROGRESS → COMPLETED`，未完工时可进入 `CANCELLED`。草稿必须显式发布后才能派工或登记实绩；第一条实绩确认后进入进行中，累计主产出达到计划后进入已完成，全部已确认实绩被冲销后回到已发布。历史 `CONFIRMED / PICKED / DISPATCHED` 在读取侧归并为已发布，`RUNNING / QC_WAITING / QC_DONE` 归并为进行中；本阶段不批量改写旧数据。

```mermaid
flowchart TD
  A["选择主产出物料与启用 BOM"] --> B["保存生产订单基本信息与 BOM 快照"]
  B --> R["显式发布生产订单"]
  R --> C["班后打开订单并登记日期 / 员工"]
  C --> D["填写全部主产出 / 副产出及去向库位"]
  D --> E["填写任意类别投入物料的来源库位与损耗"]
  E --> I["确认或修正实际投入"]
  I --> V{"保存校验：字段 / 快照 / 库位 / 可用库存"}
  V -->|失败| X["保留输入并提示具体错误"]
  V -->|通过| J["保存员工关联及工号 / 姓名快照"]
  J --> F["生成班后实绩草稿"]
  F --> K{"是否确认"}
  K -->|草稿| L["进入仪表盘待确认"]
  K -->|已确认| N["同一事务扣减全部投入并增加全部产出"]
  N --> G["累计订单主产出并按实绩日期更新仪表盘"]
  K -->|已冲销| M["保留状态但不计入有效产量"]
  I --> H["核对物料库存"]
```

## 流程转移流程

流程转移使用独立入口，不选择 BOM，不存在不同的输入/输出物料字段。用户从员工资料中选择一名启用的操作员工，并只选择一个物料；系统在左右两侧同时显示该物料及图片，用来源/目标库位表达位置或待检、合格等流程节点变化。

```mermaid
flowchart TD
  A["选择日期 / 启用员工 / 物料"] --> B["选择来源和目标库位"]
  B --> C{"两个库位是否不同"}
  C -->|否| X["拒绝保存"]
  C -->|是| D["录入唯一转移数量"]
  D --> E["左右核对同一物料和同一数量"]
  E --> V{"来源库位可用量是否足够"}
  V -->|否| X["拒绝保存并提示可用量"]
  V -->|是| F["保存草稿及员工工号 / 姓名快照"]
  F --> G{"确认"}
  G --> H["原子扣减来源库位、增加目标库位"]
  H --> I["写入一出一入库存流水"]
  I --> J["总库存 / 计价数量 / 总成本 / 成本层不变"]
```

流程转移工作区、草稿创建/编辑、确认和冲销统一由 `modules/production` 的查询、命令和状态服务执行。4 条 Route Handler 不持有 Prisma、编号或库存事务；确认和冲销始终在同一事务内更新两个库位余额、成对库存流水和转移状态。

仪表盘按生产订单和班后实绩两个层次统计：订单数量按创建时间统计，产量只汇总 `CONFIRMED` 实绩中的主产出 `actualQty`，草稿实绩进入待处理，已冲销实绩不计入产量。旧独立生产日报不再参与仪表盘，避免同一批生产重复报产。

## BOM 关系与成本计算流程

BOM 在“BOM 设置”页按主产出物料维护多方案/版本和基准批次。新建和复制版本先保存为草稿；发布后该版本只读并成为同用途默认版本，需要调整时从任一历史版本复制出下一版本草稿；作废只停止后续引用，不删除历史关系。左侧每条记录直接对应一个已建立的 BOM，主标题显示 BOM 名称、版本、生命周期和生产/包装用途，主产出及投入物料仅作为摘要；顶部搜索同时匹配投入、产出、BOM 和版本。右侧使用左输入、右输出的整批配方：两侧均可搜索添加多项物料并填写每批数量，长度和重量可选择同量纲录入单位并自动换算，首项输出作为主产出，后续可添加副产品、可回收料、废料或废屑。包装 BOM 必须只有一项产出，用于表达散件与整箱等包装物料的真实库存转换及库存穿透。全部输入组成整体消耗并共同对应全部输出，底层按各物料主库存单位保存每批绝对量及录入单位偏好，新 `BOMItem.outputMaterialId` 置空。标准生产 BOM 不另设固定或百分比损耗。生产订单创建时只选择已发布 BOM 并保存明确快照；BOM 成本在未显式指定时读取默认已发布方案。

```mermaid
flowchart TD
  A["填写整批输入物料与数量"] --> B["填写整批输出物料与数量"]
  B --> V["填写或修改 BOM 方案名称"]
  V --> D["保存整批输入与整批输出"]
  D --> E["物料查看投入组成"]
  D --> F["投入物料反查使用 BOM"]
  D --> G["成本试算按数量基准计算"]
  D --> P["生产订单显式选择 BOM 并计算投入与产出"]
  P --> L["逐项选择来源库位及固定或百分比损耗"]
  L --> M["确认或修正实际耗用"]
  H["维护成本对象"] --> I["录入单位材料成本、人工时、机时、直接费"]
  I --> J["成本对象可加入物料 BOM"]
  J --> G
  G --> K["汇总 BOM 成本并保存快照"]
```

边界：

- `MATERIAL` BOM 项保存整个批次共同消耗的绝对投入量，单位固定为所选投入物料主库存单位；同一投入物料在一个 BOM 中只能出现一次，不归属于某项输出。
- 同一主产出物料可有多个方案/版本，版本号不可重复；一个方案可一次产出多种物料。只有草稿可编辑，生产订单提交时必须保存本次明确选择的已发布版本，成本计算在未显式指定时读取默认已发布方案。
- BOM 不再有1:1、比例或转换模型等方案类型；`purpose` 只区分生产和包装用途。1:1 仍是普通生产比例，同物料流程转移不建 BOM，进入独立 `FlowTransfer` 流程。
- 库存包装穿透只递归展开默认已发布的包装 BOM，排除分类为“包装物”的纸箱、标签等投入，将包装产出库存按 BOM 批量换算为内容物等效数量。真实散件、整箱和各库位余额继续独立记账，等效合计不得写回 `Stock`。
- BOM 编辑器左右两侧都支持连续添加物料并直接修改每批数量；用户完成新增、数量修改或移除后，通过方案名称区唯一的“保存 BOM”一次提交整个 BOM，未保存状态必须明确可见。
- 生产订单实绩将保存 BOM 名称、版本、基准批次及全部投入/产出快照；每项实绩保存数量和库位。实绩按主产出计算批次倍数后展开共同投入，确认与冲销均按快照原子更新总库存、库位余额、成本层和流水。
- `SAWING_COST` / 成本对象 BOM 项只参与成本结构和 BOM 成本计算。
- 固定费用分摊只写入本次成本快照，不写回 BOM。
- 派工仍由工艺路线和工单驱动，不由 BOM 成本快照驱动。
- BOM 设置页用于创建和修改任意投入物料与一个或多个产出的转换关系；BOM 全览页以物料为中心，分别检查它作为产出和作为投入关联的全部直接 BOM，并可精准跳回对应 BOM 设置；物料全景图同步展示该物料相关 BOM、加工参数和成本对象。

### 派单与不派单逻辑

| 模式 | 适用场景 | 操作逻辑 |
| --- | --- | --- |

```mermaid
flowchart TD
  A["发现账实差异"] --> B{"差异来源"}
  B -->|来料整单错误| C["来料整单红冲"]
```

库存调整不是业务退货单据，只用于账实修正、盘点差异、损耗和历史数据尾差。

库存页会做一致性检查：每个有效 `Material` 必须有对应 `Stock` 余额行。`Product` 只是旧外键兼容投影；Product 独占历史库存只进入模型收敛审计，不再自动创建或补齐。

若只缺少 0 余额行，具备库存修改权限的人员打开库存页时会自动调用“补齐库存余额”动作创建缺失的 Material 库存记录；该动作不调整已有数量和金额，只补物料对应余额行并写操作记录。Product 独占余额、负库存、预留大于库存或关联异常必须列入审计并由人工处理。
