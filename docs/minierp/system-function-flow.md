# MES-lite 系统功能与流程总览

本文用于统一当前系统建模口径，并标出后续需要补齐的功能。

## 核心建模原则

- 所有可库存、可采购、可生产、可销售、可报废、可回收的对象统一称为“物料”。
- 当前默认启用轻量生产业务模式：仪表盘、生产订单及班后实绩、流程转移、物料、来料、库存、发货、退货作为主线入口。
- 物料 BOM 关联和 BOM 反查保留在轻量主线中；BOM 以各投入物料主库存单位和主产出单位保存基准批量关系。投入不限制物料分类。派工暂时隐藏，待日常流转稳定后再逐步打开。
- 原材料、成品、辅材、废料、废品是物料分类，不是独立主数据体系。
- 当前轻量流程用可配置库位和产出物料表达成品、不良、报废、待检等实物去向，不在生产实绩中固定质量分类字段。
- 来料红冲保持整单冲销；非整单反向业务后续通过独立来料退货/冲销单处理。
- 普通数量、重量、金额尾差通过库存调整处理，并写入库存流水和操作记录。
- 库位由“配置 / 库位配置”维护；来料选择收货库位，班后实绩为每项投入选择来源库位、为每项产出选择去向库位，流程转移选择来源和目标库位，发货选择出库库位。待检、合格等状态可用库位表达。
- 工序类型和是否派单分开配置；派单节点进入派工管理，不派单节点只随报工记录。
- 产品文档保持通用：关联成品物料、可配置文档类别和可选适用工作中心，不保存具体工序实绩；适用范围等说明写入备注，产品全景图展示该物料的全部相关文档。图片和 PDF 的方向校正按附件保存；缩略图由服务器首次生成后存入附件持久化目录，列表、详情和全景图统一复用。
- BOM 继续只表达“料”；工作中心与设备表达“机”，产品文档中的工艺文件表达“法”。工艺文件可以关联多个适用工作中心，未关联时表示通用；具体设备不写入 BOM。
- 工作中心由“配置 / 工作中心”维护，设备在“设备 / 设备台账”维护并必须归属一个启用的工作中心。
- 员工档案由“配置 / 员工资料”维护，系统在新增时自动生成不可修改的业务员工编码；数据库内部 ID、员工编码和账户菜单中的登录账号三者分离。管理员可显式建立一对一账号绑定，但绑定不改变账号审核状态、角色或权限。业务单据只允许选择启用员工，并保存工号、姓名快照。
- 工作台提供账号级常用入口，支持系统默认、按主动访问次数智能排序和自定义摆放；“所有功能”页按一级业务域列出当前权限内全部页面。刷新和后台数据请求不计入使用频率。
- 页面层级上限为一级业务入口、一级页面和可选二级详情/稳定子页，不再增加第三级业务页面。

## 扫码计数与标签打印底座

当前阶段先验证硬件接入和通用能力，不与发货、库存或生产状态联动。

```mermaid
flowchart LR
  A["Honeywell 1900<br/>USB HID 键盘模式"] --> B["扫码输入适配器"]
  B --> C["独立计数会话"]
  C --> D["匹配 / 未识别 / 超量事件"]
  C --> E["完成计数"]

  F["通用标签数据"] --> G["选择介质尺寸<br/>默认 105×70 mm"]
  G --> H["自适应模板 + Code 128 SVG"]
  H --> I["浏览器打印"]
  I --> J["PC310T 203 dpi"]

  K["后续业务适配器"] -.-> C
  K -.-> F
  L["后续 QZ Tray / 打印桥"] -.-> J
```

边界：

- 扫码会话不修改发货单、库存或生产订单实绩。
- 标签打印不依赖扫码会话是否完成。
- 浏览器只能发起系统打印对话框；打印机 IP 不代表浏览器可以直接连接 RAW 9100 端口。
- 后续业务联动通过 `referenceType + referenceId` 接入，不修改设备适配器。
- 详细设备配置和验收方法见 `docs/minierp/hardware-print-scan.md`。

## 物料编码一次性规范化

“工具 / 数据工具”提供一次性物料编码转换，不作为持续运行的后台开关。

```mermaid
flowchart LR
  A["读取全部物料编码<br/>含已归档记录"] --> B["删除全部空白并转大写"]
  B --> C{"空编码或最终编码冲突？"}
  C -- 是 --> D["阻止执行并列出冲突"]
  C -- 否 --> E["事务更新 Material.code"]
  E --> F["同步 MAT-物料编码 / 历史同编码 Product.sku"]
  F --> G["写入操作记录"]
```

边界：

- 空白包括空格、制表符和换行，名称、规格、备注不转换。
- 已归档物料也参与预检和转换，避免后续恢复时占用规范化编码。
- 历史业务单据中的编码快照不追改。
- 若任何最终物料编码或关联产品编码重复，整批不执行。

## 物料编码数字自然排序

“工具 / 系统设置”提供持续生效的排序开关，和一次性编码规范化工具相互独立。

```mermaid
flowchart LR
  A["管理员开启数字自然排序"] --> B["SystemSetting 持久化"]
  B --> C["物料列表按编码排序"]
  B --> D["物料导出按编码排序"]
  C --> E["读取完整筛选结果"]
  E --> F["按数字片段排序"]
  F --> G["再执行分页"]
  D --> H["按相同规则输出"]
```

- 开启后所有客户端共享设置，`2` 排在 `12` 前，`A2` 排在 `A10` 前。
- 关闭后恢复原有数据库字符串排序。
- 该开关只影响排序结果，不会补零或改写物料编码。
- 非编码字段及用户选择的创建时间、库存等排序方式不受影响。

## 数据关系检查

“工具 / 数据工具”持续提供物料、BOM、生产耗用和库存成本层关系检查。检查本身只读；管理员选择具体问题后，修复或删除在单个数据库事务中执行并写入操作记录。

```mermaid
flowchart LR
  A["扫描关键数据关系"] --> B{"问题类型"}
  B --> C["BOM单位/产出单位漂移"]
  B --> D["BOM重复、自引用、无效投入物料"]
  B --> E["日报失效BOM明细指针"]
  B --> F["有效成本层使用旧单位"]
  C --> G["同步当前单位标签<br/>不换算数值"]
  D --> H["逐条确认后删除错误BOM明细"]
  E --> I["保留日报耗用快照<br/>仅清空失效指针"]
  F --> J["仅报警<br/>人工核对库存调整"]
  G --> K["写入操作记录"]
  H --> K
  I --> K
```

边界：

- 删除只开放给可独立移除的错误 `BOMItem`，不删除物料、库存流水、成本层或旧生产日报快照。
- 删除 BOM 明细时，引用该明细的日报只清空 `bomItemId`；`quantityPerUnit`、损耗、实际耗用、单位和成本快照继续保留。
- 仍有余额的成本层参与 FIFO 和库存成本运算，工具禁止直接修复或删除，只列出物料、旧单位和当前单位供人工处理。
- 所有处理都会重新扫描确认问题仍存在，避免对已经变化的数据执行过期操作。

## 归档记录永久删除

日常业务页面仍只提供归档。“工具 / 归档记录”提供受保护的永久删除，用于清理误建、未使用且持续占用唯一编码的记录。

```mermaid
flowchart LR
  A["选择归档记录"] --> B["输入“永久删除”确认"]
  B --> C["检查业务状态、库存净额和全部引用"]
  C -->|有有效库存/未冲销流水/下游业务引用| D["阻止并列出原因"]
  C -->|无引用或库存历史已完整红冲| E["事务永久删除主体及自有内容"]
  E --> F["释放唯一编码"]
  E --> G["写入操作记录"]
```

- 已确认、已收货、已发货、已完成或已处理的业务单据不能永久删除。
- 已完整红冲的来料单在库存数量、核算数量和成本金额净影响均为零，且成本层余额为零、没有成本消耗或其他下游引用时，可以永久删除；其成对库存流水和红冲成本层一并清理。
- 归档物料只有在库存余额为零、来料历史均已完整红冲或已拒收、且没有 BOM、领料、生产、发货等下游引用时，才可连同上述失效来料历史永久删除。
- 附件属于被删除记录的自有内容，不作为阻断引用；永久删除时同步删除附件记录和文件。
- 未冲销库存流水、仍有效单据及其他业务引用继续禁止删除，不能通过级联破坏有效业务追溯。

## 统一物料模型

```mermaid
flowchart LR
  M["物料主数据"] --> C["物料分类"]
  C --> C1["原材料"]
  C --> C2["成品"]
  C --> C3["辅材"]
  C --> C4["废料"]
  C --> C5["废品"]

  M --> A["业务属性"]
  A --> A1["可采购"]
  A --> A2["可生产"]
  A --> A3["可销售"]
  A --> A4["可领料"]
  A --> A5["可回收"]

  M --> U["计量规则"]
  U --> U1["主计量方式"]
  U --> U2["主库存单位"]
  U --> U3["参考/计价单位"]
  U --> U4["默认参考换算"]

  M --> K["成本方法"]
  K --> K1["移动加权"]
  K --> K2["FIFO"]
```

当前用户侧统一使用 `Material` 作为唯一物品主数据。`Product` 仅作为旧 BOM、工单、发货、退货和成本表的内部兼容视图，由后端按物料自动映射，不再作为独立产品资料入口。

物料主计量方式分为长度、重量、数量和其他。库存、领料与生产耗用只按主库存单位记账；其它单位作为来料实测、采购计价和成本参考。物料不保存标准长度。来料单并列记录件数、总长度和总重量：总长度可以直接填写，也可以由件数乘单件长度计算；总重量始终表示本批总重量。三值完整时可锁定本批比例进行录入联动，但收货保存的是三个独立实测快照。采购计价可选米、kg 或件，单价和总价格任一项修改都会按对应实测数量换算另一项。

## 来料流程

```mermaid
flowchart TD
  A["创建来料单"] --> B{"是否收货"}
  B -->|拒收| C["来料单状态: 已拒收"]
  B -->|收货| D["库存增加"]
  D --> E["生成库存流水"]
  D --> F["生成成本层"]
  F --> G["来料单状态: 已收货"]
  G --> H{"是否需要冲销"}
  H -->|整单错误| I["整单红冲"]
  H -->|部分退料| J["来料退货/冲销单_待补"]
  H -->|数量金额尾差| K["库存调整"]
```

现状：

- 已有来料单、收货、拒收、整单红冲、附件。
- 来料录入保存件数、总长度、总重量和总价格；单价支持按米、kg、件计价。
- 已有旧数据兼容红冲和库存调整。
- 缺少独立来料退货/冲销单。

## 生产订单与班后实绩流程

生产统一从“生产订单”进入。订单可事前保存计划，也可在产后补录基本信息；创建时必须选择当前主产出物料的启用 BOM 并冻结全部投入/产出快照。BOM 投入可为原材料、半成品或已有产品，以支持二次加工。班后从订单详情登记一名或多名启用员工、全部实际投入、损耗、来源库位、全部实际产出和去向库位。

```mermaid
flowchart TD
  A["选择主产出物料与启用 BOM"] --> B["保存生产订单基本信息与 BOM 快照"]
  B --> C["班后打开订单并登记日期 / 员工"]
  C --> D["填写全部主产出 / 副产出及去向库位"]
  D --> E["填写任意类别投入物料的来源库位与损耗"]
  E --> I["确认或修正实际投入"]
  I --> V{"保存校验：字段 / 快照 / 库位 / 可用库存"}
  V -->|失败| X["保留输入并提示具体错误"]
  V -->|通过| J["保存员工关联及工号 / 姓名快照"]
  J --> F["生成班后实绩草稿"]
  F --> K{"是否确认"}
  K -->|草稿| L["进入仪表盘待确认"]
  K -->|已确认| N["同一事务扣减全部投入并增加全部产出"]
  N --> G["累计订单主产出并按实绩日期更新仪表盘"]
  K -->|已冲销| M["保留状态但不计入有效产量"]
  I --> H["核对物料库存"]
```

## 流程转移流程

流程转移使用独立入口，不选择 BOM，不存在不同的输入/输出物料字段。用户从员工资料中选择一名启用的操作员工，并只选择一个物料；系统在左右两侧同时显示该物料及图片，用来源/目标库位表达位置或待检、合格等流程节点变化。

```mermaid
flowchart TD
  A["选择日期 / 启用员工 / 物料"] --> B["选择来源和目标库位"]
  B --> C{"两个库位是否不同"}
  C -->|否| X["拒绝保存"]
  C -->|是| D["录入唯一转移数量"]
  D --> E["左右核对同一物料和同一数量"]
  E --> V{"来源库位可用量是否足够"}
  V -->|否| X["拒绝保存并提示可用量"]
  V -->|是| F["保存草稿及员工工号 / 姓名快照"]
  F --> G{"确认"}
  G --> H["原子扣减来源库位、增加目标库位"]
  H --> I["写入一出一入库存流水"]
  I --> J["总库存 / 计价数量 / 总成本 / 成本层不变"]
  J --> K{"是否冲销"}
  K -->|是| L["校验原目标库位可用量并反向转回"]
```

仪表盘按生产订单和班后实绩两个层次统计：订单数量按创建时间统计，产量只汇总 `CONFIRMED` 实绩中的主产出 `actualQty`，草稿实绩进入待处理，已冲销实绩不计入产量。旧独立生产日报不再参与仪表盘，避免同一批生产重复报产。

## 后续可选派工生产流程

工单流程保留在轻量业务菜单中，派工管理暂时隐藏。需要完整追踪负责人、计划时间、工序进度和责任时，再打开派工。

```mermaid

  A["先保存生产订单基本信息与 BOM 快照"] --> B["按需要下达派工"]
  B --> C["领料"]
  C --> D{"工序是否派单"}
  D -->|是| E["生成派工单"]
  E --> F["派工/开工/完工"]
  F --> G["报工"]
  D -->|否| G
  G --> H["在线检测或流程记录"]
  H --> I{"是否合格"}
  I -->|合格| J{"是否最后工序"}
  I -->|可返工| K["现场返工记录"]
  K --> H
  I -->|不可返工| L["记录废品/废料"]
  J -->|否| D
  J -->|是| M["成品入库"]
  L --> N["库存调整或报废处理_后续增强"]
```

现状：

- 已有工单、领料、派工、报工、成品入库基础能力。
- 现场检测和返工可以先随报工记录表达，不强制生成质检单或返工单。
- 辅助流程默认只作为工艺/报工结果记录；如果打开派单开关，则进入派工管理。
- 待检库存、返工单、报废处理单属于后续增强，不作为当前简单生产的前置条件。

## BOM 关系与成本计算流程

BOM 在“物料 BOM 关联”页按主产出物料维护多方案/版本、基准批量多项产出和对应多项投入。左侧只列已经建立的 BOM，可切换“按产出”和“按投入”两个观察维度；按投入选择时同时定位引用它的主产出、方案和投入条目。顶部搜索同时匹配投入、产出、BOM 和版本。右侧以左侧“投入（物料）”、右侧“输出（产品）”两个可搜索输入框直接建立关系；投入可选择原材料、半成品或已有产品，首个产出为主产出，继续搜索可添加副产品、可回收料或废料等其他产出。方案类型已删除，1:1 仅是数量比例。投入/产出选定后立即显示标准净用量、百分比损耗、固定损耗和按当前量纲命名的批量换算模型，例如“长度 → 件数”“重量 → 件数”或“数量 → 数量”；底层统一保存基准批量关系。生产订单创建时保存明确 BOM 快照；BOM 成本在未显式指定时读取默认启用方案。

```mermaid
flowchart TD
  A["选择产出物料"] --> V["选择或新建 BOM 方案/版本"]
  V --> Q["设定基准批量多项产出"]
  Q --> B["添加任意投入物料"]
  B --> C["选择净用量、损耗或量纲批量换算"]
  C --> R["计算每 1 产出单位的单位用量"]
  R --> D["按基准批量保存物料 BOM"]
  D --> E["物料查看投入组成"]
  D --> F["投入物料反查使用 BOM"]
  D --> G["成本试算按数量基准计算"]
  D --> P["生产订单显式选择 BOM 并计算投入与产出"]
  P --> L["逐项选择来源库位及固定或百分比损耗"]
  L --> M["确认或修正实际耗用"]
  H["维护成本对象"] --> I["录入单位材料成本、人工时、机时、直接费"]
  I --> J["成本对象可加入物料 BOM"]
  J --> G
  G --> K["汇总 BOM 成本并保存快照"]
```

边界：

- `MATERIAL` BOM 项保存基准批量输入，单位固定为所选投入物料主库存单位；界面以 `批量输入 / 主产出批量` 显示“投入单位/产出单位”。
- 同一主产出物料可有多个方案/版本；一个方案可一次产出多种物料。生产订单提交时必须保存本次明确选择，成本计算在未显式指定时读取默认启用方案。
- BOM 不再有方案类型；1:1 也是普通生产比例。同物料流程转移不建 BOM，进入独立 `FlowTransfer` 流程。
- BOM 计算器的“添加或更新”只把有效结果合并到待保存投入明细，已有同投入物料条目覆盖待保存比例而不重复；已有关系显示“当前已保存比例”和“待保存比例”，新关系显示为尚未保存。用户完成多个新增、比例修改、直接编辑或移除后，通过工作区标题栏唯一的“保存 BOM”一次提交整个 BOM；未保存状态必须明确可见，保存按钮不得悬浮遮挡表单。
- 生产订单实绩将保存 BOM 名称、版本、基准批量及全部投入/产出快照；每项实绩保存数量和库位。确认与冲销均按快照原子更新总库存、库位余额、成本层和流水。
- `SAWING_COST` / 成本对象 BOM 项只参与成本结构和 BOM 成本计算。
- 固定费用分摊只写入本次成本快照，不写回 BOM。
- 派工仍由工艺路线和工单驱动，不由 BOM 成本快照驱动。
- 物料 BOM 关联页用于维护任意投入物料与一个或多个产出的转换关系，BOM 反查页用于按投入物料检查引用关系；物料全景图同步展示该物料相关 BOM、加工参数和成本对象。

### 派单与不派单逻辑

| 模式 | 适用场景 | 操作逻辑 |
| --- | --- | --- |
| 派单 | 需要追踪负责人、计划数量、计划时间、进度和责任的工序 | 工单领料后生成派工单，执行派工、开工、完工，再报工 |
| 不派单 | 辅助流程、在线检测、简单返工、临时处理 | 不进入派工管理，只在报工时记录数量、质量结果、备注和附件 |

## 库存调整流程

```mermaid
flowchart TD
  A["发现账实差异"] --> B{"差异来源"}
  B -->|来料整单错误| C["来料整单红冲"]
  B -->|业务退货| D["退货/冲销单_待补"]
  B -->|盘点差异| E["库存调整"]
  B -->|称重/小数尾差| E
  B -->|早期数据成本缺失| E
  E --> F["调整数量/核算数量/库存金额"]
  F --> G["写入库存流水"]
  F --> H["写入操作记录"]
```

库存调整不是业务退货单据，只用于账实修正、盘点差异、损耗和历史数据尾差。

库存页会做一致性检查：物料或内部兼容记录必须有对应 `Stock` 余额行。`Material` 是用户侧主数据，`Product` 仅作为旧外键兼容视图，`Stock` 是库存余额表，库存页只是在展示时把物料与库存余额组合成库存清单。

若只缺少 0 余额行，具备库存修改权限的人员打开库存页时会自动调用“补齐库存余额”动作创建缺失的物料/产品库存记录；该动作不调整已有数量和金额，只补主数据对应余额行并写操作记录。若自动补齐失败，页面会显示手动补齐入口；若当前人员没有库存修改权限，页面会保留一致性异常提示，等待有权限人员处理。若存在负库存、预留大于库存或关联异常，则停止展示并列出需要人工处理的明细。
