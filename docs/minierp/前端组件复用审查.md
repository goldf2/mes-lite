# MES-lite 前端组件复用审查

审查日期：2026-08-04；增量复核：2026-08-09

## 1. 审查目标

本次审查聚焦 `app/components`：识别重复的视觉原语和交互实现，优先收口低风险、高复用的部分，并给后续页面拆分提供顺序。业务算法、接口和数据库模型不在本轮改造范围内。

## 2. 当前概况

- `app/` 与 `modules/` 的前端 TSX 约 29,016 行。
- 当前最大页面是 `BomCostPage.tsx`（720 行），其次是 `MaterialPage.tsx`（709 行）和 `SalesOrderPage.tsx`（686 行）。不可达的 936 行旧生产日报页已经删除；库存协调页从 853 行降至 304 行，派工页迁入生产领域并从 730 行降至 646 行。系统当前已无超过 800 行的页面。物料全景已从 1,485 行降至 187 行，来料主页面从 1,679 行降至 684 行，作业文档主页面从 1,497 行降至 591 行，`SystemPage.tsx` 已降至 31 行纯分派层。
- `modules/materials/ui/MaterialPage.tsx` 已降至 709 行，物料契约、HTTP client、详情、编辑、导入、集合视图、页内选项、显示偏好、双形态工具栏、BOM 工作区和 BOM 草稿编辑均已移出页面正文。
- 代码中约有 299 个原生按钮和 121 个 `AppButton` 调用。原生按钮包含表格行、选项和紧凑工具等合理场景，不能只按数量机械替换。
- 约有 34 个原生下拉框、37 个 `SearchableSelect` 调用和 6 个 `MaterialChoiceSearch` 调用。动态业务数据应继续迁移到可输入筛选的选择器。
- `BomCostPage.tsx` 当前没有被 `app/page.tsx` 或其他页面引用，属于保留但未接入的功能模块。确认产品方向前不直接删除；若不再启用，应连同专属接口和文档单独清理。

行数和标签数量只是定位信号。是否抽取组件仍以业务语义、交互一致性和重复修改风险为判断依据。

## 3. 本轮已收口

### 3.0 应用入口与领域页面所有权

原 `app/page.tsx` 同时承担鉴权、导航、URL 连续性、工作台、生产订单和库存数据状态，已按业务所有权拆分：

- `app/page.tsx` 只保留稳定入口；公共应用壳迁入 `app/HomeApp.tsx`。
- 导航分组、功能目录和页面连续性读写迁入 `app/app-navigation.ts`，桌面与移动布局继续读取同一份定义。
- 工作台、生产订单、库存、业务配置、物料、BOM、系统设置和运维工具已分别迁入对应 `modules/*`，并只通过模块根目录 `index.ts` 对应用壳公开。
- 物料/BOM 页面不再直接发起 HTTP 请求，数据访问已分别集中到 `modules/materials/client` 和 `modules/bom/client`，共享数据结构进入各自 `contracts`。
- 公共 `PageModuleBoundary`、`TopBarPortal`、`ResponsiveToolbarActions`、导航组件及权限回调继续作为唯一装配路径，没有复制第二套应用壳或工具栏。
- 文档领域的创建与详情编辑共用 `WorkInstructionFormFields`；卡片/列表、创建、详情/附件与全屏查看分别作为可独立验证的领域 UI 模块，不复制公共弹窗、预览、正文编辑或一对多关联控件。
- 来料领域的集合、编辑与详情已成为独立用户任务；供应商和物料联想统一复用支持异步检索的 `SearchableSelect`，主 API 的查询、计量计价和多明细事务规则进入领域服务。
- 物料全景按业务认知拆为六组纯展示任务，并把布局设置与文件查看器独立出来；布局顺序、宽度、密度和格式规则由领域视图模型统一维护。

本次只改变代码所有权，不修改接口契约、数据库模型、业务状态流转和页面视觉结构。后续拆分其他超大页面时沿用同一原则：先形成可独立验证的领域垂直切片，再从应用壳移除对应业务状态。

### 3.1 数值输入

新增 `NumberInputField.tsx`，统一标签、输入高度、焦点态、最小值、步长和单位后缀。锯切成本、BOM 成本和生产日报不再维护局部数值字段。

### 3.2 指标卡片

新增 `MetricCard.tsx`，提供常规与紧凑两种密度，并使用语义化的主值、成功、警告和危险色。锯切成本、BOM 成本、生产日报和流程转移共用同一实现。

### 3.3 物料搜索

扩展 `MaterialChoiceSearch.tsx`，支持空状态、结果上限和 BOM 版本徽标。两个成本页面删除各自的物料搜索弹层，统一获得输入筛选、键盘选择、Esc、点击外部关闭和焦点样式。`MaterialChoiceSearch` 与 `SearchableSelect` 共用弹层方向计算，在视口底部自动向上展开并限制可用高度。

本轮删除了 5 个页面中的重复局部组件；公共数值字段和指标卡片目前分别覆盖 26 和 35 个调用位置。

## 4. 后续优先级

### P1：继续迁移视觉原语

- 将普通表单输入逐步迁移到 `FormField` 和输入样式常量。
- 按语义审查原生按钮；页面主操作、保存、危险操作优先迁移到 `AppButton`，选项行和原生控件保留合理例外。
- 动态客户、物料、库位和人员选择不得新增普通 `select`。

### P2：继续拆分超大领域页面

- `SystemPage.tsx`：数据工具、设置和生产工程职责已全部迁入对应模块；下一步优先拆分物料协调页及其他根级领域页的稳定业务视图。
- `MaterialInPage.tsx`：来料单编辑、历史集合和详情已完成拆分；后续只有形成第二调用方时才继续抽取领域表单原语。
- `MaterialPanoramaPage.tsx`：稳定业务视图、布局设置和文件查看器已完成拆分；后续功能直接进入相应任务模块，不回流协调页。
- `StockPageModule.tsx`：集合、详情、调整和一致性提示已完成拆分；后续库存展示进入对应任务，HTTP 和格式规则不得回流协调页。

拆分时保持数据请求和状态在最接近其所有者的位置；只有多个业务区块共享的状态才提升到页面层。

### P3：补齐公共能力

- 建立统一状态标签，消除页面内重复的状态文字与颜色映射。
- 评估通用数据表格和详情面板，只在至少两个稳定页面模式一致后抽取。
- 为公共选择器、弹窗和字段增加聚焦的交互测试，防止统一组件变更扩大回归范围。

## 5. 新代码约束

- 新需求先检查现有公共组件；能力不足时扩展公共组件，不复制一份局部实现。
- 业务页面保留业务组合和领域规则，颜色、尺寸、焦点、关闭方式等视觉交互由公共组件负责。
- 不以“消除所有原生标签”为目标；简单、语义正确且没有重复风险的原生控件可以保留。
- 单个页面持续增长时，优先按业务所有权拆分，不以任意行数切割文件。
