# MES-lite 桌面端界面开发规范

本文是 `docs/minierp/系统交互与设计规范.md` 的桌面端专项细则，主要补充桌面应用壳、信息密度、表格和工作区布局；公共组件、颜色语义、保存模型、弹窗行为和完成定义以主规范为准。

桌面端面向电脑大屏、鼠标键盘、长时间录入和批量处理。核心目标是信息密度高、操作入口清楚、对比方便、重复操作效率高。

## 1. 适用范围

- 默认适用于宽度大于等于 1024px 的电脑浏览器。
- 1280px 到 1920px 是主要设计区间。
- 桌面端不按手机逻辑隐藏大量功能，不能为了移动端简化而牺牲大屏效率。
- 具体断点和截图验收要求见：`docs/minierp/响应式断点与验收矩阵.md`。
- 应用壳、导航分层和工作区类型见：`docs/minierp/layout-architecture.md`。

## 2. 页面结构

- 顶部横向导航始终显示稳定的一级业务分类，作为桌面基础控制区；其下采用左侧辅助区、中央主显示区、可选右侧上下文辅助区。
- 左侧辅助区只显示当前分类下的功能页面，宽度可调并保存在当前浏览器；右侧辅助区承载详情、BOM 编辑等上下文功能，宽度可调，没有内容时自动收起。
- 登录成功或首次进入系统时默认显示“工作台 / 仪表盘”；无仪表盘权限时回退到首个可读页面。
- 工作台常用功能支持系统默认、按当前账号使用频率智能排序和用户自定义摆放；“所有功能”页按一级业务域展示完整权限内入口并支持搜索。
- 用户主动从顶部、侧栏、移动端导航、工作台或所有功能页打开一级页面时才记录使用次数；刷新、数据重载和详情返回不计数。
- 导航层级固定为一级业务入口、一级页面和可选二级详情/子页，禁止出现第三级业务页面。
- 左侧当前模块菜单已经显示选中页面时，顶部工具栏不再重复显示“业务功能/页面标题”；仪表盘没有搜索或页面操作时不渲染空工具栏。
- 顶部增加“配置”一级分类，供应商资料、客户资料、员工资料、库位配置、单位配置、加工工艺、物料路线和系统设置归入“配置”；归档、日志、数据工具、计算和硬件功能留在“工具”；账户菜单只保留登录账号和权限。
- 管理类页面通过左侧功能入口直接打开，不再在内容区重复显示“系统管理”横向页签。
- 存在稳定子页面的业务模块使用左侧可展开分级导航；父项负责展开和进入模块，子项必须明确显示当前选中状态。
- “物料”模块只保留物料管理、物料 BOM 关联、BOM 反查三个二级入口，BOM 维护不再重复提供另一套关系设定页。
- 物料 BOM 关联工作区明确显示投入物料主库存计算单位，内置标准净用量、百分比损耗、固定损耗和量纲批量换算四种录入模型，最终统一保存换算比例；班后实绩在每种投入行展示基准耗用、本批额外损耗、计算耗用和实际耗用。
- 物料 BOM 关联使用主从工作区：左侧只列已有 BOM，并提供按产出/按投入两个观察维度；顶部搜索同时匹配产出、投入物料、BOM 和版本。右侧负责新建和修改，首屏固定使用左侧“投入物料”和右侧“产出明细（可多项）”，投入和首项主产出允许任意顺序选择。产出区使用同一搜索框逐项添加：选择物料后先进入待确认卡片，数量大于 0 并点击确认后才加入明细、重新开放下一项选择；不得在选择时直接按默认数量加入。产出达到 4 项时，明细行使用带稳定滚动槽的限高区域，搜索框和已添加数量保持可见。投入不按物料分类设限。不得增加独立的产出选择过渡页，未选完整时仍显示标题栏保存按钮及禁用原因。禁止把全部物料分页列表放回左侧。
- 生产订单创建页先选主产出和启用 BOM；订单详情中的班后实绩使用“左投入—右产出”双栏，二者都列出全部 BOM 快照明细及逐项库位。流程转移是独立入口，使用“左来源—中转移—右目标”布局，左右展示同一物料图片和信息。
- 班后实绩的员工字段使用可搜索多选和可移除标签；流程转移使用可搜索单选。员工列表只显示启用档案，并同时展示员工编码、姓名和可选部门。
- 员工资料列表增加登录账号列；新增弹窗的员工编码显示为系统生成提示，编辑弹窗只读显示既有编码；账号绑定使用可搜索、可清除控件，并在选项中显示账号姓名和状态。
- 全局成功和错误提示固定在顶部应用栏下方，并通过根级 Portal 显示在普通弹窗遮罩之上；弹窗打开期间不得被遮挡或应用后台模糊效果。
- 来料、生产订单实绩、流程转移和发货表单必须明确显示库位选择；发货和转移选择物料/来源库位后就地展示该库位可用量。
- BOM 用量、损耗和比例输入必须允许直接键入小数，至少支持 `0.001`，不能在用户输入 `0.` 的过程中提前转换为整数或清空。
- BOM 录入内置标准净用量、百分比损耗、固定损耗和批量换算四种模型；长度型投入默认按 `mm` 录入，并允许切换 `cm`、`m`。长度→件数等批量换算的投入总长度使用当前尺寸单位，最终结果统一换算为 `m/产出主单位` 保存。
- 物料的主库存单位和参考/计价单位必须使用受控下拉列表；单位选项来自系统单位目录，自定义单位在“配置 → 单位配置”维护并显示其基准换算关系。
- 业务录入中的物料、客户、供应商、库位、工单、工序、文档类别、单位和模板等数据选择器统一支持直接输入关键词筛选，并忽略拉丁字母大小写；只有状态、排序、损耗方式等少量固定枚举保留普通下拉。
- 物料 BOM 关联固定顶部应用栏、已有 BOM 搜索和新建按钮。桌面宽屏左侧已有 BOM 列表可在视口范围内独立滚动，右侧编辑区随页面主内容区滚动；主内容区滚动轨道固定显示在页面最右侧，不得用 `overflow-hidden` 截断右侧表单。移动端上下排列并使用页面正文单一纵向滚动，禁止在右侧表单中再嵌套滚动区。
- 右侧 BOM 编辑区只在工作区标题栏放一个“保存 BOM”按钮，随标题自然排列，不得悬浮覆盖转换模型、输入控件或组成明细。
- 分级导航优先复用 Radix UI 等成熟、可访问的组件原语，不重复实现展开状态和 ARIA 语义。
- 所有业务页面统一固定顶部工具栏，承载关键词、筛选、视图切换、主操作、用户菜单；桌面端仅标题栏下方的页面内容区纵向滚动，并保留稳定、可发现的最右侧滚动轨道。
- 页面主体优先使用表格、左右分栏、详情面板、统计卡片。
- 标准业务清单的文字、数值和时间列统一支持点击表头升序/降序；当前列显示方向箭头并提供键盘焦点。图片、附件和操作列不排序。
- 表格和详情可以并列展示时，优先并列，不要强制进入全屏弹窗。
- 仪表盘和统计分析使用图表、指标卡、预警列表，不使用普通业务列表模板。

## 3. 顶部工具栏

- 桌面端首层必须尽量暴露高频功能。
- 关键词搜索放左侧或标题后方。
- 页面主关键词后紧邻“快捷搜索”入口；弹层显示当前页已保存的搜索词，可保存当前词、点击应用或单项删除，并明确标注“仅保存在当前浏览器”。
- 筛选按钮和筛选摘要放关键词之后。
- 新增、导入、导出、调整、打印等主操作放右侧。
- 视图切换按钮放主操作左侧。
- 用户菜单固定在最右侧。
- 顶部工具栏可以换行，但不能出现页面级横向滚动条。
- 高频按钮不进入“更多”菜单，除非一行无法承载并且该按钮低频。

## 4. 筛选模式

- 桌面端允许首层显示关键词、核心客户筛选、核心状态筛选。
- 复杂筛选统一进入筛选弹窗。
- 筛选弹窗可以是浮层，宽度建议 480px 到 640px。
- 筛选弹窗内允许多列布局，减少垂直滚动。
- 筛选结果必须显示摘要，例如“筛选 3”或标签摘要。
- 筛选项不能在页面上拆成多排杂乱按钮。

## 5. 表格优先原则

- 桌面端业务列表优先使用表格。
- 表格列顺序一般为：预览、编码/单号、名称/标题、类型、状态、关联对象、数量/金额、凭证/附件、操作。
- 操作列固定最右侧。
- 行内操作顺序固定：全屏打开 / 详情 / 编辑 / 上传 / 打印 / 归档。
- 表格行高保持紧凑但可读，普通行 48px 到 64px，附件预览行可到 72px。
- 表格允许自身横向滚动，但不得撑破页面。
- 大字段可以截断并提供详情，不要把表格列拉到不可读。
- 列宽默认根据页面和内容自动分配；物料等长字段列表支持拖动表头分隔线手动调整，双击分隔线恢复该列自动宽度，并提供恢复全部自动列宽入口。
- 长度型来料在桌面端使用同一区块展示数量（件）、总长度/单件长度切换、总重量和入账主数量预览；不得把三个字段拆到不同弹窗。
- 来料新增/编辑在桌面端使用宽弹窗和 12 列表单网格：凭据、供应商、物料同行，其中供应商和物料均可直接输入筛选；来料实测与采购计价左右并列。常见 768px 高度下应尽量整体可见；不设弹窗内层滚动容器，仅在整体高度确实超出视口时由遮罩层统一滚动。

## 6. 卡片使用

- 桌面端卡片只用于仪表盘、统计指标、实体摘要、图片资料。
- 桌面端业务列表可以提供卡片视图，但不是默认必需。
- 卡片不能嵌套卡片。
- 卡片内信息顺序固定：编码/状态、名称、关键属性、数量/金额、操作。
- 卡片操作放底部右侧。

## 7. 详情与编辑

- 桌面端详情优先使用大弹窗或右侧详情面板。
- 详情面板宽度建议 720px 到 1200px。
- 编辑状态在详情内切换，不再打开第二层弹窗。
- 表单字段按 2 到 3 列布局。
- 长备注、附件、操作记录独立成区块。
- 新增表单不能是一长条，必须用 `FormGrid`。
- 保存、取消按钮固定在弹窗底部右侧。
- 普通弹窗统一使用可点击遮罩和 `Esc` 关闭，关闭后焦点回到触发按钮；保存处理中禁止关闭。标题区、正文区和固定底部操作区不得由页面重新拼装不同样式。
- 弹窗底部顺序固定为取消在左、保存/提交在右；新增按钮统一绿色，保存/提交统一蓝色，危险确认统一红色，按钮高度统一为 40px。
- 浏览器偏好（视图、列宽、快捷搜索）可自动保存；业务表单和单据统一显式点击保存，失败时保留输入。

## 8. 文件与图片

- 桌面端文件查看优先使用全屏查看器。
- 图片和 PDF 统一使用 `FileViewer`。
- 产品文档的类别管理从页面工具栏进入，一级和二级类别在筛选、表单和全景图中使用一致的“一级 / 二级”名称展示。
- 列表首层需要直接提供“全屏打开”。
- 文件详情内仍可提供“打开”，但打开的是同一个查看器。
- PDF 全屏打开后默认完整适合页面并居中显示；用户需要阅读细节时再从查看器切换到适合宽度或手动缩放。
- 图片查看按钮顺序固定：上一份、下一份、缩小、放大、左转、右转、复位、新窗口、关闭。

## 9. 按钮尺寸

- 顶部工具栏按钮高度 36px 到 40px。
- 表格行内按钮高度 28px 到 32px。
- 弹窗底部按钮高度 36px 到 40px。
- 同一行按钮必须同高、同圆角、同字号。
- 文字按钮优先用于明确命令，图标按钮必须有 tooltip 或可理解图标。

## 10. 桌面端禁止事项

- 禁止把主要业务按钮全部收到二级菜单。
- 禁止用手机卡片布局替代所有桌面表格。
- 禁止表格列无序堆叠。
- 禁止一行按钮高度、颜色、文案不统一。
- 禁止在桌面端让用户频繁进入全屏弹窗才能完成基础比对。
- 禁止页面主体出现横向滚动条。

## 11. 桌面端验收清单

1. 1280px 宽度下顶部工具栏是否清楚。
2. 主要操作是否暴露在首层。
3. 表格是否能完成扫描、对比、批量判断。
4. 行内操作是否在最右列且顺序统一。
5. 详情和编辑是否在同一面板内完成。
6. 附件查看是否使用统一 `FileViewer`。
7. 页面主体是否没有横向滚动条。
8. 长时间操作时是否减少不必要弹窗层级。
9. 1024、1366、1440、1920 宽度下是否均完成实际页面模拟。
