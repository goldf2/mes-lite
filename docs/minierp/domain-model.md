# MiniERP 领域模型

## 建模原则

1. 先做内部管理后台，不做消费者商城。
2. 以库存流水为核心事实，当前库存由流水汇总或快照维护。
3. 所有业务数据必须带租户边界。
4. 小程序账号信息只作为接入配置，不作为业务数据归属依据。
5. 第一版宁可少功能，也要把采购、销售、库存三个闭环跑通。

## 模块边界

### 1. 租户与组织

用于描述谁在使用系统。

核心对象：

- 租户
- 员工
- 角色
- 权限
- 门店
- 仓库

第一版建议角色：

- 超级管理员：开发商运维账号，不能默认查看客户业务数据。
- 租户管理员：客户公司负责人。
- 提交人员：录入并提交业务内容。
- 审核人员：审核注册人员和业务提交内容。
- 管理人员：管理人员、权限和系统配置。
- 仓管：入库、出库、盘点、查库存。
- 销售：客户、报价、销售单。
- 采购：供应商、采购单、入库。
- 财务查看：只读报表，不做会计系统。

操作人员注册流程：

1. 操作人员提交注册。
2. 首位注册人员自动成为管理人员，用于初始化系统。
3. 后续注册人员进入待审核状态。
4. 审核人员或管理人员审核通过后，账号才能登录系统。
5. 管理人员可以调整角色或停用账号。

当前实现将业务员工与登录账号明确分开：`Employee` 保存员工编码、姓名、部门、电话和在职状态，用于生产记录与流程转移选人；`Operator` 保存登录、审核、角色和权限。管理员可将一名员工显式绑定一个已注册账号，一个账号只能绑定一名员工；绑定不会自动审核账号、授予权限，停用员工也不会自动停用账号。

### 2. 商品与库存基础资料

用于描述系统管理什么货。

核心对象：

- 商品分类
- 品牌
- 商品
- SKU
- 单位
- 条码
- 价格
- 库存预警规则

商品和 SKU 的关系：

- 商品是业务名称，例如“白色 T 恤”。
- SKU 是库存单位，例如“白色 T 恤 / M 码 / 纯棉”。
- 第一版可以让一个商品默认对应一个 SKU，保留多规格扩展位。
- 当前用户侧统一使用 `Material` 物料编码；历史编码可通过一次性数据工具删除全部空白并转换为大写，转换前必须检查最终编码唯一性。
- 编码转换只更新物料主数据及其内部兼容产品编码，不改写历史单据快照。
- 管理员可开启系统级物料编码数字自然排序，使 `2` 排在 `12` 前、`A2` 排在 `A10` 前；排序规则不补零、不改写编码。
- 归档是默认删除方式；管理员只能永久删除没有有效库存和下游业务引用的归档记录。完整红冲且数量、核算数量、金额净影响均为零的来料历史可以随归档主体安全清理，自有附件随主体删除。
- 产品文档直接关联成品 `Material` 和 `DocumentCategory`，不单独维护文档编码、标题、客户或适用工序；通用说明使用备注。
- BOM 只定义材料组成和单位消耗，不保存工作中心、实际设备或加工方法。产品文档中的“工艺文件”承担方法、参数、图片和 PDF 指导，并可关联一个或多个适用工作中心。
- 工作中心表示锯切、钻孔、检验等逻辑生产能力区域；设备表示实际机器并必须归属工作中心。设备只保存类型、型号、状态、位置和基础能力参数，不承载产品的具体加工方法。
- `DocumentCategory` 最多两级。“作业指导书”是默认一级类别，其下可配置“机床作业、环境作业”等二级类别；类别名称不由前端或 API 枚举写死。
- 同一产品可维护任意类别的多条图片/PDF 文档，产品全景图展示该产品的全部相关文档。
- 产品文档永久删除时级联删除自身附件；其附件属于文档内容，不作为永久删除阻断。
- 物料定义主计量方式（长度、重量、数量、其他）和主库存单位；库存、领料、生产耗用以主单位为准。
- 物料可定义参考/计价方式与单位，但不保存标准长度；默认换算只用于缺少来料实测值的兜底。
- 来料同时记录件数、总长度和总重量，三者作为独立实测快照保存。同长批次可用“件数 × 单件长度”得到总长度，混合长度批次直接录入总长度；总重量始终是本批实测总量。采购单价可选择按米、kg 或件计价，总价格与单价双向换算。
- 同一产出物料可维护多个 BOM 方案/版本，但同时只有一个启用的默认 BOM 作为日报初始选择和成本兼容读取；日报允许显式选择其他启用方案。
- BOM 以“基准批量”保存产出和输入：`BOM.outputQuantity` 是基准产出数量，`BOMItem.quantity` 是该批次对应的原料主库存单位数量。界面继续按 `BOMItem.quantity ÷ BOM.outputQuantity` 显示每一产出单位的单位用量。
- 录入时可用“标准用量 + 损耗”或“成品数量 : 原料数量”计算；长度尺寸可用 mm/cm 录入，底层仍按原料主库存单位保存。
- 生产记录必须选择当前产出物料的启用 BOM，保存本次 BOM 和基准批量快照，按总加工数量乘换算比例计算基准耗用，再逐项选择来源库位和本批次额外的固定或百分比损耗；生产员工从启用的 `Employee` 中多选，并保存工号、姓名快照。
- 流程转移是独立业务单，不使用 BOM，只允许同一物料、同一数量从一个库位/流程节点进入另一个。每单从启用的 `Employee` 中选择一名操作员工并保存快照；确认只移动库位余额，物料总库存、计价数量、总成本和成本层不变。
- 主库存单位允许直接修改；系统只更新主数据、递增单位版本并记录审计，不判断量纲、不换算业务数值，也不自动改写既有 BOM 和历史快照。
- 数据关系检查持续扫描 BOM/兼容产品单位漂移、错误 BOM 明细、日报失效指针和有效成本层旧单位风险；可安全关系逐条修复或删除，仍参与库存成本运算的数据只报警。

### 3. 往来单位

用于描述和谁交易。

核心对象：

- 客户
- 供应商
- 联系人
- 地址

第一版客户和供应商可以共用一张往来单位表，通过类型区分。

### 4. 采购

用于描述从供应商进货。

核心对象：

- 采购订单
- 采购订单明细
- 采购入库单
- 采购入库明细

第一版流程：

1. 创建采购订单。
2. 采购订单审核。
3. 到货后创建采购入库单。
4. 入库确认后生成库存流水。
5. 采购订单根据入库数量更新状态。

采购订单状态：

- 草稿
- 待审核
- 已审核
- 部分入库
- 已完成
- 已取消

### 5. 销售

用于描述向客户出货。

核心对象：

- 销售订单
- 销售订单明细
- 销售出库单
- 销售出库明细

第一版流程：

1. 创建销售订单。
2. 检查可用库存。
3. 销售订单审核。
4. 创建销售出库单。
5. 出库确认后生成库存流水。
6. 销售订单根据出库数量更新状态。

销售订单状态：

- 草稿
- 待审核
- 已审核
- 部分出库
- 已完成
- 已取消

### 6. 库存

用于描述货在什么地方、数量如何变化。

核心对象：

- 库存余额
- 库存流水
- 库存调整单
- 盘点单
- 调拨单

库存流水类型：

- 采购入库
- 销售出库
- 盘盈入库
- 盘亏出库
- 手工调整入库
- 手工调整出库
- 调拨出库
- 调拨入库

库存数量建议分层：

- 现存量：仓库里实际有多少。
- 锁定量：已被销售订单占用但未出库的数量。
- 可用量：现存量减锁定量。

第一版可以先不做锁定量，但数据模型保留字段。

### 7. 报表

第一版只做经营摘要，不做财务总账。

基础报表：

- 当前库存表
- 库存流水表
- 低库存预警
- 采购汇总
- 销售汇总
- 商品销售排行

### 8. 原始单据附件

用于保存业务动作背后的原始凭证，通常是单据照片，也可以是 PDF。

核心对象：

- 附件
- 业务对象类型
- 业务对象 ID
- 上传人

附件适用对象：

- 采购入库单
- 销售出库单
- 盘点单
- 调整单
- 调拨单
- 生产工单
- 来料单
- 发货单
- 退货单

附件不改变业务状态，只用于追溯和审计。归档附件不应影响业务单据，附件文件和记录原则上保留。

### 9. 微信小程序接入

小程序作为移动端入口，不作为业务主体。

核心对象：

- 小程序应用
- 微信用户绑定
- 员工登录会话
- 租户小程序配置
- 原始单据照片上传

登录关系：

1. 微信用户通过小程序登录。
2. 系统拿到 openid 或 unionid。
3. 用户绑定到某个租户员工。
4. 员工按角色获得权限。

一个微信用户可以绑定多个租户员工身份，但默认进入最近使用的租户。

## 核心业务闭环

### 查库存

员工选择租户和仓库，按商品名、SKU、条码搜索库存余额。系统展示现存量、锁定量、可用量和最近库存流水。

### 采购入库

采购或仓管创建入库单，选择供应商、仓库和 SKU，确认后写入采购入库流水，并增加库存余额。

### 销售出库

销售或仓管创建出库单，选择客户、仓库和 SKU，确认后写入销售出库流水，并减少库存余额。

### 库存盘点

仓管创建盘点单，录入实盘数量。系统计算账面数量和差异，审核后按差异生成盘盈或盘亏流水。

## 多租户边界

所有业务表必须包含 `tenant_id`。

禁止通过小程序 AppID 判断数据归属。AppID 只是入口，用户进入后必须落到租户身份。

开发商运维账号需要单独授权和审计，不能默认跨租户查询客户业务数据。
