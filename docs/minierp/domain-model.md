## v0.1.479 企业业务平台接入增量

v0.1.479 新增 platform-integration 边界，仅通过 configuration/server-index 的只读客户出口提供目录；企业业务平台消费 API，MES 保留独立业务、数据库和发布。不会共享 Cookie、跨域写库或把部署标签宣称原生租户实体。

状态：当前单厂边界的领域说明；早期商城/多租户内容仅作长期候选

## 建模原则

v0.1.474 将“主库存事实/金额”与“辅助数量是否完整”分开：重量来料可不测长，`UNMEASURED` 来源不产生换算依据，`valuationComplete=false` 随库存和流水保留。辅助台账的零占位或分摊数不等于物理零长度。完整性核实属于带原因及审计的存货调整，不可通过修改历史已发布 BOM 或替换单位标签完成。

1. 先做单厂轻量 MES，不做消费者商城。
2. 以库存流水为核心事实，当前库存由流水汇总或快照维护。
3. 当前业务数据属于单一工厂实例；多租户边界只有重新立项后才实施。
4. 小程序账号信息只作为接入配置，不作为业务数据归属依据。
5. 第一版宁可少功能，也要把采购、销售、库存三个闭环跑通。

## 模块边界

### 1. 租户与组织

用于描述谁在使用系统。

核心对象：

- 租户
- 员工
- 角色
- 权限
- 门店
- 仓库

第一版建议角色：

- 超级管理员：开发商运维账号，不能默认查看客户业务数据。
- 租户管理员：客户公司负责人。
- 提交人员：录入并提交业务内容。
- 审核人员：审核注册人员和业务提交内容。
- 管理人员：管理人员、权限和系统配置。
- 仓管：入库、出库、盘点、查库存。
- 销售：客户、报价、销售单。
- 采购：供应商、采购单、入库。
- 财务查看：只读报表，不做会计系统。

操作人员注册流程：

1. 部署人员临时配置一次性安装令牌，通过受限安装接口显式创建首个管理人员；安装完成后删除令牌。
2. 公开注册默认关闭；管理员只在受控时间窗口临时开启。
3. 所有密码注册和首次微信登录统一创建待审核操作人员，永不因账号顺序自动提权。
4. 审核人员或管理人员审核通过后，账号才能登录系统。
5. 管理人员可以调整角色或停用账号；密码连续失败和来源请求频率由独立安全状态限制。

当前实现将业务员工、数据库身份与登录账号明确分开：`Employee.id` 是不对业务展示的内部关联主键，`Employee.code` 是系统自动生成且创建后不可修改的业务员工编码，`Operator` 保存登录、审核、角色和权限。员工档案另存姓名、部门、电话和在职状态，用于班后生产实绩与流程转移选人。管理员可将一名员工显式绑定一个已注册账号，一个账号只能绑定一名员工；绑定不会自动审核账号、授予权限，停用员工也不会自动停用账号。

`OperatorDataScope` 将生产数据限定为全厂、本人或指定工作中心，将库存数据限定为全部或指定库位。权限组/个人临时授权回答“能执行哪些动作”，数据范围回答“能操作哪些单据、批次和库存”；生产、质量、库存、履约、附件与任务查询均在服务端合并两层约束。个人例外必须有原因、授权人和有效期，到期自动失效。

### 2. 商品与库存基础资料

用于描述系统管理什么货。

核心对象：

- 商品分类
- 品牌
- 商品
- SKU
- 单位
- 条码
- 价格
- 库存预警规则

商品和 SKU 的关系：

- 商品是业务名称，例如“白色 T 恤”。
- SKU 是库存单位，例如“白色 T 恤 / M 码 / 纯棉”。
- 第一版可以让一个商品默认对应一个 SKU，保留多规格扩展位。
- `Material.code` 是唯一物料编码；`Product` 保留旧外键 ID，通过 `materialId` 显式绑定且 `sku` 同码。真实 `MAT-` 属于物料编码，不是可无条件删除的标记。
- 历史编码可通过一次性数据工具预览后删除全部空白并转换为大写，同时补齐无歧义产品绑定和同码 SKU；空编码、占码和多物料匹配会阻断整批执行。具体边界见 [数据模型的库存余额与统一编码说明](data-model.md#库存余额一致性补齐)，不修改 BOM、库存成本或历史快照，不通过部署自动执行。
- 管理员可开启系统级物料编码数字自然排序，使 `2` 排在 `12` 前、`A2` 排在 `A10` 前；排序规则不补零、不改写编码。
- 归档是默认删除方式；管理员只能永久删除没有有效库存和下游业务引用的归档记录。完整红冲且数量、核算数量、金额净影响均为零的来料历史可以随归档主体安全清理，自有附件随主体删除。
- 文档必须维护独立标题和 `DocumentCategory`，可选关联成品 `Material`；未关联产品时表示跨产品通用文档。正文以结构化 JSON 保存并同步纯文本搜索投影，客户仍只从关联产品读取，不保存独立客户、适用工序或工作中心。标题、类别、产品、版本、状态、备注和正文属于不可删除的基础字段；每个类别可另外维护自己的扩展字段定义。
- BOM 只定义材料组成和单位消耗，不保存工作中心、实际设备或加工方法。产品文档中的“工艺文件”承担方法、参数、图片、PDF 和 Office 附件指导；工作中心由工艺路线、计划、派工和生产实绩负责。
- 工作中心表示锯切、钻孔、检验等逻辑生产能力区域；设备表示实际机器并必须归属工作中心。设备保存类型、型号、当前状态、位置和基础能力参数，`EquipmentEvent` 保存开停机、故障、恢复的状态事实；`EquipmentInspectionPlan`/`Item` 保存周期标准，`EquipmentInspectionRecord`/`Result` 保存不可改写的逐项点检事实。它们都不承载产品的具体加工方法。
- `DocumentCategory` 最多两级。“作业指导书”是默认一级类别，其下可配置“机床作业、环境作业”等二级类别；类别名称不由前端或 API 枚举写死。
- 扩展字段支持文本、数字、日期、布尔和单选。未使用字段可在页面修改名称、类型和选项或删除；字段已经保存到任一文档后仍可安全改名，但不得删除或改变类型/选项。批量修改仅允许同一类别的文档，并且只覆盖操作者明确选择的基础字段或扩展字段。
- 批量导入以“一份文件对应一篇文档”为边界：一次选择同类文件并共用类别及元数据，服务端仍逐份创建文档、保存原文件和记录逐文件结果，不把多个图纸塞进一条附件集合。
- 生产实绩只允许选择订单派工/默认路线工作中心内的可用或运行设备，以及适用于订单物料或通用的已生效作业文件。保存时冻结设备身份、状态、工作中心及文件版本、正文、附件清单等事实；来源主数据后续变化不改写历史。
- 同一产品可维护任意类别的多篇在线文档及通用附件，产品全景图只展示明确关联该产品的全部文档。
- 产品文档永久删除时级联删除自身附件；其附件属于文档内容，不作为永久删除阻断。
- 物料定义主计量方式（长度、重量、数量、其他）和主库存单位；库存、领料、生产耗用以主单位为准。
- 物料可定义一个参考/计价方式与单位，但不保存标准长度；统一使用“1 主库存单位 = N 参考单位”保存计划换算关系，主要供 BOM 在长度与重量等跨计量方式之间换算。来料实际核算不直接使用该标准值兜底。
- 来料使用 `MaterialReceipt` 单头和一至多条 `MaterialIn` 明细。一张来料单的所有明细先进入同一待分库库位，确认后再通过流程转移分配到实际库位；每条新明细只要求一个主单位实收量，并可保存一个辅助单位实测量。辅助实测缺失时，系统只允许使用当前单位版本至少 3 批已收货实测记录的加权换算率；推算值不进入历史样本。旧件数、总长度和总重量字段只保留数据库兼容，不再作为普通录入界面的依赖。
- 同一主产出物料可维护多个 BOM 方案/版本，版本号在产品内唯一。BOM 采用草稿、已发布、已作废三态；只有草稿可编辑，调整已发布关系必须派生新版本。每种用途同时只有一个已发布默认 BOM 作为生产订单和成本的默认选择。
- BOM 用途分为生产和包装。包装 BOM 只允许一项产出，可将散件和包装物转换为独立整箱物料；库存页只读穿透包装 BOM，将真实散件库存与整箱库存换算为内容物等效总量，不改变任何库存余额。
- BOM 以“基准批次”保存多项共同投入和多项同时产出：`BOMItem.quantity` 是每批绝对投入量，`BOMOutput.quantity` 是每批绝对产出量，每个 BOM 只有一项主产出。投入物料不限制为原材料，半成品和已有产品均可用于二次加工；`BOM.outputQuantity` 仅是主产出数量的兼容投影。
- 所有输入组成一个整体消耗集合，不分配给某项输出。单位目录处理同量纲换算；物料配置有效参考计量和标准换算后，BOM 还可在主计量与参考计量之间换算，例如按 kg 录入长度库存物料。保存时统一写入主库存数量，并冻结原始录入量、换算率、来源和单位版本，避免历史 BOM 随主数据变化漂移。标准 BOM 不设固定或百分比损耗，废料、废屑和可回收料作为明确产出记录；生产实绩只保留本批次计划外差异。
- 生产订单同时承载事前计划和班后实绩，也允许产后补录；目标产出物料必选，BOM 是可选的标准转换预设。选择 BOM 时只能引用已发布版本，并冻结 ID、名称、版本及全部投入/产出快照；BOM 后续作废不改变历史订单。不选择 BOM 时可建立临时生产/转换订单。班后实绩可从 BOM 快照预填，也可增删或修正本批实际投入与产出；无 BOM 或含临时明细时必须填写说明。确认后才按实际明细原子更新库存，且不反向修改已发布 BOM。没有设备或适用文件时必须分别记录例外原因，不允许静默留空。
- 新生产实绩确认后，每项产出生成唯一内部批次、待检余额、批次交易和质量任务。待检与冻结成本层不参与普通领料或发货；质检员整批判定合格时只把状态转为可用，判定不合格时转为冻结，总库存、核算数量和总成本均不改变。
- `DailyProductionReport` 是独立于生产订单的 BOM 快捷转换事实：冻结已发布 BOM 的身份、主产出和最终审核后的实际投入/产出明细，确认时原子扣减投入、按可用批次 FIFO 保存每条投入的实物耗用、增加产出和结转成本；不创建订单、派工或报工。BOM 基准数量只是编辑初值，主产出原位修改可同比例更新尚未手工修正的其它行，逐行库存只是权限范围内的录入参考，均不取代事务校验。产出可直接进入可用库存，也可建立待检批次和独立 `QualityInspection`，后续复用统一质量判定与处置。冲销必须精确恢复原耗用批次；原批次流水缺失或与正式耗用流水不一致时，不得以当前 FIFO 估算，整笔冲销必须回滚。库存盘点仍只管理账面与实盘差异，不能替代 BOM 转换。
- 存货调整是库位级操作：必须指定启用库位并录入该库位调整后数量，差额同步进入物料总库存和对应库位流水；核算数量与总成本继续保存在物料总账，不按库位拆分。
- 流程转移是独立业务单，不使用 BOM，只允许同一物料、同一数量从一个库位/流程节点进入另一个。每单从启用的 `Employee` 中选择一名操作员工并保存快照；确认只移动库位余额，物料总库存、计价数量、总成本和成本层不变。
- 单据草稿不是错误数据暂存区：保存时必须校验字段范围、主数据有效性、单位、库位和当时可判断的数量/可用库存关系；最终确认继续事务内复检状态与实时库存，以防保存后的并发变化。
- 主库存单位允许直接修改；系统只更新主数据、递增单位版本并记录审计，不判断量纲、不换算业务数值，也不自动改写既有 BOM 和历史快照。
- 数据关系检查持续扫描 BOM/兼容产品单位漂移、错误 BOM 明细、日报失效指针和有效成本层旧单位风险；可安全关系逐条修复或删除，仍参与库存成本运算的数据只报警。

### 3. 往来单位

用于描述和谁交易。

核心对象：

- 客户
- 供应商
- 联系人
- 地址

第一版客户和供应商可以共用一张往来单位表，通过类型区分。

### 4. 采购

用于描述从供应商进货。

核心对象：

- 采购订单
- 采购订单明细
- 采购入库单
- 采购入库明细

第一版流程：

1. 创建采购订单。
2. 采购订单审核。
3. 到货后创建采购入库单。
4. 入库确认后生成库存流水。
5. 采购订单根据入库数量更新状态。

采购订单状态：

- 草稿
- 待审核
- 已审核
- 部分入库
- 已完成
- 已取消

### 5. 销售

用于描述向客户出货。

核心对象：

- 销售订单
- 销售订单明细
- 销售出库单
- 销售出库明细
- 货箱单据
- 货箱内容物

第一版流程：

1. 创建销售订单。
2. 确认销售订单，订单本身不扣减库存。
3. 发货单从发货管理独立登记，只保存一个客户和一至多条实际发货物料，不保存销售订单或订单明细引用。
4. 页面按客户和物料汇总销售需求、待发、已发、未发及超发作为参考；发货数量不受订单数量限制。散货所选库位不足时明确提示预计欠库，但不阻止保存或确认发货；所选货箱本身必须有足额真实可用批次。
5. 仓库可先独立装箱并打印每箱标签；货箱身份属于本次货物内容，包装类型不建立容器资产状态。新仓库箱绑定真实可用批次、数量和唯一摆放库位，装箱不增加库存。既有发货现场装箱保留兼容。
6. 发货可选已有货箱、添加散货或混合。每个产品行的货箱数量与散货数量之和等于实际发货数量；保存待发货单占用选中箱，箱内容版本和实际批次必须固定，不能被另一张待发货单重复使用。
7. 待发货单可在库存过账前有原因取消并释放货箱占用；归档占用仓库箱的待发单同步取消，恢复只恢复历史记录，不得按散货再次确认，需重新新建选箱单。确认发货按所选箱实际批次和散货来源扣减库存并生成流水。散货可用库存不足部分沿用受控欠库，已实物装箱部分不得凭空欠库，货箱同步进入已发货。
8. 后续同物料、同库位的可用入库按欠库创建时间自动补齐实际发货批次与成本；欠库未补齐时不能建立客户退货。
9. 已发货但尚未签收、且没有退货依赖的错误过账，可由具备独立冲销权限的仓库主管填写原因后冲销；系统恢复原库位库存、总库存、可用量、金额、FIFO 成本层、内部批次余额、欠库补账和货箱状态，并追加与原发货流水关联的反向流水。
10. 确认签收只更新履约事实与操作人，不重复改变库存；已签收单不得直接冲销，实际退回必须建立客户退货单。
11. 发货不回写销售订单明细已发量或订单状态；订单状态由销售业务独立维护。
12. 确认发货后生成含甲乙双方资料、货箱摘要、发货二维码和签收栏的发货单 PDF。
13. 可按已补齐批次的原发货单登记退货；接受时按原发货成本比例恢复所选库位和总库存，拒绝时库存不变。

v0.1.499 装箱/混合发货为实施候选，验收和发布以正式版本说明为准。独立箱的占用由 `ShipmentPackageAllocation` 表达，货物身份、空间摆放和记账库存分别管理；生产、散货和移库等其他库存出口不能直接消耗已分配到有效箱内的数量。

发货单冻结每条明细已实际消耗的成本层快照；欠库和每次后补入库分配另存不可覆盖的补账记录。发货、签收、取消和冲销分别保存操作人、时间与原因。冲销不覆盖或删除原发货事实，而是将单据、批次分配、欠库和货箱标为已冲销并保留正反向库存流水。

销售订单状态：

- 草稿
- 已确认
- 部分发货
- 已完成
- 已取消

### 6. 库存

用于描述货在什么地方、数量如何变化。

- 库存流水
- 库存调整单
- 盘点单
- 调拨单

库存流水类型：

- 采购入库
- 销售出库
- 盘盈入库
- 盘亏出库
- 手工调整入库
- 手工调整出库
- 调拨出库
- 调拨入库

库存数量建议分层：

- 锁定量：已被销售订单占用但未出库的数量。

### 9. 微信小程序接入

小程序作为移动端入口，不作为业务主体。

- 微信用户绑定
- 员工登录会话

登录关系：

## 核心业务闭环

### 查库存

员工选择租户和仓库，按商品名、SKU、条码搜索库存余额。系统展示现存量、锁定量、可用量和最近库存流水。

### 采购入库

采购或仓管创建入库单，选择供应商、仓库和 SKU，确认后写入采购入库流水，并增加库存余额。

### 销售出库

销售或仓管创建出库单，选择客户、仓库和 SKU，确认后写入销售出库流水，并减少库存余额。

### 库存盘点

仓管创建盘点单，录入实盘数量。系统计算账面数量和差异，审核后按差异生成盘盈或盘亏流水。

## 多租户边界

本节是暂停的长期候选，不是当前实现。当前业务表没有统一 `tenant_id`，禁止为了未来设想先行增加可空租户字段。

禁止通过小程序 AppID 判断数据归属。AppID 只是入口，用户进入后必须落到租户身份。

开发商运维账号需要单独授权和审计，不能默认跨租户查询客户业务数据。

## 附录：任务协同本地候选（2026-10-20）

任务协同属于现有单厂 MES 内部领域，服务于任务要求、任务 BOM、资料版本、备注异常和发放记录。本附录只描述当前独立源码候选的增量，不改变历史版本基线；模型说明本身不充当验收证据。默认真实本地界面整轮已有通过记录，证据与后续收尾复核见任务候选说明和交付报告，不代表生产部署。

领域聚合以 `TaskCollaboration` 为根，拥有任务行、追加式进度记录、不可变发布包和发布包发放证据。关联员工、供应商、物料、销售订单、生产订单、派工和工作中心均引用现有权威模型。模板复用只复制固定说明、任务行和文件引用；新任务独立保存负责人、交期、执行状态与历史。供应商是收件业务对象，本阶段仅由已授权的 MES 人员操作，不建立供应商自助登录或第二份联系人清单。

生产事实由原生产领域拥有：关联既有 `Dispatch`，通过既有派工页面/API 建立和流转派工，任务协同不建立另一套派工引擎。关联 `ProductionOrder / Dispatch` 后，执行状态和完成/报废数量是经过原数据范围过滤的只读投影，协同进度只记录备注和异常；不能由协同状态或备注触发库存、成本和财务过账。未关联生产执行的任务可在自身 `ASSIGNED → IN_PROGRESS → COMPLETED` 路径推进，或由允许状态取消；关联 MES 生产事实时拒绝另行维护执行状态。

任务 BOM 是本次工作的配套清单，其物料、正数数量、合法物料单位、说明与图纸引用属于任务要求，不改变生产/包装 BOM 用途及计算规则。任务处于可编辑状态时，修改当前要求通过 `expectedRevision` 乐观校验并增加版本；历史发布包保存当时任务、任务行、物料身份、收件对象和文件确定版本，保持不可变。发布前预览令牌绑定任务版本、收件人与源文件内容及元信息，发布时再次校验；发布 `operationId` 与同任务版本唯一约束防止重试产生多次有效发布。

资源权限和数据范围为两个独立边界。`taskCollaboration` 负责查看、新建、修改与归档；`taskCollaborationPublish.update` 负责资料预览、发布和发放登记。两项新资源对非管理员默认关闭，不从旧系统、订单或派工资源继承；引用资料仍检查既有资源读取权限。任务范围直接复用生产范围：ALL 全部、SELF 仅负责人为本人绑定员工、WORK_CENTERS 仅授权工作中心；创建、引用、详情、历史、文件和状态命令都由服务端校验，关联订单/派工另行校验原范围。供应商引用、任务创建者或前端按钮不会扩大范围。

归档是可恢复的可见性标记，不是取消或永久删除。任务自有归档/恢复命令分别写入或清空 `deletedAt / deletedBy`、校验当前版本并保留业务状态；进度、资料清单、冻结文件和发放历史继续保留。归档历史仅供同权限同范围人员回溯，文件仍受主体归档限制。本候选不进入统一永久删除流程。发布、进度、归档和发放证据与操作审计在同一领域事务中写入；`EMAIL / WECHAT` 仅为人工发放记录，不触发真实外发。
