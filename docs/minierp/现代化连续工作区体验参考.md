# MES-lite 现代化连续工作区体验参考

本文记录 MES-lite 在用户可直接感知的操作体验上的产品方向，重点吸收现代邮箱、Notion、Linear 等产品的连续工作方式，而不是复制其视觉风格。

目标是让操作人员明显感受到：页面跳转更少、上下文不丢失、反馈更及时、录入更省力，并且仍然满足 MES 对权限、审计、显式保存和业务确定性的要求。

本文是产品体验参考；具体组件、尺寸、响应式、保存和危险操作规则以 `系统交互与设计规范.md` 为准。

## 1. 核心体验目标

MES-lite 与传统 MES 的主要体验差异应体现为：

1. 用户围绕当前对象连续工作，而不是在多个孤立页面间往返。
2. 查看、编辑、关联和继续处理尽量在同一工作区完成。
3. 系统持续保留用户的搜索、筛选、选中对象和滚动位置。
4. 每次操作立即有可见反馈，失败不丢失输入，成功后无需重新寻找当前位置。
5. 系统主动带出已知信息、推荐下一步，减少重复录入和重复选择。
6. 同类关系操作保持同一模型，用户学会一次即可操作全系统。

“流畅”不等于省略业务确认，也不等于所有操作自动保存。库存、生产、成本、状态流转等业务数据仍采用显式保存和服务端校验。

## 2. 连续工作区模型

### 2.1 列表与详情连续浏览

- 桌面端点击列表行后，优先在右侧详情面板或同一主从工作区打开对象，不默认跳走整个页面。
- 详情面板支持切换上一条、下一条，用户不需要反复关闭详情再重新查找。
- 关闭详情后，列表保留搜索、筛选、排序、分页、选中行和滚动位置。
- 小于适用宽度时，详情可以降级为全高抽屉或独立详情页，但返回后仍应恢复列表上下文。
- 只有需要大面积画布、完整文件阅读或复杂多阶段处理时才进入沉浸式页面。

### 2.2 查看与编辑连续切换

- 详情中的“编辑”优先在同一容器切换编辑态，不再叠加一个风格不同的弹窗。
- 保存成功后回到同一对象的详情态，并局部刷新受影响内容。
- 保存失败保留全部输入、面板位置和用户选择，焦点定位到首个可处理问题。
- 有未保存内容时切换对象或关闭面板必须提示；只读浏览不增加无意义确认。

### 2.3 对象全景与关系穿透

物料、工单、设备、客户、供应商等核心对象应逐步形成统一全景页，在同一上下文中查看：

- 身份与状态。
- 关键业务信息。
- BOM、文档、库存、工单、供应商、质量等关联对象。
- 最近活动和审计记录。
- 当前用户有权执行的下一步动作。

关联对象默认在当前工作区展开或预览；需要深度处理时再进入对应完整页面，并提供明确返回路径。

## 3. 用户强感知的公共能力

### 3.1 统一关系编辑

一对一、一对多、多对一和多对多在数据层可以采用不同约束，但用户侧统一使用以下操作模型：

1. 搜索候选对象。
2. 选择一个或多个对象。
3. 在已选列表中填写数量、单位、页码、角色等领域附加字段。
4. 防止重复并允许移除、排序或替换。
5. 整单保存并显示影响结果。

BOM 添加物料、文档关联物料、供应商关联物料、工单关联文档等场景必须优先复用该模型。

### 3.2 全局搜索与命令中心

- 在固定入口搜索物料编码、名称、工单号、客户、供应商、设备、文档和系统功能。
- 搜索结果按对象类型分组，展示足以判断身份的编码、名称和状态。
- 支持直接打开对象、进入功能或发起“新增物料”等有权限的动作。
- 支持最近访问、收藏和键盘上下选择。
- 命令入口只显示当前账号有权查看或执行的结果。

### 3.3 岗位化工作台

- 首页优先展示当前岗位今天需要处理的任务、异常和快捷动作，而不是完整菜单的重复入口。
- 仓管、计划、质量、设备和管理岗位采用不同默认布局。
- 用户可保存自己的筛选、列宽、显示字段、面板宽度、常用入口和工作区布局。
- 必须提供恢复岗位默认和恢复系统默认，不让个性化配置变成维护负担。

### 3.4 智能默认与快速复用

- 根据当前对象和业务上下文带出单位、仓库、库位、供应商、工艺、文档和检验要求。
- 支持从现有物料、BOM、工单或单据复制创建，并在保存前明确展示继承内容。
- 保存后可提供“继续新增相似记录”“打开刚创建对象”等连续动作。
- 智能默认必须可见、可修改；不得静默生成用户无法判断的业务数据。

### 3.5 表格高效操作

- 支持固定列、调整列宽和顺序、保存视图、快速筛选与恢复默认。
- 高频资料维护可在安全边界内使用表格内编辑；复杂事务仍进入统一详情或编辑容器。
- 支持键盘移动、连续录入、多选和批量操作。
- 批量操作必须先显示影响数量、跳过项和阻断原因。
- 可复制的数据允许与电子表格进行受控复制粘贴，并在提交前校验。

### 3.6 扫码进入任务上下文

- 扫物料码进入物料全景，扫工单码进入工单处理，扫设备码进入设备状态与维护记录。
- 连续扫码场景保留当前任务，自动累计或追加明细，不在每次扫码后返回首页。
- 扫码结果不存在、重复或状态不允许时立即反馈，并保留此前已经扫描的有效结果。

## 4. 即时反馈与节奏

### 4.1 反馈层级

- 点击、选中、展开和切换必须立即出现视觉反馈。
- 请求未完成时显示稳定的局部处理中状态，不冻结整个页面。
- 加载使用保持结构的骨架或占位，避免列表、按钮和面板大幅跳动。
- 成功结果明显时不重复弹出打断式提示；结果不明显时使用轻量通知。
- 失败提示必须说明发生了什么、哪些内容已保留以及用户下一步可以做什么。

### 4.2 动效边界

- 动效只用于解释面板进入、对象切换、保存完成和层级变化。
- 常规面板与抽屉过渡保持短促，避免等待动画结束后才能操作。
- 动效不得改变最终布局位置、阻塞输入或掩盖真实加载时间。
- 必须遵循系统“减少动态效果”设置。
- 不以玻璃拟态、大面积渐变、持续漂浮或复杂转场作为现代化的主要表现。

### 4.3 可恢复性

- 归档成功后在业务允许时提供短时撤销入口。
- 网络或服务失败不清空表单、不关闭面板、不重置筛选。
- 刷新和返回应恢复只读浏览断点；业务草稿只有在明确支持草稿时才恢复。
- 冲销、库存过账、生产确认等事务使用业务反向记录，不用前端“撤销动画”伪装恢复。

## 5. 可吸附工作区的定位

可吸附面板是连续工作区的增强能力，不是首要目标。优先采用有限吸附区：

- 顶部命令区。
- 左侧导航或筛选区。
- 中央主工作区。
- 右侧详情或关系区。
- 底部状态区。

用户可以调整宽度、显隐和有限顺序，并保存个人或岗位布局；系统始终提供稳定默认布局和一键恢复。第一阶段不实现任意漂浮、多层窗口互相覆盖和无限嵌套停靠。

## 6. 体验验收指标

页面改造后至少检查：

- 从列表选择对象到看到详情只需一次操作。
- 保存后仍停留在原对象和原列表上下文，不要求重新搜索。
- 切换相邻对象不需要关闭并重新打开详情容器。
- 新增关联对象不离开当前工作区，并使用统一关系编辑器。
- 搜索、筛选、排序、分页和滚动位置在详情开关及数据刷新后保持稳定。
- 请求失败时输入和已选关联不丢失。
- 用户可以只用键盘完成搜索、选择、编辑、保存和关闭。
- 移动端能力不减少，只根据空间切换为抽屉、单区或分步布局。
- 危险操作仍有影响说明、明确确认、权限校验和审计记录。

评审不能只看静态截图，应以“选择对象 → 查看 → 编辑 → 保存 → 切换下一条 → 返回列表”的连续任务录像或现场操作作为验收依据。

## 7. 建议落地顺序

1. 统一资源列表、右侧详情、同容器编辑和状态保持。
2. 统一多对象关系编辑，并先覆盖 BOM 与产品文档。
3. 建立物料、工单和设备对象全景。
4. 增加全局搜索与命令中心。
5. 增加岗位工作台、保存视图和有限吸附布局。
6. 增加智能默认、复制创建、扫码连续处理和操作影响预览。

每一阶段都必须先扩展公共框架，再迁移业务页面；不得通过页面级特例换取局部流畅。
