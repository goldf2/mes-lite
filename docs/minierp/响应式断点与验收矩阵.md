# MES-lite 响应式断点与验收矩阵

本文定义主流分辨率下的布局规划和实际模拟验收流程。MES-lite 不只写 CSS 响应式规则，关键页面必须用浏览器实际模拟多个尺寸，确认页面真实呈现效果后再交付。

本文是 `docs/minierp/系统交互与设计规范.md` 的响应式验收附件；设备形态、交互语义和页面完成定义以主规范为准。

## 1. 基本判断

按多个主流分辨率模拟页面效果是正确的开发流程，尤其适合 MES/ERP 这类信息密度高、操作多的系统。原因：

- 断点规则只能推测布局，不能发现文字挤压、按钮重叠、弹窗超出、表格撑破页面等真实问题。
- 桌面端和移动端的目标不同，大屏追求效率，手机追求轻量和可触控。
- 同一页面在 1024、1366、1920 宽度下的工具栏、表格、详情面板表现会明显不同。
- 未来接入小程序时，提前建立移动端验收矩阵可以减少重复返工。

## 2. 主流分辨率矩阵

| 类型 | 分辨率 | 主要用途 | 布局策略 |
| --- | --- | --- | --- |
| 小手机 | 360 x 800 | 低端安卓、小屏手机 | 单列卡片、底部导航、操作菜单 |
| 标准手机 | 390 x 844 | iPhone 常见尺寸 | 单列卡片、关键词 + 筛选、底部抽屉 |
| 大手机 | 414 x 896 | 大屏手机 | 单列或紧凑双区块，操作仍进菜单 |
| 平板竖屏 | 768 x 1024 | iPad 竖屏、折叠屏 | 沿用移动端外壳，可增加卡片列数 |
| 小桌面 | 1024 x 768 | 小笔记本、平板横屏 | 左侧导航压缩，顶部保持“搜索 + 工具”单行 |
| 常规笔记本 | 1366 x 768 | 常见办公电脑 | 表格优先，主操作首层显示 |
| 中等桌面 | 1440 x 900 | 常见办公显示器 | 表格 + 详情弹窗，工具栏一行优先 |
| 高分屏笔记本 | 1536 x 864 | Mac/Windows 缩放后常见 | 表格信息密度提升，卡片多列 |
| 标准大屏 | 1920 x 1080 | 办公大屏 | 表格 + 分栏详情，可展示更多字段 |
| 超宽/2K | 2560 x 1440 | 大显示器 | 限制单行阅读宽度，允许左右分栏 |

## 3. 布局断点规划

### 3.1 小于 1024px

- 统一移动端外壳，不再区分手机、折叠屏和平板导航。
- 顶部只保留一行：菜单按钮、弹性搜索区、页面工具和账户入口；不得因工具增加第二行。
- 页面切换优先使用底部常用入口；顶部菜单按钮打开左侧全高功能抽屉，按一级业务分组展示全部页面，并允许设置常用入口。底栏不再提供重复的“更多”按钮。
- 卡片是默认视图，但用户仍可从“工具”切换列表，宽表只在自身容器滚动，不能强制锁定卡片。
- 可根据可用宽度增加卡片列数或筛选摘要，但不得改变导航和工具入口位置。
- 详情、编辑、上传、文件查看使用全屏、宽弹窗或底部抽屉。

### 3.2 1024px 到 1279px

- 小桌面布局。
- 左侧导航显示，但宽度可以压缩。
- 顶部工具栏保持单行，搜索靠左，高级搜索、视图、页内选项、二维码和业务操作收进右侧“工具”菜单。
- 表格作为主视图，但列数量要克制。
- 行内操作保持最右列。

### 3.3 1280px 到 1535px

- 标准桌面布局。
- 顶部工具栏优先一行显示。
- 保留固定顶部基础导航；左侧辅助区可调宽，提供详情/BOM 上下文的页面显示可调宽右侧辅助区，中央主工作区使用剩余宽度。
- 表格显示完整核心字段。
- 详情使用大弹窗。
- 卡片视图按资源密度最多显示 2 到 4 列；使用明确响应式列数，单条或少量结果仍保持正常卡片宽度，禁止用 `auto-fit + 1fr` 拉伸占满整行。

### 3.4 1536px 到 1919px

- 宽桌面布局。
- 可以增加分栏、更多统计卡、更多表格字段。
- 详情弹窗可以更宽，但表单仍保持 2 到 3 列。
- 不因为宽度大就无限拉长文本行。

### 3.5 大于等于 1920px

- 大屏布局。
- 允许表格和详情并列。
- 统计页允许多图表并列。
- 内容区应保持可读宽度，避免文字行过长。
- 可以展示更多辅助字段，但不能破坏核心字段扫描效率。

## 4. 每个尺寸必须检查的问题

### 4.1 通用检查

- 页面主体是否出现横向滚动。
- 顶部工具栏是否按钮重叠。
- 当前页标题是否在各断点可见且不挤压筛选、主操作和用户菜单。
- 左侧导航或底部导航是否遮挡内容。
- 筛选弹窗是否超出屏幕。
- 操作菜单是否能点击空白关闭。
- 详情弹窗是否能完整关闭。
- 普通弹窗是否同时支持右上角关闭、遮罩空白、`Esc`，关闭后是否恢复触发按钮焦点。
- 全局成功和错误提示在普通弹窗、全屏预览和开启磨砂遮罩时是否仍位于最上层且文字清晰。
- 动态业务选择器是否能输入筛选、键盘确认并点击外部收起，列表是否被弹窗或工具栏裁切。
- 标准业务表格的可比较列是否均可点击表头升降序，排序图标和 `aria-sort` 是否同步。
- 表格是否只在自身容器内横向滚动。
- 按钮文字是否溢出。
- 状态标签是否挤压主字段。
- 文件查看器是否能正常显示图片、PDF、文本和 Word/Excel/PowerPoint 预览，并为其他格式提供下载降级。
- 质量标准页内标签、项目列表、逐项判定和趋势汇总是否在当前断点保持可读，且标准版本、建议抽样和失败项目不会被截断为不可辨识状态。

### 4.2 桌面端检查

- 主要操作是否在首层显示。
- 表格列顺序是否稳定。
- 行内操作是否在最右侧。
- 批量扫描时是否需要频繁打开弹窗。
- 1024px 下工具栏换行后是否仍可读。
- 1920px 下内容是否过度拉伸。

### 4.3 移动端检查

- 是否默认使用卡片。
- 顶部是否始终显示当前页标题。
- 每张卡片是否只显示核心字段。
- 操作是否收敛到菜单或底部抽屉。
- 筛选是否使用底部抽屉或全屏页。
- 上传/拍照入口是否足够大。
- 触控区域是否不小于 36px。
- 弹窗底部取消/保存是否未被底部导航或安全区遮挡。

## 5. 模拟验收流程

每次修改页面布局、工具栏、列表、卡片、弹窗、文件查看器时，必须执行以下流程：

1. 启动本地服务。
2. 使用浏览器或 Playwright 设置目标 viewport。
3. 分别打开相关业务页面。
4. 对每个主流尺寸检查布局、按钮、筛选、弹窗、详情。
5. 对发现的问题回到组件或页面修复。
6. 再次模拟受影响尺寸。
7. 最后执行类型检查和构建。

建议保留的检查命令：

```bash
npx tsc --noEmit --pretty false
npm run build
```

后续可以增加：

```bash
npm run verify:responsive
```

该脚本应自动打开关键页面，在多个 viewport 下检查页面级横向滚动、按钮重叠、工具栏可见性和主要弹窗可用性。

## 6. 首批必须纳入模拟的页面

1. 仪表盘
2. 物料与 BOM（物料管理、BOM 设置、BOM 全览）
   - BOM 输入和输出行的物料、每批数量与主库存单位在桌面端和移动端均可见；不显示逐输出投入关系、跨量纲转换模型或固定/百分比损耗字段，废料、废屑和可回收料使用输出明细表达。输入/输出编辑区在桌面端为双栏，在手机端按输入、输出顺序纵向堆叠且不溢出。生产员工多选标签必须自动换行，员工搜索下拉不得越出弹窗；流程转移员工单选及员工资料中的注册账号绑定在手机端保持整行可操作。
- 宽度大于等于 1024px 时，各业务页面顶部按钮工具栏不随内容区滚动；普通页面只滚动标题栏下方内容，页面最右侧必须显示稳定的主内容滚动轨道，确有必要的主从工作区才增加分区滚动。
- BOM 设置在桌面端使用左侧 BOM 列表、右侧创建/修改的主从工作区；左侧每张卡片对应一个 BOM，以名称/版本为主信息，产品、产出和投入物料仅作为摘要与搜索条件。右侧固定为左输入、右输出，两者均可键入筛选并逐项添加；长度和重量行在数量右侧显示同量纲单位选择器，切换时数值同步换算。下方显示唯一 BOM 方案名称、默认开关、版本状态和保存按钮。较窄桌面不得把物料名称或单位压成竖排；移动端输入和输出上下排列，页面只保留一个纵向滚动容器。
- BOM 全览在桌面端使用左侧物料选择、右侧双向关系的主从布局；右侧“作为产出”和“作为投入”必须同时可达。移动端改为上下排列，物料选择与关系内容不得横向溢出；从任一结果点击“打开编辑”后，BOM 设置必须选中对应方案。
3. 产品文档
   - “业务配置 → 文档类别”在桌面端和移动端均可新增、编辑一级/二级类别，且无页面级横向滚动；产品文档工具抽屉不再出现类别管理。
   - 在 390、1024 和 1440 宽度验证批量导入、字段设置和批量修改：多文件清单不溢出，基础字段不可删除，扩展字段编辑可触达，已使用扩展字段只能改名且不可删除，卡片/表格复选框与当前页全选一致；跨类别选择必须阻止提交，未勾选的字段不得被覆盖。
   - PDF 第一页缩略图可见，点击后全屏打开；产品全景图显示全部相关文档。
   - 卡片列数必须根据主内容区实际可用宽度自动计算，不能只按浏览器视口断点切换；窄窗口不得突然出现占满整屏高度的超大预览图。
   - 文档详情在桌面端为左侧紧凑摘要、右侧大预览；编辑态左侧字段区必须保持至少 22rem 可用宽度，不能把中文标签压成逐字换行，低于大桌面断点时改为单列。移动端改为预览优先的单列顺序；上传完成后停留在详情内，不自动进入全屏查看器。
4. 来料管理

来料管理在 360、768、1024 和 1440 宽度下均需验证长度型录入：供应商/物料输入筛选、数量（件）、总长度/单件长度切换、总重量、入账总长度预览和比例联动开关不得被遮挡或横向溢出。桌面端应并列实测与计价区，1024×768 及以上尽量不出现弹窗内层滚动条；窄屏只保留遮罩层的单一纵向滚动。编辑已有待收货单据时，连续修改至少两条明细，确认每次“保存整单”成功后仍停留在当前弹窗、清单使用服务端返回值刷新，点击“关闭”后才退出。
5. 生产订单
6. 派工管理
7. 库存管理
8. 管理类页面（生产 / 物流 / 工具中的对应入口）
9. 设备台账与事件弹窗
   - 1024、1440 和 1920 宽度核对事件入口、命令表单、时间线与固定底部操作区；360、390、414 和 768 宽度核对单列状态/动作、原因输入和事件卡，不得产生页面级横向滚动。
   - 基础资料弹窗不得出现状态字段；无 `equipmentEvents.update` 的账号可读时间线但不显示命令按钮。

## 7. 交付标准

- 桌面端至少验证：1024 x 768、1366 x 768、1440 x 900、1920 x 1080。
- 移动端至少验证：360 x 800、390 x 844、414 x 896、768 x 1024。
- 页面级 `document.documentElement.scrollWidth` 不得大于 `clientWidth`。
- 顶部工具栏、底部导航、操作菜单、详情弹窗不得互相遮挡。
- 主要业务操作在当前设备形态下必须可发现。
- 验证结果应记录在测试说明或修复报告中，不能只凭主观印象。
