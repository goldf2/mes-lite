# MES-lite 页面模块分类与接入清单

本文是全系统页面骨架的唯一分类清单。功能页面只能归入以下六类；新增页面必须先选择既有类别，不得默认新建一套页面结构。

## 1. 六类页面模块

| 模块 | 适用场景 | 公共职责 | 业务页面保留职责 |
| --- | --- | --- | --- |
| 工作台 `workspace` | 仪表盘、全部功能 | 页面边界、间距、导航连续性 | 指标聚合、快捷入口规则 |
| 资源 `resource` | 设备、员工、客户、供应商 | 搜索、筛选、列表/卡片、空态、新增入口 | 字段、校验、接口与领域动作 |
| 主从 `master-detail` | 物料、BOM、文档、库存 | 列表/详情连续布局、窄屏模式、浮动呼出 | BOM 计算、附件、库存成本等领域内核 |
| 交易 `transaction` | 订单、来料、发货、退货、流程转移 | 页面边界、工具栏位置、连续上下文 | 状态流转、过账、冲销和审计 |
| 设置 `settings` | 单位、库位、工艺、权限、归档 | 统一设置页边界和资源操作约束 | 设置项语义、权限边界 |
| 工具 `utility` | 锯切成本、扫码打印、数据工具 | 工具页边界、响应式空间 | 计算器与硬件交互 |

六类模块由 `lib/page-modules.ts` 统一注册，所有生产页面由 `PageModuleBoundary` 渲染。每个页面都声明 `toolbar: required` 并通过 `TopBarPortal` 或应用壳注册公共工具栏；没有列表能力的页面也由公共框架显示禁用搜索、高级搜索和视图槽位。遗漏时公共边界会在开发环境直接报错。修改通用页面间距、页面语义或模块级响应式规则时，只修改公共边界。

## 2. 全系统覆盖

- 工作台：仪表盘、所有功能。
- 资源：设备台账、供应商、客户、员工。
- 主从：物料管理、BOM 设置、BOM 全览、产品文档、库存管理。
- 交易：生产订单、生产订单新增/详情、派工、流程转移、来料、销售订单、发货、退货。
- 设置：库位、单位、文档类别、工作中心、加工工艺、物料路线、业务设置、显示设置、导航与工作区、AI 服务、归档、操作记录、人员管理、人员权限、组权限。
- 工具：锯切成本、硬件工具、数据工具。

`npm run verify:page-modules` 会校验全部 38 个稳定页面入口均已归类、物料三个子页面映射正确，并核对 38 个页面全部强制使用公共顶部工具栏。页面注册有增删时，必须同步修改注册表与校验脚本。

## 3. 全页面标准化审计（2026-08-08）

审计口径不是要求每个页面都出现卡片和列表按钮，而是判断同一数据集合是否确实存在两种有价值的阅读方式。没有集合、以编辑为主、层级关系固定或以事务步骤为主的页面，应保留固定形态，并由公共框架显示禁用的视图槽位。

统计结论：

- 稳定页面入口：38 个，全部已注册六类页面模块并要求公共顶部工具栏。
- 已标准化多视图：19 个，具备公共视图切换和用户偏好保存。
- 应补多视图：0 个，本轮审计确认的集合型页面均已完成。
- 固定形态合理：19 个，不应为了形式统一强行复制卡片或列表。
- 核心附件单据：6 类；生产订单、销售订单、来料、派工、发货、退货均已将列表收口为附件摘要，并在详情使用同一附件管理骨架。

### 3.1 本轮改造结果与后续顺序

1. 已完成：销售订单接入 `usePersistedViewMode` 和公共 `ViewModeToggle`，卡片与紧凑列表共用同一搜索、筛选、排序、附件摘要和详情入口。
2. 已完成：流程转移增加紧凑列表；保留卡片作为现场可读模式，不复制请求和状态流转逻辑。
3. 已完成：来料、派工、发货、退货的列表附件控件改为 `compactMode="summary"`，完整附件管理进入公共 `BusinessDocumentDetailDialog`。
4. 后续 P2：交易页逐步迁入 `modules/<domain>/`，但只有在触及该页面或能明显降低耦合时实施，不为目录统一进行一次性大搬迁。

### 3.2 标准化验收条件

- 卡片和列表必须共用同一数据源、搜索条件、排序、分页和业务动作，禁止复制两套请求。
- 视图切换使用公共 `ViewModeToggle`，偏好通过 `usePersistedViewMode` 按页面键保存。
- 列表只显示附件数量摘要；上传、预览、下载、归档与 AI 识别进入详情的公共 `AttachmentPanel`。
- 固定形态页面仍使用公共顶部工具栏；没有可切换视图时保留禁用槽位，不伪造无意义的卡片模式。
- 新增或删除页面入口时必须同步更新本表，并通过 `npm run verify:page-modules`。

## 4. 公共能力的生产调用

- `ResourcePage` / `ResourcePageShell`：设备台账、员工资料、单位、库位、供应商、客户、工作中心、加工工艺和工艺路线；统一标题、搜索、高级条件、列表/卡片、加载、空态和新建入口。
- `AdaptiveMasterDetailWorkspace`：供物料、BOM、文档和库存等主从页面按垂直切片继续接入；窄屏浮窗、上下分区和切换模式由公共模块提供。
- `OneToManyRelationField`：产品文档的适用工作中心。
- `ManyToOneRelationField`：员工档案绑定登录账号。
- `OneToOneRelationField`：固定单对象关联；和多对一共享单对象骨架。
- `RelationSearch`、`RelationItemRow`：统一搜索、防重复、对象身份和移除操作。

复杂业务页允许保留专用内核，但外围必须经过所属页面模块，不得复制页面工具、响应式边界或关联选择骨架。

## 5. 新页面接入顺序

1. 在 `lib/page-modules.ts` 注册稳定页面键并选择六类模块之一。
2. 在页面入口使用 `PageModuleBoundary`；常规主数据直接组合 `ResourcePage`。
3. 将 `toolbar` 声明为 `required`，并通过 `TopBarPortal`、`ResourceToolbar` 或应用壳工具槽注册；不得在内容卡片复制工具栏。没有列表能力时仍保留公共禁用槽位。
4. 对象关联使用 `OneToOneRelationField`、`OneToManyRelationField` 或 `ManyToOneRelationField`，领域附加字段通过 `renderFields` 注入。
5. 库存、成本、状态流转、确认和冲销继续使用专用领域组件，不配置化其事务规则。
6. 运行类型检查、页面模块校验、构建，并至少回归一个桌面视口和一个窄屏视口。
