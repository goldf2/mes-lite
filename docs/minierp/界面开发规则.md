# MES-lite 界面开发规则

> 全系统页面只允许使用工作台、资源、主从、交易、设置和工具六类公共骨架。完整分类、覆盖清单和接入顺序见《页面模块分类与接入清单》。新增页面先注册模块类型；公共能力不足时先扩展公共组件，再由业务页调用。

本文用于后续界面开发前自查，目标是让所有页面的视觉、按钮、筛选、表格、卡片、弹窗保持统一。页面不应各自自由拼样式，通用视觉必须集中在公共组件和设计令牌中维护。

系统级交互语义、设计令牌、公共组件边界和页面完成定义以 `docs/minierp/系统交互与设计规范.md` 为主。本文作为开发阶段的详细实现清单；如有冲突，以主规范为准。

本文件只定义共通规则。桌面端和移动端必须分开设计、分开验收：

- 系统主规范见：`docs/minierp/系统交互与设计规范.md`
- 桌面端规则见：`docs/minierp/桌面端界面开发规范.md`
- 移动端规则见：`docs/minierp/移动端界面开发规范.md`
- 响应式断点和模拟验收见：`docs/minierp/响应式断点与验收矩阵.md`
- 应用壳、导航分层和单区/双区工作区见：`docs/minierp/layout-architecture.md`
- 草图到实现的协作流程见：`docs/minierp/界面草图到实现流程.md`
- 吸收低代码平台优点的内部配置化框架见：`docs/minierp/配置化页面框架规划.md`
- 公共资源、关系和主从布局模块调用见：`docs/minierp/公共前端模块使用指南.md`

## 1. 核心原则

- 视觉规则集中：按钮、状态标签、表格、卡片、筛选、弹窗、文件查看器必须由公共组件提供。
- 所有前端页面必须使用公共应用壳、资源工作区和公共语义组件；不得为单个模块独立创建平行的页面框架。
- 业务页面只负责数据、权限和业务动作，不直接决定按钮颜色、行高、圆角、阴影、状态颜色。
- 一个功能只允许一个标准文案：创建独立对象统一使用“新建＋对象名称”，加入已有对象或明细使用“添加”，不要混用“新增”“新建”“创建”。
- 一个功能只允许一套标准尺寸，例如行内“详情”按钮不能有的高 28px、有的高 36px。
- 一个功能尽量固定一个位置，例如列表行操作统一在最右列，页面主操作统一在顶部工具栏右侧。
- 不通过复制粘贴页面代码保持一致；通过 `Button`、`DataTable`、`ResourceToolbar`、`DetailPanel` 等组件保持一致。
- 开发前先搜索现有控件、Hooks、资源配置和相邻页面；已有能力必须复用，能力不足时必须先扩展公共模块或增加稳定扩展点。
- 常规查询、新增、修改、归档、恢复和关联编辑必须使用统一页面骨架，业务页面主要提供字段配置与领域扩展，不独立复制整套 CRUD。
- 同一交互出现两次或已有明确的第二使用场景时，必须提取公共模块；仅领域主体允许有记录理由的专用组件，外围结构仍使用公共框架。
- 页面或组件迁入 `modules/` 后必须确认 Tailwind 扫描范围仍覆盖新目录；结构验收必须阻止“组件迁移成功但模块专用样式未生成”的发布。

## 2. 推荐组件分层

当前第一批公共原语已经落地，后续新增或重构页面优先直接复用：

```txt
app/components/
  AppButton.tsx               # 按钮颜色、尺寸、禁用和键盘焦点
  ControlTooltip.tsx          # 顶部纯图标工具按钮的深色提示标签
  FormField.tsx               # 标签、必填、提示、错误和输入框样式
  NumberInputField.tsx        # 数值约束、步长和单位后缀
  MetricCard.tsx              # 常规/紧凑指标与语义色
  ModalOverlay.tsx            # 遮罩、Esc、焦点恢复和页面滚动锁定
  ModalDialog.tsx             # 标题、正文、固定底部操作区和响应式宽度
  SearchableSelect.tsx        # 动态业务数据的输入筛选选择器
  MaterialChoiceSearch.tsx    # 物料编码、名称和业务徽标搜索
  SortableTableHeader.tsx     # 可排序表头及 aria-sort
  ResponsiveToolbarActions.tsx
  ViewModeToggle.tsx
  resource/                    # 资源列表、卡片、详情、表单和页面骨架
  relations/                   # 一对一、一对多、多对一关系模块
  layout/                      # 主从工作区、分隔线和边缘呼出按钮
```

状态标签、数据表格和文件查看器继续按本文规则收敛。已有公共组件覆盖的交互禁止业务页面重新手写同类样式。

### 2.1 系统级配色

- 系统配色用于调整视觉对比度，不作为按钮品牌色换肤。蓝色继续表示主操作，绿色表示新增或成功，琥珀色表示提醒或归档，红色表示错误或危险操作。
- 页面背景、容器背景、边框、标题、正文和辅助文字统一读取 `--mes-color-neutral-50` 至 `--mes-color-neutral-950` 中性色令牌，业务页面不得建立独立灰阶。
- 系统预置“柔和”“标准”“高对比”三种模式，由“配置 / 系统设置 / 页面对比度配色”统一维护；切换后必须同步影响页面层级和可读性，而不是只改变按钮颜色。
- 高对比模式必须强化容器边界、标题、正文和辅助文字反差；柔和模式可以弱化分隔，但正文仍需保持可读。
- 配色由服务端首屏直接应用，避免刷新闪色。公共组件需要新的层级色时，先在 `app/globals.css` 增加语义令牌，再由组件调用。

## 3. 按钮规范

### 3.1 标准按钮文案

- 新增：统一写“新增”。页面标题已经说明模块时，不写“新增来料”“新增派工单”“新增指导书”。
- 详情：统一写“详情”。用于打开资料、单据、指导书等详情面板。
- 全屏打开：统一写“全屏打开”。用于直接查看图片、PDF、指导书、图纸等展示内容。
- 编辑：统一写“编辑”。详情内编辑基础信息时可写“编辑信息”。
- 保存：统一写“保存”。保存后进入上传流程时可写“保存并上传文件”。
- 取消：统一写“取消”。
- 关闭：统一写“关闭”或使用关闭图标，但同一弹窗内不能同时混用多个关闭文案。
- 归档：统一写“归档”。所有软删除都用归档文案。
- 恢复：统一写“恢复”或“恢复归档”，归档记录页面优先写“恢复归档”。
- 导入、导出、上传、下载、打印、调整：必须使用这些固定词，不再另写近义词。
- 业务页面展示客户时只显示客户名称，不同时拼接客户编码；客户编码是系统内部编码，由后端自动生成，只用于旧版导入兼容和内部关联。
- 用户侧统一使用“物料”作为物品主数据名称，不再新增“产品资料”维护入口；成品通过物料分类表达。
- 输入筛选式弹出列表统一使用筛选框响应模式：输入框聚焦后展开，点击列表外任意页面区域或按 `Esc` 收起，点击列表内部选项不误触底层页面。

### 3.2 按钮视觉级别

- `primary`：页面主确认动作，例如保存、确认、全屏打开。
- `create`：新增类动作，例如新增、新建首条记录。
- `secondary`：普通动作，例如详情、导出、下载、取消。
- `archive`：归档动作，使用琥珀色边框或弱警示样式。
- `danger`：不可逆或高风险动作，使用红色；当前系统原则上少用。
- `ghost/icon`：顶部菜单、关闭、视图切换等弱操作。
- 颜色映射固定：新增为绿色，保存/提交/确认等主动作为蓝色，取消/导入/导出等普通动作为白底灰边，归档为琥珀色，冲销/永久删除等危险动作为红色。颜色表达动作语义，不由各页面自行选择。

### 3.3 按钮尺寸

- 顶部工具栏按钮：高度 36px 到 40px，文字 12px 到 14px。
- 表格行内按钮：高度 28px 到 32px，文字 12px。
- 卡片底部按钮：高度 30px 到 34px，文字 12px。
- 弹窗底部按钮：高度 36px 到 40px，文字 14px。
- 图标按钮：宽高一致，常规 32px；移动端不得小于 36px 可点击区域。
- 同一行内按钮必须同高、同圆角、同字号。

### 3.4 按钮位置

- 页面主操作放顶部工具栏右侧：新增、导入、导出、调整。
- 行内操作放最右列，顺序固定：全屏打开 / 详情 / 编辑 / 上传 / 打印 / 归档。
- 卡片操作放卡片底部右侧，顺序同表格行内操作。
- 弹窗底部操作放右侧，顺序固定：取消、保存。
- 弹窗底部只保留一组最终操作；“保存”“提交”“确认”按真实结果三选一，不能在正文和底部重复放置同一动作。
- 关闭按钮放弹窗右上角。
- 不能把高频操作只藏在二级菜单里；二级菜单只放低频、危险或批量操作。

## 4. 应用壳与页面工具栏

### 4.1 桌面工作区形态

- 公共应用壳只提供“标准管理”和“画布工作”两种桌面形态。标准管理由左侧导航、顶部页面工具和中央正文组成；画布工作由顶部导航、中央正文和右侧页面工具组成。
- 两种形态必须复用同一页面注册表、权限、路由、正文节点和 `ResponsiveToolbarActions`。切换只改变公共容器位置，不得让业务页维护第二份导航、工具栏或页面实现。
- 全局形态切换入口固定在应用壳右侧全局控制区，并在“系统设置 → 显示设置”提供持久化设置；禁止把工作区形态或左栏行为放入每个页面的页内选项。
- 标准管理的左栏允许“常驻显示”和“自动隐藏”。常驻模式占据固定宽度；自动隐藏收起后只保留一个导航图标，鼠标进入左侧感应区或点击图标时以覆盖层呼出。
- 自动隐藏的临时呼出必须使用 `transform` 等不参与正文排版的覆盖层，不能修改主内容边距、触发重排或让页面左右跳动；鼠标离开后延时收回，进入面板或操作按钮时取消收回计时。
- 左栏自身必须提供固定/自动隐藏切换按钮。固定后正文按保存宽度让位；改为自动隐藏后正文立即释放占位。导航选择成功、按 `Esc` 或明确关闭时收起临时面板。
- 画布工作的顶部一级导航使用紧凑纯文字按钮，不显示一级菜单文字图标或下拉箭头；导航保持单行，宽度不足时把低优先级入口收进“更多”。右侧页面工具栏独立滚动，搜索、高级搜索、视图、页内选项、二维码和业务动作仍由公共工具组件提供。
- 小于 `1024px` 时忽略桌面形态偏好并复用统一移动端外壳；不得再引入第三套平板工作区。

### 4.2 公共工具栏

- 顶部首层固定保留关键词搜索、高级搜索、视图方式和页内选项四个公共槽位；当前页面不支持搜索、高级搜索或视图切换时必须显示禁用态，不得删除槽位造成切页跳动。
- 高级搜索、视图方式和页内选项统一使用公共图标按钮；业务页不得复制文字版页内选项或把视图切换塞进新增、导入等业务操作组。
- 快捷搜索、高级搜索、视图方式、页内选项、页面二维码和 AI 助手属于顶部通用工具，桌面端统一使用纯图标按钮与 `ControlTooltip` 深色提示标签；新增、导入、导出等业务动作继续保留文字。
- 轻量主线页面必须在首层提供文字搜索：物料、来料、工单、库存、销售订单、发货、退货和产品文档都不能只有下拉或勾选筛选。
- 关键词搜索和搜索选择统一忽略拉丁字母大小写；例如输入 `abc` 必须能匹配编码或名称中的 `ABC`。
- 公共关键词搜索框内置“智能搜索”开关并默认开启，偏好保存在当前浏览器。开启时空格分隔多个关键词，每个关键词可以分别命中当前页面声明的任意搜索字段，全部关键词均命中才保留记录；关闭时将整段输入作为一个连续短语查询。
- 公共关键词搜索框允许资源声明即时或显式提交模式。数据量较大的服务端列表应使用显式模式：输入过程中不得发请求，回车或点击纯图标搜索按钮后执行；存在待执行关键词时搜索按钮使用主色提示。清空输入立即执行空搜索，快捷搜索预置点击后直接执行。业务页面不得自行添加第二个搜索状态或复制搜索按钮。
- 智能搜索的字段范围仍由每个资源的 `ResourceSearchProfile` 或对应服务端查询配置声明，页面不得将未授权字段、密钥、内部备注或任意数据库列自动暴露到搜索范围。
- 具有主关键词搜索的列表页统一提供“快捷搜索”：用户可将当前搜索词保存为页面独立的预置项，后续点击立即回填并执行搜索；快捷项只保存到当前浏览器，不写入业务数据库，最多保留 20 项并支持单项删除。
- 快捷搜索只用于页面主列表筛选，不用于新增/编辑弹窗中的临时物料选择器；同一页面的桌面和紧凑布局必须共用同一份本地预置。
- 类别、状态、客户、供应商、物料和文件类型等业务条件统一进入高级搜索；生效条件数显示在高级搜索入口上。
- 排序、字段显示、摘要可见性和列宽恢复属于当前视图偏好，统一进入页内选项，不得混入业务搜索条件。
- 页内选项至少提供当前页面顶部工具组排序和“显示不可用工具占位”开关；占位默认开启，全局显示偏好不得进入页内选项。
- 页内选项使用紧凑设置布局：标题和控件已能表达含义时不再重复段落说明；必要提示压缩为标题旁短语，避免说明文字挤占纵向操作空间。
- 高级搜索窗口不得超过视口，内容超高时在窗口内部滚动，不能贴边溢出页面。
- 新增、导入、导出、上传、调整等高频操作按钮必须暴露在首层。
- 顶部工具栏不得换行或产生页面级横向滚动条；搜索框固定占据左侧弹性空间，其他按钮靠右。宽度不足时按公共框架收进“工具”菜单，筛选窗口可作为手机底部抽屉或浮层。
- 仪表盘、统计分析等总览页不默认提供卡片/列表切换，避免变成生硬表格。
- 仪表盘生产指标分开表达“生产订单”和“班后实绩”：订单按创建时间统计，产量只汇总已确认实绩的主产出；实绩草稿作为待处理项，已冲销实绩不计入产量。旧独立生产日报不得继续叠加，避免重复报产。

## 5. 筛选控件

- 勾选类筛选在筛选窗口内使用可见复选框。
- 不在显示界面提供筛选项手动排序、拖动排序、左移右移按钮，避免浪费空间。
- 筛选状态应尽量保存在浏览器本地，避免刷新后丢失用户习惯。
- 当前一级页面、物料子页面和页面纵向滚动位置按账号保存在浏览器本地；刷新后恢复到原页面和浏览断点。已失效或当前账号无权限的入口必须回退到默认可访问页面，不能绕过权限检查。
- 物料、客户、供应商等数据量可能较大的选项，优先使用“输入搜索后选择”，避免长下拉框。
- 搜索选择不能只依赖前端已加载的少量数据；输入关键字时应调用后端查询。
- 来料新增/编辑弹窗中的供应商和物料字段必须使用可输入筛选选择器：供应商支持名称、编码、联系人和电话，物料支持名称、编码和规格；两者均支持键盘上下选择、回车确认、`Esc` 收起和清除已选项，不得退回原生长下拉框。
- 客户筛选必须和页面显示逻辑一致，例如产品文档只按关联产品的客户判断有效客户。
- 动态业务数据统一使用可输入筛选选择器，包括物料、客户、供应商、库位、工单、工序、单位、文档类别和模板；匹配忽略拉丁字母大小写，并允许用编码、名称和业务关键词命中。
- 高级搜索属于所有可搜索数据页面的公共检索能力，按钮固定紧邻关键词搜索栏；各页面只声明可检索字段、字段类型和取值范围。弹层必须列出该页面的全部精确检索字段，用户直接在对应字段输入或选择条件；具有预置取值的字段也必须使用可编辑联想框，允许键入标签或底层值并随输入显示候选，不得退化为只能下拉选择。不得用快捷筛选集合冒充高级搜索。旧 `filters` 工具栏接口禁止使用；无可搜索数据的页面统一显示禁用占位。
- 只有固定且数量较少的枚举可保留普通下拉，例如状态、优先级、排序方向、每页条数、损耗方式；动态数据不得使用会无限增长的原生长下拉。
- 输入筛选选择器统一支持：聚焦展开、上下键移动、回车确认、`Esc` 收起、点击外部收起、清除已选项；弹出列表不得被父容器裁切或误触底层页面。

## 6. 表格规范

- 所有表格优先复用 `DataTable`。
- 表头背景、字号、行高、边框、空状态、分页位置必须统一。
- 表格可以在自身容器内横向滚动，但不能撑破页面主容器。
- 操作列固定在最右侧；字段显示过多时优先做字段控制，不随意缩小所有列。
- 桌面表格默认自动分配列宽；数据内容差异较大时，表头右边界应允许拖动调整列宽，双击单列或点击“恢复自动列宽”回到自动布局，个人列宽保存到浏览器本地。
- ID、编码、单号使用等宽字体；名称、备注允许换行或截断。
- 金额、数量、库存应有统一格式化方法，不能每个页面自行 `toFixed`。
- 标准业务清单中有明确比较意义的文字、编码、状态、时间、数量和金额列都必须点击表头排序；首次点击升序，再次点击降序，当前列显示箭头并设置 `aria-sort`。
- 图片、附件、操作列、可编辑明细、权限矩阵和横向指标对比表不排序；例外必须由内容性质决定，不能因为实现麻烦而省略。

## 7. 卡片规范

- 卡片只用于移动端优先视图、资料卡、实体摘要，不用于包裹整个页面大区块。
- 卡片圆角不超过 8px，避免过度装饰。
- 卡片信息顺序固定：编码/状态、名称、关键属性、数量/金额、操作。
- 卡片操作放底部右侧；不要把主要按钮放在卡片中部打断阅读。
- 卡片和列表必须展示同一批核心字段，不能卡片有字段、列表缺字段导致理解不一致。

## 8. 详情、编辑、弹窗

- 详情页优先使用 `DetailPanel` 或统一 `Modal`。
- 所有弹出窗口默认居中显示，统一使用会屏蔽底层点击的遮罩层，避免误触底层按钮。
- 弹窗遮罩默认使用磨砂玻璃效果；用户可在“工具 / 系统设置”中关闭磨砂，只保留半透明遮罩。
- 详情顶部固定显示：编码、名称/标题、状态、关闭按钮。
- 详情内结构固定为：基础信息、业务信息、附件/原始凭证、操作记录。
- 编辑态在详情内切换，不单独弹出另一个样式完全不同的编辑窗口。
- 新增弹窗使用 `FormGrid`，字段按 2 到 3 列布局，避免一长条表单。
- 上传入口必须在详情里清晰可见，支持拖放时要有明确的拖放区域。
- 资料详情中的主图默认使用 `object-contain` 并限制响应式高度，不能按原图比例无限撑高弹窗；查看完整尺寸由全屏查看或原图链接承担。
- 全景页和总览页的卡片按自然高度排列，不能为了两列齐高把空状态或短列表拉成大块留白。
- 全景页应按业务模块组织内容，至少支持用户在本地调整模块显示、顺序、宽度和显示密度；后续可迁移到账户级配置。
- 一次性批量数据工具统一放在“工具 / 数据工具”，必须先展示影响数量、冲突和转换示例；存在阻塞问题时禁用执行按钮，并在执行前再次确认。
- 全局业务规则统一放在“工具 / 系统设置”，必须标明对所有客户端生效；当前物料编码数字自然排序开关需说明 `2 < 12`、不修改编码，并保证列表和导出使用相同规则。
- 当前浏览器偏好也可集中展示在“系统设置”，但必须明确标注仅保存在当前浏览器，不能与全局业务规则混淆。

### 8.1 标准弹窗行为

- 普通新增、编辑、确认、冲销、类别管理和资料详情统一使用 `ModalDialog`；沉浸式文件查看器、全景工作区和移动端全高导航抽屉是明确例外。
- 弹窗结构固定为“标题/说明 → 可滚动正文 → 固定底部操作区”，关闭按钮固定在右上角；普通表单默认 `md`，多列业务表单用 `lg/xl`，只有高密度录入工作区使用 `wide`。
- 非处理中状态统一支持三种退出方式：右上角关闭、点击遮罩空白、按 `Esc`。关闭后键盘焦点返回原触发按钮；保存或提交过程中锁定关闭，防止产生不明确的半完成状态。
- 点击弹窗内部不得关闭；打开弹窗时锁定底层页面滚动；多弹层应避免，确需叠加文件全屏预览时，查看器必须通过公共根级浮层显示在详情之上，`Esc`、关闭按钮和焦点圈定只作用于最上层，退出后恢复原详情上下文。
- 移动端弹窗接近全屏，底部操作区避开系统安全区和 MES-lite 底部导航；桌面端不得无限放大表单阅读宽度。

### 8.2 表单与保存反馈

- 字段统一显示标签，必填项使用红色 `*`；帮助说明放字段下方，校验错误就近显示在对应字段下方，并在提交失败后聚焦首个错误字段。
- 保存采用显式提交：普通业务表单修改不会静默写入数据库，用户点击“保存/提交”后统一校验并提交；只有视图模式、列宽、快捷搜索等浏览器偏好可以自动保存。
- 提交期间主按钮显示处理中状态并禁用重复点击；业务保存接口确认成功后立即关闭弹窗，列表和关联缓存改在后台刷新，不得让已保存的表单继续停留在“处理中”。业务保存失败时保留用户输入并显示可操作的错误信息；仅后台刷新失败时应明确提示“已保存但刷新失败”，不能误报保存失败。
- 全局操作提示必须使用高于普通弹窗遮罩的根级固定层；弹窗内触发校验或请求错误时，提示保持在遮罩上方清晰显示，不能跟随后台内容一起模糊。
- 有未保存修改的长表单在关闭前应提示；只读详情、空表单和未修改表单可直接关闭。
- 设备运行状态不是普通资料字段：设备新增/编辑不得出现状态下拉。开机、停机、故障和恢复使用独立事件弹窗，当前状态、合法动作、原因、操作人、发生时间和故障/停机持续时间必须可见；无命令权限时保留只读时间线，不显示动作按钮。

### 8.3 加载、空状态与数据格式

- 加载、空结果、无权限、请求失败必须使用稳定且可辨识的状态，不得留下空白页面；空结果应说明是“暂无数据”还是“筛选无结果”，并在有权限时提供新增或清除筛选入口。
- 服务端列表搜索必须保证“最后一次查询生效”：新关键词发起查询时取消或废弃上一轮请求并显示加载状态，旧响应不得覆盖新结果；请求失败时不得保留旧列表伪装成当前搜索结果。
- 时间统一按中文本地格式显示，编码/单号使用等宽字体；数量保留业务所需有效小数并去除无意义尾零，金额统一使用人民币符号和固定货币精度，单位紧跟数值且来源于单位目录。
- 列表刷新时尽量保持搜索、筛选、排序、页码和滚动位置；提交成功后仅重置本次弹窗表单，不重置用户的页面浏览偏好。
- 页面断点恢复只保存导航与只读浏览位置，不自动恢复或提交未保存的业务表单；业务草稿仍遵守各单据明确的暂存规则。

### 8.4 页面深链接与二维码

- 每个功能页面必须拥有稳定的可分享 URL；页面、子页面、选中记录、列表/卡片模式以及明确允许分享的筛选条件写入查询参数，刷新或扫码进入后能够恢复。
- 业务卡片使用明确的响应式列数，物料等紧凑信息卡最多四列、文档预览等大卡最多三列；筛选后只有一条记录时也必须保持正常列宽，不得因 `auto-fit + 1fr` 被拉伸成列表行。
- 加载、错误提示、滚动位置、拖动位置、临时弹窗以及未保存表单不得写入二维码或分享链接。
- 公共顶部框架统一提供当前页面二维码入口；宽屏显示独立图标，紧凑桌面和移动端收进“工具”菜单，二者必须调用同一个二维码弹窗，业务页面不得各自实现不同版本。
- 顶部一级菜单按钮已经承担分组标题语义，普通二级菜单弹层不得再次显示相同的一级菜单名称；搜索和“更多”这类聚合弹层可以保留独立标题。
- 普通顶部二级菜单根据项目数量使用 288px 或 384px 宽度；仅搜索和“更多”聚合菜单允许使用 544px 宽度，避免普通菜单出现大面积空白。
- 二维码下载使用公共信息卡模板，支持编辑页面标题、功能路径、说明、页脚及显示字段；二维码本体和四周留白属于受保护区域，不允许被装饰或文字覆盖。
- 下载模板保存为受校验的结构化配置，不接受任意 HTML；系统模板和个人模板必须明确区分，本次临时编辑不得隐式覆盖默认模板。
- 扫码进入系统后仍执行登录和资源权限校验；二维码只表达入口和状态，不能作为授权凭证。

## 9. 文件与图片查看

- 图片、PDF、文本、Office 文档、作业指导书和单据凭证统一使用公共文件查看器。
- 产品文档中的 PDF 和 Office 文件必须显示第一页缩略预览；Office 原文件由服务器按需转换为只读 PDF，预览 PDF 和缩略图保存在附件持久化目录。图片派生图同样由服务器生成，禁止每次在浏览器重复渲染。物料列表与关系选择器使用缩略图，详情使用展示图，并保留明确下载原文件的入口；方向变化使用对应方向的持久派生图。
- 优化图片 URL 必须包含原图大小、方向和优化规则版本，响应使用私有不可变缓存；物料缩略图默认缓存 90 天、展示图缓存 30 天，原图保持短缓存。客户端缓存只用于加速，不得作为原始图片备份。
- 从列表、详情或全景图打开文件时默认进入占满视口的查看器；查看器必须挂载到公共根级浮层并高于普通详情弹窗，不能被触发它的详情窗口遮挡。PDF 和 Office 预览初始完整适合页面并居中显示，不按页宽过度放大。图片、PDF 和 Office 预览均可按 90° 左右旋转，方向校正保存到附件记录，卡片、全屏查看和全景图必须使用同一方向。
- 产品文档不显示或录入“适用工序”，通用说明使用备注；文档类别从“业务配置 → 文档类别”维护，支持最多两级的新增、改名和无引用删除，产品文档工具栏不得重复提供类别管理。产品全景图不得截断相关产品文档。
- 产品文档必须录入独立标题，正文使用结构化在线编辑器并显式保存；产品关联是可选范围条件，未绑定时显示为通用文档。正文阅读优先于附件列表，附件仍使用统一文件查看器。
- 库存页展示物料库存时应显示物料封面缩略图，并提供打开原图的入口；成品图片需等产品附件模型补齐后再接入。
- 列表首层常用展示动作统一用“全屏打开”。
- 详情内附件可使用“打开”，但其行为也应进入同一个 `FileViewer`。
- 图片查看应支持放大、缩小、旋转、复位。
- PDF 查看应支持多页纵向滚动；渲染时将 PDF 页面的内置方向与附件保存的方向校正叠加，不改写原始文件。
- 文件归档只影响记录显示，不物理删除原始文件，除非后续明确增加物理清理功能。

## 10. 状态标签

- 状态颜色集中在 `status-styles.ts`。
- 同一状态在所有页面必须同色同文案。
- 常用状态建议：
  - 草稿：灰色。
  - 待处理、待审核、待收货：琥珀色。
  - 进行中、已派工：蓝色。
  - 已完成、已收货、已发货：绿色。
  - 拒绝、异常、库存不足：红色。
  - 已归档、已取消：灰色弱化。

## 11. 平台分离规则

- 桌面端服务大屏高效率录入、扫描、比对、批量处理，应优先展示表格、工具栏、筛选摘要、行内操作。
- 移动端服务窄屏快速查看、拍照上传、现场确认，应优先使用卡片、弹出菜单、底部抽屉、全屏详情。
- 移动端固定底部导航必须为主内容区预留“底栏实际高度 + 安全区 + 页面尾部间距”；分页、保存栏和步骤栏不得被底部导航覆盖，所有低于 `1024px` 的宽度均沿用同一规则。
- 不能用同一套布局硬适配两端；只能共用组件语义、按钮文案、状态颜色、数据格式。
- 同一功能在桌面端可以暴露多个高频按钮；在移动端应收敛到“更多”菜单或底部操作面板。
- 桌面端和移动端修改都必须分别检查，不能只看一个视口。
- 关键页面必须按主流分辨率矩阵做实际模拟，不能只凭 CSS 断点推测效果。

## 12. 权限、归档与危险操作

- 没有权限的操作应隐藏或置灰，不能显示后点击才报错。
- “删除”默认是归档/软删除，界面文案统一写“归档”。
- 高风险动作必须二次确认。
- 归档记录必须能在“工具 / 归档记录”中恢复。
- 永久删除只允许出现在“工具 / 归档记录”，必须要求输入“永久删除”，并在后端确认记录已归档、处于可删除状态且没有业务引用。
- 所有会改变数据的操作必须写入审计日志。

## 13. 禁止事项

- 禁止在业务页面里自由写一套新的按钮颜色、表格行高、卡片样式。
- 禁止同一功能出现多个文案，例如“打开/查看/详情”混用。
- 禁止同一页面顶部同时出现两排筛选按钮。
- 桌面端禁止把新增、导入、导出等高频操作藏进二级菜单；移动端统一收进首层“工具”抽屉。
- 禁止页面级横向滚动。
- 禁止卡片嵌套卡片。
- 禁止为了临时显示数据把表格列压到不可读。
- 禁止在日常业务页面新增物理删除入口；归档记录页的受保护永久删除是唯一例外。

## 14. 菜单和页面注册规则

- 当前轻量模式的一级菜单为工作台、物料、生产、文档、设备、物流、销售、库存、业务配置、系统设置、工具、账号与权限；标准管理布局在左侧原位展开二级功能页面，画布工作布局在顶部单行显示一级分类并通过弹出菜单展示二级功能。顶部一级菜单只允许点击打开或切换二级弹层，鼠标经过只提供视觉悬停反馈，不得触发任何菜单展开或切换。一级入口固定区分三态：当前页面使用浅蓝底、蓝字和细描边；临时选择并打开菜单的入口使用实心蓝主高亮；其余释放状态使用中性灰。再次点击当前选择、关闭弹层或点击空白处只释放临时选择，不得丢失当前页面标识。二级弹层必须从触发入口下方展开并受导航可用宽度约束，只有一至两个功能时使用紧凑单列尺寸，更多功能才使用宽型双列尺寸。两种布局必须使用同一菜单注册和权限结果。“产品文档”独立归入“文档”，“物流”保留来料，“销售”依次包含销售订单、发货和退货。桌面端在“物料”分类下直接提供物料管理、BOM 设置、BOM 全览；不再设置重复的 BOM 关系页面。“业务配置”包含供应商资料、客户资料、员工资料、库位配置、单位配置、加工工艺和物料路线；“系统设置”收纳显示设置和 AI 服务；“工具”只保留计算、硬件、归档、审计和数据维护工具；“账号与权限”收纳登录账号管理和权限配置。右上角账号下拉菜单只显示当前身份、版本和退出登录，不承载任何管理页面入口。低于 `1024px` 时统一使用移动端外壳：顶部使用菜单按钮、当前页标题和账户入口，菜单按钮打开按一级业务分组的左侧全高功能抽屉；底部只显示常用入口且不再重复设置“更多”，页面操作进入“工具”抽屉；模块内部稳定子页面最多保留一排二级页签。派工管理暂时作为隐藏高级模块。
- 桌面左侧栏不得重复显示“功能导航 / 当前页面 / 功能菜单 / 当前分类”等标题；当前位置直接由一级展开态或高亮和二级入口表达。双列导航的全局功能搜索横跨两列置顶，下面才分出一级列和二级列，不能把全局搜索框放进二级列。一级菜单使用单行排列，默认显示“图标＋文字”，并允许用户在“系统设置 → 显示设置”切换为“图标”或“文字”；三种模式必须复用同一菜单注册和导航逻辑。一级菜单行高保持约 `36–40px`，二级菜单约 `30px`，在保证桌面点击可用的前提下优先让常用笔记本高度展示完整业务分组。
- 标准业务清单的可排序列统一使用可点击表头；首次点击升序，再次点击降序，并用箭头和 `aria-sort` 明确当前排序。图片、附件、操作按钮、权限矩阵、输入明细和指标对比表不强制排序。
- 来料弹窗必须并列呈现数量（件）、总长度/单件长度切换和总重量，并实时显示主库存入账数量；比例联动只能在三值完整后由用户主动开启。采购计价区同时提供单价和总价格，单价单位只允许选择米、kg、件，修改任一金额时自动换算另一项。
- 来料弹窗在桌面端展开为宽幅 2–3 列表单，实测和计价并列，避免窄弹窗造成过长纵向滚动。表单自身禁止内层滚动；小高度屏幕确需滚动时，只使用遮罩层的单一滚动容器。
- BOM 工作区必须显示当前方案/版本、方案名、基准产出数量和默认状态；同一物料的不同方案不得共用未保存草稿，不显示已废弃的“方案类型”。
- 左侧是 BOM 的唯一选择区：每张卡片以 BOM 名称/版本为主信息，主产出和投入物料只作为摘要及搜索条件，不显示按产品/按投入切换。右侧只保留一个“BOM 名称”字段，用于新建命名和已有 BOM 重命名；不得再增加方案选择器或内部新建按钮，“新建 BOM”只在顶部工具栏出现一次。
- 所有页面必须在应用顶栏显示统一的页面选项齿轮；通用界面偏好始终可配置，页面专属参数按当前页面追加，不在页面工具栏重复入口。
- BOM 工作区必须明确分开“输入”与“输出”：每个 BOM 有且只有一项主产出，两侧均使用“搜索选择物料 → 直接填写每批数量”的逐项录入流程。全部输入组成整体消耗并共同对应全部输出，不建立逐输出投入关系，也不提供跨量纲转换。长度、重量行允许从单位目录选择同量纲录入单位，切换时同步换算当前数值；系统初始默认 `mm/g`，用户可通过页面选项修改当前浏览器的新行默认单位。每行必须显示可点击放大的物料缩略图、可直接检查和修改的数量、单位和移除操作；所有输出均可移除，移除主产出后按输出顺序自动选择下一项。BOM 不显示固定/百分比损耗字段，废料、废屑和可回收料通过其他输出录入；生产订单实绩中的计划外差异、实际投入和产出与 BOM 标准值分开展示。
- 生产订单创建页的方案字段命名为“BOM 方案”，且必须选择主产出物料的真实启用 BOM；班后实绩在订单详情内按“左侧投入—右侧产出”布局，逐项显示编码、名称、主单位、库位和实际数量。投入物料不按原材料分类限制。
- 业务选人必须使用员工资料选择器：班后实绩支持多选并以可移除标签显示，流程转移使用单选可搜索控件；员工编码、姓名和部门均可检索，不允许退回自由文本人员字段。
- 员工资料的编码由系统自动生成：新增弹窗显示“保存后自动生成”，编辑弹窗只读显示现有编码，不提供手工修改入口。账号绑定使用可清除的搜索选择器，列表同时显示已绑定账号及其状态。已经绑定其他员工的账号不可选，界面说明绑定不会改变账号权限。
- 流程转移必须使用独立页面和表单，不显示 BOM 选择器。只选择一个物料，左右卡片必须同时显示它的图片和基本信息；中间明确显示“同物料·同数量”，来源与目标库位不得相同。
- BOM 编辑器选择物料后立即在对应输入或输出区域新增一行，每种物料在同一区域只能出现一次。数量字段直接表示每批绝对量；数据库提交入口只保留方案名称区的“保存 BOM”，一次保存所有新增、数量修改和移除。存在未保存修改时必须明确提示，普通提示消息或服务端内容未变化的后台刷新不得覆盖待保存明细。
- 物料列表的 BOM 简况必须允许按浏览器偏好整列隐藏；显示时固定为统计和摘要两行，超出内容截断，不得因 BOM 内容较多撑高列表行。点击 BOM 简况表头按“组成行数 + 被引用行数”排序，排序必须覆盖全部筛选结果和分页。有 BOM 权限时，高级筛选必须支持区分未建立产出 BOM、有 BOM 但无启用方案、有启用方案但无默认方案和已有可用默认 BOM；操作列提供“创建 BOM”，在当前页打开宽模态窗口并自动将当前物料作为主产出。模态窗口复用完整编辑器的输入、输出、单位和保存口径，保存后关闭并刷新简况，同时保留“完整 BOM 设置”入口处理复杂维护。
- 物料新增、编辑、导入或归档成功后，必须同时刷新物料清单和 BOM 候选缓存；快速创建 BOM 和完整 BOM 设置都应立即使用最新物料，不得要求用户刷新页面。
- 桌面端所有业务页面的搜索、高级搜索、视图和主按钮进入公共页面工具容器：标准管理布局横向固定在顶部，画布工作布局纵向固定在右侧。当前一级与二级位置由公共导航明确表达，不再重复渲染页面标题带；页面列表、表单和统计内容使用单一内容滚动容器，滚动轨道必须稳定可见，禁止用父级 `overflow-hidden` 截断超出视口的正文。
- 页面注册必须显式声明是否要求顶部工具栏；存在页级搜索、筛选、视图、刷新、返回或新增操作时必须声明 `required` 并注册公共 `TopBarPortal`。只有没有独立页级操作的页面才能声明 `none`，禁止把 `none` 当作绕过公共框架的手段。
- 计量单位必须显示真实业务单位或通用国际符号（如“根、件、套、kg、m、mm”），不得把程序字段名 `unit` 当作界面单位；BOM 比例显示为“投入物料主单位/产出物料主单位”。
- BOM 设置是“BOM 列表 + 创建/修改”的主从工作台：左侧一条记录直接对应一个已有 BOM，以 BOM 名称/版本为主标题，产出和投入物料只作为摘要及顶部搜索条件。右侧首屏使用左“输入”、右“输出”，两侧均可搜索添加多项物料并直接填写每批数量；首项输出为主产出。下方只保留唯一“BOM 方案名称”、默认开关、版本状态和保存按钮。投入允许原材料、半成品或已有产品。未选完整时保存按钮仍显示但禁用。右侧编辑区整体使用页面最右侧的主内容滚动条；桌面左侧已有 BOM 列表允许受控独立滚动，移动端输入和输出上下排列。
- BOM 全览与 BOM 设置保持独立：左侧选择统一物料，右侧分别展示该物料作为产出和作为投入关联的直接 BOM。全览结果按 BOM 去重，每项显示版本、状态、目标产出及基准批量关系，并通过“打开编辑”精准进入 BOM 设置；不得在全览页重复放置创建或编辑表单。
- 登录成功或首次进入系统时默认打开“工作台 / 仪表盘”；如果当前人员无仪表盘权限，则打开其首个可读页面。
- 系统层级上限为“一级业务入口 + 一级页面 + 可选二级详情/子页”；高频入口放工作台，完整入口放工作台下的“所有功能”页，不得以嵌套第三级页面扩展菜单。
- 工作台常用功能设置保存到操作员账号，支持系统默认、按主动访问次数智能排序和自定义摆放；页面刷新、后台请求与程序自动跳转不得增加使用次数。
- 已进入左侧业务分类的页面不得再重复显示一整排同级页内导航，避免侧栏和内容区出现重复入口。
- 左侧分级菜单由公共应用壳统一管理展开、收起、键盘操作和 ARIA 状态，业务层只维护页面注册数据和选中状态。
- “工具 / 硬件工具”将扫码计数和标签打印并列展示，两者当前互不作为前置条件；设备状态、目标数量、错误反馈和打印校准参数必须在首屏可见。
- 新增功能页必须先进入统一页面注册表，桌面顶部、桌面侧栏、移动抽屉、移动常用入口和同级菜单必须共用同一份权限过滤后的导航模型，不得分别维护并行数据源。移动功能抽屉必须直接复用桌面 `DesktopNavigation` 的单列折叠模式；桌面顶部弹层与该单列菜单的“一级分组 → 二级条目”继续由公共 `UnifiedNavigationMenu` 渲染。各终端只允许配置外层位置和呼出方式，不得再次手写分组与条目循环。移动常用入口和同级菜单属于统一模型上的快捷入口，不得演变成第二套主菜单。
- 页面 `pageKey`、路由、权限资源与显示名称必须分离；改名和移动菜单不得改变权限或业务行为。
- 系统管理员负责一级目录、二级名称、默认顺序、启停和可隐藏范围。
- 终端用户只能在管理员配置和自身权限内调整个人顺序、折叠、隐藏和移动端常用入口。
- 第一阶段个人布局保存到带版本号的 `localStorage`；后续可同步到用户账户，并提供 JSON 导入导出。
- 菜单必须先应用管理员配置和权限过滤，再应用个人布局。
- 新页面不得覆盖现有菜单配置；未分类时放入“未分类功能”。
- 必须保留不可被普通用户隐藏的菜单管理和恢复默认入口。
- 完整数据模型、合并算法、安全边界和默认模板见 `docs/minierp/配置化页面框架规划.md`。

## 15. 新模块开发前检查

1. 是否已搜索 `app/components/`、`lib/`、资源配置和相邻页面，并列出准备复用的现有能力。
2. 公共框架能力不足时，是否先扩展公共模块或增加稳定扩展点，而不是在业务页面增加局部替代实现。
3. 常规 CRUD 是否使用统一资源页面骨架；多对象关联是否使用统一关联编辑骨架。
4. 若领域主体保留专用实现，是否记录公共能力不能满足的领域约束、影响范围和后续复用边界，并继续复用外围公共框架。
5. 是否使用统一按钮文案、尺寸、位置。
6. 是否有首层关键词筛选。
7. 精确条件是否进入统一高级搜索，并显示已生效条件数。
8. 是否把高频操作按钮放在首层。
9. 是否同时符合桌面端和移动端规范。
10. 是否避免页面级横向滚动。
11. 是否支持卡片 / 列表视图或明确说明为什么不需要。
12. 是否使用统一状态标签和统一状态文案。
13. 是否使用统一详情弹窗或详情面板。
14. 是否支持软删除 / 归档与恢复路径。
15. 是否按响应式验收矩阵检查主流分辨率。
16. 是否完成 `npx tsc --noEmit --pretty false` 和 `npm run build` 验证。
17. 是否通过统一页面注册表接入，并保持管理员与终端用户的已有菜单配置。
18. 动态业务选择器是否支持输入筛选、键盘选择、外部点击和 `Esc` 收起。
19. 标准业务表格是否为所有可比较列提供可访问的表头排序。
20. 普通弹窗是否支持关闭按钮、遮罩空白、`Esc`、焦点恢复和固定底部操作区。
21. 必填、校验、加载、空状态、失败和提交中状态是否明确。
22. 修改公共模块后，是否按调用方清单完成全局影响回归，而非只验证当前页面。

## 16. 后续重构顺序

1. 先抽 `Button`、`StatusBadge`、`FilterPopover`、`FileViewer`。
2. 再抽 `ResourceToolbar`、`DataTable`、`EntityCard`。
3. 先迁移产品文档、物料管理，因为这两个页面最能验证图片、筛选、详情和列表规范。
4. 再迁移来料、库存、派工、发货、退货。
5. 最后整理系统管理、权限管理、统计分析。
